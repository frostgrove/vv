### GAP-1 [high][immediate] `Spec.Park` beside `OnPermanentFailure: Halt` runs the whole blocking-and-parking path at a tier `New` refuses for `ParkSequence` — outside any transaction, and it duplicates letters

- **Where:** `event/projection/pass.go:376-381` (`delivering`), `:415-441`
  (`unblockedPage`), `:507-523` (`parking`); the gate that is missing is in
  `event/projection/spec.go:219-234` (`refusedPark` returns `nil` for anything that
  is not `ParkSequence`). The plan's refusal list item 11
  (`EVENTSOURCE_P4_PLAN.md:1276-1281`) declares this combination *"not refused; they
  are harmless"*.

  ```go
  func (this *Projection) delivering() applier {
      if this.spec.Park == nil || this.parked == 0 {
          return this.matchedPage()
      }
      return this.unblockedPage()          // no test on OnPermanentFailure
  }
  ```

- **What:** the *discovery* path is policy-gated (`applyFailed` reaches
  `sequenceBySequence` only when `OnPermanentFailure == ParkSequence`), but the
  *blocking* path is gated on `spec.Park != nil && this.parked != 0` alone. A spec
  with a `Park`, `OnPermanentFailure: Halt` (the zero value) and `Advance:
  AfterApply` (the zero value) is accepted by `New` and then asks `Holds` per
  envelope and writes letters — from `outsideAUnit`, where there is no transaction
  at all.

- **Why this severity:** driven, not argued. Two runs, both against the shipped
  tree with a `Park` decorator that records whether a unit was bound:

  ```
  # Spec{Park: held}, OnPermanentFailure default (Halt), Advance default (AfterApply)
  phase=degraded applied=1 quarantined=1 parked=1
  model rows=[C1]
  letters for a = 2
  park calls outside a unit = 3, written = 1, holds = 2
  ```

  and with the checkpoint save refused once with `ErrBackend` after the page has
  already parked:

  ```
  letters for a after the retried page: 3
    A1 at position 1
    A2 at position 1
    A2 at position 1          <- the same envelope parked twice
  quarantined=1
  ```

  The letter write cannot roll back because there is nothing to roll it back, so a
  postponed pass re-delivers the page and parks the same envelope again. The queue
  now holds a duplicate that a later `Redrive` applies **twice** (`drain` walks the
  letters it was handed, and a SQL park keys rows by `(sequence, index)`), and
  `Park.Holes` — which S4's `Cutover` is gated on — is inflated by one for ever
  while `Progress.Quarantined` reads 1. This falsifies INV-090's own clause *"It
  holds in every configuration that constructs, because `ParkSequence` constructs
  only at tier A"* and INV-091 outright, and it contradicts the module page's *"It
  constructs at that tier and no other, and `New` refuses the rest"*
  (`docs/modules/en/projection.md:346`). The same reachable-by-accident shape exists
  at `InUnit` + `Destination: Unchecked` + `Halt`, where the letter commits with the
  advance and the handler's writes do not.

- **Why this timing:** it is a public-contract hole S4 and S5 are about to build on
  — `Cutover` reads `Park.Holes`, and P-7's whole argument is that a composition
  root wires **one** spec builder for a live generation and a rebuild, which is
  exactly the wiring that leaves a `Park` beside a policy that is not
  `ParkSequence`. Fixing it after S4 means re-arguing INV-098's evidence.

- **Close criteria:**
  - [ ] `delivering()` and `parking()` are reachable only when
        `this.spec.OnPermanentFailure == ParkSequence`, **or** `New` refuses a
        `Park` supplied beside any other policy, naming the field.
  - [ ] A test with `Spec.Park` set and `OnPermanentFailure: Halt` asserts `Holds`
        is never called and no letter is written, with a `ParkSequence` control.
  - [ ] Plan refusal item 11 corrected: `Park` beside a non-`ParkSequence` policy is
        no longer described as harmless.
  - [ ] `go test -race -count=1 ./event/...` green.
- **Status:** CLOSED — see Round 2

### GAP-2 [high][immediate] The published `Park` contract says every method runs inside the caller's unit of work; `Sequences` runs outside it and `Holes` is never called at all

- **Where:** `event/projection/park.go:41-45`

  ```go
  // Every method runs inside the caller's unit of work under InUnit, through the
  // context it is given, and OnPermanentFailure: ParkSequence constructs at no
  // other tier. That is what orders a redrive's eviction against the loop's own
  // blocking test: they are rows in one transaction rather than two opinions
  // about what is parked.
  ```

  against `event/projection/pass.go:47-49` and `:78-89` — `counted` runs from
  `once`, **before** `deliver` opens the unit. `docs/ai/flows/FL-038…md:155` carries
  the same reading (*"The whole pass is one unit, the queue included"*).

- **What:** a decorator counting the bound unit per method, over a tier-A projection
  that parks and then meets a later page, reports:

  ```
  Sequences: inside=0 outside=4
  Holds:     inside=1 outside=0
  Park:      inside=2 outside=0
  Holes:     inside=0 outside=0
  ```

  Two of the four methods do not behave as the contract states. (`Holes` is S4's
  and is called by nothing in this phase, which is fine — but the comment promises
  otherwise.)

- **Why this severity:** `Park` is an extension point the **application** implements,
  and this comment is its only contract. Its own argument ("rows in one transaction
  rather than two opinions") invites an implementation that requires the ambient
  transaction — `crud.ExecutorFor(ctx, source)` followed by a refusal when `!bound`
  is the ordinary spelling in this repository. Such an implementation fails on every
  `Sequences` call; `counted` classifies a `Sequences` failure as a **postpone**
  (`pass.go:83-85`), so the projection retries for ever at `PhaseRetrying`, never
  advances, never halts, and reports an error about a table that is in fact
  reachable. The correctness of reading the count outside the unit is fine — I drove
  the redrive/loop interleaving and no envelope is applied out of order — so the
  defect is purely that the contract states the wrong fact about a seam a consumer
  writes against.

- **Why this timing:** it is a published interface contract that S4 extends
  (`Generations` gets the same treatment, and `Holes` becomes a real caller in
  `Cutover`). Getting the per-method statement right once is cheap; correcting it
  after two more implementations exist is not.

- **Close criteria:**
  - [ ] `park.go`'s comment states, per method, whether it is called inside the
        caller's unit — `Sequences` outside, `Holds` and `Park` inside, `Holes`
        wherever S4 calls it.
  - [ ] `docs/ai/flows/FL-038…md` step 6/7 and `docs/modules/{en,ru}/projection.md`
        carry the same statement.
  - [ ] A test counts, per method, whether a unit was bound on the context it was
        handed, and pins the four answers.
- **Status:** CLOSED — see Round 2

### GAP-4 [high][immediate] The mechanism's per-failure enqueue decision has no counterpart and no rejection note; an exhausted attempt budget parks every sequence of the page over a transient failure

- **Where:** the mechanism, quoted in
  `.agents/artifacts/usecases/EVENTSOURCE_P4_STUDY.md` §ES-03 §1 — *"The
  `EnqueuePolicy` returns an `EnqueueDecision` built by `Decisions.enqueue(cause)`,
  `Decisions.doNotEnqueue()`, `Decisions.evict()`, `Decisions.requeue(cause,
  modifier)`"* with the worked retry-counter policy that **evicts** after five
  attempts. The tree: `event/projection/pass.go:591-599`

  ```go
  func (this *Projection) permanent(err error) bool {
      if _, panicking := asPanic(err); panicking { return true }
      if this.spec.Classifier(err) == Permanent { return true }
      return this.attempt >= this.spec.Attempts
  }
  ```

  and `:461-500` (`sequenceBySequence`, which parks anything `permanent` answers
  true for). `grep -rn 'EnqueuePolicy\|EnqueueDecision\|Decisions\.'` over
  `EVENTSOURCE_P4_PLAN.md`, `EVENTSOURCE_P4_USECASES.md` and `docs/` returns **0** —
  it is neither adopted, adapted, nor listed under "What is deliberately absent from
  the surface" (`EVENTSOURCE_P4_PLAN.md:1393-1403`).

- **What:** the source has a four-way per-letter decision (enqueue, do-not-enqueue,
  evict, requeue-with-diagnostics). vv has a two-way per-**projection** flag
  (`Halt` / `ParkSequence`) and an attempt budget that silently promotes any
  retryable failure to permanent once spent. `Letter.Attempt` is published *"so a
  requeue can raise it and an implementation can decide when to stop trying"*
  (`park.go:18-19`) and there is no contract by which an implementation can act on
  that decision: `Touch` is the only call the redrive makes on a repeat failure and
  its documented meaning is "requeue with the new cause".

- **Why this severity:** a dropped nuance from the named mechanism, with nothing
  documenting why it does not apply, and a driven operational failure. `Attempts: 2`,
  a handler failing with a plain pool-exhaustion error (retryable by `Classify`), a
  page of four streams:

  ```
  quarantined=4 parked=4 phase=degraded
  sequences parked by a transient failure: [orders/a orders/b orders/c orders/d]
    b1 cause=the read model's pool is exhausted
    c1 cause=the read model's pool is exhausted
    d1 cause=the read model's pool is exhausted
    a1 cause=the read model's pool is exhausted
  ```

  A database that went away for `Attempts` passes converts the whole page into
  parked sequences that only an operator's redrive clears, walks the queue toward
  `ErrParkFull` (and thence `PhaseBlocked` for the partition), and leaves
  `Park.Holes` non-zero until every one is drained — which is what S4's `Cutover`
  refuses on. The rule itself is stated in `sequenceBySequence`'s comment and in the
  module page's failure table (`| Retryable, Attempts exhausted | Apply | becomes
  permanent |`); the **consequence under `ParkSequence`** is stated nowhere a
  consumer reads, and there is no seam by which they can refuse it.

- **Why this timing:** the shape of the answer decides whether `RedriveSpec` grows a
  field (GAP-3), whether `Letter.Attempt` means anything, and whether `Park.Park`
  gets a "do not enqueue" answer beside `ErrParkFull`. All three are public surface
  S5 extends.

- **Close criteria:**
  - [ ] A recorded decision: adopt a per-failure decision seam, or state in the plan
        and in `docs/modules/{en,ru}/projection.md` why `Classifier` + `Attempts` +
        the operator's eviction is the whole answer and what an operator does when a
        transient outage parks a page.
  - [ ] A use case covering "the attempt budget is spent on a retryable failure
        under `ParkSequence`", with its control (a permanent failure), in
        `EVENTSOURCE_P4_USECASES.md`.
  - [ ] A test asserting what a page of transient failures does once the budget is
        spent, counted in S3's (or a later section's) `-list` pattern.
- **Status:** CLOSED — see Round 2
