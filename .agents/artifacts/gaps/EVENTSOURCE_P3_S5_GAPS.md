  `eventmemory: a checkpoint row moved between the save this transaction staged and its commit`.
  Exactly one landed, and the row held one cursor. The fence holds; the loser's half is rolled
  back, as the page says.

### GAP-1 [high][immediate] INV-072's named proof exempts any exactly-once promise whose preceding sentence contains a negation, and a live sentence in [[D-128]] is already hidden by it

- **Where:** `scripts/docs_test.go:971-973` (`wording.refuses`), `scripts/docs_test.go:782`
  (the English `negation` regex), reached from `TestNoDocPromisesExactlyOnceDelivery`
  (`scripts/docs_test.go:801-820`); the live wording is
  `docs/ai/decisions/D-128-the-log-delivers-in-position-order.md:74`.
- **What:** `refuses` treats a promise as refused when the `negation` regex —
  `\bno\b|\bnot\b|\bnever\b|\bnothing\b|\bnone\b|non-goal|\bcannot\b|\bwithout\b|n't\b` — matches
  `attachedTo`, which is *the whole preceding sentence* plus the clause the phrase sits in. Any
  negation word anywhere in the sentence before a promise licenses that promise. In a repository
  whose house style is deliberately negative-heavy prose ("Nothing here writes a line", "The
  framework deduplicates nothing", "there is no head"), that is not a narrow exemption.

  Driven: replacing the delivery row's own sentence in `docs/modules/en/projection.md:77` with
  `The framework deduplicates nothing. Every event reaches the handler exactly once, so a read
  model needs no idempotency of its own.` left `TestNoDocPromisesExactlyOnceDelivery` **green**.
  Deleting only the four-word first sentence made it fail immediately —
  `../docs/modules/en/projection.md:77 promises exactly-once delivery, and delivery in this
  repository is at least once`. The identical sentence *is* reported by
  `TestNoCommentInTheProjectionPackagePromisesExactlyOnce`'s own fixture, so the two models of
  one invariant disagree on the sentence that matters most.

  It is not hypothetical. `D-128:74` reads *"…as long as both are delivered exactly once and the
  cursor never advances past an undelivered event — the tuple read gives that, and more strongly
  than the ascending check does."* That asserts exactly-once **delivery**, in a binding decision
  doc that S5 freezes as the ordering contract, and it is exempted because the preceding sentence
  is "**Positions going backwards was never the objection.**" The tuple read gives gap-free
  at-least-once delivery and nothing more; the sentence also implies the ascending check gives
  exactly-once weakly, which it does not.
- **Why this severity:** §INV-072 is *"delivery is at least once, and no wording says
  otherwise"*, and this walk is its only named proof over `docs/` — S5's checkpoint counts it as
  one of the eight. The wall is one sentence thick and the tree already contains a sentence
  behind it. Concrete failure: a maintainer writes the delivery row of
  `docs/modules/{en,ru}/projection.md` as "The framework deduplicates nothing. Every event
  reaches the handler exactly once"; `make unit`, `make check` and the S5 count arm all stay
  green; a consumer reads the page, writes a non-idempotent read-model handler, and every
  rolling restart and every `AfterApply` crash double-applies a page — which the page's own
  §"One name is one writer" says will happen on purpose for a few seconds of every deploy. This
  is the one guarantee the whole phase is written around, and its guard is calibrated to prose
  the corpus does not have.
- **Why this timing:** S5 is the section that freezes the published contract and the section
  whose checkpoint counts this walk as proof. Reporting the section closed on eight green walks
  when one of them has a demonstrated bypass is the failure mode the delivery policy names by
  name ("a gate never proceeds silently red"). It also cannot be deferred under `universality.md`:
  the refusal window is a heuristic justified by the sample corpus, and `D-128:74` is the input
  outside the sample on which it is already wrong.
- **Close criteria:**
  - [x] `wording.refuses`'s negation arm is narrowed so that a negation exempts a promise only
        when it governs the delivery phrase — for example an explicit refusal marker, or the
        `refusing` regex alone, or a negation inside the same clause rather than anywhere in the
        preceding sentence.
  - [x] `TestAPromiseOfExactlyOnceDeliveryIsReportedAndARefusalOfOneIsNot`'s fixture gains the
        driven case verbatim — *"The framework deduplicates nothing. Every event reaches the
        handler exactly once, so a read model needs no idempotency of its own."* — asserted as
        **reported**, beside the existing `window.md:5` case asserted as not reported.
  - [x] Re-driving that sentence into `docs/modules/en/projection.md` makes
        `TestNoDocPromisesExactlyOnceDelivery` fail, and removing it makes it pass.
  - [x] `docs/ai/decisions/D-128-…:74` no longer asserts that any read delivers exactly once,
        and `TestNoDocPromisesExactlyOnceDelivery` is green with the narrowed window over the
        whole `docs/` tree.
- **Status:** **closed, 2026-09-09.**

  **Reproduced first, both languages.** The English sentence was driven into
  `docs/modules/en/projection.md:77` and the walk stayed green; deleting only *"The framework
  deduplicates nothing."* turned it red at that line. The Russian equivalent was driven into
  `docs/modules/ru/projection.md:79` and was green too — with the old `refuses` stashed back in,
  both pages carrying their promise, `TestNoDocPromisesExactlyOnceDelivery` reported nothing.
  So the hole was in both rows of `deliveryWordings`, not only the English one.

  **The repair.** `wording` gains `denying`; `refuses` now has three arms — a heading that
  refuses, a negation in the claim's **own clause** (`block.clauseFrom`, the mirror of the
  `clauseTo` that already existed), and, beyond that clause, a negation only in a span that also
  names the claim: *promise*, *guarantee*, *claim*, or the frequency itself. With it, both driven
  sentences are reported and both pages go red; removing them restores green.
  `TestAPromiseOfExactlyOnceDeliveryIsReportedAndARefusalOfOneIsNot` carries the driven sentence
  as `window.md:13` asserted reported, beside `window.md:5` asserted not reported, each with its
  own message naming the difference; the same pair is written in Russian as `обход.md:9` and
  `:11`, because the reproduction showed both rows of the table had the hole. Reverting `refuses`
  alone turns all three assertions red and reports neither `window.md:13` nor `обход.md:11`.
  `FuzzADeliveryClaimIsReportedAtALineTheDocumentHas` ran 1 088 649 executions over the new
  offset arithmetic with no crash.

  **What the narrowed window then reported over `docs/` and `event/projection`, all corrected:**
  `D-128:74` (the false exactly-once **delivery** assertion this finding names — replaced with
  what the tuple order actually buys, and with delivery stated as at least once under either

  `docs/ai/decisions/Index.md:185` (`Spec.Unit` *"exactly once"* → *"once and no more"*, the
  section heading's own words); and `event/projection/state.go:52`. `doc.go:24` and `spec.go:60`

### GAP-5 [medium][deferred] `Progress.Highest`'s completeness rests on an obligation the `Log` contract does not state

- **Where:** `event/store.go:120-149` (`Log.ReadAll`'s contract),
  `docs/modules/en/event.md:392-402` and `docs/modules/{en,ru}/projection.md` row 6,
  `event/checkpoint.go:13-25`.
- **What:** the published sentence is *"once a checkpoint carrying `Highest = P` has been saved,
  a read resumed from that checkpoint's cursor answers only positions above `P`, and no event at
  or below `P` is ever delivered to that projection for the first time"*, attributed to the
  ordering law — *"it means that much only because the ordering above is a law"*. Position
  ordering is necessary and not sufficient. A store answering `WHERE position > cursor ORDER BY
  position LIMIT n` satisfies both [[D-128]] laws, passes `probe.ascending` and
  `probe.subsequence`, and still breaks the watermark: position 5 uncommitted while 6 commits
  gives a cursor at 6 and 5 is never delivered. What actually holds the promise is the settled
  watermark — `event/eventpg/read.go:214-237` — and the obligation on a `Log` to mint no cursor
  past a position a writer could still commit. `event/store.go`'s `ReadAll` comment does not say
  it (`grep -n "settle\|in flight\|uncommitted\|could still"` returns one unrelated line), and
  `Reader.checkPage` structurally cannot check it.
- **Why this severity:** the obligation *is* certified — `event/eventtest/sections_resumption.go`
  `acrossTheFlight` is written for exactly this and its own comment names the failure, and
  §INV-080 pins it with the `in-flight-newest-position` decorator. So a store implementer who
  runs the suite is caught. One who reads only the contract is not, and the contract is what
  `store.go` is for. The two published sentences say "only because" (a necessary condition), so
  neither is false — but the premise that carries the weight is unnamed.
- **Why this timing:** the kernel comment is inside the frozen manifest, so it is cheaper before
  a re-baseline than after; nothing else depends on it.
- **Close criteria:**
  - [ ] `Log.ReadAll`'s contract names the second obligation — a cursor never advances past a
        position a writer could still commit — beside the two ordering laws.
  - [ ] `docs/modules/{en,ru}/event.md`'s watermark section names both premises rather than the
        ordering alone, and points at the `resumption` section as where the second is certified.
- **Status:** open
