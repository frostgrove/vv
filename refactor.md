# Раскладка репозитория: что куда переезжает

Статус: **предложение**, ничего не сделано. Ни один шаг ниже не выполняется до
решения владельца по разделу «Открытые вопросы».

Момент дешёвый и второй раз не наступит: тега нет, `remote` пустой, переезд
стоит `git mv` + `sed`. После `v0.1.0` то же самое стоит цикла депрекации —
`[[D-035]]` говорит это прямым текстом, `Roadmap` §1 повторяет.

---

## 1. Что не так сейчас

Верхний уровень — 14 директорий с кодом, и ни одна не отвечает на вопрос «где
живёт подсистема X»:

```
adapter/ auth/ catalog/ cmd/ crud/ errs/ http/ internal/
port/ probe/ query/ remote/ repo/ rpc/ sqlfault/ tools/ vvflag/
```

Три конкретные болезни.

**Подсистема размазана по дереву.** Auth сейчас лежит в пяти местах: `auth/`,
`auth/apikey/`, `auth/authjwt/`, `http/auth{http,net,gin,fiber}/`,
`rpc/authgrpc/`. Чтобы прочитать подсистему целиком, надо знать, что она
разложена по оси транспорта, а не по оси предмета. То же самое с crud, только
хуже: `crud/`, `repo/`, `query/`, `port/`, `adapter/`, `catalog/`, `probe/`,
`sqlfault/`, `http/`, `rpc/` — десять входов в одну подсистему.

**Ось выбрана так, что новая подсистема добавляет запись в каждую транспортную
директорию.** `[[D-035]]` уже держит в сетке строку `i18n` с ячейками
`i18nfiber` и `i18ngin`. По сегодняшней раскладке эта строка добавит две папки
в `http/`, ноль папок «где живёт i18n» и ни одного места, где видно, что это
одна подсистема.

**Имена по рангу, а не по предмету.** `repo/basic` — «базовый репозиторий».
Базовым можно назвать что угодно: `auth` тоже базовый, `errs` тоже базовый,
`crud` тем более. Слово не отвечает ни на один вопрос читателя. Ниже — §4.

Чего *не* надо чинить и что переезд обязан сохранить: правило именования
`[[D-035]]` (имя пакета — по предмету, префикс — только чтобы разбить
коллизию), стену `[[D-016]]`/`[[D-033]]` (корневой модуль без сторонних
зависимостей), и границу `[[D-045]]` (транспортно-нейтральная половина отдельно
от HTTP-половины).

## 2. Принцип раскладки

**Ось верхнего уровня — подсистема. Ось второго уровня внутри подсистемы —
транспорт.** Сетка `[[D-035]]` (подсистема × библиотека) остаётся ровно та же,
разворачивается только порядок вложения:

```
было:  http/crudgin  http/authgin      — строка сетки размазана по столбцам
стало: crud/http/crudgin  auth/http/authgin — столбец собран под строкой
```

Четыре следствия, каждое проверяемое.

**Префиксы в именах пакетов остаются, хотя путь их уже как будто повторяет.**
`crud/http/crudfiber` выглядит заикающимся, но `package fiber` рядом с
`github.com/gofiber/fiber/v3` не компилируется, а потребитель, поднимающий
и CRUD-роуты, и auth-middleware на Gin, импортирует `crudgin` и `authgin` в
одном файле. Прецедент в стандартной библиотеке ровно такой же:
`net/http/httptest`.

**Пакет и группа могут делить одну директорию.** `crud/` остаётся пакетом
`crud` и одновременно становится корнем поддерева — как `net` и `net/http`, как
уже существующие `errs` + `errs/sqlerr` и `auth` + `auth/apikey`. Путь импорта
`github.com/shardit-io/vv/crud` не меняется — а это 189 мест.

**Общая половина остаётся снаружи подсистем.** `port/` — это половина биндинга
для *любой* подсистемы, не только для CRUD, поэтому она не уезжает под `crud/`.
См. §5: сегодня auth-middleware импортирует пакет с именем `crudhttp`, и это не
опечатка в раскладке, а настоящая зависимость, которую переезд обязан порвать.

**Глубина — не самоцель.** Директория-обёртка заводится там, где под ней три и
более пакета одного рода (`crud/http/`, `crud/decorators/`), и не заводится
ради красоты. В `crypto/` стандартной библиотеки двадцать детей и никто не
жалуется — потому что каждое имя точное.

## 3. Целевое дерево

`(M)` — отдельный модуль, `*` — новый пакет, `←` — откуда приехал.

```
crud/                        package crud     контракты, Opt, предикаты, Meta, пагинация
├── crudtest/                                 источник в памяти
├── query/                   ← query/         DSL на проводе: JSON → crud.Options
├── sqlrepo/                 ← repo/basic/    репозиторий, говорящий на SQL
├── decorators/
│   ├── specs/               ← repo/decorators/specs/
│   ├── security/            ← repo/decorators/security/
│   └── faults/              ← repo/decorators/faults/
├── adapter/
│   ├── crudsql/             ← adapter/crudsql/
│   └── crudpgx/        (M)  ← adapter/crudpgx/
├── catalog/                 ← catalog/       схема базы, прочитанная один раз
├── probe/                   ← probe/         один лишний запрос → все нарушения
├── sqlfault/                ← sqlfault/      ошибка драйвера → errs.Fault
├── http/
│   ├── crudhttp/            ← http/crudhttp/ (часть уезжает в port/porthttp, §5)
│   ├── crudnet/             ← http/crudnet/
│   ├── crudfiber/      (M)  ← http/crudfiber/
│   └── crudgin/        (M)  ← http/crudgin/
└── rpc/
    └── crudgrpc/       (M)  ← rpc/crudgrpc/

auth/                        package auth     Principal, Role, Permission, Guard, 401
├── apikey/                                   Authenticator поверх общего секрета
├── authjwt/            (M)                   проверка JWT
├── http/
│   ├── authhttp/            ← http/authhttp/
│   ├── authnet/             ← http/authnet/
│   ├── authgin/        (M)  ← http/authgin/
│   └── authfiber/      (M)  ← http/authfiber/
└── rpc/
    └── authgrpc/       (M)  ← rpc/authgrpc/

port/                        package port     транспортно-нейтральная половина биндинга
└── porthttp/           *    ← http/crudhttp/ HTTP-проекция: таблица статусов,
                                              конверт, шов Renderer
remote/                      package remote   репозиторий, которого нет в этом процессе
└── remotehttp/         *    ← http/crudhttp/transport.go   (этап 5, опционально)

errs/                        package errs     контракт ошибки (будущий модуль, Roadmap §2)
└── sqlerr/                                   ошибка драйвера → код, таблица на диалект

utils/                       мелочи для приложения потребителя, не для библиотеки
├── vvcfg/              (M)  ← tools/vvcfg/
└── vvflag/                  ← vvflag/

cmd/vv/  internal/codegen/  docs/  test/ (M)  _examples/ (M)
```

Верхний уровень: **6 директорий с кодом вместо 14** — `crud`, `auth`, `port`,
`remote`, `errs`, `utils` — плюс `cmd`, `internal`, `docs`, `test`,
`_examples`.

Что *не* переезжает и почему: `errs/` и `errs/sqlerr/` — их держит
`Makefile:TIER0_SEALED` и планы вынести `errs` в отдельный модуль (`Roadmap`
§2); переезд под `crud/` или `port/` убил бы и то и другое. `cmd/vv` —
соглашение Go. `internal/codegen` — соглашение Go.

## 4. Переименование: `basic` → `sqlrepo`

**Почему `basic` плохое имя.** Оно называет ранг, а не предмет, и ранг у него
чужой: базовый по отношению к чему? Любой слой здесь можно назвать базовым, и
именно поэтому слово не различает. Имя пакета обязано отвечать на вопрос «чем
эта реализация `crud.Core` отличается от остальных», а их три:

| реализация шва | где лежат данные | пакет |
|---|---|---|
| `crudtest` | в процессе, в памяти | `crudtest` |
| `repo/basic` → | в базе, за SQL | **`sqlrepo`** |
| `remote.Resource` | в другом сервисе, за сетью | `remote` |

Два соседа уже названы по месту, где живут данные. Третий назван по рангу — он
и выпадает. `repository.go` в первой же строке говорит про себя правду:
«repository is the SQL implementation of `crud.Core`». Имя просто повторяет
за ней.

Как это читается на месте вызова:

```go
var Products = sqlrepo.Define[Product, int64, ProductUpdate]("products",
    sqlrepo.DefaultLimit(20),
    sqlrepo.MaxLimit(100),
    sqlrepo.DefaultSort(crud.Desc("CreatedAt")),
    sqlrepo.Scope(crud.Eq("Tenant", tenant)),
    sqlrepo.SoftDelete("DeletedAt"))

users := Products.Bind(db, security.Gate(policy), faults.Enrich[User, int64]())
```

Рассмотренные и отклонённые варианты:

| вариант | как читается | почему нет |
|---|---|---|
| `sql` | `sql.Define(...)` | не импортируется рядом с `database/sql`; `[[D-035]]` ровно про этот случай и требует префикса |
| `table` | `table.Define[Product,…]("products", table.SoftDelete(…))` | читается лучше всех, но называет вход, а не предмет: пакет — это репозиторий, а не таблица. Держу вторым номером, если владелец предпочтёт звучание точности |
| `store` | `store.Define(...)` | тот же порок, что у `basic`: хранилищем можно назвать и `crudtest`, и `remote` |
| `sqlstore` | `sqlstore.Define(...)` | «store» не добавляет ничего к «repo», а слово `Repo`/`Repository` уже в вокабуляре `crud` |
| `crudsql` | — | занято адаптером `database/sql` |

Ни один экспортированный символ при этом не переименовывается: `Define`,
`TryDefine`, `New`, `Blueprint`, `Setting`, `Scope`, `RelationScope`,
`SoftDelete`, `DefaultLimit`, `MaxLimit`, `DefaultSort`, `PreloadDepth`,
`UnstablePagination`, `DefaultPageSize` остаются как есть. Меняется только
квалификатор.

**Что не переименовывается больше нигде и почему.** `crud`, `query`, `errs`,
`port`, `catalog`, `probe`, `remote`, `crudtest`, `sqlfault`, `crudsql`,
`crudpgx`, `crudfiber`, `crudgin`, `crudnet`, `crudgrpc`, `authjwt`, `apikey` —
каждое уже названо по предмету, и `[[D-035]]` разбирает поимённо трудные из них
(`remote` вместо `client`, `sqlfault` вместо `fault`). Переезд не повод их
трогать.

Одно имя оставляю с оговоркой: `decorators/`. Слово называет паттерн, а не
предмет, а тип в коде зовётся `crud.Middleware` и собирается через `crud.Chain`
— то есть в репозитории два слова для одного. Держать директорию
`crud/middleware/` было бы честнее по отношению к коду; держать `decorators/`
честнее по отношению к документации, где «decorator» стоит в
`[[D-030]]` в самом названии решения. Предлагаю оставить `decorators/` и не
плодить третью правку на 42 документа — но это ровно тот случай, где решение
владельца, а не моё.

## 5. Что переезд чинит по дороге

Две зависимости сегодня направлены не туда, и обе становятся видны, как только
подсистемы разложены по осям.

### 5.1. Auth зависит от CRUD

Факт: `http/authhttp`, `http/authgin`, `http/authfiber`, `http/authnet`
импортируют `http/crudhttp` — ради `Renderer`, `RenderOption`, `NewRenderer`,
`WithLocale`, `AcceptLanguage`. А `crudhttp` тянет `port`, `query`, `crud` и
`remote`. То есть middleware, проверяющий токен, транзитивно зависит от
репозитория, предикатов и HTTP-клиента к чужому сервису. Если оставить как
есть, `auth/` будет «самодостаточной подсистемой» только на картинке.

Причина в том, что `crudhttp` держит две разные вещи. Одна — HTTP-проекция
контракта ошибок: таблица статусов, конверт ответа, шов `Renderer`, разбор
`Accept-Language`, откат на сырое тело. Она нужна **любой** подсистеме, которая
отвечает по HTTP. Вторая — собственно CRUD: декодирование тела в модель,
`BulkDeleteRequest`, `CoerceID`, сужение запроса под count/entity, клиентский
транспорт к `remote`.

Предлагаемая граница — тем же тестом, которым `[[D-045]]` уже разделил `port`
и `crudhttp`, только заданным на шаг шире: **сможет ли не-CRUD подсистема
(auth, завтра i18n) взять это, не импортируя `crud`?**

| файл сегодня | куда | почему |
|---|---|---|
| `render.go` | `port/porthttp` | `Renderer`, `EnvelopeRenderer`, `RenderOption` — их зовёт auth |
| `envelope.go` | `port/porthttp` | конверт один на весь фреймворк |
| `errors.go` | `port/porthttp` | таблица `Kind → status`; у `authgin` сегодня своей нет именно потому, что она берётся отсюда |
| `bodyindex.go` | `port/porthttp` | импортирует только `errs`; про CRUD ничего не знает |
| `decode.go` | `port/porthttp` | разбор JSON-тела и локаль — общий HTTP |
| `model.go`, `repository.go` | остаётся `crud/http/crudhttp` | алиасы `port.Repository` |
| `request.go` | остаётся `crud/http/crudhttp` | `BulkDeleteRequest`, `NarrowForCount` — это `query.Request` |
| `transport.go` | см. 5.2 | клиент к чужому сервису |

Имя `porthttp` — это ячейка сетки `[[D-035]]`: подсистема `port` × библиотека
`net/http`, ровно как `crudhttp` — это `crud` × `net/http`. Место — `port/`, а
не `errs/`: половина этих файлов зовёт `port.KindOf`, `port.MaxViolations`,
`port.FirstLanguageTag`, а `errs` запечатан `Makefile:TIER0_SEALED` и обязан
остаться с пустым `require` до собственного тега (`Roadmap` §2).

Ломать потребителей не нужно: `crudhttp` оставляет алиасы на всё, что уехало —
приём, которым `[[D-034]]` уже переносил символы в `port`.

Побочный выигрыш, который стоит записать: у `rpc/crudgrpc` и `rpc/authgrpc`
сегодня две независимые таблицы «вид ошибки → gRPC-код», и они уже могут
разойтись. Место для общей появляется само — `port/portgrpc/`. Заводить сейчас
не предлагаю: это отдельный модуль ради одной таблицы.

### 5.2. Серверный пакет импортирует клиента

`http/crudhttp` импортирует `remote` — из-за `transport.go`, где живёт
`crudhttp.Transport`. `[[D-035]]` объясняет это правилом «транспорт живёт рядом
с биндингом, который он зовёт», и правило разумное: транспорт и биндинг обязаны
говорить на одном проводе, а рядом они расходятся заметнее.

Но после 5.1 конверт лежит в `port/porthttp`, и HTTP-транспорт клиента может
переехать в `remote/remotehttp` — без единой сторонней зависимости и без нового
модуля. Тогда «всё про разговор с чужим сервисом» действительно лежит в
`remote/`, а серверная половина перестаёт знать о клиенте.

gRPC-транспорт при этом остаётся в `crud/rpc/crudgrpc`: вынести его в
`remote/remotegrpc` — значит завести ещё один модуль ради одного файла.
Асимметрия честная, но это асимметрия, и она требует правки `[[D-035]]`.
Вынесено в открытые вопросы (§9).

один конфиг для приложения потребителя. Свалка на два пакета, у которой есть
граница: **`utils/` не импортирует ничего из `crud/`, `auth/`, `port/` и
`remote/`.** Пакет, которому это понадобилось, — не утилита, и он переезжает к
своей подсистеме. Без этой строчки `utils/` за год соберёт половину
репозитория.

## 7. Что придётся править кроме файлов с кодом

Это та часть, где предыдущие два переименования в этом репозитории протекали
(`Roadmap` §1: «импорты — лёгкая половина»). Список полный, по нему и проверять.

**`Makefile` — три арма `check-tiers`, и два из них ломаются молча.**

- `TIER0 := crud query errs port` → `crud crud/query errs port`. Арм строит
  регексп `^($re)(/|$)`, то есть **по префиксу**. С `crud` в списке любой импорт
  `crud/...` начнёт считаться внутриманифестным — и `port`, импортировавший
  `crud/sqlrepo`, пройдёт проверку. Арм обязан перейти на точное совпадение
  пути пакета (альтернация без хвоста `(/|$)`), иначе манифест перестанет
  что-либо держать и никто этого не заметит.
- `TIER0_STDLIB := crud` перечисляет `./crud/...` рекурсивно. После переезда под
  `crud/` окажутся `sqlrepo`, `query`, `catalog`, `crudsql` — арм упадёт на
  первом же прогоне. Нужно перечислять `./crud` без `...`. Правило `[[D-016]]`
  при этом сужается с директории до пакета — см. §8.
- `TIER0_SEALED := errs` не трогается.
- `MODULES`/`ALL_MODULES` вычисляются через `find . -name go.mod` — правки не
  требуют. Это ровно то, ради чего список не написан руками.

**Пути модулей:** `module` в семи сателлитных `go.mod` (включая `vvcfg` —

## 8. Документация: что обязано поехать в том же коммите

По правилам `CLAUDE.md` расхождение документа с кодом — дефект, а не
неаккуратность.

**`docs/flows/` — полный свип.** Флоу — единственное место, где вообще
разрешены пути и символы, поэтому переезд бьёт по ним весь. В `Index.md`
обратный индекс перечисляет каждый исходник поимённо (`repo/basic/repository.go`
стоит в одиннадцати флоу); заголовок `FL-004` называет `basic.Define` в тексте.
Двадцать флоу + индекс.

**`docs/modules/` — по файлу на пакет, и `en/` и `ru/` параллельны.**
`basic.md` → `sqlrepo.md` в обеих; новый `porthttp.md` в обеих; `crudhttp.md`
переписывается по новой границе; строки в обоих `Index.md`. Тридцать три файла
на язык — переименований два, правок путей — по всем.

**`docs/usecases/` — не трогается, и это проверено:** `grep` по путям
пакетов не находит в них ничего. Правило «use case ссылается только на флоу»
держится; переезд — как раз тот случай, ради которого оно и заведено.

**`docs/decisions/` — семь затронутых, и это не механическая правка:**

| решение | что с ним |
|---|---|
| `[[D-016]]` | «no file in `crud/`» сужается до «no file in package `crud`». Правило то же, область — пакет, а не поддерево. Без этой правки `crud/sqlrepo` формально нарушает решение, которое ничего не запрещало |
| `[[D-033]]`, `[[D-051]]` | списки путей модулей |
| `[[D-034]]` | «биндинг — оболочка над `crudhttp`» → над `porthttp` + `crudhttp` |
| `[[D-035]]` | раздел «Where it lives»; плюс §2 этого документа — ось вложения. Само правило именования не меняется, меняется, куда оно раскладывается |
| `[[D-045]]` | граница «port ↔ crudhttp» становится «port + porthttp ↔ crudhttp». Тест тот же |
| `[[D-053]]` | абзац про размещение транспорта — только если принят этап 5 |

**Новое решение** — `D-057`, «раскладка по подсистемам»: фиксирует ось,
объясняет, почему префиксы пакетов остаются при вложенном пути, и запрещает
возврат к транспортной оси без нового решения. Если принят §5.1, то и
`D-058` — «HTTP-проекция контракта ошибок принадлежит `port`, а не подсистеме».

> Номера занимать созданием файла **до** правок: в этом дереве работает
> несколько сессий сразу, и два `D-057` дороже, чем один лишний пустой файл.

## 9. Открытые вопросы — на них отвечает владелец

1. **Ось.** Подсистема сверху, транспорт внутри — принимается? Всё остальное
   ниже висит на этом ответе.
2. **`sqlrepo` или `table`?** Первое точнее, второе лучше читается на месте
   вызова (`table.Define[Product,…]("products")`). Моя рекомендация —
   `sqlrepo`, потому что оно ставит пакет в один ряд с `crudtest` и `remote` по
   признаку «где лежат данные».
3. **Разрезать ли `crudhttp` (§5.1).** Не разрезать — дешевле на день работы, и
   `auth` остаётся зависимым от `crud` навсегда. Разрезать — `auth/`
   становится тем, чем названа. Рекомендую разрезать: `[[D-034]]` уже даёт
   готовый приём совместимости.
4. **Переносить ли HTTP-транспорт клиента в `remote/remotehttp` (§5.2)** ценой
   асимметрии с gRPC-транспортом и правки `[[D-035]]`. Рекомендую перенести —
   но последним этапом, отдельным коммитом, который легко откатить.
5. **`decorators/` или `middleware/`** (§4, последний абзац). Рекомендую не
   трогать.

## 10. Порядок работ

Каждый этап — отдельный коммит, и каждый заканчивается зелёным
`make unit vet fmt` плюс `make integration` дважды подряд. Ни один этап не
меняет поведение: всё это `git mv`, `package`-строка, импорты и документы.

| этап | что | цена отката |
|---|---|---|
| 0 | ответы на §9; завести `D-057` (и `D-058`) пустыми, чтобы занять номера | — |
| 1 | `auth/`: пять директорий переезжают под `auth/http/` и `auth/rpc/`. Самый изолированный кусок, на нём и проверяется вся механика свипа | один `git revert` |
| 2 | `crud/`: `repo/`, `query/`, `adapter/`, `catalog/`, `probe/`, `sqlfault/`, `http/crud*`, `rpc/crudgrpc` — под `crud/`. Здесь же `basic` → `sqlrepo` и правка обоих армов `check-tiers` | большой, но механический |
| 3 | `vvflag` и `tools/vvcfg` → `utils/`; `README`, `CLAUDE.md`, `docs/modules/*/Index.md` | тривиальная |
| 4 | разрез `crudhttp` → `port/porthttp` с алиасами (если принят §9.3) | средняя |
| 5 | `remote/remotehttp` (если принят §9.4) | тривиальная |

Порядок «сначала auth, потом crud» не случаен: auth — пять пакетов и семь
документов, на нём видно, что свип полон, прежде чем тем же свипом двигать
пятьдесят.

**Механика одного этапа**, чтобы не изобретать её трижды:

```bash
git mv http/authhttp auth/http/authhttp        # 1. директории
# 2. пути импорта — по всему дереву, включая docs, README, CLAUDE.md,
#    go.mod, go.work, //go:generate и их копии в тестах
grep -rl 'shardit-io/vv/http/authhttp' . --exclude-dir=.git \
  | xargs sed -i 's|shardit-io/vv/http/authhttp|shardit-io/vv/auth/http/authhttp|g'
# 3. голые упоминания путей в прозе документов (без префикса модуля)
grep -rn 'http/authhttp' docs README.md CLAUDE.md
# 4. имя пакета — только если оно менялось (этап 2, basic → sqlrepo)
make fmt vet unit && make integration && make integration
```

Шаг 3 руками намеренно: `sed` по голой строке `http/auth` съест куски прозы,
где путь — часть предложения, а не ссылка.
