# i18n — deterministic internationalized presentation

**Covers:** `github.com/frostgrove/vv/i18n`
**Sweep:** happy paths · public DX · edge boundaries · release evidence
**Verdict:** the optional core module and offline CLI are ready for bounded
in-process presentation. Durable delivery policy, tenant authorization,
external catalogue distribution/watch, HTTP cache policy and telemetry export
remain application-owned integrations; the package does not claim them.

## What a consumer is trying to do

An application author wants one declaration for a human message, complete
locale policy and a typed argument contract. The same intent should render in a
request or later in a worker without ambient locale, host time zone, mutable
registry or first-request compilation. A bad translation should stop release
work before traffic, and localization of a failure must not change its machine
contract.

[[UC-033]] is the contract. [[D-135]] keeps the Unicode dependency decision in
one nested module and leaves protocol projection in the existing transports.
[[FL-039]] maps the implementation.

## Happy cases

### H-I18N-01 — Declare and compile one catalogue

`CatalogSpec` assembles module declarations, reviewed translations, required
and supported locales, parent edges, capabilities, bounds and approved
application overrides. `New` returns one immutable snapshot only after the
whole effective catalogue passes. `EncodeSource`/`DecodeSource` provide a
canonical strict authoring document; `Compile` and `Load` provide a canonical
runtime artifact with pinned profile, engine and data identities. Long-running
assembly and encoding use `NewContext`, `EncodeSourceContext`,
`CompileContext` or the corresponding `Compiler`/`SourceCodec` context methods.

### H-I18N-02 — Choose a recipient locale explicitly

`Exact` and `AcceptLanguage` form bounded ordered choices from explicit, user,
protocol, tenant and application sources. Resolution handles canonical tags,
weights, exclusions, wildcard, lookup or opt-in best fit and returns the actual
supported locale plus closed provenance. A view then pins message locale,
formatting locale, time zone and bidi presentation separately.

### H-I18N-03 — Bind a typed deferred message

The dynamic `Snapshot.Bind` path validates one known key and closed typed
arguments. Generated Go contracts use `Definition[A]` and a literal
`ContractRef`, so schema drift is rejected when the generated catalogue binds
to a snapshot. `Optional[T]` distinguishes absent, explicit null and present.
Deferred messages copy caller-owned values and select no locale by themselves.
A hand-written integration can compile the same typed definition from one
ordinary struct during assembly; field mapping, exact types and optional/null
shape are rejected eagerly, while generated code remains the reflection-free
fast path.

### H-I18N-04 — Render the declared MF2 profile exactly

The `frostgrove-mf2/v1` profile supports cardinal and ordinal number selection,
exact numeric and string selection, nested/multiple selectors, plain text and
allowlisted rich markup. Signed, unsigned and big integers remain exact;
lexical decimals preserve visible fraction digits. Formatting locale is
independent of template grammar locale. Money is not converted, calendar dates
do not shift through a zone and instants use the explicit zone. Literal `u:id`
and `u:dir` survive in bounded rich parts, and exact number/date values expose
typed subparts without flattening their lexical values through floating point.
The same closed exact values are available without a synthetic message through
the view's typed number, money, percent, unit, calendar-date, instant-date,
time and datetime methods; list, relative-time, duration and display-name
formatters share the same pinned policy and bounds. A standalone formatter or
one derived from a view can validate immutable named policies once. Numeric and
date/time ranges preserve start/shared/end part provenance, and plural-range
selection follows locale data rather than choosing one endpoint.

### H-I18N-05 — Explain and identify output safely

`Rendered` records actual template locale and layer, resolved locale provenance,
snapshot revision/digest and a deterministic render key. `Explain` returns a
bounded preference/fallback trace without text or arguments. Plain output is
unescaped; rich output is structural and never trusted HTML. Interpolated text
is isolated by default, and unsafe directional controls in untrusted values are
refused.

### H-I18N-06 — Localize the existing error contract

`Snapshot.ErrorMessages` validates allowlisted ladder mappings, params and
field labels and returns `i18n.ErrorSource`, which implements
`errs.LocalizedMessageSource`, so the existing HTTP
and CRUD gRPC renderers receive actual template-locale provenance without
changing kind, code, public path, status, partial marker or internal-error
redaction. A failed i18n mapping declines to the pre-existing safe wording.
When a request already owns one `View`, `Snapshot.ErrorPlan` plus
`View.ErrorMessages` binds the same resolution, formatting locale, zone and
presentation to the error source; a later transport locale argument cannot
renegotiate it.

### H-I18N-07 — Author and publish reproducibly

`vv-i18n check`, `extract`, `merge`, `review`, `pseudo`, `compile`, `generate-go` and
`export-ts` are deterministic offline commands with per-file atomic output and
read-only drift checking. `export-ts -publication-root` additionally publishes
an immutable content-addressed generation through one atomic `current.json`
commit, so a reader that pins the pointer cannot mix files across generations.
Source/review digests make wording or translator-context edits stale.
Extraction type-checks local packages within its roots as one source graph and
finds static, bounded-domain and exact typed `Bind` callback/interface uses
without executing application code. A type-check diagnostic in the selected
graph, including a partial file root, or an external import that cannot be typed
offline downgrades requested completeness, so missing usage cannot be reported
as definitely unused. Usage v1 preserves reproducible exact and
bounded-dynamic call sites plus the analyzed Go module/build scope; any other
schema or analyzer identity is rejected. `extract` produces
usage for `check`, while `merge` carries structurally eligible authoring work
verbatim from the previous catalogue into the next authoritative source and
refuses implicit pruning. Go helpers pin runtime contracts. TypeScript export
includes only public types and explicitly reports no formatting parity. The
context-aware `PseudoContext`, `GenerateGoContext` and `ExportPublicContext`
paths receive the destination's per-file ceiling before building output.
`SourceCodec.EncodedSizeContext` exposes the same exact canonical source count;
generated Go, artifacts, public exports, pseudo additions and review stamps use
count-only N/N-1 preflights before formatting, hashing or cloning.

### H-I18N-08 — Activate a whole release

Application and tenant overlays can only replace whole approved messages at a
strictly higher allowed layer. `Controller` publishes a fully built snapshot by
opaque-head compare-and-swap, retains bounded rollback candidates and grants
finite bounded pins. A stale or invalid activation does not disturb the active
snapshot, and a view already in flight remains immutable.

## Edge cases that define the contract

- Unknown profiles/functions/options/option values, expression attributes,
  forbidden markup, missing selector fallback and invalid plural keys are
  construction errors, not best-effort rendering.
- Required locale completeness is evaluated after effective application
  overrides. Optional locale debt remains visible to `check` and becomes an
  error under strict policy.
- A resolution is issued and sealed by one resolver. Forged metadata and a
  result from another resolver cannot create a view.
- Message fallback and locale resolution remain separate: the resolved locale
  and actual template locale may differ and both are reported.
- Non-UTC formatting needs a caller-declared time-zone-data version. That string
  is identity, not runtime proof; the application must align it with installed
  IANA data.
- Every accepted catalogue, source/artifact input, locale preference, typed
  argument, conservative formatter expansion, output, explanation, generator
  and controller retention is bounded. Derived producers refuse a too-small
  output ceiling before formatter/hash work, and meaningful producer loops poll
  cancellation. External callback work is not.
- Required-locale completeness polls cancellation through both message and
  required-locale loops in source construction and artifact reconstruction.
- Merge budgets carried translations and overrides before append and retains
  only an obsolete count plus the lexical first diagnostic. Review validates a
  selector before cloning even a hostile catalogue.
- Observer events contain closed operation/outcome/reason, duration and count
  only. Panics are isolated. There is no message identity, locale input, text,
  argument, path, cause, revision, principal or tenant value.
- Tenant overlays carry no tenant identity and pins carry no authority. The
  application authenticates and authorizes before selecting either.
- Controller retention is process-local. It is not a durable job archive and
  constructors create no watcher, timer or goroutine.
- Public TypeScript output is a type manifest, not a JavaScript renderer or a
  claim of cross-runtime MF2 parity.
- Direct numeric formatting accepts only exact signed, unsigned, decimal and
  immutable big-integer values. Its typed rounding modes, precision priorities,
  trailing-zero policy and increments reject invalid combinations before a
  formatter is invoked.
- Reflective typed definitions accept only direct exported fields with a closed
  exact shape. Missing/duplicate mappings, invalid tags, native-width integers,
  floats, embedded fields and wrong optional/null topology fail at construction.
- Named formatter registries are immutable and bounded. Duplicate or invalid
  policies fail at construction, and missing names never fall back to a global
  registry or an unrelated default.

## Release evidence

The catalogue, locale, rendering, formatter, artifact, source, overlay,
error-source, generator/export, authoring and controller suites run under the
race detector in the nested module. Fuzz targets cover catalogue/MF2
validation, application overlays, error mapping and canonical source decoding.
Standalone scripts prove the optional dependency boundary, import lifecycle,
generated consumer and full HTTP/gRPC integration path with the workspace
disabled.

The remaining work is additive at application boundaries: a durable source and
poller if a product needs external releases, health/readiness policy around
that poller, durable pinned-delivery records, authorized tenant settings,
application cache policy and a separately chosen telemetry adapter. None is an
implicit promise of the core package.
