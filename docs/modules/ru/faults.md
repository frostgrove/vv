# faults — декоратор, который называет поле

```go
import "github.com/frostgrove/vv/crud/decorators/faults"
```

**Модуль:** корневой · **Зависит от:** `crud`, `errs`, `probe`

Адаптеры классифицируют — отклонённый запрос возвращается как `errs.Fault` с
кодом, `Kind` и одним нарушением с тем именем, что дал драйвер. Чего они не
могут заполнить — это **path**, потому что колонка бессмысленна без таблицы, к
которой она принадлежит, а у адаптера нет `crud.Meta`.

Этот декоратор — тот самый один переход ([[D-043]]). Здесь же подключается
[probe](probe.md).

---

## Минимум

```go
users := Users.Bind(db, faults.Enrich[User, int64]())
```

Теперь 409 называет поле модели, на котором это произошло, а не ничего.

Оба параметра типа нужно писать явно в месте вызова, потому что больше нигде в
сигнатуре они не фигурируют.

## Всё целиком

```go
cat, err := catalog.Load(ctx, db)
if err != nil { log.Fatal(err) }

users := Users.Bind(db,
    security.Gate(policy),
    faults.Enrich[User, int64](
        faults.WithProbe(probe.Full(cat)),
        faults.WithProbeError(func(op string, err error) {
            log.Printf("the %s probe failed: %v", op, err)
        }),
    ),
)
```

`WithProbe` — то, что превращает **одно** нарушение во **все** нарушения,
которые вызвал payload ([[UC-017]]).

## Опции

| Опция | Что делает |
|---|---|
| `WithProbe(h)` | подключить обработчик к трём однострочным записям — `Save`, `SaveOnly` и `Update` |
| `WithProbeFor(op, h)` | подключить один поддерживаемый глагол по имени: `Save`, `SaveOnly`, `SaveAll`, `InsertBatch` или `Update` |
| `WithProbeError(fn)` | куда уходит ошибка пробы. **Это рекомендательно — логируйте её, никогда не рендерите** |
| `WithSource(src)` | назвать источник данных, на котором работает проба. Нужно только когда это не самый внутренний middleware |

Батчевые глаголы остаются на дешёвом ответе. Батч — это там, где стоимость
умножается и где клиент меньше всего похож на форму, поэтому `SaveAll` и
`InsertBatch` держатся за `probe.Simple`, пока `WithProbeFor` не скажет иначе.
Probe для `InsertBatch` сохраняет create-only контракт даже для назначенных
ключей и никогда не проверяет upsert.

`WithProbe` устанавливает три глагола сразу, а `WithProbeFor` — один, поэтому
**побеждает последняя опция** — более узкую ставьте второй.

```go
faults.Enrich[Doc, int64](
    faults.WithProbe(probe.Full(cat)),                       // Save, SaveOnly, Update
    faults.WithProbeFor("SaveAll", probe.Full(cat)),         // …и батчи тоже
    faults.WithProbeFor("InsertBatch", probe.Full(cat)),     // …включая native/portable insert
)
```

## Порядок: он идёт последним

Это **самый внутренний** middleware — последний в списке `Bind`, так что он
оборачивает репозиторий напрямую.

```go
Users.Bind(db, security.Gate(policy), faults.Enrich[User, int64]())
//              ^ внешний              ^ внутренний
```

Две причины, и обе важны:

- любая ошибка драйвера обогащается **до** того, как её увидит что-то выше, так
  что собственной обёртке слоя сервиса не нужно знать про faults;
- отказы gate проходят насквозь без изменений — 403 не является ошибкой
  драйвера, и добавить к нему здесь нечего.

Если поставить его в другое место, репозиторий под ним перестаёт быть
`crud.Sourced`, и декларация отказывает. `faults.WithSource(db)` — выход из
этой ситуации.

## Чего он не делает

- **Он никогда не выдумывает fault.** Ошибка, которая им не является,
  возвращается ровно такой, какой пришла. Декоратор, который фабриковал бы
  faults, превратил бы любой закрытый пул соединений в структурированную 500,
  выглядящую классифицированной.
- **Он никогда не выдумывает path.** Колонка из другой таблицы, неизвестная
  колонка или отсутствие колонки вовсе оставляют path равным nil и помечают
  нарушение как `Approximate`. Имя колонки в `field` было бы живым нарушением
  [[D-044]] — path это единственное, что рендерится.

## Отказ на этапе декларации

С подключённой пробой `Bind` отказывает на старте приложения, а не во время
запроса ([[D-021]]): таблица, которую не знает каталог, первичный ключ, не
являющийся идентичностью строки сам по себе, `Skip`, не называющий ни одного
ограничения. См. [probe](probe.md#fails-at-start-up-not-at-request-time).

## Savepoint

При `probe.WithSavepoints()` на транзакции, которой владеет vv, декоратор
берёт savepoint **перед** записью — взять savepoint после факта нельзя — и
откатывается к нему при неудаче записи, так что транзакция PostgreSQL,
отравленная сбоем, всё ещё может выполнить запрос пробы.
