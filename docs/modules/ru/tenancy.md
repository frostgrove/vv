# tenancy — один арендатор, проверенный, до самого низа

```go
import (
    "github.com/frostgrove/vv/tenancy"            // the core: a verified scope
    "github.com/frostgrove/vv/tenancy/tenancyrow" // and one package per seam you adapt
)
```

**Модуль:** root · **Ядро зависит от:** `crud` и стандартной библиотеки

Опциональное расширение для развёртывания, которое обслуживает многих арендаторов
одним процессом. Хост проверяет, кто вызывает; это превращает результат в
**проверенный scope**, а scope — в суженный запрос, пространство имён объектов,
партицию кэша, долговременную идентичность задачи или одну выбранную базу — так,
что аргумент «арендатор» нигде в бизнес-коде не появляется.

**Берите его, когда** строки, объекты, кэшированные значения и фоновая работа
принадлежат организации-клиенту, а недопустимый отказ — это запрос, забывший,
какой именно.

**Он опционален в том смысле, который важен.** Ни `crud`, ни `port`, ни `storage`,
ни `cache`, ни `jobs`, ни `auth` его не импортируют. Развёртывание, которое его не
импортирует, не компилирует из него ничего ([[D-116]]).

---

## Одно ядро, по пакету на каждый шов

Ядро — это то, что развёртывание берёт, чтобы вообще иметь арендаторов: authority,
scope, admission, grant'ы и печать, которая переносит арендатора в долговременную
запись. Каждый шов, который оно умеет адаптировать, — отдельный пакет рядом, так
что импорт одного стоит только этого шва и ничего больше: `tenancyrow` —
единственный, кто дотягивается до `security`, а через него до `auth` и `errs`.

| Пакет | Что даёт | Во что обходится |
|---|---|---|
| `tenancy` | authority, scope, admission, grant'ы, долговременная печать | `crud` |
| `tenancy/tenancyrow` | сужение по строке: `security.Policy` и middleware поверх неё | `crud/decorators/security` |
| `tenancy/tenancydb` | база на арендатора: directory и lease | `crud` |
| `tenancy/tenancyjobs` | долговременная работа: захват при постановке, идентичность при исполнении | `jobs` |
| `tenancy/tenancystorage` | пространство имён объектов и привязанный к нему store | `storage` |
| `tenancy/tenancycache` | ключ кэша, несущий свой scope, и партиция, в которую он превращается | `cache` |

Направление одностороннее, а вес измеряется, а не декларируется:
`TestNoTenancyPackageCostsMoreThanTheSeamItNames` падает, если ядро дотянулось до
шва или адаптер — до второго шва ([[D-116]]).

## Форма

```go
authority := tenancy.Must(tenancy.Spec{Resolver: controlPlane})

invoices := Invoices.Bind(database, tenancyrow.Repository[Invoice, int64](authority,
    tenancyrow.Column[Invoice]("TenantID", tenancyrow.Derive, nil,
        tenancyrow.Relation{Path: "Lines", Field: "TenantID"})))
```

На пути запроса, после того как хост аутентифицировал вызывающего:

```go
ctx, err := authority.Bind(ctx, tenancy.ClassWrite)
```

Дальше не меняется ничего. `invoices.GetAll(ctx)` возвращает строки этого
арендатора, `invoices.Save(ctx, &Invoice{...})` проставляет владельца, а чужая
строка — это `crud.ErrNotFound`, а не 403, который подтвердил бы её существование
([[D-008]]).

## Authority — это то, что внедряет развёртывание

```go
type Resolver interface {
    Resolve(ctx context.Context) (Resolution, error)
    Lookup(ctx context.Context, reference Reference) (Resolution, error)
}

type Resolution struct {
    Reference Reference
    Lifecycle Lifecycle
    Epoch     Epoch
}
```

`Resolve` отвечает про вызывающего текущего запроса; `Lookup` — про названного
арендатора, и это то, чем пользуются долговременная работа и когортные задачи. Он
возвращает **обычные данные**, а не `Scope`. Это сделано намеренно: если бы
прикладной код мог вернуть тип, который принимает data plane, этот тип был бы
конструируемым прикладным кодом ([[D-117]]).

Поэтому у `Scope` нет экспортированного конструктора. Тест собирает scope тем же
путём, что и production:

```go
authority := tenancy.Must(tenancy.Spec{
    Resolver: tenancy.Fixed{Reference: ref, Lifecycle: tenancy.Active, Epoch: epoch},
})
```

`tenancy.Fixed` — обычный resolver, а не подделка. Тестового конструктора, который
мог бы утечь в production, здесь нет.

### Допуск по жизненному циклу — это whitelist, отдельный на класс операции

```go
tenancy.Spec{
    Resolver:  controlPlane,
    Admission: tenancy.Admit(tenancy.ClassRead, tenancy.Active, tenancy.Suspended).
        Merge(tenancy.Admit(tenancy.ClassWrite, tenancy.Active)).
        Merge(tenancy.Admit(tenancy.ClassDurable, tenancy.Active)),
}
```

По умолчанию — `Active` для всех трёх классов. Всё остальное, включая значение
жизненного цикла, которого не объявляла ни одна версия этого пакета, получает
отказ. Развёртывание, которому нужен читаемый приостановленный арендатор, говорит
об этом явно, и записи ему всё равно отказывают.

Согласованность допуска проверяется при конструировании: состояние, допущенное к
записи или к долговременной работе, но не к чтению, отвергается с указанием
состояния. Любой изменяющий глагол сначала вычисляет своё сужение для класса
чтения, поэтому такая политика означала бы не то, что в ней написано.

Там же отвергается допуск, который называет **то, чего в этом пакете нет**: класс
или значение жизненного цикла, которых не существует, либо класс вовсе без
состояний. `Admit(tenancy.ClassRead)` — это не read-only развёртывание, а
политика, которую невозможно прочитать; она отвергается, а не заменяется
разрешительным значением по умолчанию.

### `Origin` отделяет одно развёртывание от другого

`Spec.Origin` входит в binding каждого scope, поэтому scope, приехавший из другого
окружения, здесь не проверяется.

### Насколько свеж принесённый scope

По умолчанию scope проверяется один раз, на `Bind`, и его жизненный цикл и
поколение действуют до следующей явной границы — следующего `Bind`, входа в
обработчик долговременной задачи, участника когорты. Спрашивать control plane на
каждый запрос сделало бы его горячей зависимостью каждого обращения.

```go
tenancy.Spec{Resolver: controlPlane, Revalidate: true}
```

`Revalidate` покупает другой размен: каждый глагол заново спрашивает resolver про
арендатора, отвечает `ErrStale`, если поколение сдвинулось, и `ErrInactive`, если
жизненный цикл больше не допускает этот класс. Развёртывание, которому нужно
остановить удалённого арендатора посреди запроса, включает это; то, которое не
может позволить себе обращение, объявляет окном «один `Bind`» и пишет это в своём
runbook.

## Владение — это стратегия, а не колонка

```go
tenancyrow.Column[Invoice]("TenantID", tenancyrow.Derive, nil)     // строка несёт владельца сама
tenancyrow.Through[Line]("Owner", "TenantID", nil)              // строка принадлежит через связь
```

| | Чем сужает | Создание | Заморожено |
|---|---|---|---|
| `Column` | `TenantID = ?` на самой строке плюс объявленное сужение для каждой связи, названной в вызове | `Derive` проставляет владельца, когда поле пусто; `Validate` требует, чтобы вызывающий прислал верного. В обоих случаях чужой владелец получает отказ | колонка владения |
| `Through` | путь через точку в **to-one** владельца, который компилируется в коррелированный `EXISTS` из [[FL-005]] | отказ — владелец, к которому строка присоединилась бы, не был прочитан | ключ, указывающий на владельца: его перенаправление переносит строку, не меняя ни одной её собственной колонки |

Путь to-many отвергается при связывании. Он скомпилировался бы в «хотя бы одна
строка на той стороне — моя», поэтому родитель, чьи дети принадлежат двум
арендаторам, отвечал бы обоим — и на чтение, и на запись, — а замораживал бы он
собственный ключ строки, а не связь с владельцем.

Третий аргумент отображает `Reference` в значение колонки; `nil` означает саму
строку ссылки. Развёртывание, где колонка владения — `BIGINT` или UUID, задаёт
преобразование:

```go
tenancyrow.Column[User]("TenantID", tenancyrow.Derive, func(r tenancy.Reference) (any, error) {
    return strconv.ParseInt(r.Value(), 10, 64)
})
```

**Возвращайте тип самой колонки и никогда — ничего.** Значение проверяется по
колонке до того, как попадёт в запрос, и значение, которое колонка вместить не
может, — это отказ, а не преобразование: Go превращает `int` в `string`, читая
его как руну, а широкое целое в узкое — усечением, так что `65` для текстовой
колонки сузил бы на `"A"` и проставил бы это в строку. Отсутствующее значение в
любом написании — нетипизированный `nil`, нулевой указатель, пустой `Opt` —
отвергается по той же причине: `crud.Eq` превращает его в `IS NULL`, а это
совпадает с каждой ничьей строкой вместо ни одной.

Создание через `Derive` требует обычной колонки. Колонку-указатель или `Opt`
проставить нельзя — объявляйте `Validate` и передавайте владельца сами.

`Ownership` — интерфейс: `Narrow`, `Relations`, `NarrowsRelations`, `Apply` и
`Frozen`. Ресурс, чьё владение не описывается ни одной из этих двух форм,
реализует его, а не выкручивает одну из них. `NarrowsRelations` объявляется, а не
выводится: стратегию спрашивают, сужает ли она связи, и никогда не зондируют
выдуманным арендатором, — потому что зонд, на который стратегия ответила ошибкой,
выключил бы сужение ровно в той тишине, ради предотвращения которой всё это и
сделано.

**Объявляйте каждую связь, принадлежащую арендатору.** Preload — это второй
запрос ко второй таблице, и `WHERE` корня до него не достаёт ([[D-007]]); внешний
ключ — обычные бизнес-данные, которые gate не замораживает. Поэтому арендованный
родитель с необъявленной связью отдаёт строки чужого арендатора любому, кто может
задать ключ, — а это ровно тот отказ, ради предотвращения которого написаны
decision-документы этого фреймворка. `tenancyrow.Relation{Path, Field}` в вызове
`Column` — и есть объявление; оно разрешается при конструировании, поэтому опечатка
падает на этапе сборки графа. Связь, которую вы не объявили, читается целиком —
намеренно и заметно.

### Композиция с политикой, которая у вас уже есть

`tenancyrow.Policy` возвращает `security.Policy`, поэтому приложение, у которого gate
уже есть, объединяет, а не ставит один на другой:

```go
gate := security.Gate(security.Combine(
    tenancyrow.Policy[Invoice, int64](authority, ownership),
    security.RequirePermission[Invoice, int64]("invoices:write"),
))
```

`security.Combine` соединяет scope через AND, выстраивает инспекции в цепочку,
объединяет замороженные колонки и сохраняет оба отказа несужённым bulk-операциям.
**Предпочитайте его двум gate в одной цепочке**: scoped upsert — точная capability
ядра непосредственно снизу, и gate её не пробрасывает, поэтому два вложенных gate
не выполнят `Save` с назначенным ключом.

## Остальные швы

```go
// долговременная работа — захват при постановке, повторный вывод при исполнении
provider, err := tenancyjobs.ContextProvider(authority, provenance, epoch)
restorer, err := tenancyjobs.IdentityRestorer(authority)

// объекты — пространство имён фиксированной ширины, поколение включено
store, err := tenancystorage.Store(ctx, authority, "invoices", tenancy.ClassWrite, backend)

// кэш — ключ несёт scope, потому что кэш партиционирует по своему ключу
values := tenancycache.Partitioned[string](namespace)
key, err := tenancycache.Keyed(ctx, authority, tenancy.ClassRead, "invoice:1")
```

Оба идут через authority, а не принимают значение scope: держать scope означает,
что его когда-то выпустил authority, — но не что этот authority допускает этот
класс работы сейчас. Приостановленный арендатор не получает права назвать свой
бакет для записи, scope, выпущенный другим authority, отвергается здесь ровно так
же, как его отвергает строковый шов, а grant только на чтение не сможет писать
объекты. Варианта, принимающего scope, нет ни у одного из них: непроверяющее
отображение не экспортировано, потому что нужное ему значение — в одном публичном
вызове `From(ctx)`.

**Долговременному шву нужен ключ.** `Spec.DurableKey` (32 байта и больше, одно и то
же значение у producer и worker) аутентифицирует ссылку, которую producer пишет в
запись. Без него `ContextProvider` и `IdentityRestorer` отказываются конструироваться, и в
этом смысл: таблица очереди долговечна, разделяема и доступна на запись всему, что
дотягивается до этой базы, поэтому неаутентифицированная ссылка в записи
превращает право записи в очередь в выдачу себя за арендатора.

**Долговременная запись — это ссылка, а не полномочие.** Producer записывает
арендатора и поколение под MAC; worker проверяет MAC — и всё равно не верит
записи: он спрашивает control plane, что верно *сейчас*. Арендатор,
приостановленный, удалённый или восстановленный после постановки задачи, до своего
обработчика не доходит, а запись, сделанная чем-то, что не владеет durable-ключом,
не доходит вообще никуда.

### Что ядро даёт шву

Шов — это пакет рядом с ядром, поэтому то, что он берёт у ядра, публично — и
намеренно узко:

```go
tenancy.Classify(err)              // ошибка приложения, сведённая к нашему sentinel
scope.Digest()                     // этот арендатор в этом поколении, как адрес фиксированной ширины

sealer, err := authority.Sealer()  // откажет, если не задан Spec.DurableKey
token, err := sealer.Seal(scope, queue, definition)
reference, generation, err := sealer.Unseal(token, queue, definition)
```

`Digest` ничего не авторизует и не является анонимизацией: он стабилен и выведен
из reference, который можно угадать, поэтому им адресуют бакет или кэш — и он не
уезжает в телеметрию. `Seal` откажет scope, который эта authority не минтила, и
жизненному циклу, который не допускает durable-класс, и связывает переданные
поля: запись, переигранная в другую очередь или другую задачу, не сойдётся ни с
одной. `Unseal` отвечает reference и поколением, но никогда `Scope`, поэтому
запись всё равно превращает в работу control plane. Собственный шов пишут против
этих пяти, а не в обход них.

**Пространства имён и партиции — это дайджесты, а не ссылки.** Путь в бакете
цитируется в ошибках провайдера и журналах доступа — ровно там, где имени
арендатора быть не должно; а пространство имён фиксированной ширины не может
оказаться префиксом чужого, как бы ни назвали ссылки. Поколение входит в дайджест,
поэтому восстановленный арендатор не читает ни объектов, ни кэша предыдущего
поколения.

## Одна база на арендатора

```go
directory, err := tenancydb.NewDirectory(tenancydb.DirectorySpec{
    Authority: authority,           // обязательно — directory сам перепроверяет допуск
    Sources:   sources,             // ваша фабрика: проверенный scope -> один crud.Source
    MaxCached: 64,                  // обязательно
    TTL:       10 * time.Minute,    // обязательно
    Close:     func(s crud.Source) error { return s.(*pgxpool.Pool).Close() }, // обязательно
    Fence:     этоДействительноЕгоБаза, // необязательно: доказать, что источник тот самый
    OpenTimeout: 30 * time.Second,      // необязательно; это значение по умолчанию
})

lease, err := directory.Borrow(ctx, tenancy.ClassWrite)
defer lease.Release()
repository := Invoices.Bind(lease.Source(), ...)
```

Directory владеет контрактом и границами; драйвер и хранилище секретов — решение
приложения. Выбор происходит до любого запроса и ключуется по арендатору **и**
поколению, поэтому привязка, закэшированная до ротации, никогда не достаётся
поколению, которое её заменило. Ни значения по умолчанию, ни отката на
«последнюю использованную» нет. Вытеснение отвязывает привязку немедленно, а
закрывает источник только когда последний заёмщик вернул lease.

`MaxCached`, `TTL` и `Close` обязательны, а не заданы по умолчанию. Первые два —
потому что неограниченный пул на арендатора это то, как один арендатор кладёт
развёртывание; `Close` — потому что `crud.Source` это интерфейс, и стоящие за ним
пулы не реализуют `io.Closer`: директория без него вытесняла бы, ротировала и
завершалась всё время жизни процесса, ни разу не вернув соединение. Источник,
которому закрытие действительно не нужно, говорит об этом одной строкой. `Authority`
обязателен по более острой причине: `Borrow` заново спрашивает, допускает ли
жизненный цикл принесённого scope *этот класс* работы. При схеме «база на
арендатора» под ним нет строковой политики, которая поймала бы приостановленного
арендатора, привязавшегося на чтение и открывшего свою базу на запись.

**Чего он не делает:** не мультиплексирует один репозиторий по базам на каждый
запрос. Репозиторий привязан к одному источнику ([[UC-012]]); directory говорит, к
какому, а привязка — ваша.

## Работа поверх нескольких арендаторов

```go
grant, err := authority.Accept(purpose, cohort, deadline, tenancy.ClassRead)
outcomes, err := authority.Each(ctx, grant, tenancy.ClassWrite, func(ctx context.Context) error {
    return billing.Roll(ctx)
})
```

Выдача grant — политика control plane; authority его **принимает**, ограничивает и
отказывается расширять. Grant называет *классы* работы, которые разрешает, и эти
классы едут вместе с работой: grant только на чтение выше не сможет записать, как
бы ни называлась его purpose, потому что purpose — это метка, а не разрешение. Ни
wildcard-когорты, ни пустой не существует. В каждого
участника входят отдельно, с повторной проверкой его жизненного цикла; участник,
переставший быть активным, попадает в `outcomes` и пропускается, а не роняет весь
прогон, — поэтому частично применённый прогон возобновляем, а не повторяем.

## Ошибки

Каждый отказ — сентинел, сравниваемый через `errors.Is`, и ни один из них не несёт
ни арендатора, ни базу, ни ключ, ни собственный текст resolver'а.

```go
tenancy.ErrNoScope    tenancy.ErrUntrusted     tenancy.ErrInactive
tenancy.ErrStale      tenancy.ErrIncompatible  tenancy.ErrUnmapped
tenancy.ErrGrantRequired                       tenancy.ErrPinned
tenancy.ErrCapacity   tenancy.ErrUnavailable   tenancy.ErrMalformed
```

Первые семь оборачивают `crud.ErrForbidden`, поэтому транспорт отвечает 403, не
импортируя этот пакет. `ErrPinned` оборачивает `crud.ErrConflict`. `ErrCapacity` и
`ErrUnavailable` намеренно не оборачивают ни того, ни другого: заполненный пул —
не отказ авторизации и не должен поднимать команду безопасности.

Resolver, упавший по своим причинам, даёт `ErrUnavailable` и ничего больше: его
сообщение называет арендатора, базу и часто учётные данные, и этот текст никуда не
едет. Логируйте его в самом resolver — это ваш код, и канал принадлежит ему.

`tenancy.OutcomeFor(err)` отображает любой из них в одну из двенадцати закрытых
констант — это то, что может нести дашборд или метка метрики.

## Чего он не покрывает

- **`Tx`.** Gate наследует его, а не переопределяет, по причине, записанной в
  [[D-030]]: сам он не трогает ни одной строки, а всё, что делает замыкание,
  доходит до базы через тот же самый gated-репозиторий. Поэтому
  `orders.Tx(ctx, fn)` без scope открывает транзакцию, а первый же глагол внутри
  отказывает. Если ваш код открывает единицу работы раньше, чем определяет
  арендатора, определяйте сначала.
- **`Save` с назначенным ключом обязан нести владельца.** Записывается вся строка
  целиком, а колонка владения заморожена, поэтому пустой владелец читается как её
  изменение. `Derive` проставляет владельца при создании, а не при перезаписи.
- **Сырой запрос, `crud.UnsafeExecFor` или репозиторий, связанный без middleware.**
  Сужение — это предикат, который здесь подмешивается, а не свойство соединения.
- **Курсор пагинации, выпущенный под scope другого арендатора** — тот же класс
  оракула, что и создание по глобально уникальному ключу.
