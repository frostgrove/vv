# i18n

`github.com/frostgrove/vv/i18n` — опциональный модуль полноценного
представления. Он компилирует один ограниченный профиль `frostgrove-mf2/v1` в
неизменяемые snapshots, разрешает локали, связывает типизированные отложенные
сообщения, форматирует их без ambient-состояния процесса и адаптирует к
stdlib-only шву `errs.MessageSource`.

Это вложенный Go-модуль. Его MessageFormat-движок и Unicode-данные попадают
только в приложение, которое явно выбрало i18n. Корневой модуль, transports и
`errs` его не импортируют ([[D-135]]).

## Установка и декларация

```sh
go get github.com/frostgrove/vv/i18n@VERSION
```

Приложение собирает один полный `CatalogSpec`. Модуль вносит обычные значения
`Module` и `MessageSpec`; сам импорт ничего не регистрирует.

```go
pending := i18n.MessageSpec{
    ID:          "pending",
    Revision:    "pending/v1",
    Source:      "You have {$count :number} pending actions",
    Description: "Dashboard pending-action count",
    Arguments: []i18n.ArgumentSpec{
        {Name: "count", Type: i18n.TypeInteger, Required: true},
    },
    Output:   i18n.OutputPlain,
    Override: i18n.OverrideApplication,
    Public:   true,
}

snapshot, err := i18n.New(i18n.CatalogSpec{
    Revision:            "2026-09-09",
    SourceLocale:        "en",
    DefaultLocale:       "en",
    TimeZoneDataVersion: "tzdb/2026a:embedded",
    Supported:           []string{"en", "ru", "kk"},
    Required:            []string{"en"},
    Modules: []i18n.Module{
        {Name: "tasks", Messages: []i18n.MessageSpec{pending}},
    },
})
```

`New` проверяет всю декларацию до возврата `Snapshot`: квалифицированные
идентификаторы, ревизии, BCP 47 локали, fallback graph, схемы аргументов,
проверенные переводы, обязательные локали, права overrides, поддерживаемый MF2,
formatting, allowlist rich-markup и каждый заданный предел. При ошибке
возвращается один детерминированно упорядоченный набор проблем и никакого
частичного snapshot.

Идентичность профиля публична и входит в identity snapshot:

```go
i18n.GrammarProfile    // frostgrove-mf2/v1
i18n.MessageFormatSpec // базовая версия Unicode MessageFormat 48.2
i18n.EngineVersion     // messageformat-go/v0.8.6
i18n.LocaleDataVersion // закреплённые plural- и formatting-данные
i18n.TimeZoneDataModel // runtime-selected модель Go location
```

Всегда доступны функции `number`, `integer`, `currency`, `percent`, `offset` и
`string`. Стабильная numeric-поверхность принимает Unicode-спеллинги
`select=plural`, `useGrouping=never`, integer `maximumSignificantDigits`,
currency `fractionDigits`, точный 0–99 `offset add/subtract` и наследование
numeric options без преобразования integer/decimal через binary float. String
selection сравнивает NFC, но не меняет исходные байты при форматировании.
Для `date`, `time` и `datetime` нужна `CapabilityDateTime`, для `unit` —
`CapabilityUnit`. Operand функции должен быть объявленным типизированным
аргументом. Options должны быть литералами из allowlist функции. Неизвестные
имена, значения, selector keys, attributes и markup options отвергаются при
сборке. Автоопределения грамматики и тихого переключения на другой formatter
нет.

Имя `frostgrove-mf2/v1` честно обозначает ограниченный профиль Frostgrove, а не
полную совместимость с editor HEAD. Он основан на опубликованной версии из
`MessageFormatSpec`, требует объявленные typed operands вместо literal
operands, отвергает неизвестные options вместо их игнорирования, сохраняет
один канонический selector vocabulary, а draft vocabulary date/time/unit
версионирует за capabilities.
Профиль поддерживает литеральные `u:id` и
`u:dir=ltr|rtl|auto|inherit` на function expressions и литеральный `u:id`
на rich markup. Universal options с variable-значениями не входят в
эту версию: pinned engine пока не умеет разрешать их из
точных typed-значений Frostgrove без потери семантики.

## Source и review identity

`CatalogSpec` — декларация в памяти. `EncodeSource` пишет её канонический JSON
формата `frostgrove.i18n.source/v1`, а `DecodeSource` строго читает его.
Неизвестные или повторные поля, невалидный UTF-8, хвост после JSON и превышение
depth/cardinality/byte limits — отказы.

У каждого несырьевого перевода и override две разные группы идентичности:

- `ContractRevision` и contract digest закрепляют key, схему аргументов, output
  kind и markup contract.
- `SourceDigest` покрывает profile, каноническую source locale, разрешённый key,
  contract, исходный текст и описание для переводчика.
- `ReviewDigest` покрывает source digest, каноническую локаль и перевод.

Для собственного authoring-инструмента есть `ExpectedSourceDigestForLocale` и
`ExpectedReviewDigest`. В обычном репозитории значения ставит команда `review`.
Изменение source locale, исходной формулировки или описания делает review
устаревшим даже при неизменной типизированной схеме.

После перегенерации деклараций новый authoritative source нужно слить с
предыдущим reviewed-документом до review:

```sh
vv-i18n merge -source messages.generated.json -previous messages.i18n.json \
  -out messages.i18n.json
```

`MergeSource` и команда `merge` переносят отсутствующие в новом source
структурно допустимые переводы и application overrides с всё ещё валидными
key, locale и permission. Stale, review-required и rejected identities
сохраняются дословно для `check`; merge никогда не повышает их статус. Явно
заданное новое значение всегда побеждает. Смена source locale или любая
obsolete authoring-работа даёт
`ErrMergeWouldDiscard`; `-prune-obsolete` явно разрешает её удаление. Review,
source и contract identities не пересчитываются; inputs не мутируются, а
результат каноничен и идемпотентен. Для каталогов, намеренно превышающих
консервативные default limits, задайте локальный ceiling через
`SourceMerger{CatalogLimits: ...}`; convenience-функции сохраняют defaults.
`SourceMerger.SourceLimits` независимо ограничивает canonical source output.
Merge учитывает candidate translations и overrides по обоим ceilings до append
и хранит для obsolete work только точное число и лексикографически первую
диагностику.

В runtime snapshot допускается только `ReviewApproved`. `ReviewRequired` и
`ReviewRejected` остаются валидными состояниями source-документа, чтобы `check`
показал настоящую работу, а не сделал файл нечитаемым. Application override
может заполнить обязательную локаль. Пробел в необязательной локали — warning,
пока check не запущен в strict-режиме.

## Check, pseudo и compile

Установите или запускайте команду из вложенного модуля:

```sh
go install github.com/frostgrove/vv/i18n/cmd/vv-i18n@VERSION

vv-i18n check -source messages.i18n.json -out report.json
vv-i18n review -source messages.i18n.json -out messages.i18n.json \
  -locale ru -scope translations -state approved
vv-i18n pseudo -source messages.i18n.json -out messages.pseudo.json \
  -locale en-XA -mode accent
vv-i18n compile -source messages.i18n.json -out messages.i18n.bin
```

### Единая limits policy для authoring-команд

Все команды принимают одну optional policy `-limits PATH`: `check`, `compile`,
`pseudo`, `generate-go`, `export-ts`, `extract`, `review` и `merge`. Это
отдельный строгий JSON-документ. Пропущенные секции и поля сохраняют
консервативные library defaults; явное значение обязано быть положительным
целым в поддерживаемых библиотекой границах.

```json
{
  "schema": "frostgrove.i18n.limits/v1",
  "catalog": {
    "locale": {
      "max_supported": 256,
      "max_fallback_depth": 24
    },
    "max_messages": 12000,
    "max_translations": 96000,
    "max_catalog_bytes": 134217728
  },
  "source": {
    "max_bytes": 268435456,
    "max_depth": 96,
    "max_members": 8388608
  },
  "compiled": {
    "max_bytes": 268435456,
    "max_depth": 96,
    "max_members": 8388608
  },
  "output": {
    "max_bytes": 268435456
  }
}
```

`catalog` — operator-owned local ceiling для каждого объявленного catalogue
limit. Source-документ не может его расширить. Snake-case поля этой секции:
`locale` (`max_choices`, `max_header_bytes`, `max_ranges`, `max_supported`,
`max_tag_bytes`, `max_fallback_depth`) и `max_modules`, `max_messages`,
`max_translations`, `max_locales`, `max_arguments`, `max_enum_values`,
`max_markup_names`, `max_catalog_items`, `max_identifier_bytes`,
`max_revision_bytes`, `max_description_bytes`, `max_enum_value_bytes`,
`max_argument_bytes`, `max_big_integer_bits`, `max_template_bytes`,
`max_catalog_bytes`, `max_declarations`, `max_selectors`, `max_variants`,
`max_local_depth`, `max_template_parts`, `max_markup_depth`,
`max_output_bytes`, `max_output_parts` и `max_explain_steps`.

`source` ограничивает streaming decode source и каждый canonical source output
от `pseudo`, `review` и `merge`. `compiled` ограничивает только compiled
artifact. `output` ограничивает каждый производный файл от `check`,
`generate-go`, `export-ts` и `extract`, включая каждый файл generational
publication, но не сужает неявно source или compiled artifacts. Defaults трёх
byte ceilings равны 128 MiB, абсолютная поддерживаемая граница — 1 GiB.
Hostile-input ceilings для Go sources extraction и usage manifest команды
`check` остаются фиксированными их собственными document contracts, а не
catalogue limits.

Library caller управляет usage-границей через `CheckPolicy.UsageLimits`. Ноль в
поле выбирает `DefaultUsageLimits`, ненулевое значение сужает локальный ceiling
и не может превысить hard default. Максимумы: по 262144 keys, dynamic ranges и
occurrences; 1024 roots; по 100000 files и metadata records; по 256 элементов в
каждом build/tool/release tag и environment ledger; 4 MiB на одну строку; 64
MiB aggregate semantic material. Usage decoder и `Check` используют один контракт,
независимый от `CatalogSpec.Limits`.

Команда передаёт соответствующий ceiling и `context.Context` внутрь producer до
построения output. Невозможный маленький предел поэтому отвергается до
пропорционального clone, Go formatting или manifest/address hashing, а значимые
build, encode и digest loops проверяют cancellation. Тот же путь доступен через
`NewContext`, `CompileContext`, `Compiler.CompileContext`,
`EncodeContext`, `Compiler.EncodeContext`, `EncodeSourceContext`,
`SourceCodec.EncodeContext`, `SourceCodec.EncodedSizeContext`, `PseudoContext`,
`GenerateGoContext`, `ExportPublicContext`,
`MergeSourceContext`, `SourceMerger.MergeContext` и
`ExpectedPublicExportAddressContext`. Usage evidence digests дают тот же
lifecycle через `ExpectedUsageSourceDigestContext` и
`ExpectedUsageManifestDigestContext`. Старые convenience APIs используют
`context.Background()` и конечные default или snapshot ceilings.

`GoGeneratorSpec.MaxOutputBytes`, `PseudoSpec.MaxOutputBytes` и
`PublicExportSpec.MaxOutputBytes` задают per-file ceiling внутри producer. Ноль
выбирает предел snapshot/catalogue; большее запрошенное значение не может его
расширить.
`SourceCodec.EncodedSize` и `SourceCodec.EncodedSizeContext` возвращают точный
размер canonical source wire representation под catalogue/artifact ceilings
codec. Go, source, compiled artifact, pseudolocale, review, public manifest и
TypeScript выполняют точный count-only pass до formatter, digest, clone или
зависящей от output materialization: точный ceiling принимается, N-1
отвергается.

Сам limits-документ ограничен 64 KiB и обязан быть regular non-symlink файлом.
Duplicate/unknown names, trailing values, неверная schema и невалидные значения
отвергаются; обычные JSON whitespace и порядок полей допустимы. Source paths
используют ту же regular non-symlink policy и передаются прямо в `SourceCodec`
без промежуточного `ReadAll`. Отсутствующая или невалидная policy никогда не
заменяется defaults молча.

`check` выдаёт детерминированные findings `missing`, `stale`,
`review_required`, `rejected`, `unused` и `invalid`, а также coverage по
локалям. `-strict` превращает долг необязательной локали в ошибки.
`-max-findings` ограничивает сохранённые подробности, не теряя точное число
errors, warnings и structural errors; `FirstStructuralError` доступен даже при
усечённых подробностях. Поэтому `review` не блокируется из-за усечённого долга
по переводам, но отказывает при любой структурной невалидности. `-usage`
принимает манифест от `extract`; вывод о неиспользуемом сообщении достоверен
только для манифеста с полными roots.

`pseudo` возвращает новый канонический source. `-mode accent` расширяет и
акцентирует человеческий текст, `-mode rtl` проверяет right-to-left
представление. Литералы, имена аргументов и MF2-структура не переводятся. По
умолчанию локаль добавляется к supported; `-add-supported=false` не меняет
policy.

`compile` проверяет source и пишет канонические байты
`frostgrove.i18n.catalog/v1`. В библиотеке тот же путь дают `Compile` и
`Encode`; их context-варианты предпочтительны в lifecycle запроса, job и
команды. Runtime-загрузка строгая и офлайн:

```go
snapshot, err := i18n.Load(ctx, bytes.NewReader(compiled))
snapshot, err = i18n.LoadFS(ctx, embedded, "messages.i18n.bin")
```

Через `Loader` и `Compiler` приложение задаёт локальные `ArtifactLimits` и
`CatalogLimits`. Заявленные внутри artifact пределы не могут расширить эти
ceilings. `Load` сверяет точные artifact/profile/engine/locale-data/time-zone
identities, semantic digest и каноническое байтовое представление. Сети здесь
нет, а `LoadFS` закрывает файл на любом пути.

Каждый прямой output CLI проходит staging, sync и atomic rename. Раздельные
multi-file outputs атомарны только на уровне каждого файла и делают best-effort
rollback при возвращённой process error; для crash-consistent generation reader
использует `-publication-root`. `-check` проверяет drift и ничего не пишет. Для
него нужен файл, а не stdout.

## Extract, generate и export

```sh
vv-i18n extract -root ./internal -root ./cmd -out usage.i18n.json
vv-i18n extract -root ./internal -tags enterprise,postgres -out usage.i18n.json
vv-i18n extract -root . -tags= -out usage.i18n.json
vv-i18n extract -complete -root ./my-module -out usage.complete.i18n.json
vv-i18n check -source messages.i18n.json -usage usage.i18n.json -out report.json
vv-i18n generate-go -source messages.i18n.json -out messages_gen.go -package messages
vv-i18n export-ts -source messages.i18n.json \
  -out messages.d.ts -manifest messages.public.json -address-out messages.address
vv-i18n export-ts -source messages.i18n.json -publication-root public.i18n
```

`extract` запрашивает у context-bound Go tool реальный effective package graph
с compiled-file и export-data facts, затем type-checks выбранные локальные
пакеты как единый source graph. Application initialization не выполняется.
Распознаются static и bounded-domain употребления через `Snapshot.Bind`, все
четыре конструктора `Define`/`NewDefinition`, generated definitions, error
mappings, typed method values, callbacks, interfaces и selected-graph wrappers.
Неограниченный key и escaped/reassigned constructor callable — жёсткая ошибка
extraction; escape уже созданного definition или contract сохраняет полезный
partial result, но принудительно даёт `complete:false`.

Completeness также fail-closed, если `Snapshot.Bind`, его method expression или
value, binder-bearing interface, `*Snapshot` либо другая i18n capability
возвращается, сохраняется в field/map/heap, проходит через reflection/`unsafe`
или передаётся неизвестному/external call. Передача точного capability type в
typed call или callback остаётся complete, когда тело callee входит в точный
selected source graph, включая выбранный sibling package. Generated marker
не является trust boundary: result field definition factory считается
доказанным только тогда, когда это поле известно на каждом reaching assignment
и return; parameters, mixed paths и escapes не доверяются.

Для полного доказательства directory root обязан быть корнем Go module.
Selection следует эффективным GOOS, GOARCH, compiler, CGO, quoted persisted
`GOENV`/`GOFLAGS`, явному `-tags`, активному `go.work`, границам nested modules,
replacements, vendoring и overlays. Явный `-tags=` переопределяет inherited
tags. Инструмент использует private disposable build cache, установленный local
toolchain, отключённые module proxy/checksum database и read-only shadow-копии
module/workspace metadata, поэтому не скачивает зависимости и не обновляет
checkout. Cgo packages, package/dependency/load errors, отсутствующие или
конфликтующие export facts, несмоделированное multi-root environment, file
roots и любой reachable non-standard dependency, способный скрыть i18n call,
делают evidence incomplete. Dependency, для которого доказана недостижимость
i18n, всё ещё может дать точную export type information. Файлы, исключённые
эффективным production build, включая tests и другие platform/tag variants,
остаются хэшированными в ledger; одно их наличие не делает доказательство этого
effective build неполным.
Корень модуля без Go source candidates всё равно даёт каноническое v1 evidence
с пустыми file, aggregate и occurrence ledgers и `complete:false`; `-complete`
запрашивает proof и понижается, а не делает честный пустой результат
нечитаемым.

Usage v1 хранит sorted unique exact/dynamic aggregates и one-based source
occurrences, canonical root/file ledgers, selected state и SHA-256 каждого
candidate, effective Go settings, module/workspace/vendor/overlay/toolchain
metadata и digest resolved package graph. `source_digest` пересчитывается из
scope ledger; `manifest_digest` дополнительно связывает completeness,
aggregates и occurrences. Decoder и `i18n.Check` проверяют counts,
containment, coordinates, reverse evidence, sorting, uniqueness и оба digest.
Перед выделением больших JSON slices выполняется bounded streaming preflight.
Build, tool и release tag ledgers каноничны только в sorted unique форме. Любая
другая schema или analyzer identity отвергается.

Эти hashes доказывают self-consistency ledger, но не authenticity и не
physical freshness: тот, кто может переписать manifest, может пересчитать и
их. Release, полагающийся на non-use, запускает ту же команду
`extract -complete ... -check` для manifest из trusted checkout и controlled Go
environment. Этот путь заново строит graph и хэширует physical roots без
записи; обычный `check -usage` намеренно не читает source files.

`generate-go` создаёт типизированный `Catalog`, args-структуру на сообщение,
enum types и encoders. Его `NewCatalog(snapshot)` вызывает `Define` с
литеральными `ContractRef`: бинарник, сгенерированный для старого контракта,
отвергнет новый snapshot при сборке приложения, до первого запроса.
Необязательные поля имеют тип `Optional[T]`: zero value — absent, `Some(v)` —
present, `NullValue[T]()` — explicit null.

`export-ts` пишет types и канонический manifest только для сообщений с
`Public`. Content address покрывает оба результата. Integer, unsigned, big
integer, decimal, currency и instant представлены явными branded wire scalars.
`FormattingParity` намеренно равен `false`: export не поставляет JS formatter и
не обещает, что browser воспроизведёт Go MF2/CLDR output. Private messages в
результат не попадают.

`-publication-root` — process-crash-safe и concurrent-reader-safe альтернатива
прямым output flags, совместно с ними он не используется. Команда пишет immutable
`generations/sha256-<digest>/messages.d.ts` и `messages.public.json`, затем одним
rename коммитит bounded pointer `current.json`. Reader один раз читает pointer,
открывает только названное generation и проверяет объявленные byte counts и
SHA-256 digests. Старые generations сохраняются, поэтому concurrent switch не
ломает уже pinned read. Generation files, новые root/directory entries и
publication root синхронизируются в dependency order на системах кроме Windows.
На каждой платформе temporary file body синхронизируется до rename. Read-only
directory handle в Go на Windows возвращает `ACCESS_DENIED` из `File.Sync`,
поэтому Windows-сборка выбирает явный compile-time no-op для directory sync, а
не подавляет произвольную runtime-ошибку. Atomic visibility и целостность для
concurrent readers сохраняются; durability directory-entry updates при потере
питания остаётся границей OS/filesystem. `-check` строго проверяет pointer и всё
generation, ничего не создавая и не меняя. Контракт предполагает trusted
writable local filesystem с atomic same-directory rename; non-Windows гарантия
при потере питания дополнительно требует рабочего file и directory `fsync`.
Retention cleanup принадлежит delivery pipeline и не должен гоняться с pinned readers.

Все mutating single-file, staged-set и generational writers в одном output
directory используют единый persistent `.vv-i18n.lock`. Это проверенный через
descriptor regular non-link файл: создание использует exclusive create, а для
существующего файла identity обязана совпасть между inspect, open и stat и
повторно проверяется после acquisition. Команда context-aware повторяет
nonblocking Unix `flock` или Windows `LockFileEx`, затем удерживает descriptor и
OS lock через commit, rollback и последний directory sync. Crash процесса
освобождает lock ownership; сам файл намеренно остаётся. На target platform без
реализации команда завершается до filesystem mutation. Check mode остаётся
строго read-only и не создаёт и не захватывает этот lock.

Lock сериализует cooperating `vv-i18n` publishers, если filesystem соблюдает
контракт OS advisory locking. Произвольный external writer может его
игнорировать. Существующие identity checkpoints отвергают замеченную мутацию,
но linearizability относительно external mutation между checkpoint и операцией
не обещается.

Publisher, library reader и standalone reference reader идут от filesystem или
volume root и открывают каждый компонент иерархии через стабильные descriptors,
сравнивая identity открытого объекта с проверенной entry. Linked component или
замена identity между inspection и opening отвергается. После pin component
последующая замена ancestor не может перенаправить чтение или запись. Отсутствующий
финальный publication root создаётся только через pinned parent descriptor,
который затем синхронизируется там, где доступен directory sync. Writer удерживает
pinned handle проверенного `generations` для создания temporary generation,
записи, rename, cleanup и sync, а перед commit `current.json` проверяет, что root
entry всё ещё указывает на тот же directory. Pointer target также работает как
compare-and-swap: изначально отсутствующий файл должен остаться отсутствующим, а
существующий regular file — сохранить точную identity. Readers также ограничивают
directory enumeration, а library reader проверяет cancellation между bounded file chunks.

`current.json` имеет schema `frostgrove.i18n.publication/v1`: lowercase
`sha256:` generation и public-export address плюс упорядоченную таблицу `files` —
сначала `manifest/messages.public.json`, затем `typescript/messages.d.ts`, с
byte count и lowercase SHA-256 каждого файла. Имена и roles фиксированы и не
являются caller-controlled paths; в переносимом имени directory двоеточие
address заменено на `sha256-`. Generation digest связывает public address и все
role, name и file body через domain-separated framing с unsigned 64-bit
big-endian длиной. Malformed, non-canonical, linked, missing, extra или
digest-mismatched entry приводит к отказу.

Независимый Go reader после bounded чтения и проверки SHA двух фиксированных
файлов может вычислить protocol content identity через
`ExpectedPublicExportAddress(manifest, typeScript)`. Publisher и Frostgrove
reader используют ту же derivation; даже внутренне согласованный generation
pointer отвергается, если его address был вычислен для другого content.

```json
{
  "schema": "frostgrove.i18n.publication/v1",
  "generation": "sha256:<64 lowercase hex digits>",
  "address": "sha256:<64 lowercase hex digits>",
  "files": [
    {"role": "manifest", "name": "messages.public.json", "bytes": 123, "sha256": "sha256:<64 lowercase hex digits>"},
    {"role": "typescript", "name": "messages.d.ts", "bytes": 456, "sha256": "sha256:<64 lowercase hex digits>"}
  ]
}
```

## Resolver и view

Locale resolution отделён от fallback конкретного сообщения. На границе
приложения соберите упорядоченные choices:

```go
resolution := snapshot.Resolve(
    i18n.Exact(i18n.SourceExplicit, routeLocale),
    i18n.Exact(i18n.SourceUser, userLocale),
    i18n.AcceptLanguage(i18n.SourceProtocol, r.Header.Values("Accept-Language")...),
    i18n.Exact(i18n.SourceTenant, tenantDefault),
    i18n.Exact(i18n.SourceApplication, "en"),
)
if !resolution.Matched() {
    return errNoAcceptableLocale
}

view, err := snapshot.View(i18n.ViewSpec{
    Resolution:       resolution,
    FormattingLocale: "kk",
    TimeZone:         "Asia/Almaty",
    Presentation:     i18n.PresentationDefault,
})
```

`AcceptLanguage` понимает повторные поля, веса, исключения `q=0` и wildcard под
лимитами bytes/ranges. `MatchLookup` находит точный supported tag либо
последовательно сокращает более конкретный запрос; он не расширяет общий `zh`
до случайного первого `zh-Hans` или `zh-Hant`. `MatchBestFit` явно включает
закреплённый matcher, если такой вывод нужен. `DefaultOnMiss` — явная policy, а
не environment fallback. Результат сообщает canonical supported locale,
source, outcome и reason. `Resolution` запечатан создавшим его resolver: его
нельзя изготовить вручную или использовать с чужим resolver.

Для одной точной локали есть shorthand `snapshot.For("ru")`. `ForContext`
принимает те же choices и возвращает default view.

View закрепляет четыре входа, меняющие output: разрешённую message locale,
formatting locale, time zone и presentation. Грамматика использует фактическую
локаль шаблона, а number/date formatting — `FormattingLocale`. По умолчанию это
resolved locale. Пустая zone во view использует `DefaultTimeZone` каталога, чей
zero default — UTC. Не-UTC зона разрешена только когда catalog объявляет
`TimeZoneDataVersion`; соответствие реальным IANA-данным в build/runtime
обеспечивает приложение. Go разрешает named zones через `ZONEINFO`, данные
хоста, GOROOT или embedded fallback, поэтому `TimeZoneDataModel` намеренно не
заявляет закреплённый IANA release. Для byte-identical исторического zoned
output приложение должно контролировать runtime-данные и объявлять их
проверенную identity самостоятельно.

## Bind и render

Проверяемый динамический путь выглядит так:

```go
message, err := snapshot.Bind(
    i18n.Qualify("tasks", "pending"),
    i18n.Integer("count", 21),
)
rendered, err := view.Render(ctx, message)
```

Аргументы — закрытые типизированные значения: `Text`, `Bool`, `Integer`,
`UnsignedInteger`, `BigInteger`, `Decimal`, `Money`, `Date`, `Instant`, `Enum`
и `Null`. Missing, extra, duplicated, неверно типизированные и запрещённые null
аргументы отвергаются. Строки, `big.Int` и slices копируются до того, как
отложенный `Message` уйдёт вызывающему коду.

`Integer`, `UnsignedInteger` и `BigInteger` не проходят через `float64`.
`Decimal` — ограниченная лексическая десятичная дробь: видимые знаки после
запятой участвуют в plural selection, поэтому `1` и `1.0` не обязаны выбирать
одну категорию. Exact selector остаётся точным. `Money` сохраняет currency и не
конвертирует её. `Date` — календарная дата без сдвига через zone; `Instant`
форматируется в явно заданной зоне view.

С generated code связывайте typed definition:

```go
catalog, err := messages.NewCatalog(snapshot)
pending, err := catalog.TasksPending.Bind(messages.TasksPendingArgs{Count: 21})
rendered, err := view.Render(ctx, pending)
```

Generated definitions — рекомендуемый production-путь, когда каталог входит в
build: bind не использует reflection, а drift контракта обнаруживается при
assembly. Небольшая hand-written интеграция может получить тот же типизированный
`Definition[A]` без генератора:

```go
type PendingArgs struct {
    Count int64
    Note  i18n.Optional[string]
}

pending, err := i18n.NewStructDefinition[PendingArgs](
    snapshot,
    i18n.Qualify("tasks", "pending"),
)
message, err := pending.Bind(PendingArgs{Count: 21, Note: i18n.Some("сегодня")})
```

`DefineStruct[A](snapshot, contract)` делает то же для уже закреплённого
`ContractRef`. Constructor один раз использует reflection, проверяет всю mapping
и компилирует encoder; `Bind` читает только готовый план прямых полей. Exported
direct fields сопоставляются по ASCII case с игнорированием `_`, `-` и пробелов;
точный tag `i18n:"argument_name"` имеет приоритет, а `i18n:"-"` игнорирует поле.
Embedded и unexported fields не связываются неявно. Required non-nullable
аргументы используют direct fields; optional или nullable обязаны использовать
точный контейнер `Optional[T]`, а не embedding-wrapper. Definition key проверяется
по `Limits.MaxIdentifierBytes` до lookup; то же относится к keys в `Snapshot.Bind`,
`Descriptor`, `ContractRef` и `SourceDigest`. Полная raw-строка struct tags
ограничена `Limits.MaxDescriptionBytes` до разбора tags. Затем полная syntax Go
tag декодируется по semantics строковых литералов Go; malformed syntax или
повторный ключ `i18n` отвергаются до automatic field matching.
`Descriptor.ContractRef` также возвращает zero reference для вручную созданного
descriptor с malformed key или key выше package hard identifier ceiling.
Поддерживаются string
kinds для text/decimal/enum, bool kinds,
`int64`/`uint64` kinds и точные `*big.Int`, `MoneyValue`, `DateValue`,
`time.Time`. Native-width integers, floats и структурно похожие named composites
отвергаются при construction. `Some` означает present, нулевой optional — absent,
`NullValue` — explicit null; `Some` с typed nil pointer после обычной argument
validation также становится explicit null.

`Rendered` содержит plain `Text`, безопасные структурные `Parts`, фактическую
`TemplateLocale`, resolved locale/provenance, победивший `Layer`, revision и
digest snapshot, terminal outcome и `RenderKey`. `RenderKey` —
детерминированный SHA-256 по всем влияющим на output входам, включая
скопированные аргументы. Это cache identity, а не авторизация и не замена самим
значениям для render. `View.Explain(message)` возвращает ограниченный trace
preference/template fallback без текста и аргументов.

`OutputPlain` — неэкранированный текст; его HTML/JSON/URL/shell sink обязан сам
экранировать данные. `OutputRich` выдаёт только границы text/value/markup/bidi.
Markup name должен быть объявлен; перевод не добавляет attributes/options, а
parts никогда не становятся trusted HTML. Каждый part сохраняет стабильный Frostgrove
`Kind` и исходный MF2 `Type`; авторский `u:id` становится opaque correlation
metadata, а не DOM ID или trust primitive. Number/date values возвращают копию
плоских `Subparts`, например `integer`, `group`, `fraction`, `year` и `literal`;
их конкатенация всегда равна parent text. Nested nodes считаются в
`MaxOutputParts`, а их байты не считаются второй раз. По умолчанию включена FSI/PDI
изоляция. `PresentationNoIsolation` — явный opt-out. Недоверенные аргументы с
directional controls отвергаются; authored text допускает direction marks и
сбалансированные isolates, но не embeddings, overrides и несбалансированные
isolates.

View также форматирует отдельные значения через `FormatNumber`, `FormatMoney`,
`FormatPercent`, `FormatUnit`, `FormatDate`, `FormatInstantDate`, `FormatTime`,
`FormatDateTime`, `FormatList`, `FormatRelative`, `FormatDuration` и
`FormatDisplayName`. Числа задаются закрытыми exact-типами (`SignedNumber`,
`UnsignedNumber`, `DecimalNumber` или immutable `BigIntegerNumber`), без
неявного float. Typed specs управляют grouping, sign, notation, digit ranges,
currency/unit presentation и date/time styles. `NumberFormatSpec` также задаёт
режимы округления и приоритет точности ECMA-402, `stripIfInteger` и закрытый
набор decimal rounding increments. Increment больше единицы допустим только с
одинаковыми minimum/maximum fraction digits и без significant digits: неверная
комбинация падает до render. `Digits(min, max)` задаёт обе границы;
`MinimumDigits(min)` и `MaximumDigits(max)` сохраняют Intl default для
пропущенной стороны, включая зависящие от currency defaults. Нулевой date/time
style означает `medium`. `FormatDate(DateValue, ...)` форматирует calendar date
без timezone shift, а instant-методы интерпретируют `time.Time` в pinned zone
view. Relative-time принимает целые `int64` units только от `-(2^53-1)` до
`2^53-1`. После этой exactness guard pinned Intl backend преобразует integer в
`float64`, который точно представляет каждое принятое значение. Fractional
values и integers вне диапазона отвергаются. Все эти операции используют те же
formatting locale, presentation, cancellation, observer, conservative output
preflight и безопасные parts.

Тот же boundary работает без каталога через
`NewFormatter(FormatterSpec{...})`. Повторяемые политики можно один раз собрать
в bounded immutable registry `Formats` и вызывать через `FormatNamedNumber`,
`FormatNamedMoney`, `SelectNamedPlural`, `FormatNamedDateTime`,
`FormatNamedList` и остальные typed methods. `View.Formatter(formats)` наследует
точные locale, zone, capabilities, presentation, limits и observer view.
Duplicate, invalid, oversized или несовместимые с capabilities named formats
падают при construction; число entries и aggregate retained material проверяются
до allocation registry и backend validation. Retained names и строковые options
клонируются. Неизвестное имя возвращает `ErrFormatNotFound`; failed и canceled
named calls создают то же одно terminal observation, что и успешные named calls.

Ranges для number, money, percent, unit, calendar-date, instant-date, time и
datetime являются first-class. `FormattedRange` сохраняет общий `Text`, locale и
безопасные `RangePart` с источником `RangeSourceStart`, `RangeSourceShared` или
`RangeSourceEnd`. `SelectPluralRange` использует plural-range rules локали, а не
угадывает категорию по одному endpoint. Значения остаются exact и проходят те же
preflight, cancellation, bidi и observer policies, что scalar formatting.

```go
amount, err := view.FormatMoney(ctx,
    i18n.MoneyValue{Amount: "1234.50", Currency: "KZT"},
    i18n.MoneyFormatSpec{Number: i18n.NumberFormatSpec{
        FractionDigits:      i18n.Digits(2, 2),
        RoundingMode:        i18n.NumberRoundingModeHalfEven,
        RoundingIncrement:   i18n.NumberRoundingIncrement5,
        TrailingZeroDisplay: i18n.NumberTrailingZeroAuto,
    }},
)
```

## Ошибки и transports

`Snapshot.ErrorMessages` проверяет и создаёт неизменяемый адаптер к корневому
error seam:

```go
source, err := snapshot.ErrorMessages(i18n.ErrorSpec{
    Mappings: []i18n.ErrorMapping{
        {
            Ladder:        "email.unique",
            Key:           i18n.Qualify("errors", "email_taken"),
            FieldArgument: "field",
        },
    },
    FieldLabels: []i18n.FieldLabel{
        {Field: "email", Key: i18n.Qualify("fields", "email")},
    },
})

renderer := porthttp.NewRenderer(porthttp.WithMessages(source))
```

Если request boundary уже владеет одним разрешённым view, mappings можно
скомпилировать один раз и привязывать plan к каждому immutable view:

```go
plan, err := snapshot.ErrorPlan(i18n.ErrorPlanSpec{
    Mappings: []i18n.ErrorMapping{
        {Ladder: "email.unique", Key: i18n.Qualify("errors", "email_taken")},
    },
})

view, err := snapshot.View(viewSpec)
source, err := view.ErrorMessages(plan)
```

Bound source использует точные snapshot, resolution, formatting locale, time
zone и presentation своего view для каждой violation. Он не запускает locale
negotiation повторно и не пересобирает mapping metadata. Поэтому locale argument
интерфейсного метода `Message` не является authoritative и игнорируется;
`MessageWithLocale` по-прежнему сообщает locale действительно выбранного
шаблона. Plan отвергает view другого snapshot и безопасно переиспользуется
параллельно между view своего snapshot.

Mapping — allowlist от существующего ключа error ladder к квалифицированному
message contract. Преобразуются только объявленные violation params; для money
обязательно объявляется currency. Field labels — argument-free plain messages.
Локализация меняет только человеческий wording. `Kind`, code, public path,
partial marker, HTTP/gRPC status и redaction внутренних ошибок по-прежнему
принадлежат `errs`, `port` и transport.

Возвращаемый `i18n.ErrorSource` реализует `errs.LocalizedMessageSource`, поэтому
HTTP может записать фактическую template
locale в `Content-Language`, а CRUD gRPC — в
`LocalizedMessage.Locale`. Requested locale не выдаётся за доказательство языка
шаблона. Если mapping, binding или formatting не удались, adapter отказывается,
а существующий renderer продолжает к безопасному violation/code wording.

HTTP и gRPC остаются владельцами protocol extraction. Их небольшие встроенные
helpers берут только первый language tag. Для полноценного weighted negotiation
разрешите locale этим модулем до error boundary и положите supported result в
существующий `port.WithLocale`/transport context. Биндинги сохраняют непустую
заранее выбранную локаль.

## Overlays и публикация

`snapshot.Overlay(ApplicationOverlay(...))` и
`snapshot.Overlay(TenantOverlay(...))` заменяют целый approved translation и
возвращают новый immutable snapshot. Слои могут только повышаться: module →
application → tenant. Поверх tenant snapshot нельзя построить ещё один tenant
overlay. Base descriptor решает, какой слой разрешён; override не меняет key,
schema, output, visibility или review/source identity. В snapshot нет tenant
identity. Аутентификация, выбор tenant и авторизация происходят до его выбора в
коде приложения.

`Controller` — ограниченный механизм публикации внутри процесса:

```go
controller, err := i18n.NewController(i18n.ControllerSpec{Initial: snapshot})
head := controller.Current()
head, err = controller.Activate(head, candidate)
lease, err := controller.PinCurrent(24 * time.Hour)
defer lease.Release()
```

`Activate` и `Rollback` сравнивают opaque `Head`, а не только публичную строку
revision, поэтому stale publisher не победит после A → B → A. Неудачный swap не
трогает current snapshot. Retention count, pin count/lifetime и retained bytes
ограничены; `Prune` вызывается явно. `Lease` не несёт principal или tenant
authority и истекает по clock контроллера.

Controller не создаёт watcher, timer, goroutine, filesystem policy или durable
pin store. Storage, polling, rollout, readiness, shutdown, durable job intent и
recipient authorization принадлежат приложению. In-memory pin сам по себе не
обещает воспроизводимость queued job после перезапуска процесса.

## Лимиты и observations

Нулевой `CatalogSpec.Limits` означает конечные defaults. Основные operational
пределы:

| Ограничение | Default |
|---|---:|
| locale choices / header bytes / ranges / fallback depth | 16 / 8192 / 32 / 16 |
| modules / messages / translations / locales | 64 / 4096 / 32768 / 128 |
| arguments / enum values / markup names | 64 / 256 / 64 |
| argument bytes / template bytes / catalog bytes | 64 KiB / 64 KiB / 64 MiB |
| declarations / selectors / variants / local depth | 256 / 8 / 1024 / 32 |
| template parts / markup depth | 2048 / 32 |
| output bytes / output parts / explain steps | 1 MiB / 4096 / 64 |
| compiled artifact bytes / JSON depth / members | 128 MiB / 64 / 4 194 304 |

Полные значения возвращают `DefaultLimits` и `DefaultArtifactLimits`. Ненулевое
поле меняет принимаемый предел, но не означает unlimited. Catalog/source
material, resolver input, typed arguments, консервативная formatter work,
созданные text/parts, explanation, generators и controller retention проходят
preflight. Derived source, compiled, Go, TypeScript, manifest, report и usage
outputs применяют operator ceiling внутри producer, а не после allocation.
Application callbacks и внешние stores сами ограничивают свою работу. `New` и
`Overlay` используют тот же точный учёт snapshot material,
который `Encode` записывает, а `Load` проверяет, поэтому принятый ровно на
byte/item ceiling snapshot проходит round-trip без расхождения границы.

Любой агрегированный `*Problems` распознаётся через `errors.Is` как
`ErrInvalidCatalog`. Если хотя бы один item имеет код `ProblemLimit`, та же
ошибка дополнительно распознаётся как `ErrLimitExceeded`: invalid-catalog
категория сохраняется, а capacity failure можно обработать отдельно.

Опциональный `Observer` синхронно получает по одному panic-isolated
`Observation` на публичные resolve/render/compile/load/activate/rollback.
Поля — закрытые operation/outcome/reason, duration и bounded count. Там нет
message key, locale input, text, argument, path, cause, revision, digest,
principal или tenant. Callback обязан быть bounded/non-blocking; пакет не
создаёт очередь или exporter и не зависит от OpenTelemetry.

## Явные ограничения

- Поддерживается один профиль `frostgrove-mf2/v1`. Нет fallback в MF1,
  ICU-message, Fluent или Go templates.
- Source и compiled artifact — форматы Frostgrove, а не durable domain event и
  не cross-language rendering protocol.
- TypeScript export — public type contract, а не browser formatter.
- Нет автоматического перевода, transliteration, currency conversion,
  address/person-name formatting, localized storage/search/collation/URLs или
  CMS-модели.
- Пакет не создаёт TMS client, network fetch, runtime directory scan, watcher,
  hot-reload runner, health policy, cache/job backend или OTel adapter.
- В render не участвуют ambient locale, host-default zone, global registry,
  package-init registration или background goroutine.
