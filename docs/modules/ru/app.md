# app — композиционный корень

```go
import "github.com/frostgrove/vv/app"                 // значения
import "github.com/frostgrove/vv/app/appfx"           // uber/fx: команда сидов
import "github.com/frostgrove/vv/app/http/appfiber"   // uber/fx + Fiber: API
```

**Модуль:** `app` — корневой, импортирует только стандартную библиотеку и
`port`. `appfx` и `appfiber` — отдельные модули, потому что тянут контейнер
([[D-033]], [[D-074]])
· **Зависит от:** `port` · а `appfiber` — ещё от `authhttp` и `authfiber`

Те части старта программы, которые пишет каждый сервис и большинство пишет с
мелкими ошибками: упорядоченная цепочка вкладов, команда сидов, которую не
страшно запустить дважды, и HTTP-поверхность, собранная из модулей, которые не
импортируют друг друга.

---

## Что вы получаете

### `app` — значения, без контейнера

| | |
|---|---|
| `Ordered[H]` | один вклад и его место в последовательности: `Name`, `Order`, `Handler` |
| `Sorted(contributions)` | эта последовательность — по порядку, затем по имени, над копией вашего слайса |
| `Seeder` | одна единица сид-данных: `Name`, `Order`, `Envs`, `Run` |
| `Seeding` | из чего собирается runner: окружение, опционально набор окружений деплоя, логгер |
| `NewRunner(seeders, spec)` | сортирует и валидирует; любая ошибка проводки отклоняется здесь, а не на середине прогона |
| `Runner.Run(ctx)` | сидит это окружение, останавливаясь на первом отказе и называя сидер |
| `ErrSeeder` | то, что оборачивает каждый отказ |

Контейнер здесь не нужен. `NewRunner` принимает слайс, собранный как угодно.

### `appfx` — команда сидов в графе fx

| | |
|---|---|
| `AsSeeder(ctor)` | аннотирует конструктор, чтобы его `app.Seeder` попал в группу |
| `Seeders` | группа как параметр-объект `fx.In` |
| `Seeding(spec)` | предоставляет `*app.Runner` поверх всего, что попало в группу |

```go
fx.Options(
    fx.Provide(appfx.AsSeeder(newRoleSeeder)),
    fx.Provide(appfx.AsSeeder(newAccountSeeder)),
    appfx.Seeding(app.Seeding{Env: cfg.Env, Known: cfg.Envs}),
)
```

### `appfiber` — API в графе fx

| | |
|---|---|
| `Route` | что вносит ограниченный контекст: `Mount(fiber.Router)` и `Access() []authhttp.Endpoint` |
| `Middleware` | `app.Ordered[fiber.Handler]` |
| `OrderAuth` | место guard'а: перед всем, что предполагает вызывающего |
| `AsRoute` / `AsMiddleware` / `AsResolver` | три аннотации, которыми пользуется модуль |
| `Mounted` / `Resolvers` | две группы как параметр-объекты `fx.In` |
| `Guarding(name, guard, opts…)` | `auth.Guard` в виде упорядоченного middleware на `OrderAuth` |
| `Spec` | `Prefix`, `Addr`, `Listen` |
| `Serving(spec)` | смонтировать, проверить, слушать |
| `Mount(app, mounted, prefix)` | то же монтирование без запуска через fx |
| `Listen(lc, sd, app, spec, log)` | то же прослушивание |

```go
fx.Options(
    fx.Provide(newFiberApp),                      // ваше: CORS, шов ошибок
    fx.Provide(appfiber.AsRoute(users.NewHandler)),
    fx.Provide(appfiber.AsRoute(billing.NewHandler)),
    appfiber.Serving(appfiber.Spec{Prefix: "/api/v1", Addr: ":8080"}),
)
```

Пустой `Addr` не слушает — именно это нужно тесту, которому важны только
смонтированные маршруты.

## Гейт: старт падает, когда роутер и декларации расходятся

Каждый внесённый маршрут говорит, что нужно для доступа к нему, и `Mount`
сравнивает это с собственной таблицей маршрутов Fiber до того, как сервер начнёт
что-либо принимать:

```go
func (this *Handler) Access() []authhttp.Endpoint {
    return append(
        crudhttp.Table{Prefix: "/users"}.Guarded(PermRead, PermWrite, PermDelete),
        authhttp.Requires(http.MethodPost, "/users/:id/invite", PermInvite),
    )
}
```

Маршрут, который никто не объявил, — отказ на старте. **И декларация, маршрута
которой больше нет, — тоже**: эта половина важна не меньше, потому что
декларация, пережившая свой хендлер, — это то, из-за чего список выглядит полным,
покрывая всё меньше с каждым месяцем. Механизм — в [authhttp](authhttp.md),
почему на сборке и никогда не на запросе — в [[D-073]].

## Почему порядок — число

Value-группа fx неупорядочена. «Guard идёт перед хендлером», решённое тем, какой
провайдер fx обошёл первым, — свойство безопасности, решённое случайно; и каждый
тест, монтирующий один модуль, всё равно проходит. `Order` — число, а не позиция
в списке, чтобы вклад можно было вставить между двумя другими, не редактируя ни
один из них.

Равные значения разрешаются по имени, так что два прогона одной сборки дают одну
и ту же последовательность, а лог одного сопоставим с логом другого.

## Почему сидер обязан быть запускаемым дважды

Команду сидов перезапускают после каждой миграции те, кто не уверен, запускали её
или нет. Та, что вставляет вторую строку со второго раза, — команда, которую
никто не решается запускать; а значит, данные, которые она пишет, в итоге
набивают руками.

Пустой `Envs` означает «во всех окружениях», и этот дефолт — тот, в котором
нельзя ошибиться: сидер, забывший назвать окружения, работает везде, что видно, а
не нигде, что не видно. Задайте `Seeding.Known` — и сидер, назвавший окружение,
которого у деплоя нет, будет отклонён на проводке, а не тихо никогда не
запустится.

## Чем этот пакет не должен стать

Он держит список того, что надо выполнить, и порядок. Он не держит способ
*найти* одно из них: ни `map[reflect.Type]any`, ни `Get[T]()`, ни `...any` с
type-switch. [[D-037]] — решение с тремя шагами, по которым список компонентов
превращается в контейнер.

Это не отказ от dependency injection. `appfx` и `appfiber` отдают эти типы fx,
который и держит граф, — граф принадлежит потребителю, в модуле, который он сам
решил импортировать, а `go get github.com/frostgrove/vv` по-прежнему не
резолвит никакой контейнер ([[D-074]]).
