# security — шлюз

```go
import "github.com/frostgrove/vv/crud/decorators/security"
```

**Модуль:** корневой · **Зависит от:** `crud` и стандартной библиотеки

Row-level security как декоратор. Мультитенантность в одну строку, скоупинг
по принципалу в SQL и набор отказов, которые сложно обойти по ошибке — AST
предиката закрыт, вызывающий код не может отковырять скоуп обратно.

**Берите его, когда** строки кому-то принадлежат: тенанту, владельцу,
организации. Он стоит между транспортом и репозиторием, поэтому ни один
хендлер не пишет `WHERE tenant_id = ?` и ни один хендлер не может об этом
забыть.

---

## Мультитенантность в одну строку

```go
policy := security.ScopeField[Doc, int64]("TenantID", func(ctx context.Context) (any, error) {
    t, ok := ctx.Value(tenantKey{}).(int64)
    if !ok {
        return nil, security.Denied(security.Read, "no tenant in context")
    }
    return t, nil
})

docs := Docs.Bind(db, security.Gate(policy))
```

Дальше, без единой дополнительной строки где-либо:

- чтения фильтруются **в SQL**, поэтому нет ни лишней выборки, ни
  постфильтрации;
- чужой id возвращает `crud.ErrNotFound`, никогда не `ErrForbidden` — 403
  подтвердил бы, что строка существует ([[D-008]]);
- `Save` в чужого тенанта отказан, как и перезапись строки, принадлежащей
  чужому — после проверки create с заданным ключом делает только INSERT, а
  update привязан к проверенному снимку и скоупу **в самой БД**, поэтому строку,
  вставленную или заменённую после проверки, нельзя незаметно перезаписать;
- `TenantID` заморожен, поэтому DTO обновления, называющий его, отклоняется
  до выполнения какого-либо SQL;
- нескоупленный `DeleteAll` отказан.

## Три проверки

Каждый hook опционален, но в policy должно быть хотя бы одно настоящее правило:
`security.Gate(security.Policy{})` — ошибка при старте. Для намеренно
неограниченного репозитория привязывайте репозиторий напрямую.

| | Что это | Стоимость |
|---|---|---|
| **Scope** | предикат, добавляемый через AND к каждому чтению и каждой скоупленной записи | бесплатно — это часть запроса |
| **Authorize** | грубая: может ли этот принципал вообще делать операции такого рода | до SQL; `Save` с заданным ключом заранее проверяет обе возможные ветки (`Create` и `Update`) |
| **Inspect** | тонкая: по каждой сущности, видя саму строку | один вызов на каждую строку, о которой спрашивают |

```go
policy := security.Policy[Doc, int64]{
    Scope: func(ctx context.Context) (crud.Predicate, error) {
        t, err := tenantOf(ctx)
        if err != nil { return nil, err }
        return crud.Eq("TenantID", t), nil
    },
    Authorize: func(ctx context.Context, a security.Action) error {
        if a != security.Read && !isEditor(ctx) {
            return security.Denied(a, "read-only principal")
        }
        return nil
    },
    Inspect: func(ctx context.Context, a security.Action, d *Doc) error {
        if a == security.Delete && d.Locked {
            return security.Denied(a, "the document is locked")
        }
        return nil
    },
    Immutable:    []string{"TenantID", "OwnerID"},
    InspectReads: false,
}
```

Действия — `security.Read`, `Create`, `Update`, `Delete`.

**`Scope`, возвращающий nil или безусловный предикат, по умолчанию
отклоняется.** Так неудачный поиск тенанта — или случайный `crud.True()` — не
превращается в чтение всей таблицы. Администратор, которому намеренно разрешён
неограниченный доступ, объявляет это рядом со скоупом:

```go
AllowUnscopedScope: true,
```

Возврат ошибки по-прежнему отказывает в операции.

**`InspectReads` по умолчанию выключен.** `Scope` — дешёвый способ отфильтровать
список; инспекция каждой возвращённой строки — это вызов Go на каждую строку.

**Решение `Inspect` входит в финальную запись.** Для `Update`, `Delete` и их
bulk-вариантов шлюз привязывает statement к полному снимку проверенной строки
или строк. Конкурентное изменение значимого для действия поля тогда ничего не
совпадёт: например, разрешённое удаление разблокированной строки не удалит
строку, которую успели заблокировать.

**Свой `Scope` или `RelationScopes` без `Inspect` может читать, но не может писать body**: `Save`,
`SaveAll`, `Update` и `UpdateAll` способны записать поле, которое вынесет
строку за её старый `WHERE`-scope. Шлюз отказывает такой форме policy до любого
запроса или изменения. Для обычной мультитенантности берите `ScopeField` (он
добавляет подходящий `Inspect`) либо добавьте `Inspect` к своей policy. С этой
проверкой save с заданным ключом при отсутствии строки делает только create, а
при наличии — update, привязанный к снимку и скоупу. Это намеренный fail-closed
переход от прежнего поведения нулевой/Scope-only policy.

Scope и relation-scope resolvers запускаются перед **каждым** save, включая
generated-key insert, у которого нет SQL `WHERE` для этих predicate. Поэтому
ошибка lookup-а principal отклоняет insert, а не превращается в unscoped write.

## Пересечение связи

Скоуп — это `WHERE`-условие, а `WHERE`-условие ограничивает только свой
собственный `FROM`. Preload — это второй запрос по второй таблице, поэтому он
ничего не наследует — именно так `?preload=comments` возвращает ровно те
строки, для сокрытия которых существовал скоуп ([[D-007]], [[UC-004]]).

**Сузьте и дальнюю сторону:**

```go
policy := security.Combine(
    security.ScopeField[Article, int64]("TenantID", tenantOf),
    security.ScopeRelationField[Article, int64]("Comments", "TenantID", tenantOf),
    security.ScopeRelationField[Article, int64]("Comments.Author", "TenantID", tenantOf),
)
```

Путь разрешается на **этапе объявления**, поэтому опечатка падает при старте
приложения, а не утекает строками позже, и путь может проходить через
несколько переходов.

Для общего случая — сужения, которое следует за строками, где бы они ни были
достигнуты, что и требуется само-связи — задайте `RelationScopes` напрямую:

```go
RelationScopes: func(ctx context.Context) (*crud.RelationScopes, error) {
    t, err := tenantOf(ctx)
    if err != nil { return nil, err }
    return (*crud.RelationScopes)(nil).
        AtPath("Comments", crud.Eq("TenantID", t)).
        AtPath("Comments.Author", crud.Eq("TenantID", t)), nil
},
```

Аналог на уровне таблицы — `sqlrepo.RelationScope` на blueprint. Там, где
объявлены оба, **действуют оба**.

**`RelationScopes`, возвращающий nil или пустой набор правил, по умолчанию
отклоняется.** Это так же важно, как и корневой скоуп: отсутствующий клейм на
связи не должен превращать `?preload=comments` в неограниченное чтение. Для
намеренного admin bypass рядом с callback ставится
`AllowUnscopedRelationScopes: true`. `Combine` также fail-closed для каждого
составного relation scope.

## Готовые политики

| Конструктор | Что делает |
|---|---|
| `ScopeField[M, ID](field, valueFn)` | тот самый мультитенантный: скоуп по колонке, заморозка, сужение сохранений |
| `ScopeRelationField[M, ID](path, field, valueFn)` | то же сужение на дальней стороне связи |
| `ReadOnly[M, ID]()` | любая запись отказана |
| `Freeze[M, ID](fields...)` | эти поля никогда не могут быть обновлены |
| `Combine[M, ID](policies...)` | объединяет скоупы через AND, сливает сужения связей, выстраивает проверки в цепочку |

`Combine` — вот как строится реальная политика: скоуп тенанта, скоуп связи,
заморозка и проверка роли — это четыре значения, которые компонуются, а не
одна функция с четырьмя ветками. Он предпочтительнее нескольких вложенных
`Gate`: один шлюз может атомарно применить объединённую проверку, а непрозрачный
стек middleware при save с заданным ключом отказывается, но не обходится.

Каждое `field` и `path` выше — это имя поля модели или путь связи, а политика,
которая ничего не сужает из-за переименованной колонки, — худший отказ в этом
пакете: она читается как защита и ею не является. Сгенерированная метамодель
отдаёт и то и другое идентификаторами:

```go
security.Combine(
    security.ScopeField[Article, int64](Article_.TenantID.Name(), tenantOf),
    security.ScopeRelationField[Article, int64](
        Article_.Comments.Path(), Comment_.TenantID.Name(), tenantOf),
    security.Freeze[Article, int64](Article_.TenantID.Name()),
)
```

Как и в скоупе связи у blueprint'а, *путь* берётся из метамодели корня, а *поле*
— из метамодели цели: см. [specs](specs.md).

## Управление из аутентифицированного вызывающего

Каждый конструктор выше принимает `valueFn` — `func(context.Context) (any,
error)`, которую пишете вы, поверх придуманного вами ключа контекста. Это
по-прежнему работает и остаётся аварийным выходом. Но значение почти всегда
**и есть** вызывающий, а [auth](auth.md) — словарь, чтобы это сказать:

| Конструктор | Что делает |
|---|---|
| `RequirePermission[M, ID](perms...)` | отказ, если у вызывающего нет **всех** перечисленных |
| `RequireAnyPermission[M, ID](perms...)` | отказ, если нет **ни одного** |
| `RequireRole[M, ID](roles...)` | отказ, если вызывающий не в одной из ролей |
| `PerAction[M, ID](map[Action]auth.Permission)` | по пермишену на глагол; глагол, которого нет в карте, отклоняется |
| `ScopeAttr[M, ID](field, claim)` | `ScopeField`, сужающий по клейму из принципала |
| `ScopeRelationAttr[M, ID](path, field, claim)` | то же через связь |
| `ScopeSubject[M, ID](field)` | сузить до строк, которыми владеет вызывающий |
| `ScopeRelationSubject[M, ID](path, field)` | то же через связь |
| `InspectOwner[M, ID](allow)` | построчная проверка, видящая и принципала, и строку |

```go
policy := security.Combine(
    security.PerAction[Article, int64](map[security.Action]auth.Permission{
        security.Read:   "article:read",
        security.Create: "article:write",
        security.Update: "article:write",
        security.Delete: "article:delete",
    }),
    security.ScopeAttr[Article, int64]("TenantID", "tenant"),
)
articles := Articles.Bind(db, security.Gate(policy))
```

`ScopeAttr` **оборачивает `ScopeField`**, а не переписывает его, поэтому
наследует проверку строки и замороженную колонку. Это важнее, чем звучит:
сужение по принципалу, написанное руками, остаётся read-only, пока не добавит
`Inspect`; шлюз отказывает body write до SQL, а не принимает read narrowing за
policy создания. `ScopeAttr` поставляет эту проверку и является обычной
tenant-safe декларацией.

Четыре вещи, в которых легко ошибиться и которые решены здесь:

- **Клейм, которого у принципала нет, — это отказ, а не нулевое значение.**
  Отсутствующий tenant не должен компилироваться в `WHERE tenant_id = 0`,
  который не совпадает ни с чем на большинстве схем и со всем — на той, где 0
  реальный tenant.
- **Отсутствие принципала — это 401 у каждого из них, без единого выполненного
  запроса.** Ничего ещё не решено, поэтому не 403 — и это гарантия 16
  из [[UC-004]].
- **`PerAction` отклоняет глагол, которого не называет**, даже для вызывающего
  со всеми пермишенами карты. Глагол, добавленный в шов позже, отклоняется, а
  не наследуется ([[D-030]]).
- **Два квантора расходятся в пустом случае.** Не назвать ни одного пермишена в
  `RequirePermission` — значит не запретить ничего, поэтому список, собранный из
  конфигурации и оказавшийся пустым, не добавляет правила; не назвать ни одного
  в `RequireAnyPermission` — значит запретить всё, потому что «любой из ничего»
  невыполним.

Положить принципала **в** контекст — работа транспорта: см.
[authnet](authnet.md), [authgin](authgin.md), [authfiber](authfiber.md) или
[authgrpc](authgrpc.md). Импорт идёт в одну сторону: этот пакет знает про
`auth`, а `auth` про репозиторий не знает ([[D-055]]).

## Два разрешения, которые разделены намеренно

```go
AllowUnscopedDeleteAll: false   // по умолчанию
AllowUnscopedUpdateAll: false   // по умолчанию
```

`DeleteAll` и `UpdateAll` отказаны, когда ни политика, ни вызывающий код не
сузили запрос. Это два флага, а не один, потому что перезапись каждой строки
таблицы — не то, что политика должна наследовать из разрешения очистить эту
таблицу.

## Ошибки

`security.ErrForbidden` оборачивает `crud.ErrForbidden`, поэтому транспорт
маппит его в 403, не импортируя этот пакет. `security.Denied(action, reason)`
строит такую ошибку с приложенной причиной.

**Вне скоупа — это 404, не 403** ([[D-008]]). 403 на строке, которую
вызывающий не должен видеть, подтверждает, что строка существует, — а это и
есть утечка, для предотвращения которой существует скоуп. Отказ, которого
вызывающий *мог* избежать — запись в чужого тенанта, обновление
замороженного поля, — это 403, потому что о строке он уже знает.
