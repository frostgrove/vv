# authhttp — HTTP-половина auth-middleware

```go
import "github.com/frostgrove/vv/auth/http/authhttp"
```

**Модуль:** корневой — импортирует только стандартную библиотеку, поэтому ничего
не стоит · **Зависит от:** `porthttp`

То, что относится к HTTP, но не к фреймворку. Он относится к
[authnet](authnet.md), [authgin](authgin.md) и [authfiber](authfiber.md) ровно
так же, как [crudhttp](crudhttp.md) относится к трём CRUD-привязкам — и обе
берут таблицу статусов, конверт и `Renderer` из одного
[porthttp](porthttp.md), что и не даёт проверке токена импортировать
SQL-репозиторий ([[D-059]]).

Напрямую его импортируют редко — это делает привязка. Импортируйте, если пишете
четвёртую HTTP-привязку или рендерите отказ сами.

---

## Что вы получаете

| | |
|---|---|
| `RendererFor(opts)` | рендерер по этим опциям, с общим значением, когда опций нет |
| `Refuse(w, r, rd, err)` | единственное место, откуда 401 покидает привязку в форме net/http |
| `Locale(r)` | контекст рендеринга, прочитанный из `Accept-Language` |

## Почему отказ пишется здесь, а не откладывается

Отдать ошибку внешнему error-middleware было бы аккуратнее и неправильно: тот,
кто подключил auth-middleware, но не подключил `crudnet.Errors`, получил бы
пустой 200 на каждый неаутентифицированный запрос. **Отказ вида «дверь была
открыта» не должен зависеть от того, поставили ли вторую вещь.**

Это композируется, а не конфликтует. `crudnet.Errors`, `crudgin.Errors` и
`crudfiber.Errors` оставляют уже записанный ответ в покое, поэтому
auth-middleware внутри любого из них рендерит один раз.

## Чего он намеренно не ставит

`WWW-Authenticate`. RFC 7235 говорит, что 401 его несёт, и:

- вызов `Basic` заставляет браузер открыть модальное окно логина, которого не
  хочет ни один API;
- параметр `error=` в bearer-вызове существует ровно затем, чтобы сказать, какая
  часть токена неверна, — а это то раскрытие, ради которого написан [[D-056]].

Тот, кому заголовок нужен для клиента, проверяющего стандарт, ставит его в
обёртке.

## Чего здесь нет

Всего транспортно-нейтрального. Пропускает ли опциональный guard подделанный
токен, аутентифицирует ли второй экземпляр повторно, какой заголовок читается —
всё это `auth.Guard`, поэтому gRPC-интерсептор получает те же решения без
HTTP-пакета в сборке ([[D-045]]).

Ничто здесь не знает, что такое учётные данные.

## Гейт доступа на старте

Вторая половина пакета — та, к которой потребитель обращается напрямую: каждый
маршрут, смонтированный под префиксом, говорит, что нужно для доступа к нему, и
старт падает, когда роутер и эти декларации расходятся.

| | |
|---|---|
| `Endpoint` | одна декларация: `Method`, `Path` и либо `Needs []auth.Permission`, либо `Why` |
| `Public(method, path, why)` | вызвать может кто угодно, и вот причина |
| `Requires(method, path, perms…)` | вызывающий должен держать **все** перечисленные права |
| `Authenticated(method, path, why)` | любой вошедший — «я», «мои сессии», «выйти» |
| `Endpoint.Declares()` | говорит ли она вообще хоть что-нибудь |
| `Route` | одна запись в собственной таблице роутера: `Method`, `Path` |
| `Verify(declared, mounted, opts…)` | сравнение |
| `UnderPrefix(prefix)` | пути деклараций относительны ему; смонтированный маршрут вне его не часть поверхности |
| `ErrSurface` | то, что оборачивает любое расхождение |

```go
if err := authfiber.Verify(app, declared, authhttp.UnderPrefix("/api/v1")); err != nil {
    return err   // отказаться стартовать
}
```

Половина, читающая реальную таблицу маршрутов, принадлежит привязке —
[authfiber](authfiber.md), [authgin](authgin.md), [authnet](authnet.md), — потому
что это единственная половина, которую нельзя написать один раз.

### Почему отклоняются обе стороны

Маршрут без проверки прав и маршрут, публичный намеренно, изнутри выглядят
одинаково. Разрыв виден только снаружи — тому, кто попробует. Поэтому роутер
сравнивается с декларацией, и декларация, маршрута которой больше нет, тоже
отклоняется: пережившая свой хендлер — это то, из-за чего список выглядит полным,
покрывая всё меньше с каждым месяцем.

`Verify` сообщает обо всех проблемах сразу. Отказ старта, который называет одну
недостающую декларацию, чинится, а потом называет следующую, — это три
перезапуска, чтобы узнать то, что могло уместиться в одно сообщение.

Пустой `Endpoint` отклоняется — именно это не даёт выдать «я забыл» за «прав не
нужно» ([[D-073]]).
