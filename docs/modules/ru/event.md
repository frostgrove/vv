# event — история фактов только на добавление, поверх любого хранилища

```go
import "github.com/frostgrove/vv/event"              // словарь и шов хранилища
import "github.com/frostgrove/vv/event/eventmemory"  // полноценное хранилище в памяти
import "github.com/frostgrove/vv/event/eventtest"    // набор проверок соответствия
```

**Модуль:** все три лежат в корневом модуле. Граница модуля здесь — это граница
сторонней зависимости, и ни один из них её не добавляет ([[D-116]], [[D-121]])
· **Зависит от:** `crud` — ради классов, которые транспорт уже умеет
отображать, и сравнения источников данных, которым является backing; `errs` —
ради fault, который несёт отказ по превышению границы · **От него зависят:**
ничто, и это намеренно — тест графа откажет первому базовому пакету, который его
импортирует

Вы объявляете агрегат, его факты и то, как каждый из них сворачивается.
Фреймворк записывает факты, воспроизводит из них состояние и допускает запись
только на той версии, на которой было принято решение. Он не открывает
транзакций, не повторяет попыток и не переписывает записанный факт.

---

## Что вы получаете

### Объявление

| | |
|---|---|
| `Define[S, ID](family, key)` | `*Aggregate[S, ID]`: имя семейства и отображение вашей идентичности в ключ потока. Паникует на неверном объявлении |
| `TryDefine[S, ID](family, key)` | то же самое, но возвращает ошибку ([[D-123]]) |
| `Declare[S, ID, E](a, name, chain, fold)` | `*Fact[S, ID, E]`: имя типа на проводе, цепочка его читателей и свёртка. Паникует |
| `TryDeclare[S, ID, E](a, name, chain, fold)` | то же самое, но возвращает ошибку |
| `From[V](codec)` | `Chain[V]` на ревизии 1 |
| `Then[A, B](prev, codec, up)` | следующая ревизия и апкастер, переносящий старую форму вперёд |
| `JSON[V]()` | поставляемый `Codec[V]`, проверяемый при создании значения ([[D-124]]) |
| `Codec[V]` | `Encode` · `Decode` · `CanEncode` — вторая точка расширения |
| `Compose(parts…)` | составная идентичность, отрисованная в один `Key`, байт в байт навсегда ([[D-125]]) |
| `Aggregate.Family()` · `Aggregate.Key(id)` · `Aggregate.Fold(id, state, changes…)` | собственные читатели объявления; свёртке хранилище не нужно |
| `Fact.Name()` · `Fact.Family()` · `Fact.Revisions()` · `Fact.New(id, payload)` · `Fact.RoundTrip(byRevision…)` | идентификаторы факта, решение и прокси, доказывающий, что полезная нагрузка переживает свой кодек |
| `Fact.Read(envelope)` | записанный конверт, раскодированный собственной цепочкой читателей этого факта и всеми объявленными апкастерами, в текущем типе читателя — тот же декодер, через который сворачивает воспроизведение, и ровно четыре отказа класса истории и никаких других |
| `Change[S]` | одно решение: `Stream()` и `Err()` |
| `Declaration` | единственный неродовой вид на агрегат |

```go
type Ledger struct{ Balance int64 }

type AccountID struct{ Tenant, Number string }

type Opened struct{ Owner string }
type Credited struct{ Amount int64 }

var Account = event.Define[Ledger, AccountID]("account", func(id AccountID) event.Key {
	return event.Compose(id.Tenant, id.Number)
})

var (
	Open   = event.Declare(Account, "account.opened", event.From(event.JSON[Opened]()), openLedger)
	Credit = event.Declare(Account, "account.credited", event.From(event.JSON[Credited]()), creditLedger)
)

func openLedger(state Ledger, fact Opened) Ledger { return state }

func creditLedger(state Ledger, fact Credited) Ledger {
	state.Balance += fact.Amount
	return state
}
```

Ревизия — это **позиция** в цепочке, а не число, которое вы пишете руками:

```go
var Note = event.Declare(Account, "account.noted",
	event.Then(event.From(event.JSON[NoteV1]()), event.JSON[NoteV2](), upgradeNote), noteLedger)
```

### Что отвергает `JSON[V]()` и когда

`event.JSON[V]()` спрашивает один раз, при создании значения кодека: прочитается
ли `V`, записанный через `encoding/json`, обратно как он сам — поэтому форма
полезной нагрузки, которая закодировалась бы в `{}` и воспроизводилась бы нулевым
значением, это паника в `Declare`, а не журнал фактов, который уже не починить
([[D-124]]). Удивляет обычно **встраивание**:

```go
type Money struct{ Cents int64 }              // с MarshalJSON/UnmarshalJSON

type Line struct {
	Money                                     // отвергнуто: Go продвигает пару Money
	SKU   string                              // на Line, поэтому SKU не пишет никто
}

type Wrapped struct{ Line }                   // отвергнуто по той же причине, на шаг выше

type Priced struct {
	Amount Money                              // принято: именованное поле — не продвижение
	SKU    string
}
```

Продвижение методов — правило языка: никакой тег на встроенном поле его не
отменяет, включая `json:"-"`, и оно проходит через сколько угодно встраиваний —
поэтому вопрос задаётся всей цепочке, а отказ называет тот шаг, на котором поле
скрыто. Средства, которые называет сам отказ: назвать встроенное поле или
объявить собственный кодек.

### Корень композиции

| | |
|---|---|
| `Open(store)` | `*Binding` — таблица семейств, связанных через него. Реестра на уровне пакета нет |
| `Bind[S, ID](b, a)` | `*Repo[S, ID]`: пять проверок за константное время и одна аллокация, так что хранилище на запрос — обычное дело |
| `Read(log, after)` | `*Reader` по всему журналу, начиная с курсора |
| `ReadOnly(store)` | хранилище как `Log`, без пути обратно к поверхности записи |

### Путь записи

| | |
|---|---|
| `Repo.Load(ctx, id)` | состояние, свёрнутое из всей истории, и токен `At[S]`, на котором оно было |
| `Repo.Append(ctx, at, changes…)` | допускается только на версии токена; отвечает следующим токеном и `Commit` |
| `Repo.Within(ctx)` | контекст, помеченный транзакцией, которую это хранилище в нём нашло |
| `Repo.Authority(ctx)` | что это хранилище считает привязанным — чтобы две подсистемы могли доказать, что писали вместе |
| `Repo.Digest(at, changes…)` | байты, которые это добавление **записало бы**, в виде дайджеста — ни обращения к хранилищу, ни записи |
| `At[S]` | `Stream()` · `Version()` — выпускается `Load` и успешным `Append` |
| `Commit` | `Empty()` · `Stream()` · `First()` · `Last()` · `Count()` · `Authority()` |

```go
state, at, err := repo.Load(ctx, id)
if err != nil {
	return err
}
if state.Balance < amount {
	return ErrInsufficient
}
_, commit, err := repo.Append(ctx, at, Credit.New(id, Credited{Amount: -amount}))
```

### Историческое чтение

| | |
|---|---|
| `Repo.StateAt(ctx, id, version)` | состояние, которое агрегат держал на версии, — свёрнутое из полного префикса и **без токена** |

```go
before, err := repo.StateAt(ctx, id, disputed-1)
```

**Второго возвращаемого значения нет, и это замысел, а не упущение.** Значение,
похожее на токен загрузки, приглашало бы к `Load → Decide → Append`, чьё решение
принято против истории, которую этот вызов намеренно оставил за бортом.
Исправление прошлого — это новая доменная команда против настоящего, решённая из
`Load` ([[D-144]]).

Префикс плотный от версии 1 и **включает** запрошенную версию. Три входа дают
один отказ, `ErrVersion`: **версия ноль**, версия **за концом** потока и **поток
без событий вовсе** — версия ноль это и есть пустой поток, а пустая история и
история, которой никогда не было, в журнале только на добавление — одно и то же.
Отказ не называет ни границу, ни голову, по тому же правилу, что и все остальные
отказы здесь.

Событие, которое эта сборка прочитать не может, — это собственный отказ и
**нулевое состояние**, а никогда не тот префикс, который успел свернуться:
`ErrUnknownType`, `ErrRevision`, `ErrUpcast` и `ErrPayload` приходят ровно так
же, как из `Load`, потому что это тот же цикл с потолком, а не второй цикл.

Оно листает тем же `ReadStream`, что и загрузка, так что перечитывание — не более
**одной страницы** при любой длине потока: граница на версии 7 потока из 100 000
событий читает одну страницу и отбрасывает её остаток. Поэтому контракт хранилища
не получает потолка: параметр версии на `ReadStream` купил бы одну неполную
страницу ввода-вывода и стоил бы каждому автору хранилища сигнатуры, секции
соответствия и пересертификации.

### Отметка времени — не граница, и могла бы быть только поиском

`Repo.StateAt` принимает **версию**. На этой поверхности нет ни параметра
отметки времени, ни перегрузки, ни опции, и ни один пример здесь не сортирует по
моменту.

`Envelope.RecordedAt` — это `statement_timestamp()` там, где его пишет `eventpg`:
часы базы данных, а значит сравнимые между писателями, что уже больше, чем даёт
часы приложения. И это всё равно **не бизнес-время и не порядок фиксации**: два
писателя могут разделить один момент, а коммит может лечь много позже той отметки
времени оператора, которую он несёт ([[D-128]]). Чтение «по состоянию на 14:03»,
построенное на этом, отвечало бы на вопрос о временах операторов и подавало бы
это как вопрос об истории.

Если вход с формой времени когда-нибудь и появится, он может быть только
**поиском, разрешающимся в версию** — *на какой версии был этот поток* — и затем
ограниченным чтением выше. Ему нужен собственный контракт; это не он.

### Обход журнала

| | |
|---|---|
| `Reader.Next(ctx)` | одна страница; `false`, когда страница оказалась пустой |
| `Reader.Events()` | то, что достал последний `Next` — ваше, вместе с ёмкостью |
| `Reader.Cursor()` | безопасно сохранить и продолжить с него в другом процессе — если только обход не шёл на контексте, несущем транзакцию этого backing |

### Шов контрольных точек

Место, где потребитель записывает, что закончил со страницей. Это шов рядом со
швом хранилища, а не его часть: строка контрольной точки может лежать в базе
данных, о которой этот журнал ничего не знает, и часто должна.

| | |
|---|---|
| `Checkpoints` | `Capabilities()` · `Backing()` · `Transaction(ctx)` · `Load(ctx, name)` · `Save(ctx, checkpoint)` · `Forget(ctx, name)` · `Close()` |
| `CheckpointCapabilities` | `Transactions` · `Persistence`, каждая — `Support` |
| `Checkpoint` | `Projection` · `Cursor` · `Advance` · `Progress` и `Fresh()` |
| `Progress` | `Highest` · `Applied` · `Quarantined` · `At` — наблюдение, а не точка возобновления |
| `Track(checkpoints, name)` | `*Tracker`: единственная дверь к `Checkpoints`, как `Read` — к `Log` |
| `Tracker.Load(ctx)` · `Tracker.Save(ctx, cursor, progress)` · `Tracker.Forget(ctx)` | загрузить, предъявить на единицу выше ограды, снять имя |
| `Tracker.Projection()` · `Capabilities()` · `Backing()` · `Transaction(ctx)` | что он держит и что говорит хранилище |
| `MaxCursorBytes` | 4096 — то, что `Log` или `Checkpoints` вправе **выпустить** как курсор |

`Save` допускает контрольную точку тогда и только тогда, когда хранимая ограда
на единицу ниже предъявленной, либо строки нет, а предъявленная ограда равна
единице. Проигравшее сохранение — это `Failure(Conflict, …)`, а не
чтение-с-последующей-записью. `Load` отвечает **нулевым** `Checkpoint`, когда
строки нет, и об этом говорит `Fresh()`; пустой курсор — это начало журнала,
поэтому `Save` отвергает его через `Failure(Refused, …)`: строка, несущая его на
живой ограде, — это читаемая контрольная точка, перезапускающая потребителя с
начала. `Forget` не огорожен. Ни один из семи методов ничего не открывает, не
коммитит и не откатывает, а свой отказ хранилище классифицирует теми же семью
исходами, что и `Store`.

`event/projection` — потребитель, построенный на этом шве;
`eventtest.RunCheckpoints` — то, чем доказывается третья реализация.

### Шов хранилища

| | |
|---|---|
| `Log` | `Capabilities()` · `Limits()` · `Backing()` · `ReadAll(ctx, after)` |
| `Store` | `Log` плюс `Transaction(ctx)` · `ReadStream(ctx, s, after)` · `Append(ctx, req)` · `Close()` |
| `Capabilities` | `Transactions` · `Persistence` · `MonotoneVisibility` · `SharedBacking`, каждая — `Support` |
| `Support` | `Unstated` · `Unsupported` · `Supported` — три состояния, потому что возможность, о которой никто ничего не сказал, — это не возможность, которой ни у кого нет |
| `Limits` | `MaxPayload` · `MaxBatch` · `MaxKey` · `StreamPage` · `MaxRead` |
| `Record` / `AppendRequest` / `Envelope` | то, что пересекает шов: байты, поток, версия, позиция, момент времени. Никогда — тип Go |
| `Backing` / `NewBacking(identity)` | то, во что пишет хранилище; сравнивается через `Equal`, никогда через `==` |
| `Authority` / `NewAuthority(over, tx)` | идентичность транзакции; сравнивается через `Same` |
| `Outcome` | `Unclassified` · `Conflict` · `NotWritten` · `Unconfirmed` · `Closed` · `BadCursor` · `Refused` |
| `Failure(outcome, cause)` | весь канал ошибок от хранилища к ядру ([[D-122]]) |
| `CauseOf(err)` | единственный читатель, который добирается до собственной причины хранилища |

Все восемь методов обязательны, поэтому значение, которое передал корень
композиции, и есть значение, отвечающее на каждый вопрос — декоратор нельзя
обойти ([[D-061]]).

Два ответа принадлежат **хранилищу**, а не фреймворку, и потребитель, который
опирается на любой из них, написан под одно хранилище, а не под шов:

- `ReadStream` внутри связанной транзакции возвращает её собственные
  staged-добавления. `ReadAll` внутри неё не специфицирован: хранилище, читающее
  через транзакцию, к которой оно присоединилось, вернёт её незафиксированные
  события, а хранилище, назначающее глобальный порядок на коммите, не вернёт ни
  одного, и оба соответствуют контракту. Ни один путь, который начинает сам
  фреймворк, не открывает транзакцию и не обходит после этого журнал — но это не
  обещание, что обход не пойдёт внутри неё: `Reader.Next` выполняет чтение на том
  контексте, который вы ему дали, и ни он, ни `Read` не отказывают контексту с
  транзакцией. Обязательство ваше, и оно в том, что курсор такого обхода
  сохранять нельзя: откат затем отбросит события, которые этот курсор уже прошёл.
- `Envelope.Position` на конверте, который ещё не зафиксирован, не специфицирован
  по той же причине — ноль у одного хранилища, настоящее значение
  последовательности у другого. `Envelope.Version` — специфицирован: это версия,
  на которой добавление было допущено, и до коммита, и после.

### Потолки

| | |
|---|---|
| `MaxPayloadBytes` · `MaxNameBytes` · `MaxKeyBytes` | `1 MiB` · `128` · `2 KiB` |
| `MaxBatchCount` · `MaxPageCount` | `1024` · `4096` |
| `MaxResidentBytes` · `ResidentPage(maxPayload)` | `64 MiB` и число страниц, которым это становится при заданной границе полезной нагрузки |
| `MaxCursorBytes` | `4096` — седьмой, и единственный, который ограничивает то, что хранилище **выпускает**, а не то, что принимает. Намеренно не настраивается: граница, которую развёртывание могло бы опустить, — это граница, отвергающая курсор, выпущенный его же хранилищем |

Хранилище публикует свои числа в `Limits`, а фреймворк отказывает любому из них
выше своего потолка, у обеих дверей — `Bind` и `Read`. Хранилищу, которое
объявило ноль, отказывают, а не подставляют умолчание: `Limits` — это то, что
фреймворк проверяет от имени хранилища, поэтому ноль здесь означает хранилище,
забывшее назвать границу.

## Отказы и шесть классов

`errors.Is` никогда не пересекает класс, поэтому вызывающего, который ветвится по
одному классу, никогда не отвечает другой.

| Класс | Сентинелы |
|---|---|
| declaration — объявление написано неверно; паника, никогда не возврат | `ErrDeclaration` · `ErrSealed` · `ErrCodecType` |
| wiring — программа собрана из значений, которые не подходят друг другу | `ErrFamily` · `ErrWrongStore` · `ErrWrongStream` · `ErrNoTransaction` · `ErrNoTransactionBinding` · `ErrAmbientNotTransaction` · `ErrTransactionMismatch` · `ErrCursor` |
| request — данные, которые получила операция, использовать нельзя | `ErrKey` · `ErrVersion` · `ErrEncode` · `ErrSample` · `ErrTooLarge` |
| history — записанные байты факта эта сборка прочитать не может | `ErrUnknownType` · `ErrRevision` · `ErrPayload` · `ErrUpcast` |
| write — добавление сделало не то, о чём вы просили | `ErrConflict` · `ErrUncertain` |
| store — само хранилище отказало или сломалось | `ErrBackend` · `ErrClosed` · `ErrRefused` |

Класс request оборачивает `crud.ErrBadRequest`, `ErrConflict` оборачивает
`crud.ErrConflict`, а повторяемый отказ бэкенда — `crud.ErrUnavailable`, так что
транспорт отвечает статусом, который подразумевает класс, без собственной
таблицы. `ErrTooLarge` несёт `*errs.Fault`.

Отказ печатает свой сентинел и ничего из того, что его породило: ни ключа, ни
полезной нагрузки, ни версии, ни позиции, ни курсора, ни текста драйвера или
кодека. Причина достижима — намеренно и по имени — через `CauseOf`.

## Конфликт не повторяет никто

`ErrConflict` говорит, что поток не на той версии, на которой было принято
решение, и намеренно не говорит, на какой он *есть*. Сообщить её — значит
пригласить дописать те же факты на свежей версии, то есть записать устаревшее
решение. Перечитайте, решите заново, допишите — а там, где открыта транзакция,
единицей повтора является **транзакция**: на SQL-хранилище проигравшая вставка
отравляет блок.

`ErrUncertain` — другой ответ: добавление было выполнено, и его исход никто не
подтвердил. Читать `err != nil` как «ничего не записано» — ровно тот вывод,
который этот класс существует, чтобы отвергнуть.

## Транзакция — ваша

`Within` спрашивает хранилище, что несёт этот контекст, и помечает контекст
ответом; он ничего не открывает. Добавление, сделанное при привязанной
транзакции того же backing, записывается внутри неё и исчезает при откате.
Фреймворк нигде не выдаёт ни begin, ни commit, ни rollback ([[D-118]] — то же
правило для долговечной работы), и это удерживает AST-проверка по пакету.

Две метки складываются: `Within` над хранилищем A, а затем над B оставляет обе,
и они разрешаются по backing, так что обычная программа с двумя хранилищами не
превращается в ловушку.

## Объявление запечатывает себя

Таблица фактов доступна на запись, пока её не прочитала первая сторона, и
доступна только на чтение всю остальную наблюдаемую жизнь — именно это делает
один `*Aggregate`, разделяемый всеми горутинами запросов, безопасным без
блокировки на пути чтения. Факт, объявленный после этого, — `ErrSealed`. Шесть
читателей, которые запечатывают, перечислены в исходнике, и седьмой без строки
там роняет тест.

## Объявленный идентификатор: семейство и имя типа на проводе

Два имени, которыми ведает `MaxNameBytes`, подчинены одному правилу: непустое,
корректный UTF-8, без управляющих символов, в пределах предела — и без `[` и
`]`, потому что отказ рендерит поток одним полем в скобках, а любое из этих имён,
попав в ту же строку со скобкой, закрывает поле раньше времени и пишет после
него второе. Кавычки этого не решают: обе скобки go-кавычки оставляют как есть.

Каждое имя пересекает две двери, и правило стоит на обеих. На объявлении
`Define` и `Declare` отвергают его с `ErrDeclaration`, поэтому имя, объявленное
программой, всегда читается собой в строке журнала. На **конверте** имя не
объявлял никто, кого эта программа видит: семейство, не прошедшее правило,
рендерится как `[stream unnameable]`, а записанное имя типа, не прошедшее его,
не называет ни одного объявленного факта и не может — это `ErrUnknownType`, и в
сообщение оно не попадает.

## Одно семейство именует один агрегат

Два агрегата над одним семейством делят историю — каждый сворачивает факты
другого и дописывает на версиях, выведенных из чужих. `Bind` отвергает второе
объявление одного семейства через один `*Binding` с `ErrFamily`. Два значения
`*Binding` не видят друг друга, поэтому `Change` называет ещё и агрегат, на
котором он был решён: свернуть или дописать его через другой агрегат того же
семейства — тот же `ErrFamily`, а `eventtest.Families` — исполняемый прокси по
всем объявлениям, которые собирает одно приложение.

## Владение: всё переданное принадлежит получателю

Полезная нагрузка, переданная в `Fact.New`, клонируется в момент решения,
поэтому изменить её потом — не изменить то, что записано. Страница, которую
вернуло хранилище, принадлежит получившему её, бессрочно, вместе с ёмкостью.
Хранилище может читать срезы фреймворка на время вызова и не должно ни писать в
них, ни удерживать их.

`Fact.RoundTrip` — исполняемый прокси для половины кодека: он кодирует образец
каждой сохранённой ревизии её же кодеком, читает обратно и отказывает кодеку,
который возвращает память, переиспользуемую им самим.

**Что означает зелёный round trip и чего он не означает.** Он доказывает две
вещи, и у каждой есть названная граница:

- **Точность** — вернулось то же, что было передано; сравнение идёт в
  собственном типе ревизии по **экспортированной** половине структуры.
  Неэкспортированное поле — ваше личное дело и не сравнивается; структура, у
  которой *все* поля неэкспортированы, сравнивается своим же `Equal(T) bool`,
  если он объявлен, — именно так вообще отвечает `time.Time`, и только такой
  ответ для неё верен, — и через `==`, если не объявлен: так отвечает
  `netip.Addr`. Структура, у которой нет ни того ни другого — например,
  держащая приватный срез или `big.Int`, — решается на **проводе**: то, что
  вернулось, кодируется заново, и байты сравниваются с теми, в которые
  закодировался образец, — поэтому кодек, потерявший сумму и сохранивший
  примечание рядом с ней, даёт `ErrPayload`, как любое другое расхождение. Этот
  вопрос не требует метода, и потому именно он задаётся типу, которым вы не
  владеете: объявить `Equal` на значении из `math/big` из своего пакета нельзя.
  Он слабее сравнения значений и работает только там, где тому сказать было
  нечего: кодек, теряющий одно и то же и на выходе, и на входе, кодируется
  обратно в те же байты, и находит это только сравнение самих значений. `Equal`
  спрашивается в этой позиции и больше нигде, поэтому `Equal`, написанный под
  ваш собственный вопрос — сравнивающий заголовок, но не тело, — не может
  отключить эту проверку для структуры, на которую обход полей сам бы ответил;
  и рядом с ним не спрашивается ничего, потому что кодек, возвращающий
  `time.Time` в UTC, точен по ответу самого типа и пишет другие байты.
- **Функция** — единственный лист, о котором молчат оба ответа: ни один формат
  её не записывает и Go не сравнивает никаких двух, поэтому полезная нагрузка с
  функцией отклоняется с `ErrSample`, называющим её. Записывайте то, что
  идентифицирует поведение, — имя, код — и выбирайте функцию по нему в свёртке.
  Канал сравним, поэтому он сравнивается, и кодек, вернувший другой канал, —
  расхождение.
- За **интерфейсом** два значения могут иметь разные типы — это кодек, подменивший
  одно значение другим. Это такое же расхождение, как любое другое
  (`ErrPayload`), а не обход одного значения по форме другого. Исключение — два
  числа с одним значением: ни один допускаемый здесь формат не имеет целого,
  отличного от вещественного, поэтому `int64`, прочитанный обратно как
  `float64` того же значения, проходит, а другого значения — нет. Исключение
  заканчивается там же, где заканчивается вещественное число. Целое, которое
  `float64` не хранит точно, — идентификатор или сумма больше 2^53, обычный
  размер snowflake или баланса в сатоши, — прочитанное обратно как ближайшее
  вещественное, является таким же расхождением, как любое другое, и даёт
  `ErrPayload`.
- **Отсутствие алиасинга** — одни и те же байты декодируются дважды, и два
  ответа ищутся на общий срез или общую карту, а между двумя кодированиями
  первого ответа кодек заставляют декодировать вторую полезную нагрузку.
  Точнее, две: нулевое значение типа-читателя и — если оно ничего не сдвинуло —
  полезную нагрузку самого образца с одним изменённым байтом, которая ровно так
  же широка, как то, на что указывает первый ответ, и находит кодек,
  заполняющий свой буфер по ширине полезной нагрузки и ничего не очищающий. Для
  второй от вашего кодека не требуется ничего: нагрузка, которую он отвергает
  или на которой паникует, — та, из которой проба ничего не узнала, и вердикт
  остаётся за первой.

Для двух фактов вторую половину запустить нельзя: для **маркерного** факта, чей
тип-читатель держит одно значение — `struct{}`, — потому что его единственный
образец кодируется как его же нулевое значение и второй полезной нагрузки, чтобы
что-то потревожить, не существует; и для факта, чьим образцом вы дали нулевое
значение типа, который несёт данные, — это отказ как ошибка вызывающего
(`ErrSample`), а не проход. Маркерный факт проходит: точность доказана, алиасинг
не проверялся, а тип нулевого размера держит одно значение, как бы он ни был
записан, — поэтому с того, кто запрещает `==`, его никто и не спрашивает.

Оба обхода посещают не более **65 536 значений**. Образец больше этого
отклоняется с `ErrSample`, называющим границу: обход, остановившийся раньше, не
сравнил ничего за точкой остановки — прогоняйте образец поменьше того же типа.
Собственный `Equal` типа полезной нагрузки вызывается только в позиции выше, и
его паника — тоже `ErrSample`.

## Журнал доставляет в порядке позиций, и это закон

`ReadAll` отвечает возрастающими позициями — внутри страницы и по страницам,
которые выкладывает один курсор, — а события одного потока появляются в журнале
в том порядке, в котором их держит поток. **У `Capabilities` нет члена ни для
одного из них, и не будет.** `MonotoneVisibility` — честная возможность, потому
что потребитель, которому она не нужна, всё равно корректен без неё; порядок
доставки — вопрос другого рода. Проектор, сворачивающий по потоку, поверх
хранилища, отказавшегося от второго, молча неправ — без ошибки на любом пути и
неправ в модели чтения, а не в журнале. Хранилище, которое не держит оба, не
является соответствующим хранилищем, а `Reader.Next` отвергает страницу,
нарушающую первый, через `ErrBackend` — для любого хранилища ([[D-128]]).

## Что обещает `Progress.Highest`

Одно проверяемое предложение: после того как для проекции сохранена контрольная
точка с `Highest = P`, чтение, возобновлённое от её курсора, отвечает только
позициями выше `P`, и ни одно событие на позиции `P` или ниже никогда не будет
доставлено этой проекции впервые.

Два уточнения несущие. *Доставлено*, а не *применено*: `Progress.Quarantined`
ненулевой ровно тогда, когда в назначении есть дыры, и именно это не даёт читать
`Highest` как утверждение о полноте модели чтения. И *впервые*: доставка — не
менее одного раза, поэтому событие на `P` или ниже вполне может прийти снова
после падения. `Highest` — это водяной знак, а не «самая высокая позиция
страницы»: то же число и другое обещание, и оно означает столько лишь потому,
что порядок выше — закон.

## Окно трекера, и почему сохранение решается одной загрузкой

`*Tracker` принадлежит одной горутине, как и `*Reader`. Он держит ограду,
которую ответила его собственная `Load`, и предъявляет на единицу выше, поэтому
`Checkpoint.Advance` — поле, которое хранилище читает, а не то, которое
вычисляет вызывающий, а `Save` отвечает предъявленным числом, что бы ни сказало
хранилище.

Держит он **окно**, а не одно число, потому что его концы отвечают на разные
вопросы. Ограда — это то, на единицу выше чего предъявляет сохранение; пол — это
самое низкое значение, на котором строка ещё может стоять, то есть последнее,
про которое этот трекер видел, что хранилище закоммитило его само. Они
расходятся в двух случаях, и оба обычны: сохранение, которое хранилище не
подтвердило, и сохранение, записанное внутри транзакции, которую этот трекер не
коммитит.

- **`Load` после сохранения вправе ответить любым из концов.** Внутри окна ответ
  принимается; снаружи трекер закончил с этой строкой и говорит об этом через
  `ErrWrongStore`. Ниже пола — строка, снятая, сброшенная или восстановленная из
  дампа, и следующее сохранение приземлилось бы на ограде 1 поверх живой модели
  чтения. Выше ограды — второй писатель на том же имени, и взять его значение —
  это то, что заставляет два процесса ходить по очереди через одну контрольную
  точку.
- **Сохранение, которое хранилище не подтвердило, решается одной `Load`, а не
  вторым сохранением.** Второе сохранение могло бы только угадывать, какое из
  двух значений держит строка, и трекер отвергает его по имени.
- **Трекер, чья строка ушла за пределы его окна, закончил, а не пересаживается.**
  Пересадить ограду вниз — это молчаливый перезапуск с начала журнала поверх
  живого назначения, без ошибки на любом пути.

## Тестирование без хранилища и тестирование хранилища

`Aggregate.Fold` прогоняет ваши свёртки над вашим значением вообще без
хранилища, поэтому доменное правило — обычная чистая функция под тестом.
`eventmemory` — полноценное хранилище для всего остального, а `eventtest` —
контракт в виде набора проверок, который автор хранилища запускает на своём
хранилище.

Три прокси работают над вашим собственным объявлением, а не над фреймворковым:
`eventtest.Keys` — инъективность отображения, `eventtest.Families` — одно
семейство на агрегат, `eventtest.RoundTrip` — полезная нагрузка, переживающая
свой кодек.

## Чем это не является

Здесь нет языка запросов по истории, нет поверхности list-filter-sort, нет
удаления и нет обновления: два чтения — это один поток в порядке версий и журнал
в порядке коммитов. Нет ни снимков, ни подписок, ни публикаторов: полное
воспроизведение — единственный авторитет свёрнутого состояния, а условие для
пересмотра измерено и записано ([[D-132]]). Проектор же **есть** — это
[`event/projection`](projection.md), построенный на обходе журнала и на шве
контрольных точек с этой страницы, и доставляет он не менее одного раза, в обоих
своих режимах.
