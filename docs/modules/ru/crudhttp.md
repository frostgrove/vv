# crudhttp — HTTP-половина

```go
import "github.com/shardit-io/vv/http/crudhttp"
```

**Модуль:** корневой · **Зависит от:** `crud`, `query`, `errs`, `port`, `net/http`

Всё, что общее для трёх HTTP-биндингов и чего нет у gRPC: таблица статусов,
конверт ошибки, шов рендерера и хелперы запроса, которые вызывает каждый биндинг.

**Импортируйте**, когда рендерите собственные тела ответов, устанавливаете
middleware ошибок или заменяете конверт. Если вы просто монтируете маршруты,
[crudnet](crudnet.md), [crudfiber](crudfiber.md) или [crudgin](crudgin.md)
реэкспортируют нужное.

---

## Таблица статусов

```go
crudhttp.Status(err)          // int — всё целиком, без настройки
crudhttp.StatusFor(kind)      // int — если kind уже есть
crudhttp.KindOf(err)          // errs.Kind
```

| Kind | Статус |
|---|---|
| `KindNotFound` | 404 |
| `KindUnauthorized` | 401 |
| `KindForbidden` | 403 |
| `KindRetryable` | 503, с `Retry-After` |
| `KindConflict` | 409 |
| `KindValidation` | 422 |
| `KindBadRequest` | 400 |
| всё остальное | 500 |

**Kind — это ответ `port`, а статус — таблица этого пакета.** В этом весь
[[D-045]] одной строкой: классификация транспортно-нейтральна, а 404 — нет.

`Status` не требует настройки, поэтому приложение, которое рендерит собственные тела,
получает статусы без построения рендерера ([[UC-015]]).

## Конверт

Единственное тело, которое эта библиотека кладёт на провод для неудачного
запроса:

```json
{
  "type": "error",
  "errors": {
    "validation": [
      {"field": ["user","email"], "error_code": "unique", "message": "that address is taken"}
    ],
    "general": [
      {"error_code": "restrict", "message": "something still refers to this record"}
    ]
  }
}
```

```go
type Envelope struct {
    Type    string `json:"type"`               // всегда "error"
    Partial bool   `json:"partial,omitempty"`  // достигнут предел; список неполный
    Errors  Groups `json:"errors"`
}

type Groups struct {
    Validation []errs.Violation `json:"validation,omitempty"`  // называет поле
    General    []errs.Violation `json:"general,omitempty"`     // не называет
}
```

`Type` всегда `"error"`, поэтому клиент может разветвиться до парсинга.

**Группа говорит, что клиент может с этим сделать, а не откуда пришёл сбой** —
поэтому 409-конфликт уникальности попадает в `validation`: он называет поле,
которое отправил клиент, и форма может его пометить ([[UC-017]]).

**`Partial` — не украшение.** Ответ, перечисляющий четыре нарушения без него,
заявляет, что их было четыре.

`Groups` — структура, а не карта, чтобы порядок ключей задавался этим
объявлением, а не привычкой энкодера — та же причина, по которой [[D-014]]
требует байт-в-байт идентичности всего остального здесь от запуска к запуску.

> RFC 9457 problem+json не поставляется, как и старое тело
> `{"error":…,"message":…}`. Две формы — вдвое больше поверхности, которую нужно
> тестировать и держать честной ради выбора, который почти никто не меняет; шов
> `Renderer` существует для потребителя, которому это нужно.

## Рендерер

```go
type Renderer interface {
    Render(ctx context.Context, err error) (int, http.Header, any)
}
```

`crudhttp.NewRenderer(opts...)` строит рендерер по умолчанию.

| Опция | Делает |
|---|---|
| `WithCodes(*errs.Codes)` | словарь. Решает kind'ы и сообщения по умолчанию |
| `WithMessages(errs.MessageSource)` | ступень каталога в лестнице сообщений |
| `WithResolvers(rs...)` | объявленные переходы пути, подключены **перед** запасным вариантом по телу |
| `WithMaxViolations(n)` | ограничить список. По умолчанию 100 |
| `WithRetryAfter(seconds)` | заголовок на 503. По умолчанию 1 |

Замените его целиком — на RFC 9457, на устаревшую форму, вообще ни на что —
через `WithRenderer` на любом биндинге.

> Интерфейс `Renderer` намеренно живёт здесь, а не в `errs`: интерфейс,
> возвращающий `http.Header`, не может быть реализован gRPC-биндингом, поэтому
> он не входит в транспортно-нейтральную половину.

## Установка

```go
mux.Handle("/", crudnet.Errors(crudhttp.WithMessages(cat))(routes))   // net/http
app.Use(crudfiber.Errors(crudhttp.WithMessages(cat)))                 // Fiber
r.Use(crudgin.Errors(crudhttp.WithMessages(cat)))                     // Gin
```

Он покрывает и написанные вручную маршруты, и сгенерированные. Установка
дважды рендерит один раз — маркер это обёртка response-writer'а, а не что-то
на самой ошибке, потому что `Fault` — это значение, которое две горутины могут
рендерить одновременно.

## Именование поля на написанном вручную эндпоинте

Сгенерированный [`port.PathMap`](port.md#the-path-chain) знает соответствие.
Без него сырой индекс по телу **распознаёт** его:

```go
body, err := crudhttp.DecodeJSONKeep(r.Body, &in)
ctx := crudhttp.WithBody(r.Context(), body)
// рендерер забирает его через crudhttp.BodyFrom
```

`BodyResolver(raw)` обходит удержанное тело, строя индекс листовых путей, и
сопоставляет имя поля модели с ключами, которые фактически отправил клиент.

**Это запасной вариант, а не механизм**, и он работает только там, где
объявленные переходы ничего не изменили — так что догадка не может отменить
объявление ([[D-043]]).

Три ограничения, заявленные, а не обнаруженные:

- **Только JSON.** У тела формы нет вложенности для индексации; тело не в
  JSON отклоняется, и путь деградирует до имени поля модели.
- **Имя, сворачивающееся в более чем один лист, отклоняется.** Два ключа
  `email` на двух уровнях вложенности — два кандидата, и этот слой не выбирает.
- **Он отклоняет, а не угадывает, всегда.** Отказ помечает нарушение как
  `Approximate`.

`c.Body()` у Fiber валиден только внутри хендлера, поэтому этот биндинг
использует `crudhttp.KeepBody(b)`, чтобы сначала скопировать. `MaxKeptBody` —
64 KiB.

## Вызов другого сервиса

Клиентская сторона живёт в этом же пакете, потому что нужные ей таблицы
определены здесь: `KindForStatus` — это `StatusFor`, прочитанная наоборот, а
`ParseEnvelope` читает то, что написал `EnvelopeRenderer`. Клиент со своей
копией любой из них согласовывался бы с сервером ровно до первого изменения
одной из двух ([[D-045]]).

```go
articles := remote.New[Article, int64, ArticleInput](
    crudhttp.Transport("https://content.internal/articles"))
```

| Опция | Что делает |
|---|---|
| `WithClient(*http.Client)` | таймаут, лимиты соединений, инструментированный round tripper |
| `WithRequestHook(func(*http.Request) error)` | выполняется перед каждым запросом — заголовок `Authorization`, трассировка, `Accept-Language` |

HTTP-клиент **один**, а не три: потребитель, который ходит наружу, использует
`net/http` — чем бы он ни отдавал сам, — а три биндинга регистрируют одни и те же
маршруты. См. [remote](remote.md) и [[FL-018]].

Две функции, нужные клиенту и полезные приложению, которое само отвечает на свои
ошибки:

| Функция | Отвечает |
|---|---|
| `KindForStatus(code int) errs.Kind` | класс, из которого получился статус |
| `ParseEnvelope(body []byte) (Envelope, bool)` | конверт — и **false**, если тело им не является; именно это не даёт 404 от роутера или шлюза прочитаться как `crud.ErrNotFound` |

## Хелперы запроса

Реэкспортированы из [port](port.md), плюс специфичные для HTTP:

| | |
|---|---|
| `DecodeJSON(r, v)` / `DecodeJSONKeep(r, v)` | декодировать, опционально сохранив байты |
| `MalformedBody(err)` | ошибка декодирования становится 400 с `malformed_body` |
| `Sanitize` · `ClearGenerated` · `CoerceID` | что клиент не может выбирать |
| `NarrowForEntity` · `NarrowForCount` | отбросить то, что эти запросы не могут запрашивать |
| `BadRequest` · `BadRequestf` · `BadRequestAs` | собрать 400 с указанным путём |
| `AcceptLanguage(header)` | первый тег из заголовка `Accept-Language` |
| `WithLocale(ctx, l)` / `LocaleFrom(ctx)` | локаль, которую читает лестница сообщений |
| `BulkDeleteRequest[ID]` | тело `{"ids":[…]}` |
