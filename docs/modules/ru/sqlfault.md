# sqlfault — ошибка драйвера становится сбоем

```go
import "github.com/shardit-io/vv/sqlfault"
```

**Модуль:** корневой · **Зависит от:** `errs`, `errs/sqlerr`, `crud`, `catalog`

Слой, который всё это собирает воедино. Он обходит дерево, которое вернул
драйвер, решает, отказала ли база данных нарушить ограничение, спрашивает у
[sqlerr](sqlerr.md), какое именно это было нарушение, дополняет колонки,
которые драйвер не назвал, и отдаёт `errs.Fault` с `crud.ErrConflict` внутри.

**Именно это принимает `WithFaults`.** Для большинства это одна строка.

---

## Подключение

```go
cls := sqlfault.New("postgres")

db := crudsql.Postgres(sqlDB, crudsql.WithFaults(cls))
db := crudpgx.Open(pool,      crudpgx.WithFaults(cls))
```

Строки движков: `"postgres"`, `"mysql"`, `"mariadb"`, `"sqlite"`.

С подключённым [catalog](catalog.md) нарушение, о котором драйвер сообщил без
имён колонок, эти имена получает — составной unique в PostgreSQL как раз тот
случай, где это нужно:

```go
cat, err := catalog.Load(ctx, crudsql.Postgres(sqlDB))
if err != nil { log.Fatal(err) }

cls := sqlfault.New("postgres", sqlfault.WithColumns(sqlfault.FromCatalog(cat)))
db  := crudsql.Postgres(sqlDB, crudsql.WithFaults(cls))
```

И со своим собственным словарём:

```go
codes := errs.StandardCodes()
codes.Add("email_taken", errs.KindConflict, "that address is already registered")

cls := sqlfault.New("postgres", sqlfault.WithCodes(codes))
```

| Опция | Что делает |
|---|---|
| `WithCodes(*errs.Codes)` | словарь. По умолчанию `errs.StandardCodes()` |
| `WithColumns(Columns)` | дополняет колонки, которые драйвер не назвал. `FromCatalog(cat)` — обычный вариант |
| `WithExtractor(Extractor)` | заменяет обход дерева по форме, для драйвера, который скрывает свою ошибку |

---

## Что вы получаете без этого

Ничего не ломается. `crud.ErrConflict` по-прежнему возвращается, и 409
по-прежнему 409 — просто без `error_code` и без `field`, так что клиенту
сообщается *что* запись не удалась, но не *что именно* с ней не так.

## Движок объявляется, а не выводится

`New` принимает движок как обычную строку, и передаётся литерал.

Здесь ничто не заглядывает в `crud.Dialect`, потому что `crud.Dialect.Name()`
отвечает `"mysql"` и для MariaDB — а type switch по типам диалекта — это тот
же вывод, только записанный иначе. Он отправил бы код `4025` из MariaDB в
таблицу MySQL ([[D-046]]).

Следствие сделано намеренно: **единственный достижимый отказ — отсутствие
кода, никогда не неверный код.**

> Передача `crud.Dialect` в `crudsql.Open`, `crudsql.From` или
> `crudsql.Source` классифицирует *статус*, а не *код*. Четыре именованных
> конструктора — `Postgres`, `MySQL`, `MariaDB`, `SQLite` — объявляют движок.
> Для присоединённой чужой транзакции `WithFaults` — способ сказать, какой
> движок отвечает.

---

## Два гейта, и они отвечают на разные вопросы

| | Отвечает на | Решает |
|---|---|---|
| `sqlfault.Integrity(err)` | отказала ли база данных нарушить ограничение? | `crud.ErrConflict` |
| `sqlerr.Classify(…)` | *какое именно* это было нарушение? | `errs.Code` |

**`Integrity` намеренно шире.** Номер класса 23, который никто не
провоцировал — `1216` и `1217` в MySQL как раз такие два случая — и код
SQLite с младшим байтом 19, чей старший байт не выдала ни одна проба, здесь
считаются конфликтами, а там — неклассифицированными. Такое нарушение
доходит до вызывающего как **409 без кода**, а не как 500.

У него три ветви, потому что четыре движка отвечают тремя разными способами:

- **класс 23** — переносимая половина, и весь ответ PostgreSQL;
- **`HY000`** — MySQL говорит, что у него нет ничего более конкретного. Его
  ошибки CHECK и отсутствующего значения по умолчанию попадают сюда, так что
  единственное, что отделяет их от обычной серверной ошибки, — это *номер*;
- **вообще без состояния** — SQLite, у которого его нет и не будет.

Ветвь без состояния читает специфичный для SQLite номер, а не объединённый,
потому что SQLSTATE в пакете ошибки MySQL необязателен: без этой
осторожности отказ рукопожатия (`1043`, чей младший байт — 19) отвечал бы 409
с фразой драйвера в теле.

**Сбой строится только тогда, когда известны и код, и его вид.** Нулевое
значение `errs.Kind` — это `KindInternal`, так что сбой, построенный из
неподключённого словаря, объявил бы 500 для дублирующегося ключа — отказ
строить сбой — единственный ответ, который не может солгать.

## Составные части, если нужны напрямую

```go
sqlfault.Extract(err) *sqlerr.Err   // разворачивает дерево ошибки драйвера по форме
sqlfault.Integrity(err) bool        // гейт конфликта
sqlfault.Wrap(cls, err) error       // что вызывает адаптер
```

`Extract` отвечает nil только для nil-ошибки. Всё остальное даёт `Err`,
потому что «нет ни SQLSTATE, ни номера» — законный ответ (соединение, которое
так и не достигло сервера, — один из таких случаев), и вызывающий должен
отличать это от «ничего не извлечено».

`Wrap` тотален и чувствителен к порядку. Ошибка, уже несущая сбой,
возвращается без изменений, так что `crud.Source`, оборачивающий исполнитель
другого адаптера, не классифицирует дважды. Затем спрашивается классификатор.
Затем, **что бы он ни ответил**, сигнальную ошибку решает `Integrity` — так
что сторонний `errs.Classifier` не может ни подделать `crud.ErrConflict`, ни
потерять его ([[D-038]]).

## Принести свой

`Classifier` удовлетворяет `errs.Classifier` — это интерфейс, под который
пишет третья сторона. ORM, порождающая собственные ошибки, реализует этот
единственный метод и проходит через ту же дверь `WithFaults`.

`Columns` — это один метод, отдающий имена и ничего больше — третья сторона
может предоставить схему, не импортируя `catalog`, и **не может** отдать
предикат, определение или текст DDL — ничему из этого нет места рядом с
рендерером ([[D-044]]).
