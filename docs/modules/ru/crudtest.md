# crudtest — модульное тестирование репозитория без базы данных

```go
import "github.com/shardit-io/vv/crud/crudtest"
```

**Модуль:** корневой · **Зависит от:** `crud` и стандартной библиотеки

`crud.Source`, который записывает SQL, порождённый репозиторием, и воспроизводит
для него заготовленные строки. Форма запроса, порядок биндов, арифметика
пагинации и композиция декораторов — всё проверяется без Docker ([[UC-011]]).

Весь набор модульных тестов в этом репозитории построен на нём. SQL
детерминирован по замыслу ([[D-014]]) — именно это и делает такой подход
рабочим.

---

## Проверка запроса

```go
rec := crudtest.Postgres().Push(crudtest.Rows(
    []any{int64(1), int64(7), "ann@x.io", "Ann", 31, true, time.Now()},
))

u, err := Users.Bind(rec).GetByID(ctx, 1)

rec.Last().SQL   // SELECT "id", … FROM "users" WHERE "id" = $1 LIMIT 1
rec.Last().Args  // []any{int64(1)}
```

```go
crudtest.Postgres()          // *Recorder на crud.Postgres{}
crudtest.MySQL()             // …на crud.MySQL{}
crudtest.New(crud.SQLite{})  // …на любом диалекте
```

## Подача ответов

```go
rec.Push(crudtest.Rows(
    []any{int64(1), "first"},
    []any{int64(2), "second"},
))
```

Значения присваиваются местам назначения сканирования **позиционно**, с
конвертацией там, где это допускает Go, и с учётом `sql.Scanner`. Ставьте в
очередь столько результатов, сколько вызов реально сделает — пагинированное
чтение это два запроса, а preload добавляет ещё по одному на каждое отношение.

| | |
|---|---|
| `Push(results...)` | поставить в очередь ответы на запросы |
| `ExecResult(res)` | rows-affected и last-insert-id следующего `Exec` |
| `Fail(err)` | следующий `Exec` вернёт `err` |
| `Rows(rows...)` | успешный результат |
| `RowsFailing(err, rows...)` | строки, а *затем* ошибка |

**`RowsFailing` — не дубль отказавшего запроса.** Драйверы, которые этот дубль
подменяет, сообщают об одном сбое в двух разных местах: `crudtest.Result{Err: err}`
— это отказ самого `Query`, так устроен `database/sql`, а `RowsFailing` — это
форма pgx: запрос,
который сервер отклонил, приходит как живой `Rows`, отдающий то, что уже есть,
а *затем* отвечающий `Err`. Дубль, способный выразить только первый вариант,
не может провести чтение через ветку, которой оно обязано завершиться, а цикл,
который никогда не спрашивает, воспринимает усечённую схему как полную.

## Чтение назад

| | |
|---|---|
| `Last()` | самый последний `Statement` |
| `Statements()` | все, по порядку |
| `SQL()` | только строки |
| `TxDepth()` | насколько глубоко зашла вложенность транзакций |
| `Reset()` | очистить всё |
| `Normalize(s)` | схлопнуть пробелы, чтобы тест сравнивал запросы без оглядки на форматирование |

```go
if got := crudtest.Normalize(rec.Last().SQL); got != want {
    t.Fatalf("the update wrote the wrong columns:\n%s", got)
}
```

## Транзакции

`Recorder` реализует `crud.Beginner`, поэтому `Tx` и `InTx` работают, а
вложенность считается, а не исполняется. Этого достаточно, чтобы проверить,
что декоратор открыл транзакцию или что вложенный вызов присоединился, а не
породил новую вложенность.

## Идентичность

Recorder идентифицирует себя под `crud.KeyOf`, поэтому `crud.WithExecutorFor`
и `catalog.Set` обращаются с ним так же, как с настоящим источником данных. У
него нет метода `DataSource()`, и он ему не нужен ([[D-041]]).

## Чего он не скажет

Он подменяет драйвер, а не базу данных. Он не может сказать, *корректен* ли
SQL, сработает ли ограничение или примет ли диалект ту или иную конструкцию.
Для этого существует `make integration` — и у этих двух наборов сознательно
разные задачи: этот пришпиливает запрос, который строит библиотека, а
интеграционный набор — то, что с ним делают четыре движка.
