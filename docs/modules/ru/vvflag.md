# vvflag — один типизированный флаг, пока не всё захватил `flag.Parse`

```go
import "github.com/shardit-io/vv/utils/vvflag"
```

**Модуль:** корневой · **Зависит от:** стандартной библиотеки

Прочитать один именованный флаг из среза аргументов в типизированное значение.
Это весь пакет.

**Зачем он нужен:** стандартный пакет `flag` требует объявить все флаги заранее
через `FlagSet`, а библиотека не может сделать это от имени приложения. Этот
пакет читает один флаг и ничего больше, так что библиотека может искать
`--config-path`, не претендуя на владение командной строкой.

---

## Использование

```go
port, err := vvflag.Or(os.Args[1:], "port", 8080)
addr, _  := vvflag.Or(os.Args[1:], "addr", ":8080")
debug, _ := vvflag.Or(os.Args[1:], "debug", false)
```

| | |
|---|---|
| `Parse(args, name, def)` | если флага нет — возвращает значение по умолчанию **и `ErrAbsent`** |
| `Or(args, name, def)` | отсутствие флага сворачивается в значение по умолчанию; некорректное значение — всё ещё ошибка |
| `Lookup(name, def)` | `Or` над `os.Args` |

`args` не должен включать имя программы.

## Три формы

```
--name=value
--name value      (кроме bool, где сам флаг без значения означает true)
--name            (только для bool)
```

Аргумент `--` завершает разбор флагов, всё после него — позиционные аргументы.

## Единственное правило, которое стоит знать

**Отсутствие и некорректность — это разные ответы.**

Флаг, которого нет, возвращает значение по умолчанию и `ErrAbsent`. Флаг,
который есть, но не разбирается, возвращает значение по умолчанию и ошибку
разбора.

Если смешать эти два случая, опечатка в `--port=abc` молча запустит сервер на
порту 0. `Or` сворачивает случай отсутствия для обычного места вызова — и
всё равно возвращает ошибку разбора, потому что флаг, который написали
неправильно, — это не флаг, который забыли указать.
