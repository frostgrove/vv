# vvcfg — структура конфигурации, загружаемая и валидируемая при старте приложения

```go
import "github.com/frostgrove/vv/utils/vvcfg"
```

```bash
go get github.com/frostgrove/vv/utils/vvcfg
```

**Модуль:** отдельный — cleanenv является зависимостью, а корневой модуль не
берёт ни одной ([[D-033]], [[D-036]]) · **Требует:** `github.com/ilyakaznacheev/cleanenv`

Декодирование — целиком дело cleanenv: YAML, TOML, JSON, `.env` и теги
окружения. Модуль добавляет то, что нужно приложению вокруг этого: **заявленный
приоритет** поиска файла, **возврат ошибки** вместо паники, **валидацию каждого
блока**, а не только корня, **отказ на ключе, которого не объявляет ни одно
поле**, и **отчёт о том, откуда пришло каждое значение** ([[D-086]]).

---

## Использование

```go
type Config struct {
    Addr string      `yaml:"addr" env:"ADDR" env-default:":8080"`
    DB   vvdb.Config `yaml:"db"`
}

func (this *Config) ValidateSelf() error {
    if this.Addr == "" {
        return errors.New("addr is required")
    }
    return nil
}

func main() {
    cfg := vvcfg.MustLoad[Config]()
    …
}
```

Ничто не пробрасывает `Validate` в `cfg.DB`: загрузчик обходит дерево сам.

| | |
|---|---|
| `Load[T](path)` | декодирует названный файл, затем валидирует дерево |
| `LoadStrict[T](path)` | то же и отказ на ключе, которого не объявляет ни одно поле; отдаёт `*Report` |
| `LoadFrom[T](Source)` | явная форма: поиск файла, строгость и правила одним значением; отдаёт `*Report` |
| `MustLoad[T](path...)` | `DefaultSource()` и паника; явные сегменты соединяются `filepath.Join` |

`MustLoad` — короткий путь, `LoadFrom` — то, чем он является под капотом.

## Валидация — это дерево, а не один хук

```go
type SelfValidator interface{ ValidateSelf() error }
type CrossValidator interface{ ValidateCross() error }
type Validator     interface{ Validate() error }
```

`ValidateTree` — его вызывает каждая загрузка, и он экспортирован для
конфигурации, собранной кодом — спрашивает `ValidateSelf` ровно один раз на
узел, объединяет ошибки, поэтому файл с двумя сломанными блоками сообщает про
оба, и приписывает каждой путь блока (`db.replica: …`). Только после этого
выполняются все `ValidateCross`, так что правило, сравнивающее два блока, вправе
считать каждый блок валидным сам по себе.

**Узел, у которого метод называется старым именем `Validate`, владеет всем, что
под ним, и обход там останавливается.** Этот метод так же часто оказывается
написанным вручную форвардером, как и правилом, а блок, который сливает
фрагмент с родителем до проверки — `vvdb.Config` и его реплика — отказывает
такому фрагменту, если спросить его напрямую. Переименование `Validate` в
`ValidateSelf` — это и есть подписка поддерева на обход.

Рекурсия ограничена адресами уже увиденных указателей и map и глубиной, поэтому
конфигурация, ссылающаяся на себя, завершается.

`*ValidationError` несёт `Path` и причину; `errors.Is` и `errors.As` проходят
сквозь объединение.

## Строгость

```go
cfg, report, err := vvcfg.LoadStrict[Config]("/etc/app.yaml")
```

`adress:` не устанавливает ничего, и без строгой загрузки сервис стартует на
значении по умолчанию. `LoadStrict` читает файл вторым проходом как документ и
отказывает тому, чего не объявляет ни одно поле:

- `*UnknownKeysError` — ключи, каждый со своим путём (`billing.hsot`).
- `*UnusedEnvironmentError` — переменные под префиксом, который структура
  объявила через `env-prefix` и который не читает ни одно поле. Кандидатами
  являются только объявленные префиксы, а префикс, ведущий в блок, применяющий
  собственное окружение, исключается: такой блок владеет именами, которых обход
  не видит.

Нестрогий `Load` кладёт те же находки в отчёт вместо отказа — чтобы деплой можно
было привести в порядок до включения строгости.

Так можно осмотреть `.yaml`, `.yml`, `.json`, `.toml` и `.env`. `.edn` — нельзя:
cleanenv его декодирует, а прочитать обратно как документ этот пакет не умеет.
Строгая загрузка такого файла даёт `ErrUnreadableFormat`. Нестрогая файл всё
равно загружает — и честно об этом говорит: `Report.NotInspected` несёт причину,
`Report.String` печатает её отдельной строкой, а происхождение каждого поля —
`OriginUnknown`, а не `OriginDefault`, который утверждал бы, что значение никто
не записывал.

## Отчёт

```go
cfg, report, err := vvcfg.LoadFrom[Config](vvcfg.DefaultSource())
if err != nil {
    log.Fatal(err)
}
log.Print(report)   // config: /etc/app.yaml (--config-path)
                    //   addr <- environment ADDR
                    //   db.host <- file
                    //   db.pool.max_open <- default
```

| | |
|---|---|
| `Report.Path`, `Report.PathOrigin` | какой файл поднял процесс и какой источник его назвал |
| `Report.NotInspected` | почему файл не удалось прочитать как документ, если не удалось; тогда всё происхождение — `OriginUnknown` |
| `Report.Fields` | по полю: `OriginFile`, `OriginEnvironment` (с именем переменной), `OriginDefault`, `OriginUnknown` |
| `Report.UnknownKeys`, `Report.UnusedEnvironment` | строгие находки, сообщаемые даже без отказа |
| `Report.Deprecated` | поля с тегом `vvcfg:"deprecated=use addr"`, которые действительно заданы |
| `Report.OriginOf(path)` | происхождение одного поля |

**Отчёт никогда не несёт значение.** Не «замаскированное» — никакого. Строка,
которую дежурный копирует в тикет инцидента, — ровно та строка, где оказался бы
пароль, поэтому отчёт говорит только откуда пришло значение ([[D-086]]).

## Source

```go
source := vvcfg.Source{
    Arguments:          os.Args[1:],
    DefaultPath:        "./config/app.yml",
    AllowNoFile:        false,
    Strict:             true,
    RequireEnvironment: []string{"db.password"},
}
cfg, report, err := vvcfg.LoadFrom[Config](source)
```

| Поле | |
|---|---|
| `Path` | явный файл; выигрывает у всего остального |
| `Arguments` | где искать `--config-path`; `DefaultSource` берёт `os.Args[1:]` |
| `DefaultPath` | используется, когда файл не назвали ни флаг, ни `CONFIG_PATH` |
| `AllowNoFile` | «файл не назван никем» — легальный стиль деплоя или `ErrNoPath` |
| `Strict` | неизвестные ключи и неиспользуемые переменные означают отказ |
| `RequireEnvironment` | пути, которые обязаны прийти из окружения, чтобы пароль нельзя было закоммитить |

`Source.Resolve` отдаёт путь и `PathOrigin` — вызывающий код, `--config-path`,
`CONFIG_PATH`, значение по умолчанию или ничего, — и это то, что нужно строке
старта: флаг виден в спецификации пода, переменная обычно нет.

Пути по умолчанию на уровне пакета больше нет. Две конфигурации в одном процессе
расходятся, держа два значения `Source`, а тест меняет своё и ничьё больше.

## Приоритет

```
Source.Path / MustLoad("config", "app.yml")   явный путь
--config-path <path>                          флаг, читается из Source.Arguments
CONFIG_PATH=<path>                            переменная окружения
Source.DefaultPath                            DefaultSource берёт vvcfg.DefaultPath
AllowNoFile                                   конфигурация только из окружения
```

Внутри файла cleanenv накладывает окружение поверх того, что сказал файл, —
поэтому отчёт и различает эти два источника.

## Размеры

Дежурный пишет лимит как `25MiB`, а не как `26214400`. `Bytes` — тип для такого
поля: `int64` байт, который декодирует себя через `encoding.TextUnmarshaler`, так
что файл, окружение и `env-default` принимают одно и то же написание.

```go
type Config struct {
    Upload vvcfg.Bytes `yaml:"upload" env:"UPLOAD_LIMIT" env-default:"1MiB"`
}
```

`KiB`, `MiB`, `GiB` — степени двойки; `kB`, `MB`, `GB` — степени десяти; `B` и
голое число — байты. Регистр и окружающие пробелы значения не имеют.
`ParseBytes` — тот же разбор как значение, `Bytes.String` печатает обратно в
наибольшей двоичной единице, на которую делится нацело.

Отказ — это `ErrNotASize`, и он **не повторяет текст, который отверг**: ни одна
ошибка, которую строит этот пакет, не несёт значение конфигурации, а правило с
одним исключением — не правило.
