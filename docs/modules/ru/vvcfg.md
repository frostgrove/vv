# vvcfg — структура конфигурации, загружаемая и валидируемая при старте приложения

```go
import "github.com/shardit-io/vv/tools/vvcfg"
```

```bash
go get github.com/shardit-io/vv/tools/vvcfg
```

**Модуль:** отдельный — cleanenv является зависимостью, а корневой модуль не
берёт ни одной ([[D-033]], [[D-036]]) · **Требует:** `github.com/ilyakaznacheev/cleanenv`

Декодирование — целиком дело cleanenv: YAML, TOML, JSON, `.env` и теги
окружения. Этот модуль добавляет три вещи, которые реально нужны приложению
вокруг этого: **заявленный приоритет** поиска файла, **возврат ошибки** вместо
паники и **хук валидации**, который выполняется раньше всего остального.

---

## Использование

```go
type Config struct {
    Addr string `yaml:"addr" env:"ADDR" env-default:":8080"`
    DSN  string `yaml:"dsn"  env:"DSN"`
}

func (c *Config) Validate() error {
    if c.DSN == "" {
        return errors.New("dsn is required")
    }
    return nil
}

func main() {
    cfg := vvcfg.Must(vvcfg.Auto[Config](os.Args[1:]))
    …
}
```

| | |
|---|---|
| `Find(args)` | путь: сначала `--config-path`, затем `CONFIG_PATH` |
| `Load[T](path)` | декодирует, затем вызывает `Validate()`, если у структуры он есть |
| `Auto[T](args)` | `Find`, затем `Load` — в том порядке, в котором они нужны `main` |
| `Must[T](cfg, err)` | паника при ошибке — для `main`, которому больше нечего делать |

`args` не должен включать имя программы. `ErrNoPath` — то, что возвращает
`Find`, когда ни один из источников не называет файл.

## Хук валидации — в этом весь смысл

```go
type Validator interface{ Validate() error }
```

`Load` вызывает его после декодирования и возвращает то, что вернул он.

**Неверная конфигурация должна останавливать процесс при старте** — а не
проявляться запутанным сбоем, когда уже пошёл трафик ([[D-021]]). Это то же
правило, которому следует `basic.Define` для сломанного маппинга модели и
`probe.Full` для неизвестной таблицы.

## Приоритет

```
--config-path <path>     флаг, который можно переопределить при развёртывании из командной строки
CONFIG_PATH=<path>       переменная окружения
                         …и больше ничего. Никакого поиска, никакого расположения по умолчанию
```

Неявного `./config.yaml` нет, и это осознанно: конфигурационный файл,
случайно найденный в рабочей директории, — это развёртывание, которое ведёт
себя по-разному в зависимости от того, откуда его запустили.
