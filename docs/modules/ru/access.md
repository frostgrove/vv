# access — кто вызывающий, и что ему можно

```go
import "github.com/frostgrove/vv/auth/access"
```

```bash
go get github.com/frostgrove/vv/auth/access
```

**Модуль:** отдельный · **Зависит от:** `vv` (auth, crud, errs, port),
`google/uuid`, `golang.org/x/crypto`

`auth` — это контракт: `Principal` и `Guard`. `access` — рабочая реализация
одного такого, как `apikey` и `authjwt`: семь таблиц, сессионные учётные данные,
пароли на argon2id и RBAC с точечными исключениями.

Импортируйте, когда вход и авторизация должны быть строками в вашей базе, а не
claims в токене.

| Ещё | |
|---|---|
| [accessjwt](accessjwt.md) | подписанные access-токены поверх ротируемого refresh |
| [revokeredis](revokeredis.md) | список отзыва для него, в Redis |
| [accessnet](accessnet.md) / [accessgin](accessgin.md) / [accessfiber](accessfiber.md) | роуты, по модулю на фреймворк |

## Форма

Два вызова. Всё остальное собирается за вас.

```go
runtime, err := access.New(access.RuntimeSpec{
	Source: source,
	Config: cfg.Access,
	Logger: logger,
})

users, signUp, err := access.Mount(runtime, access.SubjectSpec[SignUpForm]{
	Type:      "user",
	Prefix:    "",                   // "" монтирует в /auth/login
	Directory: userDirectory,
	Normalize: strings.ToLower,
	Registrar: userRegistrar,
	Strategy:  access.OpaqueToken(),
})
```

`SubjectSpec` и есть документация: пропущенное поле — это ошибка компиляции, а
не поведение, о котором надо знать. Наружу не отдаётся ни `Store`, ни хешер, ни
аутентификатор — это те детали, у которых важны порядок и парность, и
потребитель, собирающий их руками, ошибётся так, что оно скомпилируется.

`Mount` отвечает двумя значениями, потому что у субъекта две половины разной
формы: `*MountedSubject`, который нужен любому биндингу, и `*SignUpUseCase[P]`,
несущий **вашу** полезную нагрузку регистрации. Никто её не стирает и не
восстанавливает ассершеном.

## Субъект

Здесь нигде не назван пользователь. Каждая строка указывает на **субъект** —
тип и id, ровно та форма, что у `model_has_roles` в Laravel. Хранилище за типом
— это `Directory`, который реализуете вы. Три метода, и все читают:

```go
type Directory interface {
	SubjectType() SubjectType
	Active(ctx context.Context, id uuid.UUID) (bool, error)
	Describe(ctx context.Context, id uuid.UUID) (Profile, error)
	Touch(ctx context.Context, id uuid.UUID) error
}
```

`Active` читается на каждом аутентифицированном запросе — именно поэтому
деактивация аккаунта блокирует его на следующем вызове, а не когда истечёт
сессия.

`Mount` отказывает на старте, если тип субъекта зарегистрирован дважды, если два
субъекта делят префикс и если директория отвечает не за тот тип, что в спеке.
Все три иначе всплывают в рантайме как вызывающий, аутентифицированный не тем
хранилищем.

## Стратегии

**Стратегия** — это то, как один вид вызывающего держит сессию. Одно значение
объявляет оба конца — что выдаётся при входе и что принимается на следующем
запросе, — потому что разведённые по разным местам они согласованы ровно до
первой правки одного из них, а отказ выглядит либо как «всех разлогинило
разом», либо как токен, выпущенный для одного типа субъекта и принятый как
другой.

| | выдаётся | проверяется | отзыв |
|---|---|---|---|
| `OpaqueToken()` | 256 случайных бит, дайджест в `sessions` | одно чтение по дайджесту | строка (allow-list) |
| [`accessjwt.Strategy(...)`](accessjwt.md) | короткий подписанный токен + ротируемый refresh | подпись, без чтения сессии | с задержкой в access TTL |
| он же с `Revocation` | " | подпись + deny-list | мгновенный, по id сессии |

`OpaqueToken` — умолчание и обычно правильный ответ. Всё, что продукт просит от
сессии, — это свойство строки: выход закрывает её, деактивация аккаунта
блокирует, снятая роль действует со следующего запроса. Цена — одно чтение на
запрос. За `accessjwt` стоит браться, когда верификатор не может дотянуться до
базы (другой сервис, другой периметр), и не раньше.

**Проверка персубъектная, а не общая на API.** У каждого смонтированного
субъекта свой guard, и группа роутов, на которую пришёл запрос, выбирает его до
всякого парсинга:

```go
guard := users.Guard()          // верификатор этого субъекта
admin := runtime.AdminGuard()   // цепочка по объявленным стратегиям, для общих роутов
```

Деплой, выдающий один вид токенов, запускает один верификатор и отвечает «это не
валидный токен», а не 401 после нескольких неудачных попыток.

## Три вещи, которых модуль не делает

Все три — это [[D-066]], и каждая ваша.

**Не создаёт аккаунты.** На порту нет `Provision`. У вашей строки ваши колонки;
порт, достаточно тонкий, чтобы библиотека могла его описать, — это список полей,
который не подходит никому. Строку вы пишете в `Registrar[P]`, а остальную часть
регистрации библиотека делает в той же транзакции.

**Не монтирует роуты.** Под `auth/access` не импортируется ни один веб-фреймворк.
Роуты — опциональные биндинги, по модулю на фреймворк.

**Не нормализует идентификаторы.** `credentials.identifier` хранится и
сравнивается байт в байт. Адрес складывается по регистру, google-овский `sub` —
нет, и знает об этом только тот, кто выдал идентификатор. Поэтому
`SubjectSpec.Normalize` применяет библиотека с обеих сторон колонки, а правило
вы задаёте один раз.

## Регистрация

Реализуйте `Registrar[P]` над своей полезной нагрузкой. Он выполняется внутри
транзакции зачисления, поэтому дубль, отбитый вашим же уникальным индексом,
откатывает и credential:

```go
func (this *Registrar) Create(ctx context.Context, form SignUpForm) (uuid.UUID, string, error) {
	if !this.config.Enabled {
		return uuid.Nil, "", registrationClosed()
	}
	account, err := this.users.Save(ctx, &User{Email: form.Email, Name: form.Name, IsActive: true})
	if err != nil {
		return uuid.Nil, "", err
	}
	return account.ID, form.Email, nil        // id, и то, чем он будет входить
}

func (this *Registrar) Password(form SignUpForm) string { return form.Password }
func (this *Registrar) Role() auth.Role                 { return "client" }
```

Добавить поле в форму регистрации — это правка `SignUpForm` и `Create`, и ничего
под `access`.

## Вход

Идентификатор уникален **в пределах** типа субъекта ([[D-067]]), поэтому вход
говорит, для какого типа он. Тип подставляет surface, из тела запроса он не
приходит никогда.

```go
response, err := users.Endpoints().SignIn(ctx, access.SignInRequest{
	Email:    form.Email,          // свёрнут через SubjectSpec.Normalize
	Password: form.Password,
}, agent)
```

Любой отказ — один и тот же отказ: неизвестный идентификатор, неверный пароль и
деактивированный аккаунт отвечают одинаково, а пароль проверяется против
`DummyHash()`, когда credential не найден, — чтобы и время ответа ничего не
сказало.

## Объявление прав

Модуль объявляет то, что сам и проверяет, рядом с кодом, который это делает:

```go
runtime.Declare(access.ModuleGrants{
	Module:      "billing",
	Permissions: []access.PermissionDef{{Code: PermInvoiceRead, Name: "See invoices"}},
	Roles:       map[auth.Role][]auth.Permission{"accountant": {PermInvoiceRead}},
})
```

`runtime.Sync(ctx)` на старте, до того как сервер начнёт принимать запросы. Он
добавляет и никогда не удаляет, и пересчитывает `admin` так, чтобы тот держал
всё — включая права, объявленные после его создания.

## Конфигурация

У `access.Config` теги cleanenv, поэтому держите одно поле на весь контекст:

```go
type Config struct {
	Addr   string        `yaml:"addr" env:"ADDR"`
	Access access.Config `yaml:"access"`
}
```

| Ключ | Env | По умолчанию | Что ограничивает |
|---|---|---|---|
| `session.ttl` | `ACCESS_SESSION_TTL` | `720h` | абсолютный срок, ничто его не двигает |
| `session.idle_ttl` | `ACCESS_SESSION_IDLE_TTL` | `168h` | закрывает простаивающую сессию |
| `session.touch_interval` | `ACCESS_SESSION_TOUCH_INTERVAL` | `5m` | насколько может протухнуть `last_used_at` |
| `password.min_length` | `ACCESS_PASSWORD_MIN_LENGTH` | `10` | нижняя граница, в символах |

Длина и ничего больше: правило по составу символов сужает пространство перебора,
которое якобы расширяет. Что угодно сверх этого проверяйте в своём `Registrar`.

`Config.Clock` ниоткуда не загружается. Это тестовый шов — иначе каждое правило
протухания здесь непроверяемо без `sleep`.

## Схема

`auth/access/migrations/00001_access.sql` — скопируйте файл в свою директорию
миграций и переименуйте со своим таймстемпом. Это именно файл для копирования, а
не embed.FS: миграция — факт о *вашей* схеме, применяемый по вашему графику.

Семь таблиц: `permissions`, `roles`, `role_permissions`, `subject_roles`,
`subject_permissions`, `credentials`, `sessions`. Добавлять свои колонки
безопасно — репозиторий выбирает те колонки, которые называет его модель.

`credentials` уникальна по `(subject_type, provider, identifier)`: два
независимых домена могут оба знать `ops@example.com` ([[D-067]]).

`subject_type`/`subject_id` не может быть внешним ключом, и файл прямо об этом
говорит: на уровне базы ничего не удаляет гранты субъекта, когда субъект
исчезает. Деактивируйте вместо удаления — за остальное отвечает директория.
