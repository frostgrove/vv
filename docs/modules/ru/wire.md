# wire — публичное тело и дорога к приватному

```go
import "github.com/frostgrove/vv/crud/wire"
```

**Модуль:** корневой · **Зависит от:** `crud`, `reflect`

Два интерфейса с одним методом и три проверки покрытия. Это весь пакет, и он
существует потому, что `<Model>Update` отвечает не на тот вопрос, когда
спрашивает клиент.

`<Model>Update` — это **persistence-патч**: каждая колонка, которую может
записать `UPDATE`, включая те, что пишет только ваш собственный код — флаг
деактивации, отметка последнего входа. Параметризуйте им публичный PATCH-биндер,
и каждая из них станет тем, что может прислать клиент. Уберите их оттуда — и их
потеряет ваш собственный код. Выход — второй тип и тотальное отображение между
ними ([[D-105]]).

---

## Шов

| | |
|---|---|
| `PatchMapper[P, U]` | `Update(patch P) U` — публичное тело PATCH становится persistence-DTO |
| `Presenter[M, R]` | `Response(model M) R` — модель становится телом ответа |
| `IdentityPatch[U]()` | `PatchMapper[U, U]`, возвращающий свой аргумент |
| `IdentityPresenter[M]()` | `Presenter[M, M]`, возвращающий свой аргумент |

Обе тождественные реализации — это ровно то, что и так получает каждый
существующий вызов: `crudfiber.New`, `NewFor`, `Serving` и `ServingFor`
подставляют их сами, поэтому ресурс, смонтированный прямо на модель, по-прежнему
принимает `U` телом и отвечает `M`. `NewWire` и `ServingWire` — явная форма под
ними, и они принимают все четыре: маппер, патчер, презентер и опции ([[D-021]]).

```go
h := crudfiber.ServingWire(
    service,
    user.UserInputMapper{},
    user.UserPatchMapper{},
    user.UserPresenter{},
)
```

Про генератор здесь не знает ничто. Напишите `PatchMapper` руками для одного
ресурса — биндинг будет тем же самым.

## Проверки покрытия

| | |
|---|---|
| `CoversPatch[U, P](except ...string) error` | у каждого поля persistence-DTO есть поле того же имени и типа в публичном теле PATCH — либо оно названо исключением |
| `CoversCreate[M, In](except ...string) error` | то же против `crud.Schema.Insert` — колонок, которые может нести `INSERT` |
| `CoversResponse[M, R](except ...string) error` | то же против `crud.Schema.Fields` — каждой колонки модели |
| `MustCoverPatch` · `MustCoverCreate` · `MustCoverResponse` | то же, с паникой, для `init` |

Сгенерированный `vv_wire_gen.go` заканчивается одним `init`, вызывающим все три
([[FL-029]]). Написанное руками тело тоже может их вызывать, а список исключений —
то место, где вы говорите, что оставили за бортом намеренно.

Сообщается четыре вида расхождения, каждое поимённо:

| что | сообщение |
|---|---|
| колонка без публичного поля | `no field for LastLoginAt` |
| публичное поле, которого нет в источнике | `a field for Nickname, which the model does not carry` |
| несовпавший тип | `Price carries *int64 where *int is expected` |
| исключение, не называющее ничего | `an exclusion for Password, which the model does not carry` |

Последнее не даёт списку исключений превратиться в кладбище: удалите колонку — и
объявленное исключение тоже станет отказом, так что строку кто-нибудь уберёт.

Сравнение намеренно ведётся против **скомпилированной** модели. Генератор читает
исходный текст; эти проверки читают `reflect` и `crud.Schema`. Колонка,
добавленная в модель без перегенерации, — паника на старте, называющая колонку;
это аргумент [[D-050]], применённый к публичной половине.

## Какие поля несёт сгенерированное тело

`vv generate resource` выводит каждое тело **сужением** и записывает выбор в
`resource.manifest.yml` рядом с пакетом:

| тело | стартует от | выбрасывает |
|---|---|---|
| create | набора полей создания — без связей, без `generated`, без блокировки, без ключа, которым владеет база | `secret` |
| patch | колонок, которые пишет `<Model>Update` | `secret` |
| response | каждой колонки | `secret` и всё, что убрал `-skip` |

Убрать имя из `fields` в манифесте не стоит ничего. Вернуть то, что сужение
исключило, требует `confirmed: true` рядом, и подтверждение привязано к тому
выводу, для которого дано, — так что модель, сменившая форму, спросит заново.
См. [vv-cli](vv-cli.md#generate-resource) и [[D-105]].
