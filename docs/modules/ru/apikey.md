# apikey — аутентификация по общему секрету

```go
import "github.com/frostgrove/vv/auth/apikey"
```

**Модуль:** корневой — импортирует только стандартную библиотеку, поэтому ничего
не стоит · **Зависит от:** `auth`, `crypto/subtle`

Вызывающий предъявляет ключ дословно; `Store` говорит, кто это.

---

## Что вы получаете

| | |
|---|---|
| `New(store, opts...)` | сам `auth.Authenticator` |
| `Store`, `StoreFunc` | шов, который реализуете вы |
| `Static(map)` | хранилище в памяти для тестов и небольших сервисов |
| `TryStatic(map)` | то же хранилище с ошибкой проверки snapshot |
| `Header(name)` | читает голый ключ из отдельного заголовка |
| `Scheme`, `AnyScheme` | какая auth-схема принимается |

## Подключение

```go
authn := apikey.New(apikey.Static(map[string]auth.Principal{
	"k-batch-1": auth.Claims{
		Sub:         "batch",
		Permissions: []auth.Permission{"article:read"},
	},
}))

guard := auth.NewGuard(authn, apikey.Header("X-Api-Key"))
```

Дальше — те же три оставшихся шага, что и с JWT, и ни один из них не специфичен
для API-ключей: guard идёт в middleware транспорта — [authnet](authnet.md),
[authgin](authgin.md), [authfiber](authfiber.md) или [authgrpc](authgrpc.md), —
а что вызывающему позволено, задаёт политика [security](security.md) на
репозитории. Guard сам по себе аутентифицирует и не более того.

`auth.Chain(jwtAuthn, apiKeyAuthn)` — способ принимать на одной точке оба вида.

`apikey.Header` намеренно отличается от `auth.Header`: первый читает
`X-Api-Key: k-batch-1` как полный голый ключ. Второй только переносит
Authorization parser и поэтому ждёт `X-Api-Key: ApiKey k-batch-1`.

## Store и три его результата

```go
type Store interface {
	Lookup(ctx context.Context, key string) (auth.Principal, bool, error)
}
```

Три — потому что два разных отказа нельзя путать:

| результат | означает | становится |
|---|---|---|
| `(p, true, nil)` | ключ выдан | вызывающим |
| `(nil, false, nil)` | такого ключа никто не выдавал | 401 |
| `(nil, false, err)` | поиск выполнить не удалось | этой ошибкой, то есть 500 |

Схлопнуть третье во второе значило бы отвечать «ваш ключ неверен» всем
вызывающим во время аварии базы — и они пошли бы ротировать ключи.

`New` отклоняет nil и interface-typed nil Store при построении.

**В настоящем деплое ключи не лежат в карте.** Там лежит хеш каждого ключа,
поиск идёт по хешу, а отзыв — это удаление строки. `Store` — этот шов:

```go
apikey.New(apikey.StoreFunc(func(ctx context.Context, key string) (auth.Principal, bool, error) {
	sum := sha256.Sum256([]byte(key))
	row, err := keys.Find(ctx, sum[:])
	switch {
	case errors.Is(err, sql.ErrNoRows):
		return nil, false, nil
	case err != nil:
		return nil, false, err
	}
	return row.Principal(), true, nil
}))
```

Любая реализация обязана сравнивать за постоянное время. Индекс в базе по хешу
предъявленного ключа так и делает — по проводу едет хеш.

## Static сравнивает все записи

`Static` — срез, а не карта, и он сравнивает все записи, а не останавливается на
первом совпадении. Поиск по карте ветвится на байтах ключа и возвращается, как
только ответ известен, — а это разное время для ключа, совпадающего по префиксу
с настоящим, и для не совпадающего. Достаточное, на достаточном числе запросов,
чтобы восстановить ключ по символу. `crypto/subtle` стоит несколько сотен
наносекунд на ту горсть ключей, для которой это средство и предназначено.

Переданная карта снимается как snapshot. Value- и pointer-формы встроенного
`auth.Claims` глубоко копируются вместе с ролями, разрешениями, циклами и
поддерживаемыми изменяемыми контейнерами атрибутов, а каждый lookup получает ещё
одну копию. Поэтому изменение декларации или principal одного запроса не влияет
на другой запрос.

Контракт копирования fallible и не угадывает через reflection. `TryStatic`
возвращает `ErrUnsupportedStaticAttribute` для функций, каналов, unsafe pointer,
небезопасных ключей map и структур со скрытым состоянием. `bytes.Buffer`,
`big.Int` и пользовательская структура со скрытым slice отклоняются: shallow
copy разделяла бы изменяемую память. Декларативный `Static` паникует на той же
ошибке старта. Храните opaque/time-like значения в immutable scalar форме либо
обрабатывайте ошибку `TryStatic`.

`Static` и `TryStatic` принимают только value- или pointer-форму `auth.Claims`.
Произвольный `Principal` даёт методы-запросы, но не состояние, из которого можно
сделать честный snapshot, поэтому `TryStatic` возвращает
`ErrUnsupportedStaticPrincipal`, а `Static` ломает старт. Custom principal
остаётся доступен через низкоуровневый `Store`/`StoreFunc`, где его lifetime и
concurrency явно принадлежат реализации хранилища. Literal- или typed-nil
principal здесь является такой же ошибкой конфигурации, а не молча сохранённым
ключом, который никогда не сможет аутентифицировать.

## Схема

По умолчанию Authorization-shaped credential должен приходить как
`ApiKey <token>`. Для отдельного голого заголовка `apikey.Header` подставляет эту схему
внутри. `AnyScheme()` снимает проверку, и он именно opt-in: точка, принимающая ещё и JWT,
иначе отдавала бы каждый протухший JWT в хранилище ключей как кандидата, а
хранилище, логирующее промахи, логировало бы токены.

`Scheme("PartnerKey")` заменяет схему для scheme-shaped credential. Сравнение
регистронезависимо, как требует RFC 7235. Пустое или whitespace-only имя ломает
старт; отключить проверку может только явно названный `AnyScheme()`.

## Зачем он существует

Отчасти потому, что API-ключи — реальный способ аутентификации сервисов.
Отчасти потому, что `auth.Authenticator` нужна вторая реализация, чтобы быть
контрактом, а не украшением над одной структурой: это счётное правило
[[D-048]], и этот пакет ему удовлетворяет ([[D-055]]).
