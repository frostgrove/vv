# event/eventtest — контракт хранилища как набор проверок, который запускает ваше хранилище

```go
import "github.com/frostgrove/vv/event/eventtest"
```

**Модуль:** в корневом модуле — только стандартная библиотека, `testing` и три
пакета, чьи контракты он заверяет · **Зависит от:** [event](event.md) ·
[projection](projection.md) · [receipt](receipt.md) · **От него зависят:** ничто

Написать хранилище событий — не самое трудное. Трудное — понять, *корректно* ли
оно, потому что каждый способ ошибиться нем: короткая страница обрезает историю,
переиспользованная позиция заставляет потребителя пропустить событие, которого он
не видел, добавление по принципу «последний победил» теряет решение, буфер из
пула переписывает значение, которое приложение уже держит. Ни одно из этого не
порождает ошибки нигде.

`eventtest` — это контракт, записанный как исполняемый набор проверок. Вы
поставляете `Factory` и вызываете `Run`; набор проходит двадцать именованных
секций и сообщает о каждой одним из трёх слов.

---

## Что вы получаете

| | |
|---|---|
| `Run(t, factory)` | весь набор, по одному `t.Run` на секцию |
| `Factory` | `New`, `Begin`, `Sibling`, `Fail`, `Tail`, `Unparsable`, `Window` |
| `Tx` | `Commit(ctx)` · `Rollback(ctx)` — что набор требует от транзакции, которую начинает фабрика |
| `Keys(t, aggregate, ids…)` | инъективность вашего отображения идентичностей, на ваших же идентичностях |
| `Families(t, declarations…)` | одно семейство на агрегат, по вашим объявлениям |
| `RunCheckpoints(t, factory)` | набор из четырнадцати секций для `event.Checkpoints`, по одному `t.Run` на секцию |
| `CheckpointFactory` | `New`, `Begin`, `Sibling`, `Cursor`, `Instant`, `Window` |
| `RunLedger(t, factory)` | набор из семи секций для `receipt.Ledger` |
| `LedgerFactory` | `New`, `Begin`, `Window` |
| `RunGenerations(t, factory)` | набор из пяти секций для `projection.Generations` |
| `GenerationsFactory` | `New`, `Begin`, `Closes`, `Window` |
| `RunPark(t, factory)` | набор из шести секций для `projection.Park` |
| `ParkFactory` | `New`, `Begin`, `Sequences`, `Letters`, `Window` |
| `RoundTrip(t, fact, byRevision…)` | ваша полезная нагрузка переживает свой кодек, по каждой сохранённой ревизии |

```go
func TestMyStoreSatisfiesTheContract(t *testing.T) {
	eventtest.Run(t, eventtest.Factory{
		New: func(t *testing.T) event.Store {
			store := open(t)
			t.Cleanup(func() { _ = store.Close() })
			return store
		},
		Begin: func(t *testing.T, ctx context.Context, s event.Store) (context.Context, eventtest.Tx) {
			tx := begin(t, s)
			return withTransaction(ctx, tx), tx
		},
	})
}
```

## Три слова, а не два

| Слово | Что оно означает |
|---|---|
| `passed` | секция отработала, и хранилище сделало то, что говорит контракт |
| `not certified` | хранилище не заявляет возможность или не дало хука, чтобы её задействовать, — значит, ничего не было показано ни в ту, ни в другую сторону |
| `failed` | хранилище сделало то, что контракт запрещает, и причина это называет |

Секция, которую никто не смог запустить, — это **не** пройденная секция. Ради
этого различия набор и сделан в такой форме: хранилище, тихо пропустившее
половину, выглядело бы так же, как прошедшее всё.

Есть и четвёртое состояние, и оно никогда не печатается как проход: секция, не
сообщившая никакого вердикта. Хук фабрики, вызвавший `t.Fatal`, покидает
подтест через `runtime.Goexit`, поэтому ничто внутри секции не возвращается — а
безопасное умолчание для вердикта, который никто не вычислил, не может быть тем
единственным словом, которое означает, что хранилище корректно.

## Отсутствующий хук — не то же самое, что незаявленная возможность

Хранилище, которое **заявляет** возможность и не даёт под неё хук, роняет прогон
до начала любой секции. Хранилище не должно иметь возможности заявить
возможность и затем уклониться от проверки на неё.

| Хук | Требуется, когда |
|---|---|
| `New` | всегда — конструирует фабрика, и никогда набор |
| `Begin` | хранилище заявляет `Transactions` |
| `Sibling` | хранилище заявляет `SharedBacking` |
| `Fail` | никогда; без него секция отказов хранилища — not certified |
| `Tail` | никогда; без него каждая обходящая секция сама доходит до конца |
| `Unparsable` | никогда; без него пункт о нечитаемом курсоре — not certified |

`Window` — дедлайн, под которым идёт каждая секция. Хранилище, чьи операции за
сетью или которое ждёт конкурирующую транзакцию вместо немедленного отказа,
задаёт здесь своё значение, а не получает failed за ожидание.

## Четырнадцать секций контрольных точек

Хранилище контрольных точек — второй шов, который сертифицирует этот пакет, и
сертифицируется он так же: те же три слова, те же правила против пустых
прогонов, то же «отсутствующий хук — не то же самое, что незаявленная
возможность».

`binding` · `absence` · `round trip` · `fence` · `forget` · `names` · `bounds` ·
`refusal classes` · `lifecycle` · `concurrency` · `transactions` · `durability` ·
`topology` · `topology handoff`

`transactions` и `topology handoff` идут только для хранилища, заявившего
`Transactions`, а `durability` — только для заявившего `Persistence`; хранилище,
заявившее любую из двух и не давшее хук, роняет прогон до начала первой секции.
Поэтому `eventmemory.Checkpoints` сертифицировано на тринадцати и сообщает
`durability: not certified`, а живое `eventpg.Checkpoints` проходит четырнадцать.

| Хук | Обязателен, когда |
|---|---|
| `New` | всегда. Он вызывается несколько раз за секцию, и более позднее значение не должно сбрасывать написанное более ранним: секция перечитывает вторым значением то, что записало первое |
| `Begin` | хранилище заявляет `Transactions` |
| `Sibling` | хранилище заявляет `Persistence` — второе значение поверх того же backing, а это и есть перезапуск |
| `Cursor` | всегда. Курсор **того журнала, против которого пишет это хранилище**, настоящий, а не литерал, придуманный набором, и два подряд вызова обязаны ответить двумя разными курсорами: секция, которая не отличает несвежий ответ от свежего, сертифицирует хранилище, которое ничего не записало |
| `Instant` | никогда; это гранулярность, с которой хранит момент собственная колонка хранилища, а без него набор мерит своей |

Четыре из четырнадцати стоит назвать здесь, потому что это обязательства,
которых стороннее хранилище может не ожидать. **`round trip` требует, чтобы курсор,
который вошёл, вышел байт в байт, через второе значение**: хранилище,
перекодирующее его, отвергается там, а разбор в проекции сравнивает курсоры,
чтобы отличить собственное сохранение от чужого. И **`bounds` требует, чтобы
пустой курсор отвергался и ни одна строка не двигалась**: пустой курсор — это
начало журнала, поэтому строка, несущая его на живой ограде, перезапускает
потребителя с начала поверх живого назначения.

Две пришли вместе с партиционированными проекциями, и на них стоит split.
**`topology` обязательна**: курсор, записанный под одним именем проекции, обязан
читаться обратно **неизменным под другим** — это и есть весь механизм передачи
позиции от родителя детям, — а сохранение на advance 1 поверх живой строки обязано
отвергаться собственной оградой хранилища, а не только оградой трекера: строка
ребёнка, записанная поверх уже пишущей, — это молча присвоенный partition.
**`topology handoff`** зависит от заявленного `Transactions` и требует, чтобы
`Load`, два `Save` на advance 1 и `Forget` внутри одной открытой вызывающим
транзакции были всё или ничего.

Это **три обязательства**, и до появления партиционированных проекций достижимы
были только первые два. **Хранилище, сертифицированное набором фазы 3, может
покраснеть на третьем**, и это расширение набора, а не регрессия хранилища:
`Checkpoints`, которое заявляет `Transactions` и фиксирует свои записи по одной,
проходило всё, о чём спрашивал прежний набор, и оставляет split наполовину
сделанным — строка ребёнка рядом с живым родителем, два писателя над одной долей
журнала, у каждого своя ограда и свой водяной знак. Расширение записано здесь и в
доке пакета, потому что релизная база его не видит: `docs/api/surface.md`
записывает сигнатуру, а `RunCheckpoints` сигнатуру не менял.

```go
func TestMyCheckpointsSatisfyTheContract(t *testing.T) {
	eventtest.RunCheckpoints(t, eventtest.CheckpointFactory{
		New:    func(t *testing.T) event.Checkpoints { return open(t) },
		Cursor: func(t *testing.T) event.Cursor { return mint(t) },
	})
}
```

## Три интерфейса, которые реализует ваше приложение

Хранилище и хранилище контрольных точек нам заверять естественно: мы поставляем
по два каждого. `receipt.Ledger`, `projection.Generations` и `projection.Park` —
вторая половина этого расширения, и **ничто в этом репозитории их не
реализует**: строка, таблица, операторы и уборка принадлежат приложению. Каждый
из трёх несёт обязательство, записанное прозой, не выражаемое ни одной
сигнатурой и не проверяемое в рантайме ничем, — и каждое из этих обязательств,
выполненное неверно, молчит.

| Прогон | Заверяет | Обязательство, которого не проверит ничто другое |
|---|---|---|
| `RunLedger` | `receipt.Ledger` | заявка — это `INSERT … ON CONFLICT DO NOTHING`, а **затем** `SELECT`, именно в этом порядке и в одной единице работы. Наоборот — оба вызывающих отвечают `Recorded` и оба добавляют под одним ключом операции. И проигравшему отвечают строкой, которую держит **таблица**, вместе с её отпечатком: верните отпечаток, с которым заявка пришла, и всякая коллизия читается как повтор — работа пропускается, а `ErrCollision` становится недостижимым |
| `RunGenerations` | `projection.Generations` | `Active` — **блокирующее** чтение. Простое — и переключение фиксируется между этим чтением и фиксацией единицы работы, а ушедшее поколение всё равно ставит эффект |
| `RunPark` | `projection.Park` | какой из четырёх методов нуждается в единице работы вызывающего и что отвечает `Holds` **снаружи** неё — там, где его спрашивает ожидание |

`RunLedger` сообщает `claim` · `repeat` · `claim order` · `unit of work` ·
`completion` · `horizon` · `transaction`. `RunGenerations` сообщает
`ungenerated` · `activation` · `fenced activation` · `unit of work` ·
`locking read`. `RunPark` сообщает `outside a unit` · `inside the unit` ·
`committed state` · `counts` · `identity` · `bounds`. Три слова — те же, что у
набора для хранилища, и правила против пустоты тоже.

```go
func TestMyLedgerSatisfiesTheContract(t *testing.T) {
	eventtest.RunLedger(t, eventtest.LedgerFactory{
		New: func(t *testing.T) receipt.Ledger { return open(t) },
		Begin: func(t *testing.T, ctx context.Context, l receipt.Ledger) (context.Context, eventtest.Tx) {
			tx := begin(t)
			return withTransaction(ctx, tx), tx
		},
	})
}
```

**`Begin` обязателен для всех трёх и вызывается дважды одновременно.** Секция
`claim order` у `Ledger` и секция `locking read` у строки владения измеряют одну
единицу работы, **ждущую** за другой, поэтому фабрика, чьи единицы работы берутся
из пула на одно соединение, заблокируется до истечения окна секции.

**Два объявления, и ни одно нельзя оставить нулевым.**
`GenerationsFactory.Closes` говорит, что закрывает окно между чтением строки
владения и фиксацией единицы работы, — `eventtest.LockingRead` или
`eventtest.SerializableUnit`, — и если не объявлено ни то ни другое, **прогон
падает раньше, чем начнётся хоть одна секция**. Объявленный `SerializableUnit`
даёт по секции `locking read` вердикт *not certified* с причиной: на этом уровне
окно закрывает прерывание, которое приходит от переключения, читающего строки
контрольных точек, записываемые единицей работы, которая ставит эффект, — а
набор проверок, держащий два метода и ни одной контрольной точки, не пишет ни
одной из них. Это отказ заверить, и это не зачёт.

`ParkFactory.Sequences` и `ParkFactory.Letters` — две границы, на которых
очередь отказывает: числа принадлежат реализации, `ErrParkFull` объявляет
фреймворк. Не объявить ни одной — `bounds` сообщается как *not certified*.
Объявить больше 64 — тоже: набор не станет писать тысячу строк в чью-то очередь,
чтобы дойти до границы, поэтому её заверяют над парком, настроенным поменьше.

**Эти наборы пишут строки, которые не убирают.** Каждый ключ, каждое имя
проекции и каждая идентичность несут собственное имя прогона, так что два
прогона по одной таблице никогда не читают строки друг друга; уборка
принадлежит приложению — здесь, как и везде.

## Двадцать секций

`binding` · `stream identity` · `expected version` · `dense versions` ·
`global order` · `conservation` · `stream paging` · `global paging` ·
`resumption` · `bounds` · `payload ownership` · `refusal classes` ·
`cancellation` · `lifecycle` · `concurrency` · `transactions` · `durability` ·
`shared backing` · `monotone visibility` · `store failure classification`

Последние пять зависят от возможности или хука; первые пятнадцать идут против
любого хранилища.

**Секция `transactions` расширилась после пятой фазы, и хранилище,
сертифицированное до этого, может покраснеть на двух пришедших пунктах.** Первый
даёт одной единице работы **два потока** и требует, чтобы добавление в каждый из
них было допущено после того, как эта единица зафиксировалась: хранилище,
хранящее взятые транзакцией потоки в одной переменной, а не во множестве,
фиксирует оба и освобождает один, а второй остаётся под заявкой, которую никто
уже не снимет, — каждому следующему писателю в него отказывают конфликтом,
конкурента для которого больше нет. Второй, идущий только для хранилища с хуком
`Sibling`, проносит единицу работы **через второе значение хранилища над одной
подложкой**: два значения над одной подложкой — одно хранилище, поэтому оба
обязаны назвать для неё один и тот же authority, а запись через любое из них
обязана идти внутри неё. Хранилище, находящее свою транзакцию по значению,
которое её открыло, оставляет каждую запись второго значения на автокоммите —
допущенной, невидимой для отката, в который верит вызывающий, и не сообщённой
ничем. Ни один из двух пунктов не является новым правилом; просто ничто в наборе
их раньше не выполняло.

## Набор фальсифицируется сам против себя

Набор проверок, переставший что-то проверять, выглядит ровно как набор,
который проходит. Поэтому вместе с обоими наборами поставляется инвентарь
намеренно сломанных хранилищ — публикующее страницу короче объявленной, переиспользующее позицию,
допускающее любое добавление на любой версии, возвращающее буферы из пула,
сообщающее об отказе после того, как уже записало, — и тест утверждает, что
**каждый дефект роняет ту секцию, которая для него названа**. Выпотрошите
секцию, и красным станет этот тест, а не набор станет тихим. У прогона
контрольных точек свои пятнадцать, не менее одного на секцию:
среди них игнорирующее ограду, отвечающее курсором, сохранённым перед последним,
чей `Load` игнорирует свой аргумент `projection`, сохраняющее вне транзакции
вызывающего, снимающее строку вне её, создающее строку на advance 1 поверх живой,
привязывающее курсор к имени, под которым он был сохранён, и отвечающее только за
те строки, которые держит записавшее их значение. Второй тест
утверждает обратное направление — то самое, которое важно, когда выпотрошили
секцию, а не сломали хранилище: **каждая секция названа дефектом, который её
роняет**, и ни одна секция не исключена.

У трёх наборов для интерфейсов приложения те же два теста поверх собственных
инвентарей: одиннадцать `Ledger`, шесть строк владения и восемь очередей, в каждой
сломано ровно одно. Среди них: заявка, читающая ключ до того, как его вставить,
и решающая по прочитанному; `Ledger`, сообщающий, что ключ взяла каждая заявка;
`Ledger`, отвечающий проигравшему тем отпечатком, с которым к нему пришли, а не
тем, который держит его таблица; строка владения, которая читает строку и затем
пишет её вместо одного
ограждённого оператора; та, что читает на собственном соединении, пока её запись
едет в единице работы вызывающего; та, что не берёт замка вовсе; очередь,
отвечающая на блокирующую проверку снимком, снятым в первый раз, когда её
спросили; и та, что считает переданные ей письма вместо строк своей таблицы.
Каждый обязан уронить названную для него секцию, а контролем той же секции
служит та же реализация без дефекта. Шесть из них прогоняются ещё раз по живому
PostgreSQL в наборе самого `eventpg`, в дочернем процессе, так что там измеряются
настоящий индекс, настоящий замок строки и настоящий снимок, а не их модель.

## Три прокси

`Run` сертифицирует хранилище. Три прокси сертифицируют **ваше объявление**, и
хранилище им не нужно:

- `Keys` отрисовывает каждую переданную идентичность и сообщает о столкнувшейся
  паре: две идентичности, дающие один ключ, — это два агрегата поверх одной
  истории, сворачивающие факты друг друга, без ошибки в какой-либо точке.
- `Families` сообщает о двух объявлениях, называющих одно семейство, — тот же
  отказ этажом выше.
- `RoundTrip` кодирует по одному образцу на сохранённую ревизию её же кодеком,
  читает обратно и сообщает о кодеке, который теряет часть переданного, о
  кодеке, который не может прочитать собственный вывод, и о кодеке, который
  возвращает память, переиспользуемую им самим. Структура без экспортированных
  полей, без собственного `Equal` и без `==` — `big.Int` и всякий объект-значение,
  на котором ни того ни другого не объявить, — решается повторным кодированием
  вернувшегося и сравнением байтов. Он также сообщает о том, что установить
  **не смог**, вместо того чтобы это пропустить: образец, держащий больше
  65 536 значений, — за пределами того, что обходит сравнение; тип полезной
  нагрузки, чей собственный `Equal` паникнул, не сравнивался вовсе; и полезную
  нагрузку с **функцией** не записывает ни один формат и не сравнивает ничто.
  **Маркерный** факт — `struct{}`, чей тип-читатель держит одно значение —
  проходит по одной только половине точности: второй полезной нагрузки, чтобы
  половине про алиасинг было что потревожить, не существует. Что означает
  зелёный прогон целиком — см. [event](event.md).

Запускайте все три в пакете, где лежит ваше объявление. Они дешёвые, идут под
`make unit`, и каждый ловит класс дефектов, единственный другой симптом которых —
неверный ответ спустя месяцы.
