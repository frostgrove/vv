# i18n

`github.com/frostgrove/vv/i18n` is the optional, full presentation module. It
compiles one bounded `frostgrove-mf2/v1` profile into immutable snapshots, resolves
locales, binds typed deferred messages, formats them without ambient process
state, and adapts them to the stdlib-only `errs.MessageSource` seam.

It is a nested Go module. Importing it adds its MessageFormat and Unicode data
dependencies only to applications that choose it. The root module, transports
and `errs` do not import it ([[D-135]]).

## Install and declare

```sh
go get github.com/frostgrove/vv/i18n@VERSION
```

The application assembles one complete `CatalogSpec`. A module contributes
ordinary `Module` and `MessageSpec` values; importing a package registers
nothing.

```go
pending := i18n.MessageSpec{
    ID:          "pending",
    Revision:    "pending/v1",
    Source:      "You have {$count :number} pending actions",
    Description: "Dashboard pending-action count",
    Arguments: []i18n.ArgumentSpec{
        {Name: "count", Type: i18n.TypeInteger, Required: true},
    },
    Output:   i18n.OutputPlain,
    Override: i18n.OverrideApplication,
    Public:   true,
}

snapshot, err := i18n.New(i18n.CatalogSpec{
    Revision:            "2026-09-09",
    SourceLocale:        "en",
    DefaultLocale:       "en",
    TimeZoneDataVersion: "tzdb/2026a:embedded",
    Supported:           []string{"en", "ru", "kk"},
    Required:            []string{"en"},
    Modules: []i18n.Module{
        {Name: "tasks", Messages: []i18n.MessageSpec{pending}},
    },
})
```

`New` validates the whole declaration before returning a `Snapshot`: qualified
identities, revisions, BCP 47 locales, fallback graph, argument schemas,
reviewed translations, required locales, override permissions, the MF2 subset,
formatting support, rich-markup allowlists and every configured bound. It
returns an aggregated deterministic error and no partial snapshot.

The profile identity is public and part of snapshot identity:

```go
i18n.GrammarProfile    // frostgrove-mf2/v1
i18n.MessageFormatSpec // Unicode MessageFormat 48.2 baseline
i18n.EngineVersion     // messageformat-go/v0.8.6
i18n.LocaleDataVersion // pinned plural and formatting data
i18n.TimeZoneDataModel // runtime-selected Go location model
```

The always-enabled functions are `number`, `integer`, `currency`, `percent`,
`offset` and `string`. The stable numeric surface accepts the Unicode spellings
`select=plural`, `useGrouping=never`, integer `maximumSignificantDigits`,
currency `fractionDigits`, exact 0–99 `offset add/subtract`, and inherited
numeric options without converting integer or decimal values through binary
floating point. String selection compares NFC while preserving the original
formatted bytes. `date`, `time` and `datetime` require
`CapabilityDateTime`; `unit` requires `CapabilityUnit`. Function operands must
be declared typed arguments. Options must be literals from the function's
allowlist, and unsupported names, values, selector keys, attributes or markup
options are construction errors. There is no grammar auto-detection or silent
fallback to another formatter.

`frostgrove-mf2/v1` deliberately names the bounded Frostgrove profile instead
of claiming full editor-head conformance. It is based on the published Unicode
MessageFormat baseline named by `MessageFormatSpec`, rejects literal operands
in favor of declared typed contracts, rejects rather than ignores unknown
options, retains the legacy `select=cardinal` and `:string select=exact`
spellings, and versions draft date/time/unit vocabulary behind capabilities.
The profile supports literal `u:id` and `u:dir=ltr|rtl|auto|inherit` on function
expressions and literal `u:id` on rich markup. Variable-valued universal options
remain outside this version because the pinned engine cannot resolve them from
Frostgrove's exact typed values without losing their semantics.

## Source and review identity

`CatalogSpec` is the in-memory declaration. `EncodeSource` writes its canonical
JSON form, identified by `frostgrove.i18n.source/v1`; `DecodeSource` reads it
strictly. Unknown or duplicate members, invalid UTF-8, trailing JSON, excessive
depth/cardinality/bytes and semantic inconsistencies are refusals.

Every non-source translation and override carries two separate identities:

- `ContractRevision` and the contract digest pin the key, argument schema,
  output kind and markup contract.
- `SourceDigest` covers the profile, canonical source locale, resolved key,
  contract, source wording and translator description.
- `ReviewDigest` covers that source digest, canonical locale and translated
  text.

Use `ExpectedSourceDigestForLocale` and `ExpectedReviewDigest` when building
authoring tools. In normal repository work, let the `review` command stamp
identities. Changing the source locale, wording or description makes review
stale even when the typed contract did not change.

When declarations are regenerated, merge the new authoritative source with the
previous reviewed document before review:

```sh
vv-i18n merge -source messages.generated.json -previous messages.i18n.json \
  -out messages.i18n.json
```

`MergeSource` and the `merge` command carry forward structurally eligible
translations and application overrides that are absent from the new source and
still have a valid key, locale and override permission. Stale,
review-required and rejected authoring identities are preserved verbatim for
`check`; merge never promotes them. The new document wins every explicit
conflict. A source-locale change or any obsolete authoring work is refused with
`ErrMergeWouldDiscard`; `-prune-obsolete` is the explicit acknowledgement that
removes obsolete entries. Review, source and contract identities are preserved
byte-for-byte, inputs are never mutated, and the result is canonical and
idempotent. `SourceMerger{CatalogLimits: ...}` is the explicit local ceiling
for catalogs that deliberately exceed the conservative default limits; the
convenience functions retain those defaults. `SourceMerger.SourceLimits`
independently bounds canonical source output. Merge accounts candidate
translations and overrides against both ceilings before append and retains only
the obsolete count plus its lexicographically first diagnostic.

`ReviewApproved` is the only state accepted into a runtime snapshot.
`ReviewRequired` and `ReviewRejected` remain valid authoring states so `check`
can report the real work instead of making the source document unreadable.
An application override may complete a required locale; an optional-locale gap
is a warning unless strict checking is requested.

## Check, pseudo and compile

Install or run the command from the nested module:

```sh
go install github.com/frostgrove/vv/i18n/cmd/vv-i18n@VERSION

vv-i18n check -source messages.i18n.json -out report.json
vv-i18n review -source messages.i18n.json -out messages.i18n.json \
  -locale ru -scope translations -state approved
vv-i18n pseudo -source messages.i18n.json -out messages.pseudo.json \
  -locale en-XA -mode accent
vv-i18n compile -source messages.i18n.json -out messages.i18n.bin
```

### One limits policy for authoring commands

Every command accepts the same optional `-limits PATH` policy: `check`,
`compile`, `pseudo`, `generate-go`, `export-ts`, `extract`, `review` and
`merge`. The file is a standalone strict JSON document. Omitted sections and
fields retain the conservative library defaults; an explicit value must be a
positive integer within the library's supported bounds.

```json
{
  "schema": "frostgrove.i18n.limits/v1",
  "catalog": {
    "locale": {
      "max_supported": 256,
      "max_fallback_depth": 24
    },
    "max_messages": 12000,
    "max_translations": 96000,
    "max_catalog_bytes": 134217728
  },
  "source": {
    "max_bytes": 268435456,
    "max_depth": 96,
    "max_members": 8388608
  },
  "compiled": {
    "max_bytes": 268435456,
    "max_depth": 96,
    "max_members": 8388608
  },
  "output": {
    "max_bytes": 268435456
  }
}
```

`catalog` is the operator-owned local ceiling for every declared catalogue
limit. A source document cannot widen it. Its snake-case fields are `locale`
(`max_choices`, `max_header_bytes`, `max_ranges`, `max_supported`,
`max_tag_bytes`, `max_fallback_depth`) and `max_modules`, `max_messages`,
`max_translations`, `max_locales`, `max_arguments`, `max_enum_values`,
`max_markup_names`, `max_catalog_items`, `max_identifier_bytes`,
`max_revision_bytes`, `max_description_bytes`, `max_enum_value_bytes`,
`max_argument_bytes`, `max_big_integer_bits`, `max_template_bytes`,
`max_catalog_bytes`, `max_declarations`, `max_selectors`, `max_variants`,
`max_local_depth`, `max_template_parts`, `max_markup_depth`,
`max_output_bytes`, `max_output_parts` and `max_explain_steps`.

`source` bounds streaming source decode and every canonical source output from
`pseudo`, `review` and `merge`. `compiled` bounds only the compiled artifact.
`output` bounds each derived file from `check`, `generate-go`, `export-ts` and
`extract`, including each file in a generational publication; it does not
silently narrow source or compiled artifacts. The three artifact/output byte
defaults are 128 MiB and their absolute supported maximum is 1 GiB. The
extraction Go-source and check usage-manifest hostile-input limits remain fixed
by their respective document contracts rather than being catalogue limits.

Library callers control the usage side with `CheckPolicy.UsageLimits`. A zero
field selects `DefaultUsageLimits`; a nonzero field narrows the local ceiling
and cannot exceed the hard default. Those maxima are 262144 keys, dynamic
ranges and occurrences; 1024 roots; 100000 files and metadata records; 256
build/tool/release tags and environment settings per ledger; 4 MiB per string;
and 64 MiB aggregate semantic material. The v4 decoder and `Check` share this
contract, independently of `CatalogSpec.Limits`.

The command passes each matching ceiling and its `context.Context` into the
producer before any output is built. An impossible small output therefore fails
before proportional cloning, Go formatting or manifest/address hashing, and
meaningful build, encode and digest loops observe cancellation. The library
exposes the same path through `NewContext`, `CompileContext`,
`Compiler.CompileContext`, `EncodeContext`, `Compiler.EncodeContext`,
`EncodeSourceContext`, `SourceCodec.EncodeContext`,
`SourceCodec.EncodedSizeContext`, `PseudoContext`, `GenerateGoContext`,
`ExportPublicContext`, `MergeSourceContext`, `SourceMerger.MergeContext` and
`ExpectedPublicExportAddressContext`. Usage evidence digesting provides the
same lifecycle through `ExpectedUsageSourceDigestContext` and
`ExpectedUsageManifestDigestContext`. Existing convenience APIs use
`context.Background()` and finite default or snapshot ceilings.

`GoGeneratorSpec.MaxOutputBytes`, `PseudoSpec.MaxOutputBytes` and
`PublicExportSpec.MaxOutputBytes` are per-file producer ceilings. Zero selects
the snapshot/catalogue ceiling; a larger requested value cannot widen it.
`SourceCodec.EncodedSize` and `SourceCodec.EncodedSizeContext` return the exact
canonical source wire size under the codec's catalogue and artifact ceilings.
Go, source, compiled artifact, pseudolocale, review, public manifest and
TypeScript paths run exact count-only passes before formatter, digest, clone or
materialization work that depends on the produced bytes; an exact ceiling is
accepted and one byte less is refused.

The limits document itself is at most 64 KiB and must be a regular, non-symlink
file. Duplicate names, unknown names, trailing values, the wrong schema and
invalid values are refusals; ordinary JSON whitespace and member ordering are
accepted. Source paths use the same regular, non-symlink policy and are streamed
directly into `SourceCodec`. A missing or invalid policy never falls back to
defaults.

`check` reports deterministic `missing`, `stale`, `review_required`,
`rejected`, `unused` and `invalid` findings plus per-locale coverage. `-strict`
turns optional-locale debt into errors. `-max-findings` bounds the retained
detail without losing exact error, warning or structural-error counts;
`FirstStructuralError` remains available even when details are truncated.
`review` therefore ignores truncated translation debt but refuses every
structural invalidity. `-usage` accepts the manifest produced by `extract`;
unused findings are meaningful only when that manifest declares its roots
complete.

`pseudo` produces another canonical source document. `-mode accent` expands and
accents human text; `-mode rtl` exercises right-to-left presentation. It does
not translate literals, argument names or MF2 structure. By default the locale
is added to the supported set; `-add-supported=false` leaves policy unchanged.

`compile` validates the source and writes canonical
`frostgrove.i18n.catalog/v1` bytes. `Compile` and `Encode` provide the same
library path; their context variants are preferred in request, job and command
lifecycles. Runtime loading is strict and offline:

```go
snapshot, err := i18n.Load(ctx, bytes.NewReader(compiled))
snapshot, err = i18n.LoadFS(ctx, embedded, "messages.i18n.bin")
```

`Loader` and `Compiler` let the application set local `ArtifactLimits` and
`CatalogLimits`. An artifact's declared limits may not widen those local
ceilings. `Load` checks the exact artifact/profile/engine/locale-data/time-zone
identities, semantic digest and canonical byte representation. It performs no
network lookup and `LoadFS` closes the opened file on every path.

Every direct CLI output file is staged, synced and atomically renamed. A legacy
multi-file export has per-file atomic replacement and best-effort rollback on a
reported process error; it is not a crash-safe reader snapshot. `-check` means
drift checking and writes nothing. It requires a file output, not stdout.

## Extract, generate and export

```sh
vv-i18n extract -root ./internal -root ./cmd -out usage.i18n.json
vv-i18n extract -root ./internal -tags enterprise,postgres -out usage.i18n.json
vv-i18n extract -root . -tags= -out usage.i18n.json
vv-i18n extract -complete -root ./my-module -out usage.complete.i18n.json
vv-i18n check -source messages.i18n.json -usage usage.i18n.json -out report.json
vv-i18n generate-go -source messages.i18n.json -out messages_gen.go -package messages
vv-i18n export-ts -source messages.i18n.json \
  -out messages.d.ts -manifest messages.public.json -address-out messages.address
vv-i18n export-ts -source messages.i18n.json -publication-root public.i18n
```

`extract` asks the context-bound Go tool for the real effective package graph
with compiled-file and export-data facts, then type-checks the selected local
packages as one source graph. It does not run application initialization. It
recognizes static and bounded-domain use through `Snapshot.Bind`, all four
`Define`/`NewDefinition` constructors, generated definitions, error mappings,
typed method values, callbacks, interfaces and selected-graph wrappers. An
unbounded key or an escaped/reassigned constructor callable is a hard
extraction error; an escaped already-created definition or contract preserves
useful partial evidence but forces `complete:false`.

Completeness also fails closed when `Snapshot.Bind`, its method expression or
value, a binder-bearing interface, `*Snapshot` or another i18n capability is
returned, stored in a field/map/heap, sent through reflection or `unsafe`, or
passed to an unknown/external call. Passing the exact capability type to a typed
call or callback remains complete when its callee body belongs to the exact
selected source graph, including a selected sibling package. Generated files are not a trust
boundary: a definition factory result field is trusted only when every reaching
assignment and return proves that field; parameters, mixed paths and escapes do
not.

Directory roots must be Go module roots for a complete proof. Selection follows
the effective GOOS, GOARCH, compiler, CGO setting, quoted persisted
`GOENV`/`GOFLAGS`, explicit `-tags`, active `go.work`, nested-module boundaries,
replacements, vendoring and overlays. Explicit `-tags=` overrides inherited
tags. The tool uses a private disposable build cache, the installed local
toolchain, disabled module proxy and checksum database, and read-only shadow
module/workspace metadata so extraction neither downloads dependencies nor
updates the checkout. Cgo packages, package/dependency/load errors, missing or
conflicting export facts, an unmodeled multi-root environment, partial file
roots, and any reachable non-standard dependency that can hide an i18n call all
force incomplete evidence. Dependencies proven unable to reach i18n may still
supply exact export types. Files excluded by the effective production build,
including tests and other platform/tag variants, remain hashed in the ledger;
their presence alone does not make that one effective-build proof incomplete.
A module root with no Go source candidates still emits canonical v4 evidence
with empty file, aggregate and occurrence ledgers and `complete:false`;
`-complete` requests a proof and is downgraded instead of making that honest
empty result unreadable.

Usage v4 records sorted unique exact/dynamic aggregates and one-based source
occurrences, plus canonical root/file ledgers, selected state and SHA-256 for
every candidate, effective Go settings, module/workspace/vendor/overlay/toolchain
metadata and a resolved package-graph digest. `source_digest` is recomputable
from the scope ledger; `manifest_digest` additionally binds completeness,
aggregates and occurrences. Counts, containment, coordinates, reverse evidence,
sorting, uniqueness and both digests are checked by the v4 decoder and by
`i18n.Check`. Bounded streaming preflight happens before large JSON slices are
allocated. Build, tool and release tag ledgers are canonical only when sorted
and unique. v1, v2 and v3 preserve their positive aggregates and occurrences,
discard legacy scope, and remain readable only as incomplete evidence; they do
not trigger v4 provenance errors or authorize unused findings.

Those hashes establish ledger self-consistency, not authenticity or physical
freshness: anyone able to rewrite the manifest can recompute them. A release
that relies on non-use must run the same `extract -complete ... -check` command
against the manifest from a trusted checkout and controlled Go environment.
That path re-lists the graph and rehashes the physical roots without writing;
plain `check -usage` intentionally does not access source files.

`generate-go` emits a typed `Catalog`, one arguments struct per message,
enum types and encoders. Its `NewCatalog(snapshot)` calls `Define` with literal
`ContractRef` values, so a binary generated for an old contract rejects a new
snapshot during assembly, before first traffic. Optional generated fields use
`Optional[T]`: the zero value is absent, `Some(v)` is present and
`NullValue[T]()` is explicit null.

`export-ts` emits types and a canonical manifest only for messages declared
`Public`. Its content address covers both outputs. Integer, unsigned, big
integer, decimal, currency and instant values use explicit branded wire
scalars. `FormattingParity` is deliberately `false`: this export does not ship
a JavaScript formatter and does not claim that a browser can reproduce the Go
runtime's MF2/CLDR output. Private messages never appear in it.

`-publication-root` is the process-crash- and concurrent-reader-safe alternative
to the direct output flags and is mutually exclusive with them. It writes immutable
`generations/sha256-<digest>/messages.d.ts` and `messages.public.json`, then
commits one bounded `current.json` pointer. A reader reads that pointer once,
opens only the named generation, and verifies the declared byte counts and
SHA-256 digests. Old generations are retained, so a concurrent switch cannot
invalidate a pinned read. Generation files, newly created root/directory entries
and the publication root are synced in dependency order on non-Windows systems.
Every platform syncs temporary file bodies before rename. Go's read-only Windows
directory handles return `ACCESS_DENIED` from `File.Sync`, so Windows selects an
explicit compile-time directory-sync no-op rather than ignoring an arbitrary
runtime error. Atomic visibility and concurrent-reader integrity still hold;
power-loss durability of directory-entry updates remains an OS/filesystem
boundary. `-check` strictly verifies the pointer and its complete generation
without creating or changing files. Publication assumes a trusted writable
local filesystem with atomic same-directory rename; its non-Windows power-loss
guarantee additionally assumes working file and directory `fsync`. Retention
cleanup belongs to the delivery pipeline and must not race pinned readers.

All mutating single-file, staged-set and generational writers in one output
directory use the same persistent `.vv-i18n.lock`. It is a descriptor-validated
regular non-link file: creation uses exclusive create, opening an existing file
requires inspect/open/stat identity agreement, and identity is checked again
after acquisition. The command retries a nonblocking Unix `flock` or Windows
`LockFileEx` while observing the caller context, then retains the descriptor and
OS lock through commit, rollback and the final directory sync. A process crash
releases lock ownership; the file intentionally remains. A target platform
without an implementation fails before filesystem mutation. Check mode remains
strictly read-only and does not create or acquire this lock.

This lock serializes cooperating `vv-i18n` publishers when the filesystem
honors the OS advisory-lock contract. An arbitrary external writer can ignore
it. Existing identity checkpoints reject mutations they observe, but no
linearizability is promised against an external mutation in the interval after
a checkpoint and before its operation.

The publisher and both readers walk from the filesystem or volume root and open
each hierarchy component through stable descriptors, comparing the opened
identity with the inspected entry. A linked component or an identity change
between inspection and opening is refused. Once a component is pinned, a later
ancestor replacement cannot redirect reads or writes. A missing final
publication root is created only through its pinned parent descriptor, which is
then synced where directory sync is available. The writer pins the verified
`generations` handle for temporary generation creation, writes, rename, cleanup
and sync, then verifies that the root entry still names that same directory
before committing `current.json`. The pointer target is also a compare-and-swap:
an initially absent file must remain absent, and an existing regular file must
retain its exact identity. Readers also bound directory enumeration; the library
reader checks cancellation between bounded file chunks.

`current.json` uses `frostgrove.i18n.publication/v1`. It contains lowercase
`sha256:` generation and public-export addresses plus an ordered `files` table:
`manifest/messages.public.json` first, then `typescript/messages.d.ts`; every
entry declares its byte count and lowercase SHA-256. Names and roles are fixed,
not caller-controlled paths. The portable directory name replaces the address
colon with `sha256-`. The generation digest binds the public address and every
role, name and file body with domain-separated unsigned 64-bit big-endian length
framing. A malformed, non-canonical, linked, missing, extra or digest-mismatched
entry is a refusal.

An independent Go reader can verify the protocol content identity with
`ExpectedPublicExportAddress(manifest, typeScript)` after it has bounded and
hashed the two fixed files. The publisher and Frostgrove reader use that same
derivation; a pointer whose generation framing is internally consistent but
whose address was chosen for different content is still rejected.

```json
{
  "schema": "frostgrove.i18n.publication/v1",
  "generation": "sha256:<64 lowercase hex digits>",
  "address": "sha256:<64 lowercase hex digits>",
  "files": [
    {"role": "manifest", "name": "messages.public.json", "bytes": 123, "sha256": "sha256:<64 lowercase hex digits>"},
    {"role": "typescript", "name": "messages.d.ts", "bytes": 456, "sha256": "sha256:<64 lowercase hex digits>"}
  ]
}
```

## Resolve and create a view

Locale resolution is separate from message fallback. Build ordered choices at
the application boundary:

```go
resolution := snapshot.Resolve(
    i18n.Exact(i18n.SourceExplicit, routeLocale),
    i18n.Exact(i18n.SourceUser, userLocale),
    i18n.AcceptLanguage(i18n.SourceProtocol, r.Header.Values("Accept-Language")...),
    i18n.Exact(i18n.SourceTenant, tenantDefault),
    i18n.Exact(i18n.SourceApplication, "en"),
)
if !resolution.Matched() {
    return errNoAcceptableLocale
}

view, err := snapshot.View(i18n.ViewSpec{
    Resolution:       resolution,
    FormattingLocale: "kk",
    TimeZone:         "Asia/Almaty",
    Presentation:     i18n.PresentationDefault,
})
```

`AcceptLanguage` supports repeated fields, weights, `q=0` exclusions and
wildcards under byte/range limits. `MatchLookup` only finds an exact supported
tag or progressively truncates a more specific request; it never expands a
generic request such as `zh` to whichever `zh-Hans` or `zh-Hant` happens to be
listed first. `MatchBestFit` opts into the pinned matcher when that inference is
wanted. `DefaultOnMiss` is explicit policy, not an environment fallback. The
result records its canonical supported locale, source, outcome and reason. A
`Resolution` is sealed by its resolver: it cannot be forged or reused with a
different snapshot's resolver.

For one exact locale, `snapshot.For("ru")` is the shorthand. `ForContext`
accepts the same ordered choices and returns a default view.

The view pins four output-affecting inputs: resolved message locale, formatting
locale, time zone and presentation. Message grammar uses the actual template
locale; number/date formatting uses `FormattingLocale`. The default formatting
locale is the resolved locale. An empty view zone uses the catalogue's
`DefaultTimeZone`, whose zero default is UTC. A non-UTC zone is accepted only
when the catalogue declares `TimeZoneDataVersion`; the application is
responsible for matching it to the IANA data installed in its build/runtime.
Go resolves named zones from `ZONEINFO`, the host, GOROOT or its embedded
fallback, so `TimeZoneDataModel` intentionally does not claim a pinned IANA
release. Applications that require byte-identical historical zoned output must
control that runtime data and declare its verified identity themselves.

## Bind and render

The dynamic checked path is:

```go
message, err := snapshot.Bind(
    i18n.Qualify("tasks", "pending"),
    i18n.Integer("count", 21),
)
rendered, err := view.Render(ctx, message)
```

Arguments are closed typed values: `Text`, `Bool`, `Integer`,
`UnsignedInteger`, `BigInteger`, `Decimal`, `Money`, `Date`, `Instant`, `Enum`
and `Null`. Missing, extra, duplicated, wrongly typed and forbidden-null
arguments are rejected. Caller-owned strings, `big.Int` values and slices are
copied before the deferred `Message` escapes.

`Integer`, `UnsignedInteger` and `BigInteger` never pass through `float64`.
`Decimal` is a bounded lexical decimal: visible fraction digits remain part of
plural selection, so `1` and `1.0` need not select the same category. Exact
selector keys remain exact. `Money` preserves its currency and performs no
conversion. `Date` is a calendar date and never shifts through a zone;
`Instant` is an instant formatted in the view's explicit zone.

For generated code, bind the typed definition instead:

```go
catalog, err := messages.NewCatalog(snapshot)
pending, err := catalog.TasksPending.Bind(messages.TasksPendingArgs{Count: 21})
rendered, err := view.Render(ctx, pending)
```

Generated definitions are the recommended production path when the catalogue is
part of the build: they have no reflection while binding and make contract drift
visible during assembly. A small hand-written integration can keep the same
typed `Definition[A]` shape without a generator:

```go
type PendingArgs struct {
    Count int64
    Note  i18n.Optional[string]
}

pending, err := i18n.NewStructDefinition[PendingArgs](
    snapshot,
    i18n.Qualify("tasks", "pending"),
)
message, err := pending.Bind(PendingArgs{Count: 21, Note: i18n.Some("today")})
```

`DefineStruct[A](snapshot, contract)` is the equivalent when the caller already
has a pinned `ContractRef`. Construction reflects once, validates the complete
mapping and compiles an encoder; `Bind` itself only reads the compiled direct
field plan. Exported direct fields map by ASCII case with `_`, `-` and spaces
ignored, while an exact `i18n:"argument_name"` tag wins and `i18n:"-"` ignores a
field. Embedded and unexported fields never bind implicitly. Required,
non-nullable arguments use direct fields; optional or nullable arguments must use
the exact `Optional[T]` container, not a struct that embeds it. Definition keys
and keys passed to `Snapshot.Bind`, `Descriptor`, `ContractRef` and `SourceDigest`
are validated against `Limits.MaxIdentifierBytes` before lookup. The complete raw
struct-tag string is bounded by `Limits.MaxDescriptionBytes` before tag parsing.
The complete Go tag syntax is then decoded with Go string-literal semantics;
malformed syntax or a repeated `i18n` key is rejected before automatic field
matching. `Descriptor.ContractRef` also returns a zero reference for a manually
constructed descriptor whose key is malformed or exceeds the package hard
identifier ceiling.
Supported field shapes are string kinds for text/decimal/enum,
bool kinds, `int64`/`uint64` kinds, and exact `*big.Int`, `MoneyValue`,
`DateValue` and `time.Time`. Native-width integers, floats and structurally
similar named composites are rejected during construction. `Some` is present,
the zero optional is absent, and `NullValue` is explicit null; `Some` containing
a typed nil pointer is also an explicit null after ordinary argument validation.

`Rendered` returns plain `Text`, safe structural `Parts`, actual
`TemplateLocale`, resolved locale/provenance, winning `Layer`, snapshot revision
and digest, terminal outcome and `RenderKey`. `RenderKey` is a deterministic
SHA-256 identity over every output-affecting input, including copied arguments;
use it as a cache identity, not as authorization or a substitute for the values
needed to render. `View.Explain(message)` returns a bounded preference and
template-fallback trace without rendered text or arguments.

`OutputPlain` is unescaped text; its eventual HTML, JSON, URL or shell sink must
escape it. `OutputRich` yields only text/value/markup/bidi boundary parts.
Markup names must be declared and translations cannot add attributes or options;
parts are never trusted HTML. Every part keeps the stable Frostgrove `Kind` and
the original MF2 `Type`; an authored `u:id` becomes opaque correlation metadata,
not a DOM ID or trust primitive. Number and date values expose copied, flat
`Subparts` such as `integer`, `group`, `fraction`, `year` and `literal`, while
their concatenation always equals the parent text. Nested nodes count against
`MaxOutputParts` and their bytes are not double-counted. Automatic FSI/PDI
isolation is the default.
`PresentationNoIsolation` is an explicit opt-out. Untrusted arguments containing
directional controls are rejected; authored text permits direction marks and
balanced isolates but rejects embeddings, overrides and unbalanced isolates.

A view also formats standalone values with `FormatNumber`, `FormatMoney`,
`FormatPercent`, `FormatUnit`, `FormatDate`, `FormatInstantDate`, `FormatTime`,
`FormatDateTime`, `FormatList`, `FormatRelative`, `FormatDuration` and
`FormatDisplayName`. Numeric inputs are closed exact values (`SignedNumber`,
`UnsignedNumber`, `DecimalNumber` or immutable `BigIntegerNumber`), never an
implicit float. Typed specs expose grouping, sign, notation, digit ranges,
currency/unit presentation and date/time styles. `NumberFormatSpec` also exposes
the ECMA-402 rounding modes and precision priority, `stripIfInteger`, and the
closed set of decimal rounding increments. An increment greater than one is
accepted only with equal minimum/maximum fraction digits and without significant
digits, so invalid formatter combinations fail before rendering. `Digits(min,
max)` sets both bounds; `MinimumDigits(min)` and `MaximumDigits(max)` preserve the
Intl default for the omitted side, including currency-dependent defaults. Zero
date/time styles mean `medium`. `FormatDate(DateValue, ...)` is a calendar date
and never shifts with the view zone; instant methods interpret `time.Time` in the
pinned view zone. Relative-time accepts whole `int64` units only from
`-(2^53-1)` through `2^53-1`. After that exactness guard the pinned Intl backend
converts the integer to `float64`, which represents every accepted integer
exactly. Fractional values and integers outside that range are rejected.
All operations use the same formatting locale, presentation policy,
cancellation, observer, conservative output preflight and safe parts model.

The same boundary is available without a catalogue through
`NewFormatter(FormatterSpec{...})`. Repeated policies can be compiled once as a
bounded immutable `Formats` registry and called through `FormatNamedNumber`,
`FormatNamedMoney`, `SelectNamedPlural`, `FormatNamedDateTime`,
`FormatNamedList` and the corresponding typed methods. `View.Formatter(formats)`
inherits the view's exact locale, zone, capabilities, presentation, limits and
observer. Duplicate, invalid, oversized or capability-incompatible named formats
fail at construction; entry count and aggregate retained material are checked
before registry allocation or backend validation. Retained names and string
options are cloned. An unknown lookup returns `ErrFormatNotFound`; failed and
canceled named calls produce the same single terminal observation as successful
named calls.

Number, money, percent, unit, calendar-date, instant-date, time and datetime
ranges are first-class. A `FormattedRange` retains joined `Text`, locale and
safe `RangePart` values marked `RangeSourceStart`, `RangeSourceShared` or
`RangeSourceEnd`. `SelectPluralRange` uses locale plural-range rules rather than
guessing from either endpoint. Range values remain exact and use the same
preflight, cancellation, bidi and observer policy as scalar formatting.

```go
amount, err := view.FormatMoney(ctx,
    i18n.MoneyValue{Amount: "1234.50", Currency: "KZT"},
    i18n.MoneyFormatSpec{Number: i18n.NumberFormatSpec{
        FractionDigits:      i18n.Digits(2, 2),
        RoundingMode:        i18n.NumberRoundingModeHalfEven,
        RoundingIncrement:   i18n.NumberRoundingIncrement5,
        TrailingZeroDisplay: i18n.NumberTrailingZeroAuto,
    }},
)
```

## Error messages and transports

`Snapshot.ErrorMessages` validates an immutable adapter to the root error seam:

```go
source, err := snapshot.ErrorMessages(i18n.ErrorSpec{
    Mappings: []i18n.ErrorMapping{
        {
            Ladder:        "email.unique",
            Key:           i18n.Qualify("errors", "email_taken"),
            FieldArgument: "field",
        },
    },
    FieldLabels: []i18n.FieldLabel{
        {Field: "email", Key: i18n.Qualify("fields", "email")},
    },
})

renderer := porthttp.NewRenderer(porthttp.WithMessages(source))
```

For a request boundary that already owns one resolved view, compile mappings
once and bind that plan to each immutable view:

```go
plan, err := snapshot.ErrorPlan(i18n.ErrorPlanSpec{
    Mappings: []i18n.ErrorMapping{
        {Ladder: "email.unique", Key: i18n.Qualify("errors", "email_taken")},
    },
})

view, err := snapshot.View(viewSpec)
source, err := view.ErrorMessages(plan)
```

The bound source uses the view's exact snapshot, resolution, formatting locale,
time zone and presentation for every violation. It neither negotiates locale
again nor rebuilds mapping metadata. Its legacy `Message` locale argument is
therefore non-authoritative and ignored; `MessageWithLocale` still reports the
locale of the template that actually rendered. Plans reject views from another
snapshot and are safe to reuse concurrently across views from their own
snapshot.

Mappings are allowlists from the existing `errs` fallback-ladder key to a
qualified message contract. Only declared violation params are converted; money
requires a declared currency. Field labels are argument-free plain messages.
Localization changes human wording only. `Kind`, code, public path, partial
marker, HTTP/gRPC status and internal-error redaction remain owned by `errs`,
`port` and the transport.

The returned `i18n.LocalizedMessageSource` extends `errs.MessageSource` without
requiring a matching root-module release. It structurally implements the root
`errs.LocalizedMessageSource`, so HTTP can emit the actual template locale as
`Content-Language` and CRUD gRPC can put it in
`LocalizedMessage.Locale`. The requested locale is never presented as proof of
the template locale. If mapping, binding or formatting fails, the adapter
declines and the existing renderer continues to the safe violation/code
wording.

HTTP and gRPC still own protocol extraction. Their small built-in helpers take
only the first language tag. For full weighted negotiation, resolve with this
module before the error boundary and put the supported result into the existing
`port.WithLocale`/transport context. The bindings preserve a non-empty prebound
locale.

## Overlays and publication

`snapshot.Overlay(ApplicationOverlay(...))` and
`snapshot.Overlay(TenantOverlay(...))` replace whole approved translations and
return another immutable snapshot. Layers may only increase: module →
application → tenant. A tenant snapshot cannot parent another tenant overlay.
The base descriptor decides whether each layer is allowed; an override cannot
change the key, schema, output, visibility or review/source identity. A
snapshot contains no tenant identity. Authentication, tenant selection and
authorization happen in application code before choosing it.

`Controller` is a bounded in-process publication mechanism:

```go
controller, err := i18n.NewController(i18n.ControllerSpec{Initial: snapshot})
head := controller.Current()
head, err = controller.Activate(head, candidate)
lease, err := controller.PinCurrent(24 * time.Hour)
defer lease.Release()
```

`Activate` and `Rollback` compare an opaque `Head`, not just a public revision
string, so a stale publisher cannot win after an A → B → A sequence. A failed
swap leaves the current snapshot untouched. Retention count, pin count, pin
lifetime and retained bytes are bounded; `Prune` is explicit. A `Lease` carries
no principal or tenant authority and expires under the controller clock.

The controller has no watcher, timer, goroutine, filesystem policy or durable
pin store. The application owns storage, polling, rollout, readiness, shutdown,
durable job intent and recipient authorization. In-memory pins do not by
themselves promise that a queued job can be reproduced after process restart.

## Limits and observations

A zero `CatalogSpec.Limits` uses finite defaults. The most operationally
important ones are:

| Bound | Default |
|---|---:|
| locale choices / header bytes / ranges / fallback depth | 16 / 8192 / 32 / 16 |
| modules / messages / translations / locales | 64 / 4096 / 32768 / 128 |
| arguments / enum values / markup names | 64 / 256 / 64 |
| argument bytes / template bytes / catalog bytes | 64 KiB / 64 KiB / 64 MiB |
| declarations / selectors / variants / local depth | 256 / 8 / 1024 / 32 |
| template parts / markup depth | 2048 / 32 |
| output bytes / output parts / explain steps | 1 MiB / 4096 / 64 |
| compiled artifact bytes / JSON depth / members | 128 MiB / 64 / 4,194,304 |

`DefaultLimits` and `DefaultArtifactLimits` return the complete values. Setting
a field changes the accepted bound; it does not mean unlimited. Catalog/source
material, resolver input, typed arguments, conservative formatter work,
produced text/parts, explanations, generators and controller retention all have
preflight limits. Derived source, compiled, Go, TypeScript, manifest, report and
usage outputs enforce their operator ceiling inside the producer rather than
after allocation. Application callbacks and external stores still own their own
work. `New` and `Overlay` use the same exact snapshot-material accounting that
`Encode` records and `Load` enforces, so an accepted snapshot at its byte/item
ceiling round-trips without boundary drift.

Every aggregated `*Problems` matches `ErrInvalidCatalog` through `errors.Is`.
If any item has code `ProblemLimit`, the same error additionally matches
`ErrLimitExceeded`; callers can preserve the invalid-catalog category while
handling capacity failures separately.

An optional `Observer` receives one synchronous, panic-isolated `Observation`
for public resolve/render/compile/load/activate/rollback operations. Its fields
are closed operation/outcome/reason, duration and bounded count. There is no
message key, locale input, text, argument, path, error cause, revision, digest,
principal or tenant value. The callback must remain bounded and non-blocking;
the package creates no queue or exporter and has no OpenTelemetry dependency.

## Stated limits

- One grammar profile only: `frostgrove-mf2/v1`. There is no MF1, ICU-message,
  Fluent or Go-template fallback.
- The source and compiled artifact are Frostgrove formats, not a durable domain
  event or a cross-language rendering protocol.
- TypeScript export is a public type contract, not a browser formatter.
- No automatic translation, transliteration, currency conversion, address or
  person-name formatting, localized storage/search/collation/URLs or CMS model.
- No TMS client, network fetch, directory scan at runtime, watcher, hot-reload
  runner, health policy, cache backend, job backend or OTel adapter is created.
- No ambient locale, default host zone, global registry, package-init
  registration or background goroutine participates in rendering.
