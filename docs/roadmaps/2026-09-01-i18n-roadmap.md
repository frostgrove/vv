# Internationalization: механизмы, референсы и развитие Frostgrove

Редакция: 2026-09-09. Статус: core/runtime, offline toolchain и transport seams
реализованы; public contract зафиксирован в [[D-135]], [[UC-033]] и [[FL-039]].
Существующая локализация ошибок через `errs.Messages` работает самостоятельно и
остаётся поддерживаемым вариантом для приложений, которым не нужен полный i18n.

**Приоритет у описания механизма: что происходит, зачем это приложению и какие
гарантии даёт текущий контракт.** У каждой карточки пять частей:
механизм/референс, необходимость, адаптация, текущая реализация и DX. Имена
`i18n` API и команды `vv-i18n` ниже относятся к реализованному контракту;
application wiring помечается отдельно. Ссылки на внешние источники проверены
2026-09-08, а выбранные engine/data identities фиксируются самим артефактом.

## Что хотим получить

Frostgrove нужен связный путь от объявления сообщения до его использования в API,
письме или worker: язык выбирается осознанно, параметры проверяются, грамматика
соответствует языку, ошибки сохраняют машинный контракт, а выпущенный каталог
можно проверить и воспроизвести.

Кандидаты для первого прикладного среза:

- уведомление о количестве ожидающих действий: русские формы для 1/2/5/21 и
  дробных величин невозможно выразить текущей подстановкой `{param}`;
- письмо с суммой и сроком: язык текста, валюта операции и часовой пояс адресата
  являются разными входами;
- модуль со своими сообщениями, отдельными переопределениями приложения и
  понятным ответом на вопрос «почему пользователь увидел английский текст?»;
- одинаковый смысл ошибки в backend и frontend при независимом обновлении их
  каталогов и неизменном коде ошибки.

Эти сценарии образуют принятый профиль `frostgrove-mf2/v1` и покрыты runtime/tooling
корпусом. Конкретное приложение всё равно выбирает свои сообщения, обязательные
языки и владельца перевода. Если нужны только простые ошибки, достаточно
`errs.Messages`.
Перевод пользовательских документов, CMS-контент и машинный перевод через LLM
принадлежат продукту; они не становятся каталогом интерфейса.
Event sourcing не является зависимостью i18n. Если событие или job хранит intent
для последующего отображения, durable policy и авторизация остаются у приложения.

|---|---|
| [`github.com/frostgrove/vv/i18n`](../modules/en/i18n.md) | Один optional nested module: строгий source/review workflow, `frostgrove-mf2/v1`, immutable `Snapshot`, resolver/view/render, exact numeric/date/time/rich output, overlays, error adapter, canonical artifact, controller, code generation и offline `vv-i18n`. Он не добавляет сеть, watcher, TMS, durable pin store, tenant authorization или OTel exporter. |
| [`errs.MessageSource`](../../errs/spi.go) | `Message(context.Context, Violation, string) (string, bool)` остаётся минимальным wording seam. Optional структурно совместимые `i18n.LocalizedMessageSource` и root `errs.LocalizedMessageSource` добавляют `MessageWithLocale` и сообщают фактическую locale шаблона, не меняя старый контракт и не связывая релизы модулей. |
| [`errs.Messages`](../../errs/message.go) | Для каждой locale перебирает ключи `first.last.code → first.code → last.code → code`, с устранением соседних повторов. `first/last` — первый/последний именованный шаг; индексы и промежуточные шаги не участвуют. | Fallback в `errs.Messages` | Точная строка locale → часть до первого `-` либо `_` → каталог `""` → сообщение из `errs.Codes`. Это намеренно меньший контракт, не BCP 47 canonicalization и не CLDR parent-locale matching optional-модуля. |
| Подстановка в `errs.Messages` | `{name}` из `Violation.Params`; отсутствующий параметр заставляет попробовать следующий вариант. Plural/select, typed schema и культурное форматирование предоставляет optional i18n. |
| [`LoadMessages`, `Messages.Load`](../../errs/catalogue.go) | Root helper использует `io/fs` и плоский JSON; `default.json` означает locale `""`. Он остаётся mutable flat-catalog API. Строгий canonical source/artifact, immutable snapshots, limits и atomic controller находятся в optional i18n и не меняют этот контракт. |
| `Locales`, `Missing` | Есть список locale с объявленными записями и отчёт об отсутствующих общих кодах с учётом fallback. Это не проверка всех употреблений, аргументов, plural-веток, качества или полноты конкретного языка. |
| [`port.WithLocale`, `LocaleFrom`, `FirstLanguageTag`](../../port/locale.go) | Один context key. Helper берёт первый элемент до запятой или `;`, обрезает пробелы. Вес `q`, запрет `q=0`, канонизация и supported set не обрабатываются. |
| HTTP | [`porthttp.WithMessages`](../../port/porthttp/render.go) подключает source. CRUD HTTP bindings сохраняют уже связанную непустую locale; только при её отсутствии берут первый header tag. Это не weighted negotiation: полный `Accept-Language` разрешает приложение через i18n resolver до handler/error boundary. |
| CRUD gRPC | [`crudgrpc.WithMessages`](../../crud/rpc/crudgrpc/status.go) использует тот же source. [`locale.go`](../../crud/rpc/crudgrpc/locale.go) сохраняет непустую context locale, иначе читает настраиваемые metadata keys. `LocalizedMessage.Locale` появляется только когда source доказал фактическую locale шаблона; fallback `fr-CA → fr` сообщает `fr`, а legacy source не получает ложную metadata. |
| Порядок рендеринга | [`port.Violations`](../../port/violations.go) сначала разрешает public path, затем передаёт нарушение source. Wording: успешный непустой source → имеющийся public `Violation.Message` → code vocabulary → строка code. `errs.Messages` внутри себя уже пробует собственный code default. |
| Защита машинного контракта | HTTP 500 и gRPC Internal возвращают обезличенный ответ; локализация не должна раскрывать внутреннюю ошибку. Status, codes и public path принадлежат `errs`/`port`/transport, а не translator. |

Следствие: приложение может сделать полный `Resolve → port.WithLocale`, и CRUD
HTTP/gRPC сохранят результат. Встроенная protocol extraction остаётся узким
first-tag fallback. Точный язык текста сообщает только
`errs.LocalizedMessageSource`; legacy `MessageSource` такой provenance не имеет.
Внешняя middleware всё ещё должна рендерить с тем operation context, в котором
приложение связало locale.

### Выбранный движок и профиль

Реализация выбрала [messageformat-go](https://github.com/kaptinlin/messageformat-go)
и один профиль `frostgrove-mf2/v1`; public identity движка —
`messageformat-go/v0.8.6`. `GrammarProfile`, `EngineVersion`,
`LocaleDataVersion` и `TimeZoneDataModel` входят в compatibility и snapshot
identity. Автоматического определения грамматики нет: смена профиля или движка
будет отдельной миграцией каталога с corpus-проверкой.

Профиль поддерживает проверенный MF2 subset: exact keys, cardinal/ordinal,
select и multi-selector, exact integer/big-integer/lexical-decimal semantics,
number/integer/currency/percent/string, capability-gated date/time/datetime и
unit, а также allowlisted rich markup, literal `u:id`/`u:dir` metadata и
typed number/date subparts. Unknown functions, options, option values, selector
keys, attributes и markup options отвергаются до публикации.
Значения universal options из variables отложены до engine-версии,
которая умеет без потерь разрешать controlled typed values Frostgrove.
Произвольные Go template functions, MF1, Fluent и silent formatter fallback не
входят в контракт. Canonical source и compiled artifact используют форматы
Frostgrove; Go/TypeScript export не означает JavaScript formatting parity.

`go-i18n/v2` и cardinal-only `go-template-cardinal/v1` были исследованными
кандидатами и не стали shipped profile. Внешние ссылки в таблице выше сохранены
как сравнительный материал, а не как dependency statement.

## Механизмы

### I01. Один объяснимый выбор языка на операцию

**Механизм и референс.** Упорядоченные providers из ASP.NET, scoped locale из
Rails и matching из `x/text`. Три разные операции: разобрать предпочтения,
сопоставить их с поддерживаемыми языками, затем при lookup пройти fallback
конкретного сообщения. Matching не заменяет поиск отсутствующего ключа.

**Зачем.** API, письмо и job должны использовать одну выбранную политику.
Первый tag в header может иметь меньший вес или вообще `q=0`; `zh-Hant` нельзя
свести к произвольному `zh` удалением суффикса.

**Наша адаптация.** Рекомендуемый порядок для обычного приложения:
явный выбор операции → сохранённое предпочтение пользователя → browser/header
preferences → default продукта/tenant → default приложения. Порядок меняется
декларативно; обязательный язык документа задаётся отдельной политикой операции.
Profile/tenant input доступен после соответствующей проверки доступа;
неавторизованная ошибка пользуется только публичными кандидатами.

Resolver принимает bounded values, а не HTTP request или tenant resolver.
Настройки supported/default проверяются при сборке. Для недоверенного header
задаются лимиты длины/числа ranges, обработка malformed элементов, wildcard,
стабильный порядок при равном весе и исключения `q=0`.
`MatchLookup` только сокращает более конкретный запрос и не расширяет общий tag
до первого специфичного supported-варианта; inference между `zh`, `zh-Hans` и
`zh-Hant` доступен только через явно выбранный `MatchBestFit` или policy default.
При отсутствии допустимого совпадения результат явно `no_match`; приложение
выбирает документированный fallback либо отказ, не выдавая исключённый язык
за результат успешного negotiation. Семантика weights задана
[RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#section-12.4.2).
Возвращаем supported tag, источник выбора и ограниченный reason; raw header
не попадает в diagnostics по умолчанию. Один resolved tag хранится в `port`;
formatting locale/timezone остаются явными входами localizer.

**Текущая реализация.** `Resolver` принимает ordered `Exact` и
`AcceptLanguage` choices, канонизирует supported locales, учитывает weights,
`q=0`, wildcard и bounds и возвращает sealed `Resolution` с provenance.
`Snapshot.View` отделяет message locale от formatting locale/time zone.
CRUD HTTP/gRPC сохраняют непустую заранее связанную locale; только без неё
используют узкий first-tag helper.

Обратного распространения дочернего context в Go нет, поэтому error boundary
должен явно получать context фактической операции. CRUD gRPC передаёт
его через `ContextError`, а CRUD HTTP middleware сохраняет последний
operation request/context для renderer. Поэтому ранний auth refusal остаётся на
публичной locale, а последующая resource error видит выбор после auth.

**Текущий DX.** `resolution := snapshot.Resolve(i18n.Exact(...),
i18n.AcceptLanguage(...))`; после проверки `resolution.Matched()` приложение
создаёт `snapshot.View(i18n.ViewSpec{Resolution: resolution, ...})` и при
необходимости связывает supported locale через `port.WithLocale`. Для batch —
отдельный view на адресата. Нет `SetCurrentLanguage` или зависимости от хоста.

### I02. Каталоги модулей, частичные overrides и детерминированный fallback

**Механизм и референс.** Symfony domains/parent locales, Laravel package
overrides и i18next namespaces. Идентичность сообщения — domain + stable ID;
перевод хранится отдельно от исходного текста, описания и схемы аргументов.
Модуль может поставлять свои сообщения, приложение — отдельный слой overrides.

**Зачем.** Изменение слова «пользователь» на «участник» не должно требовать
форка framework или копирования всех каталогов. При добавлении модуля его ключи
не должны случайно перекрывать ключи другого.

**Наша адаптация.** Сначала собираем и проверяем immutable effective catalog
для каждой locale: application override → объявленный module default.
Два владельца одного ключа без явного override — ошибка; каталог заменяется
целым сообщением, не смешиванием plural-веток разных переводов.
Поиск идёт по утверждённому locale graph: exact → разрешённые parents →
configured fallback → source locale. Parent graph использует выбранные locale
данные, проверяется на циклы и не создаётся обрезанием строк.

Пример порядка: module `fr-CA` побеждает app `fr`, потому что сначала выбирается
ближайшая locale; app `fr-CA` побеждает module `fr-CA`. Это проверяемое правило,
а не зависимость от порядка файлов. Обычный lookup не прыгает между domains.
Для error adapter внутри каждой locale действует отдельная лестница I06.
Отсутствующее сообщение и невалидный шаблон имеют разные результаты;
невалидный каталог не активируется. Пустой перевод требует явного разрешения
в схеме, иначе пропущенная работа неотличима от осознанной пустой строки.

[go-i18n Localizer](https://raw.githubusercontent.com/nicksnyder/go-i18n/main/i18n/localizer.go)
имеет собственную fallback-политику, поэтому не был взят как runtime facade.
`Snapshot` сам владеет проверенным fallback graph и provenance; скрытый переход
движка на другой язык не входит в профиль.

**Текущая реализация.** `CatalogSpec.Modules`, `Overrides` и `Parents` строят
полный immutable snapshot. Qualified keys, whole-message application/tenant
layers, required locales, циклы, permissions и review/source digests проверяются
до возврата. `Rendered` и `Explain` сообщают победившие locale и layer.

**Текущий DX.** Приложение передаёт `Modules`, `Overrides` и `Parents` в один
`i18n.CatalogSpec`, вызывает `i18n.New`, а затем при необходимости создаёт
`snapshot.Overlay(i18n.ApplicationOverlay(...))` или разрешённый
`TenantOverlay`. Автосканирования и глобальной регистрации нет.

### I03. Целые сообщения, plural/select и честная граница грамматики

**Механизм и референс.** Cardinal rules go-i18n, ICU plural/select у Symfony,
translator-owned structure у Fluent. Переводчик выбирает форму целого
сообщения; приложение передаёт количество и смысловые параметры.
Категории `one/few/many/other` — языковые правила, а не имена чисел.

**Зачем.** `count == 1` ломается уже на русском; склейка количества, существительного
и окончания ограничивает переводчика порядком слов языка разработчика.
Пол адресата, вариант обращения и ordinal нельзя подменять cardinal.

**Наша адаптация.** Один профиль ограничен, как описано выше. На нашей границе
decimal input не превращается во `float64`: сохраняются исходное значение и
видимая дробная часть в пределах проверенного диапазона движка. Обязательная fallback-ветка
и разрешённые категории проверяются для каждой объявленной locale.
Plural выбирается по языку найденного шаблона, даже если пользователь попросил
другой язык; форматирование вставленного значения использует явную политику I04.

Реализованный MF2 subset включает exact-number branches, cardinal/ordinal,
string select и multi-selector после corpus-проверки. Quoting/escaping,
обязательный catch-all, locale plural categories и допустимые literal option
values проверяются до публикации.
Fluent terms полезны для общего словаря, но не дают автоматического
склонения произвольных имён: грамматическая форма и контекст должны быть
выражены переводчиком. Generic template functions не становятся бизнес-API.

**Текущая реализация.** `frostgrove-mf2/v1` использует pinned CLDR semantics и
сохраняет exact integer, big-integer и lexical decimal values без `float64`.
Rich result сохраняет MF2 type/direction/opaque `u:id` и плоские
Intl-части number/date; все exposed nodes входят в output budget.
MF1 и Fluent не реализуются и не принимаются как fallback grammar.

**Текущий DX.** Сгенерированный `Definition` связывает
`msg.PendingActionsArgs{Count: count}` в deferred `Message`; динамический путь —
`snapshot.Bind(key, i18n.Integer("count", count))`. Переводчик заполняет
`one/few/many/other`; call site не содержит `switch locale`.

Минимальный пример поведения для русского каталога; это описание веток,
не замороженный формат файла:

| Ветка | Шаблон сообщения |
|---|---|
| `one` | «Осталось 1 действие» |
| `few` | «Осталось 2 действия» |
| `many` | «Осталось 5 действий» |
| `other` | «Число оставшихся действий: 1,5» |

По [CLDR Russian rules](https://www.unicode.org/cldr/charts/48/supplemental/language_plural_rules.html#ru)
для `1`, `2`, `5`, `21` выбираются `one`, `few`, `many`, `one`.
Лексическое decimal-значение `"1.0"` проверяется отдельно и выбирает `other`;
нельзя нормализовать его до `1` до выбора формы. Для счётчика дискретных действий
приложение обычно объявляет integer schema; decimal fixture нужен для самого
движка и сообщений о дробных величинах.

### I04. Числа, деньги и даты — отдельная культурная политика

**Механизм и референс.** ASP.NET разделяет UI/formatting cultures, Spring —
locale и timezone; `x/text/message` даёт Go locale-aware printing.
Число, денежная сумма, календарная дата и момент времени — разные типы входов.

**Зачем.** Русский текст может содержать сумму в KZT и срок в выбранной зоне.
Язык браузера не определяет ни валюту сделки, ни местное время адресата.
Выгрузка для машины и строка для человека имеют разные требования.

**Наша адаптация.** Явные formatting locale, timezone и currency code;
профили отображения называются по назначению, например `invoice.amount`.
Денежные значения сохраняют decimal/minor-unit semantics, форматтер не
конвертирует валюту. Instant + timezone отличается от date-only: у календарной
даты нельзя молча сдвинуть день из-за часового пояса.
Реализованный профиль покрывает exact number/integer/currency/percent,
capability-gated date/time/datetime и unit. View предоставляет typed direct
`FormatNumber`, `FormatMoney`, `FormatPercent`, `FormatUnit`, `FormatDate`,
`FormatInstantDate`, `FormatTime`, `FormatDateTime`, а также bounded
`FormatList`, `FormatRelative`, `FormatDuration` и `FormatDisplayName` без
фиктивного catalog key. Exact numeric types исключают неявный float; calendar
date не сдвигается зоной, instant methods используют pinned zone View, а zero
date/time style означает medium. Typed number spec включает grouping/sign,
notation, fraction/significant digit ranges, все ECMA-402 rounding modes,
precision priority, trailing-zero policy и закрытый набор rounding increments;
несовместимые комбинации отвергаются до formatter-а.
Границы digit range задаются вместе через `Digits` или независимо через
`MinimumDigits`/`MaximumDigits`, поэтому пропущенная сторона сохраняет
locale/style/currency-dependent Intl default. Relative-time намеренно принимает
только whole-unit `int64` от `-(2^53-1)` до `2^53-1`; после exactness guard
pinned backend преобразует integer в точно представляющий его `float64`.
Fractional и out-of-range values не поддерживаются.
Неподдерживаемые options и значения отвергаются, а не делегируются `time.Format`.
Отсутствующая обязательная зона — ошибка конфигурации/вызова, а не `time.Local`.
Scalar API дополнен exact ranges для number/money/percent/unit/date/time/datetime
и отдельным cardinal/ordinal plural и plural-range selection. Range parts
сохраняют start/shared/end provenance. Для повторяемой application policy
`NewFormatter` или `View.Formatter` один раз проверяет immutable named registry
`Formats`; runtime lookup не пересобирает spec. Это соответствует named formats
FormatJS/ECMA-402, но сохраняет Frostgrove bounds, exact inputs и явный
`ErrFormatNotFound` вместо ambient/global registry. Entry count и aggregate
retained bytes проверяются до allocation/backend validation, строки клонируются,
а любой successful/failed/canceled named call создаёт ровно одно terminal
observation.

**Текущая реализация.** `Money`, `Date` и `Instant` различают валютное значение,
calendar date и момент. Grammar locale выбирается по фактическому шаблону, а
formatting locale и zone закрепляются в `ViewSpec`. Пустая zone наследует
`CatalogSpec.DefaultTimeZone`, а уже его zero value равен UTC. Машинные
JSON/DB/API форматы при этом не меняются.

**Текущий DX.** `view, err := snapshot.View(i18n.ViewSpec{Resolution: resolved,
FormattingLocale: formatLocale, TimeZone: zone})`, затем
`view.Render(ctx, message)` или один из direct formatter methods.

### I05. Типизированное отложенное сообщение как обычное значение

**Механизм и референс.** Symfony `TranslatableMessage`, Django lazy translation
и compiled authoring у Lingui. Reference содержит ID, аргументы и версию их
контракта; текст появляется только при явном `Render`.

**Зачем.** Один результат операции может быть показан на странице и отправлен
разным адресатам. Ошибка в имени параметра должна обнаруживаться раньше запроса
пользователя. Изменение source wording не должно менять identity сообщения.

**Наша адаптация.** Манифест объявляет domain/ID, source text, описание для
переводчика, аргументы и их типы, selector, output kind и visibility.
Compiler генерирует Go helpers со структурой аргументов. Required/optional,
отсутствие значения, пустая строка и ноль различаются. Перевод может не
использовать часть исходных параметров, но не может самовольно добавить новый.
Изменение обязательного аргумента/типа требует contract revision или нового ID.

Есть checked escape hatch для заранее объявленных динамических IDs: вызов
валидации возвращает ошибку. Нет произвольного user-controlled ключа с
неограниченным `map[string]any` как альтернативного канала данных.
Никаких locale-sensitive `String()`/`Error()`: логирование или сериализация не
должны неявно выбирать язык. Внутренний Go reference сам по себе не wire DTO
и не формат хранения долговременного события.

**Текущая реализация.** `Message` копирует typed arguments и содержит contract
identity, но не locale-sensitive `String`/`Error`. `Snapshot.Bind` — dynamic
checked path; `Definition[A]`/`Define` и `vv-i18n generate-go` дают typed path.
Generated `NewCatalog` pin-ит literal `ContractRef` и отвергает несовместимый
snapshot при assembly, до первого render.

Для небольшого ручного wiring `DefineStruct[A]`/`NewStructDefinition[A]`
компилирует проверенный field plan один раз: обычный `Bind` не делает lookup по
reflection metadata. Exact tag имеет приоритет над forgiving ASCII field-name
mapping, optional/null topology выражается только `Optional[T]`, а native
`int`/`uint`, floats, embedded/unexported fields и структурно похожие composite
types отвергаются заранее. Generated encoder остаётся рекомендуемым fast path;
reflective binder — typed escape hatch, а не новый registry или auto-discovery.

**Текущий DX.** `notice, err := catalog.Invitation.Bind(
msg.InvitationArgs{Name: name})`; для ручной сборки —
`definition, err := i18n.NewStructDefinition[InvitationArgs](snapshot, key)`;
затем `rendered, err := view.Render(ctx, notice)`.
Context служит cancellation и
корреляции наблюдений; locale и snapshot уже выбраны у localizer.
Renderer dependencies остаются
на границе представления, а не в бизнес-модели.

### I06. Одна семантика ошибок для любого транспорта

**Механизм и референс.** Rails error scopes и
[Laravel attribute labels](https://laravel.com/framework/docs/13.x/validation#customizing-the-validation-attributes)
поверх существующих `errs`/`port`: выбираем человеческое объяснение структурного
нарушения, сохраняя код, kind, path и форму ответа.

**Зачем.** «Обязательное поле» можно уточнить для конкретного атрибута, не
меняя validator или REST/gRPC handler. Frontend продолжает ветвиться по коду.

**Наша адаптация.** В том же `i18n` package — adapter `errs.MessageSource`.
Сначала остаётся существующий locale-outer/key-inner контракт: в каждой locale
`first.last.code → first.code → last.code → code`; внутри одного ключа действует
effective override I02. Полный вложенный path не становится ключом автоматически.
Field labels относятся к отдельно объявленным сообщениям; API path остаётся
машинным. Адаптер переводит разрешённые Params в схему сообщения, не передаёт
шаблону сырую domain-модель, driver error или вызываемый метод.

Текущие `{param}`-каталоги не являются Go templates: миграция выполняется
явным import/conversion с отчётом о несовместимых placeholders. Простые
потребители продолжают использовать исходный `errs.Messages`.
Неудача локализации не меняет статус и не заменяет исходную ошибку новой 500;
adapter отдаёт отсутствие сообщения, а renderer сохраняет безопасный fallback.
Подробная причина доступна через отдельный inspection path I11.

Минимальный `MessageSource` не сообщает actual locale и не меняет signature.
Optional `errs.LocalizedMessageSource` расширяет его структурно: умеющий source
возвращает фактическую locale выбранного шаблона. HTTP renderer проецирует
доказанные значения в `Content-Language`, gRPC — в
`LocalizedMessage.Locale`; legacy source не копирует requested tag в эти поля.
Обезличивание Internal/500 остаётся прежним.

**Текущая реализация.** `Snapshot.ErrorMessages(ErrorSpec)` валидирует immutable
typed mappings, allowlisted params и field-label messages и возвращает
`i18n.LocalizedMessageSource`, структурно совместимый с одноимённым optional
root seam. При mapping/bind/render failure adapter declines,
поэтому безопасный renderer fallback, codes, paths и Internal redaction остаются
неизменными. `Snapshot.ErrorPlan` один раз компилирует mapping, а
`View.ErrorMessages(plan)` привязывает source к одним и тем же resolution,
formatting locale, zone и presentation, которые уже использует
операция. Requested locale в legacy method не может перевыбрать
этот view. CRUD transports сохраняют prebound locale.

**Текущий DX.** `source, err := snapshot.ErrorMessages(errorSpec)`;
`porthttp.NewRenderer(porthttp.WithMessages(source))` и
`crudgrpc.NewRenderer(crudgrpc.WithMessages(source))`. Для generated CRUD
предпочтителен additive `Rendering(WithMessages(source))`: он сохраняет
автоматические `port.Hops(service, mapper)`. Если view уже выбран,
предпочтителен `plan, err := snapshot.ErrorPlan(spec)`, затем
`source, err := view.ErrorMessages(plan)`. Полный путь проверяет X02.

### I07. Authoring + usage evidence → merge/review/check → compile

**Механизм и референс.** Django `makemessages/compilemessages`, go-i18n
extract/merge, Symfony extract/debug и Lingui compilation. Перевод —
проверяемый build input с отдельным человеческим review.

**Зачем.** Runtime fallback не должен месяцами скрывать забытый перевод.
После изменения source text старый перевод может оставаться синтаксически
верным, но уже не соответствовать смыслу.

**Наша адаптация.** Manifest — источник ID/schema; static и bounded-domain
употребления находит type-aware extractor, динамические перечисляются явно.
Extract не выполняет application initialization: context-bound local Go tool
вычисляет effective package graph и compiled files, exact export importer даёт
типы зависимостей, а production-пакеты выбранных module roots образуют единый
source graph. Учитываются persisted GOENV/GOFLAGS, workspace, nested-module
границы, replace, vendor и overlay. Private GOCACHE, `GOTOOLCHAIN=local`,
отключённые proxy/sumdb и read-only metadata shadows исключают implicit download
и запись в checkout. Package/dependency/type/load error, cgo, partial file root,
конфликт export evidence либо reachable dependency, способный скрыть i18n call,
понижает полноту до `complete:false`. Excluded effective-build candidates
остаются в hash ledger, но не делают доказательство именно этой build
конфигурации неполным.
Source hash/context change помечает перевод как requiring review.
Translation SaaS, XLIFF/PO import или LLM могут помогать вне runtime, но их
результат проходит тот же review/compile и не публикуется автоматически.

Compiler проверяет duplicate IDs/JSON members, schema mismatch, unknown
arguments, grammar profile, plural coverage, cycles, output kind и лимиты;
генерирует детерминированный manifest и код. Для обязательной locale/domain
release policy может запрещать untranslated/fallback, для остальных — сообщать
долг. Синтаксическая валидность и процент покрытия не доказывают качество языка:
нужен reviewer на каждый рекламируемый язык.
Build tool отделён от runtime: AST/CLI/vendor зависимости не попадают в
приложение только ради загрузки готового каталога.

**Текущая реализация.** Canonical source codec, review/source digests, `Check`,
`Pseudo`, `Compile`, `GenerateGo`, `ExportPublic`, `MergeSource` и AST extraction
доступны как library/build APIs. Отдельная команда `vv-i18n` реализует
`extract`, `merge`, `review`, `check`, `pseudo`, `compile`, `generate-go` и
`export-ts`; одиночные output writes атомарны, direct multi-file export имеет
best-effort rollback, а `export-ts -publication-root` коммитит immutable
content-addressed generation одним pointer rename. Reader проверяет fixed file
set, byte counts/digests, generation framing и вычисляет public address заново из
точных manifest/TypeScript bytes; тот же pure helper экспортирован independent Go
consumer-у. Publisher и readers проходят path от filesystem/volume root через
stable descriptors; symlink или inspection/open identity change отвергается, а
последующая замена ancestor не перенаправляет операцию. Missing final root
создаётся и его parent синхронизируется через pinned parent descriptor. `-check`
проверяет drift без записи. `extract -complete=true`
означает запрос полного манифеста, а не безусловное утверждение: любой
непрослеживаемый участок graph безопасно даёт `Complete=false`.
К таким участкам относятся return/field/map/heap/reflection/unsafe/unknown-call
escape для `Snapshot.Bind`, method expressions/values, binder interfaces,
`*Snapshot` и других i18n capabilities. Точный typed call или callback остаётся
анализируемым, если тело callee входит в exact selected source graph, включая
выбранный sibling package. Generated marker не даёт factory доверия: каждый result field с
`Definition` доказывается отдельно по всем reaching assignments и returns;
parameter, mixed path или escape делает это доказательство недостоверным.
Active production build tags задаются через `extract -tags`; если флаг не указан,
из некавыченного `GOFLAGS=-tags=...` наследуется тот же набор, что использует Go
build; явный `-tags=` его очищает. Completeness по умолчанию выключена. Usage
schema v4 связывает sorted unique exact/dynamic aggregates и bidirectional
call-site evidence с canonical root/file/metadata/environment/package-graph
ledgers через пересчитываемые source и manifest digests. Decoder и `Check`
проверяют counts, containment, selected-file backing, coordinates, sorting,
uniqueness и reverse evidence; build/tool/release tags обязаны быть sorted и
unique, bounded JSON preflight ограничивает работу до materialization. V1-v3
сохраняют positive aggregates/occurrences, отбрасывают legacy scope и читаются
только как incomplete без v4 provenance findings. `CheckPolicy.UsageLimits`
задаёт независимые от catalogue limits fixed/operator-owned ceilings; zero
выбирает hard default, caller может только сузить его. Defaults: 262144 для
keys/dynamic/occurrences, 1024 roots, 100000 files/metadata, 256
tags/environment, 4 MiB на string и 64 MiB aggregate material. Digests доказывают
self-consistency документа, но не authenticity/freshness: release non-use gate
повторно запускает `extract -complete ... -check` в trusted physical checkout.
Все восемь команд передают operator-owned catalogue/source/compiled/output
ceilings и context внутрь соответствующего builder/encoder до materialization.
Context-варианты `New`, compile/encode, source codec, pseudo, Go/TypeScript
generation, public address и merge сохраняют старые convenience APIs поверх
`context.Background()` и конечных defaults. Малый derived-output budget
отказывает до пропорционального formatter/hash work. `SourceCodec.EncodedSize`
и `EncodedSizeContext` дают точный canonical source byte count; artifact,
generated Go, manifest/TypeScript, pseudo additions и review stamps используют
точный count-only N/N-1 preflight с JSON escaping и fixed digest widths. Merge сначала учитывает
aggregate material и canonical source bytes, хранит только count + lexical-first
obsolete diagnostic и лишь затем переносит work; review проверяет selector до
clone.

**Текущий DX.** Это два composable входа, а не цепочка, где output
`extract` подаётся в `review`. Authoring-ветка: новый canonical source →
`vv-i18n merge -previous ...` → `review` → `check` → `compile`.
Usage-ветка: `extract` → `check -usage ...`. `merge` по умолчанию
отказывает удалять obsolete reviewed entries и требует
`-prune-obsolete` для явного destructive intent. При необходимости затем
`generate-go` и `export-ts`. Команда живёт в nested module и не меняет
dependency graph root `vv`.

### I08. Каталог как immutable и версионированный артефакт

**Механизм и референс.** Compiled catalogs из Django/Lingui и resource lifecycle
из [Spring resource sources](https://docs.spring.io/spring-framework/docs/current/javadoc-api/org/springframework/context/support/AbstractResourceBasedMessageSource.html).
Наша добавка — воспроизводимая активация целого каталога и его политики.

**Зачем.** Перевод меняет видимый пользователю результат. Частично загруженный
каталог или разные версии внутри одного письма делают ошибки труднообъяснимыми.

**Наша адаптация.** Артефакт включает manifest/schema revision, content hash,
grammar profile, compiler/runtime compatibility, версии locale data, supported
set, fallback graph и digest layers. Человекочитаемый release ID отделён от
content hash; недетерминированная дата сборки не входит в hashed payload.
До публикации проверяются file/count/bytes, template depth, argument size,
expansion/output budget и совместимость с binary.

Runtime loading работает из caller-owned `io.Reader`/`io/fs`, без сети.
`Controller` строит и активирует целый snapshot атомарно; concurrent
`Activate`/`Rollback` сравнивают opaque `Head`, а current/retained/pinned
snapshots ограничены count, lifetime и bytes. Текущая операция использует один
immutable `View`, поэтому поколения не смешиваются. Подпись/доверие поставщику,
storage, fleet rollout и durable retention решает application delivery pipeline:
один hash или in-process pin не аутентифицирует издателя и не переживает restart.

**Текущая реализация.** `Compile`/`Encode` создают canonical
`frostgrove.i18n.catalog/v1`; `Load`/`LoadFS` строго проверяют canonical bytes,
profile/engine/data identities, semantic digest и local ceilings.
`NewController` даёт bounded in-process CAS activation, rollback, retention и
finite leases. Watcher, timer, goroutine, durable store и network policy не входят.

**Текущий DX.** `snapshot, err := i18n.Load(ctx, embeddedBundle)`;
`view, err := snapshot.For(locale)`. Для локальной публикации приложение создаёт
`i18n.NewController`, берёт `Current()` и вызывает `Activate`/`Rollback` с этим
head; внешний loader/reload остаётся application wiring.

### I09. Общий контракт сообщений для Go и frontend

**Механизм и референс.** Typed authoring/compilation Lingui и FormatJS,
namespace-oriented i18next. Наша комбинация: один manifest → Go helpers,
TS argument types и явный public catalog subset.

**Зачем.** Backend и frontend не должны независимо угадывать имя параметра
одного сообщения или смысл error code. При этом у них разные release cycles,
часть текстов существует только в UI, а часть — только в серверных письмах.

**Наша адаптация.** Общий schema source не означает один гигантский bundle.
Экспортируются только помеченные public domains/IDs; внутренние тексты,
параметры ошибок и tenant overrides не попадают в браузер автоматически.
UI-only сообщения могут принадлежать frontend. Для отображения API ошибок
выбирается одна политика: серверное human wording либо явно объявленное
клиентское отображение stable codes; автоматически переводить уже готовую
строку повторно нельзя. Новых полей в существующий error envelope эта карточка
не добавляет.

Public export фиксирует schema/profile/generator/value contract, ES target,
capabilities и `FormattingParity: false`. Он публикует IDs, typed arguments,
output/markup contract и content address, но не private messages, tenant
overrides или обещание browser formatting. Для одинакового текста понадобятся
отдельный JS formatter, общий corpus, decimal semantics и совместимые CLDR/Intl
данные; равенство типов этого не доказывает.

**Текущая реализация.** `vv-i18n generate-go` создаёт pinned Go definitions;
`export-ts` создаёт deterministic TypeScript declarations, public manifest и
общий address только для `Public` messages. JavaScript formatter и formatting
parity намеренно отсутствуют.

**Текущий DX.** `vv-i18n generate-go -source ...` и
`vv-i18n export-ts -source ... -manifest ... -address-out ...`. Browser получает
public type/identity contract от приложения; framework не навязывает React,
CDN или runtime formatter.

### I10. Язык фоновых задач и повторяемое представление

**Механизм и референс.** Явное deferred message из Symfony и operation scope
из Rails, перенесённые на jobs. Здесь наша задача — определить, какой момент
времени выбирает язык и каталог, а не протащить request context в очередь.

**Зачем.** Между постановкой и отправкой письма пользователь может поменять
язык, а приложение — перевод. Для разных сценариев правильны разные ответы.

**Наша адаптация.** Прикладная delivery policy выбирает `at-enqueue` либо
`at-send` независимо для locale и catalog revision; формат даты/zone также
задаётся явно. В persisted payload — только разрешённые данные и revision,
без context, principal, renderer и неограниченного Params bag.
Для pinning приложение обеспечивает хранение и доступность нужного артефакта
с момента capture до отложенного запуска, ожидания в очереди, deferrals и
завершения retries; точная lifetime/expiry policy описана в X06/X07.
Отсутствующий pinned catalog — явная delivery
ошибка/операторское решение; silently выбрать latest нельзя.

Для точного воспроизведения недостаточно одной locale: нужны сообщение,
параметры, catalog, grammar/data versions и formatting policy. Если продукту
нужна неизменная копия отправленного документа, он хранит итоговый артефакт
по собственной политике, а не требует вечного rerender от i18n.
Локализация происходит на границе подготовки отправляемого представления.

**Текущая реализация.** `Message`, `SnapshotRef`, immutable `View` и in-process
`Controller` pins дают необходимые runtime values. Они не являются durable job
DTO, authorization или restart-safe lease. Locale/catalog delivery contract,
archive и recipient checks остаются приложению; точки tenant restoration — X06.

**Application DX.** Приложение создаёт delivery DTO с выбранной locale policy и
`SnapshotRef`, worker после повторной авторизации получает разрешённый snapshot,
создаёт view и вызывает `Render`. Нет `i18njobs`: компоненты соединяет обычный
код приложения.

### I11. Explain, проверка языков и псевдолокализация

**Механизм и референс.** Symfony debug translation и i18next fallback дают
основу inspection. Добавляем единое объяснение resolution и release provenance.

**Зачем.** «Перевод есть, но его не видно» обычно означает неверный domain,
locale, слой, ключ или версию. Сейчас это приходится выяснять вручную.

**Наша адаптация.** Explain показывает key, выбранную supported locale,
проверенные fallback candidates, победивший layer/key, actual template locale,
profile и catalog revision; resolution и template outcomes/reasons различают
exact, fallback и missing. Schema/argument errors возвращаются раньше из
`Define`/`Bind`, а не маскируются диагностикой.
Обычный вызов возвращает короткий result, подробный bounded trace — по запросу.
Он не содержит аргументы, rendered text, raw headers и user/tenant identity.
Полный catalog inspection остаётся developer/operator инструментом, а не
публичным endpoint, раскрывающим внутренние сообщения.

Runtime corpus включает русские 1/2/5/11/21, lexical decimals, Arabic
plural/RTL, locale со script/region и неподдерживаемый язык. `en/ru/kk` —
возможный прикладной набор, а не фиксированный список языков framework.
Pseudo locale расширяет текст, меняет символы и проверяет покрытие; RTL corpus
проверяет bidi и вставки. Реальное переполнение layout проверяется в UI,
числовые/plural fixtures — в runtime. Pseudolocalization не заменяет переводчика.
Locale-data upgrade запускает regression corpus и review изменившихся outputs.

**Текущая реализация.** `View.Explain`, `Check`/coverage/usage findings и
accent/RTL `Pseudo` реализованы и bounded. Optional `Observer` сообщает только
closed operation/outcome/reason, duration и count, без text/args/key/locale или
identity. Телеметрия не обязательна для рендеринга и отдельной i18n→OTel
dependency нет.
Источник наблюдений, схема, providers и жизненный цикл описаны в X04;
одного наличия `vvotel.Service` для этих сигналов недостаточно.

**Текущий DX.** `view.Explain(message)` и `vv-i18n check -strict` с bounded
report; `vv-i18n pseudo -mode accent|rtl` создаёт canonical source. Наблюдения
не маркируются rendered text,
параметрами, произвольными IDs и сырыми locale ranges.

### I12. Граница представления: текст, HTML, HTTP cache и локализованные данные

**Механизм и референс.** Контроль machine/human formatting у
[Django](https://docs.djangoproject.com/en/5.2/topics/i18n/formatting/),
[W3C bidi guidance](https://www.w3.org/International/articles/inline-bidi-markup/)
и HTTP language negotiation. Перевод строки не делает её безопасной для любой
среды вывода и не определяет язык хранения бизнес-данных.

**Зачем.** Plain text может попасть в email, HTML или CLI. Правильный перевод
не защищает от неправильного HTML escaping, bidi-вставок или cache, который
отдаёт русскую страницу английскому пользователю.

**Наша адаптация.** `OutputPlain` — обычный plain text; HTML/JSON/URL escaping
принадлежит конкретному renderer. Не возвращаем «trusted HTML» по суффиксу ID.
Изоляция направлений нужна уже в первом string renderer: до склейки результата
он ещё знает границы аргументов и применяет явную bidi policy. Для вставок с
неизвестным направлением исходный вариант — Unicode FSI/PDI; известное
направление и уже изолированные части обрабатываются выбранной стратегией.
Это следует [Unicode bidi isolation](https://www.unicode.org/reports/tr35/tr35-messageFormat.html#handling-bidirectional-text)
в нашем renderer, а не зависит от ambient transport. Политика обработки
недоверенных bidi controls отделена от обычных RTL-букв; неизбирательное
удаление RTL-текста недопустимо. Fixtures включают арабскую фразу с латинским
именем/номером и обратное направление. После flattening одних `dir`/escaping
на уровне страницы уже недостаточно.
`OutputRich` в том же профиле возвращает ограниченные структурные parts,
component allow-list и явные bidi boundaries, никогда trusted HTML. Browser выставляет `lang/dir`
по своей presentation policy; библиотека сообщений не управляет layout.

Для cacheable ответа, выбранного по header, приложение учитывает
`Vary: Accept-Language`; профиль пользователя требует соответствующей private
cache policy, одного `Vary` недостаточно. Application cache key включает
resolved locale, catalog revision, formatting policy и разрешённый scope,
если они влияют на результат. `Content-Language` описывает аудиторию
представления и не получается слепым копированием raw header; multilingual
response требует явной политики. Это transport/application responsibility по
[RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#section-12.5.5).

Localized URL/SEO, collation/search, input parsing, адреса, имена и переводы
полей сущности — отдельные продуктовые механизмы. Для них сначала нужны
конкретные use cases и собственные правила хранения/индексации/публикации.
Catalog i18n не превращается в ORM для `title_en/title_ru` и не переводит
storage keys или authorization policies.

**Текущая реализация.** `Rendered` содержит `Text`, cloned safe `Parts`,
фактические template locale/layer и deterministic `RenderKey`. Error adapter
даёт HTTP/gRPC фактическую template locale. Автоматическая cache policy,
localized business-content model и sink escaping остаются приложению.

**Текущий DX.** Приложение отдаёт `rendered.Text` или преобразует allowlisted
`rendered.Parts` в конкретном renderer и задаёт HTTP metadata/cache policy.
Универсальной `SafeString` нет.

## Интеграции с существующими модулями

Интеграция считается предусмотренной, когда названы вход, владелец решения,
точка подключения, отказ и проверка. Запрет перекрёстного импорта сам по себе
ничего из этого не реализует. Таблица и карточки ниже дополняют I01–I12.
Core i18n types, callbacks, compiler/CLI и error/transport seams реализованы.
Tenant settings, cache/job/storage/runtime wiring и telemetry exporter в этих
карточках являются application-owned integrations, а не скрытыми services модуля.

Под application wiring понимается composition code конкретного приложения.
Resolver, overlays, schema validation, error mapping и наблюдения реализует
сам i18n; приложение передаёт tenant settings, providers и lifecycle в явные
точки подключения и само владеет внешними ресурсами.

| Модуль | Что уже можно использовать | Текущий i18n seam / application responsibility |
|---|---|---|
| `app/module`, `appfx`, codegen | Обычные providers, deployment profiles, catalog и topology doctor | Модули передают обычные declarations; приложение собирает `CatalogSpec`, а `Check`/`vv-i18n` дают отдельный translation report до активации |
| `errs`, `port`, CRUD/auth HTTP и gRPC | MessageSource, code vocabulary, public-path hops, renderers | `ErrorMessages` реализует совместимый localized adapter; `ErrorPlan` + `View.ErrorMessages` сохраняют one-view policy; additive CRUD rendering сохраняет hops/codes/redaction |
| `tenancy`, auth | Проверенная scope, lifecycle/epoch, проверка доступа | i18n проверяет tenant overlay isolation; приложение после admission владеет locale policy, authorization, settings и выбором snapshot |
| `otel`, `port.Logger` | Command/storage spans, cache signals; общий набор injected providers и logger из context | Typed i18n observations и готовая application wiring для счётчиков/длительностей/trace events; privacy/cardinality contract |
| `cache`, `tenancycache` | Typed keys, partition/generation, изолированные shared loaders | `RenderKey` даёт полную output identity; приложение передаёт explicit inputs, partition и authorization до cache hit |
| `jobs`, `tenancyjobs`, `jobsfx` | Typed payload, durable tenant restoration, явные worker roles | `Message`/`SnapshotRef` — обычные values; приложение хранит locale/catalog policy и повторно авторизует snapshot после tenant restoration |
| `storage`, `runtime`, `health`, `vvcfg` | Потоки артефактов, supervisor, probes, strict config | `Load` и `Controller` дают bounded validation/CAS/LKG primitives; external loader, runner, durable pins и readiness принадлежат приложению |
| `remote`/`remotehttp`, frontend | Машинный контракт удалённых ошибок и отдельные transport boundaries | Public TS/type export реализован без formatter parity; приложение явно передаёт locale/выбирает повторный render и не распространяет tenant state автоматически |
| Будущий audit | Реализованной i18n/audit-связки нет | Публикация/rollback каталога может аудироваться приложением; форматирование не ждёт audit и не пишет запись на каждую строку |

### X01. Модуль поставляет сообщения, приложение проверяет всю сборку

**Механизм и референс.** Package catalogs из Laravel/Symfony на существующих
[module contributions](../modules/en/app.md). Модуль объявляет свои IDs/schema,
embedded translations и error mappings; application root собирает их в одну
проверяемую конфигурацию по I02/I07.

**Зачем.** Подключение модуля должно приносить и его сообщения. Конфликт ID,
неполный обязательный язык или несовместимый перевод должны остановить сборку
до запуска worker или приёма запросов, а не обнаружиться на первом отказе.

**Наша адаптация.** Provider сообщений остаётся обычным конструктором;
сборщик явно получает все наборы выбранного deployment. Набор языка, fallback,
grammar profile, budgets и public export policy задаются конфигурацией приложения.
Нельзя считать, что Worker/API автоматически отфильтровал каталоги: обычные
providers активны во всех профилях. Если нужна выборка domains по роли, она
объявляется в message manifest и передаётся compiler явно.

Валидация имеет реального потребителя: bootstrap сначала строит и проверяет
catalog, затем передаёт его renderers/workers. Одного ленивого `fx.Provide`
недостаточно. Одинаковая проверка работает в hand-wired и Fx сборке.
`module.Doctor` остаётся topology-only: вывод о переводах даёт отдельный
`vv-i18n check`/application check, использующий `i18n.Check`. Он читает
декларации/артефакт, не выполняет конструкторы, не открывает БД и не получает
tenant overrides из сети. Generated helpers/manifest реализует build tool I07.

**Текущая реализация.** `CatalogSpec` принимает обычные module values,
`New`/`Check` валидируют полную сборку, а CLI компилирует и генерирует contracts.
Root `module` намеренно не получает `module.Messages`, i18n group или dependency:
hand-wired/Fx application сама группирует выбранные declarations.

**Application DX.** Каждый модуль может назвать свой обычный
конструктор, например `NewMessageDefinitions`; это не framework symbol.
Приложение собирает возвращённые `i18n.Module` в `CatalogSpec`, вызывает
`i18n.New` и передаёт snapshot/view потребителям. Fx value group, если
она удобна, объявляется в application wiring; для этого не нужен
`i18nfx` или i18n type в root `module`.
Текущий module generator не создаёт group annotations и не распознаёт bare
slice как named contribution. Группировка остаётся явной: application-local
annotation либо именованный composition result; нельзя обещать её появление
только от `ProvideKind`. Deployment profile и grammar profile — разные настройки.

### X02. `errs` + auth/CRUD/transport: текст не ломает путь и классификацию

**Механизм и референс.** Существующий [error flow](../ai/flows/FL-011-an-error-becomes-an-http-status.md)
и I06. Public path формируется до локализации; тот же catalog обслуживает
прикладные сообщения и `errs.MessageSource`, сохраняя разные semantics этих API.

**Зачем.** Переведённая validation error с внутренним именем поля или изменённым
code — дефект интеграции. Auth refusal и CRUD validation должны использовать
одинаковую разрешённую locale policy, даже когда service не был вызван.

**Наша адаптация.** Для выбранной error vocabulary проверяется mapping
`Code → message schema/разрешённые Params`; path-specific wording и labels
выбираются после service/mapper hops. Tenant override не меняет `Codes`, kind,
wire path или раскрываемые параметры. Diagnostics не превращают private
constraint/table/SQL data в public аргументы — сохраняется
[D-044](../ai/decisions/D-044-the-public-payload-names-nothing-internal.md).

`MessageSource` получает Violation, но не `Fault.Entity` или module identity.
Лестница `first.last.code` не является module namespace: одинаковые
`name.required` в разных модулях требуют domain-bound mapping/source на
presentation boundary либо глобально однозначного mapping. Domain не выводится
из таблицы/SQL source. Внешний validator тоже не готовый message schema:
текущий bridge переносит Tag в Code и `param/value` в Params; приложение
нормализует свои tags, исключает чувствительные values и проверяет wire paths.

При добавлении custom codes общий registry начинается с `errs.StandardCodes()`;
`WithCodes(customOnly)` заменяет default vocabulary, а не дополняет её.
`Codes.Add` с тем же kind сохраняет первое wording, поэтому переводы и
переопределения находятся в catalog layers. В coverage входят также access
codes и authored public messages. Отдельная compatibility fixture проверяет
двойной fallback: старый `errs.Messages` может вернуть code default раньше,
чем `port` попробует существующий `Violation.Message`; новый adapter не меняет
этот приоритет незаметно.

Полностью custom renderer надо собирать с теми же codes/resolvers/лимитами, что
и default. Для обычного подключения resource `Rendering(options...)` добавляет
messages/codes/limits поверх generated renderer и сохраняет автоматический
`port.Hops(service, mapper)`. `WithRenderer` по-прежнему означает полную замену.
Проверяются переименованные и вложенные DTO paths во всех трёх HTTP bindings
и CRUD gRPC, плюс полная лестница source/public-message/code fallback.

Для общих HTTP/auth errors используется `porthttp.Renderer`; gRPC statuses,
созданные раньше, не обещаем переводить повторно. Locale и snapshot выбираются
до нужной error boundary по I01/X03. Отсутствие перевода возвращает безопасный
fallback исходной ошибки; 500/Internal и health machine codes не зависят от
переводчика. Ошибка i18n не маскирует ошибку бизнеса.
Shared source подключается ко всем владельцам ответа: resource renderers,
auth middleware/guard, RouteSet access refusal, top-level Errors и CRUD gRPC.
Отдельно настраиваются `crudgin.Routing`, `crudnet.Routing` и Fiber
`ErrorHandler`: router 404/405 формируются собственными renderers. Их проверки
учитывают реальное routing-поведение binding, а не предполагают одинаковый
путь ошибок. До admission используется публичный source/locale policy.
Одного `Errors(WithMessages(...))` снаружи недостаточно: уже записавший ответ
CRUD handler или auth guard до него не дойдёт. Health detail JSON имеет свой
renderer; Error MessageSource сам по себе его не переводит.

**Текущая реализация.** Typed `ErrorMessages`, field labels, param allowlists,
localized provenance, one-view `ErrorPlan`/`View.ErrorMessages` и additive
`Rendering` реализованы. Сквозные HTTP triplet,
auth, router, CRUD gRPC unary/stream и path-hop fixtures проверяют, что human
wording не меняет codes/status/path/redaction. Tenant admission и выбор overlay
остаются application boundary.

**Текущий DX.** Для полностью ручного renderer:

```go
renderer := porthttp.NewRenderer(
    porthttp.WithMessages(messages),
    porthttp.WithCodes(codes),
    porthttp.WithResolvers(port.Hops(service, mapper)...),
)
```

`messages` может быть обычным `errs.Messages` или реализованным
`snapshot.ErrorMessages(errorSpec)`. Для generated resource используется
`resource.Rendering(crudhttp.WithMessages(messages))`; `WithMaxViolations` и
остальные overrides передаются тем же additive способом.
На operation boundary с готовым view source создаётся через
`view.ErrorMessages(plan)`, чтобы transport не повторил locale resolution.
Для gRPC используются соответствующие options `crudgrpc`.

### X03. Tenancy: разрешённая языковая политика и изолированные overlays

**Механизм и референс.** Verified scope из
[tenancy](../ai/flows/FL-033-a-request-becomes-a-tenant-bound-statement.md)
и catalog overlays I02. Разделяем два входа: кто вправе видеть каталог и
какой язык предпочитает получатель. Locale никогда не доказывает identity.

**Зачем.** Tenant может выбрать default language и свою терминологию, а
пользователь — другой язык. Каталог A, отрицательный lookup A и настройки A
не должны попадать в ответ B даже при одинаковых message IDs и locale.

**Наша адаптация.** После auth и `Authority.Bind` приложение проверяет
`Authority.Scope(ctx, ClassRead)` и читает разрешённую
policy из своего settings/control-plane слоя: available locales, default,
formatting policy, разрешённые domains и revision tenant overlay. В
`tenancy.Resolution` этих настроек нет. Identity берётся из проверенной scope,
не из query/header с tenant ID и не из имени файла перевода.
`tenancy.From` только извлекает scope; он не заменяет проверку authority,
admission и заявленную `Revalidate` policy.

Для tenant overlay разрешённый порядок внутри одной locale:
tenant override → application override → module default. Переопределять можно
только объявленные overridable messages, сохраняя schema/output kind; системные
security messages можно запретить переопределять целиком. При отсутствии
ключа пробуем следующий разрешённый слой/язык того же effective catalog,
никогда чужой tenant. Загрузка/публикация overlay требует собственного права,
не только членства в tenant; tenant data не попадает в общий frontend export.

Отказ identity/admission не превращается в обычный language fallback: tenant
каталог не читается, исходная ошибка отображается публичным безопасным source.
После успешного admission отсутствие необязательного overlay может означать
shared app wording, если это прямо разрешено policy. Отказ settings storage и
пустой overlay — разные результаты. Last-known-good допускается только для
того же разрешённого scope и generation, с заявленной freshness policy.

Приложение создаёт immutable render view один раз на request/получателя:
effective snapshot, policy revision и выбранный formatting context. Locale
хранится в существующем `port` key. Если общий `MessageSource` выбирает view
через application-owned typed context value, это snapshot binding, не второй
locale key. Он не перечитывает current catalog на каждую violation.
Смена tenancy Epoch не равна публикации перевода: scope epoch, policy revision
и catalog digest независимы; старый tenant binding не легализуется новым hash.

**Текущая реализация.** `TenantOverlay` проверяет layer ordering, override
permissions и запрещает overlay-on-tenant; snapshot не содержит tenant identity.
`Authority.Bind/Scope`, locale settings store, publication authorization и
выбор effective snapshot остаются приложению. Автоматического tenancy binding,
tenant locale store или network publisher нет.

**Application DX.** Application boundary делает
`authority.Bind → разрешённая policy → effective catalog view → Resolve → port.WithLocale`.
App-owned `errs.MessageSource` берёт уже выбранный view и делегирует его
error adapter; i18n package получает обычные значения и не импортирует tenancy.

### X04. OTel: видимость выбора и рендеринга, а не только вызова service

**Механизм и референс.** Terminal observations существующего cache и
[vvotel](../modules/en/otel.md), injected
[OpenTelemetry APIs](https://opentelemetry.io/docs/languages/go/instrumentation/).
Сам i18n знает, был ли exact hit, fallback или отказ; source с результатом
`(string, bool)` уже потерял эту информацию.

**Зачем.** Command span не показывает, что половина русских сообщений стала
английской. Нужны ответы на вопросы: вырос ли fallback, какой класс ошибок
мешает рендерингу, сколько стоит загрузка, сохранилась ли старая версия после
неудачного обновления. Для этого не нужны тексты и tenant IDs в telemetry.

**Наша адаптация.** i18n публикует optional typed observation callback с
`context.Context`, закрытыми operation/outcome/reason, duration и bounded
counts. Событие создаётся до сведения результата к `MessageSource` и ровно
один раз на публичный resolve/render, включая error adapter. Внутренний обход
fallback graph не генерирует событие на каждого кандидата; повторного учёта
того же render на adapter boundary нет. Observation не содержит message ID,
Violation/Params, key/path, текст, error cause, revision/hash, tenant/user ID
или произвольный attribute map.

Приложение может добавить свой небольшой factory, который принимает
те же `MeterProvider`/`TracerProvider`, что были переданы `vvotel.New`, и
переводит observation в upstream metric/trace API. Runtime i18n остаётся
OTel-free, `vvotel` не импортирует i18n-owned types. У `Telemetry` нет публичного
универсального meter/record API. Не выдаём эту связку за `vvotel.I18n` и не
объявляем новые поля частью действующего `vv-otel/v1`. Универсальный
hand-wired/Fx factory не является shipped i18n API.

| Предложенный сигнал | Вопрос / правило |
|---|---|
| Счётчик render/resolve и histogram duration | Закрытые outcomes: success, fallback, missing, invalid, limited, canceled, timeout; terminal outcome одного вызова учитывается один раз |
| Load/validate counters и duration | Операционная ошибка каталога отличается от отсутствующего сообщения; результат активации пишет её владелец после swap |
| Activate/rollback result | При невалидном кандидате зафиксирован отказ, активный snapshot не изменён; сигнал поставляется вместе с механизмом X07 |
| Optional event на recording span | Bounded outcome/reason, общий лимит events на operation; по умолчанию нет span на каждый placeholder/violation |

Имена первой instrument schema принадлежат приложению, например
`app.i18n.render.duration`; они не используют namespace `vv.*`.
По умолчанию labels — только enums. Даже locale добавляется лишь из
construction-time process-wide allow-list с лимитом, сохраняющимся при reload;
tenant-specific supported sets не расширяют cardinality незаметно.
Метрики работают независимо от trace sampling.

`vvotel.Service` завершает command span до возврата ошибки; её локализация
происходит позже. Callback получает живой request/server/render context от
application transport boundary по I01, а не пытается дописать завершённый
command span. Fallback не меняет HTTP status и не является автоматически
ошибкой span — семантика наблюдаемой операции отделена от бизнес-ошибки,
как требует [OTel error guidance](https://opentelemetry.io/docs/specs/semconv/general/recording-errors/).

Nil callback — no-op. Паника наблюдателя/SDK не меняет текст, исходную ошибку
или бизнес-панику; callback обязан быть bounded и nonblocking. Таймаут
произвольной синхронной функции не обещается. Export queues/drop policy,
flush/shutdown — приложение; renderer не создаёт goroutine и не ждёт сеть.
Логи при необходимости используют `port.Logger(ctx)` с кодами причин;
trace enrichment и sampling принадлежат приложению, без автоматического
логирования каждого перевода. Полный Explain остаётся отдельной диагностикой.

**Уже есть.** `vvotel.Service/Store/Cache/CacheMemory`, closed
[registry/schema](../modules/otel-spec.md), caller-owned providers и optional
`i18n.Observer`. I18n вызывает типизированный callback ровно на terminal
operation и изолирует panic. Отсутствует только application-specific
Observer → OTel adapter; `Store` spans не заменяют его.

**Примерный DX.** Proposed application wiring:

```go
observe := applicationI18nObserver(meterProvider, tracerProvider)
catalog, err := (i18n.Loader{Observer: observe}).Load(ctx, bundle)
```

`applicationI18nObserver` — код приложения, не новый framework bridge.
Один обычный app factory может обслуживать ручную и Fx сборку. Полноценный
публичный vvotel adapter возможен только после отдельного обоснования
base-owned seam; roadmap не вводит root telemetry facade ради этого случая.

### X05. Cache: языковая identity переживает shared flight

**Механизм и референс.** Typed keys и tenant partitions существующего cache,
[D-084](../ai/decisions/D-084-shared-cache-flights-do-not-inherit-a-waiters-context.md).
Отдельно рассматриваем cache immutable catalog/template и cache итоговой строки.

**Зачем.** `key = messageID` возвращает чужой язык; `key = locale + messageID`
всё ещё смешивает tenant overlays, revisions и аргументы. Чтение locale из
loader context тоже неверно: shared work намеренно не наследует caller values.

**Наша адаптация.** Первый runtime держит проверенный catalog в памяти; внешнее
кэширование финальных строк не требуется. При его выборе key описывает все
входы, влияющие на результат: effective catalog digest, message/schema revision,
message locale, formatting locale, timezone/currency/presentation policy и
детерминированную identity аргументов. Для private данных нужны разрешённые
tenant/user partitions; hash сам по себе не делает Params анонимными.
Одного digest недостаточно для вычисления строки: loader получает сами
bounded typed аргументы либо разрешённый immutable payload по этой identity;
key, payload и snapshot dependency обязаны соответствовать друг другу.
Negative cache также scoped и versioned; публикация нового перевода меняет
namespace результата и делает старый miss недействительным.

`tenancycache.Keyed` строится после admission на каждой операции до lookup,
включая hit. Tenant partition не заменяет per-user authorization. Tenancy Epoch,
cache.Generation и catalog revision решают разные задачи; обновление текста
не должно искусственно менять identity tenant.
Общему loader передаются typed key и явная immutable dependency. Он не читает
`port.LocaleFrom(ctx)`, principal или render view из request context и не
захватывает первый caller через closure. Нужная scope проверяется/привязывается
явно через разрешённый tenancy механизм; `Disabled` сохраняет те же правила.
Telemetry shared load — метрики, не дочерний span первого ожидающего клиента.

**Текущая реализация.** `View.RenderKey` детерминированно включает snapshot,
message/formatting locale, zone, presentation и copied typed arguments;
cache/tenancycache сохраняют loader isolation и partition/generation. i18n не
импортирует cache и не включает memoization скрытым default: app-owned cache key
добавляет разрешённую tenant/user partition и хранит inputs отдельно от hash.

**Application DX.** Application declares typed `RenderedMessageKey`, оборачивает
его текущим `tenancycache.Keyed` и вызывает cache с loader, использующим key/
snapshot. Сам `i18n.Render` остаётся обычным вызовом, пригодным без cache.

### X06. Jobs: восстановленная tenant identity раньше языка и каталога

**Механизм и референс.** Delivery policies I10 на существующих
[durable jobs](../ai/flows/FL-035-a-committed-decision-becomes-a-delivered-effect.md)
и `tenancyjobs`. Очередь восстанавливает право работать от имени tenant;
приложение после этого выбирает адресата, его policy и сообщение.

**Зачем.** Подписанное задание может пережить смену tenant lifecycle, прав
адресата, locale и каталога. Ни locale в payload, ни pinned revision не дают
права прочитать данные и отправить их старому адресату.

**Наша адаптация.** Handler сначала проходит штатное tenant restoration и
admission, затем проверяет разрешение на получателя/данные и применяет pinned/
current policy I10. `tenancyjobs` восстанавливает tenant, а не актуального actor
с набором прав; recipient authorization остаётся в приложении.
Payload содержит разрешённый message intent/typed args либо ссылку на domain
данные с последующей проверкой; секреты и request context не сериализуются.
Catalog/policy pin проверяется на принадлежность восстановленному scope.

Утраченный pin, неизвестная schema и временно недоступное хранилище получают
разные delivery outcomes по политике jobs; не каждый отказ надо бесконечно
retry. Публикация каталога не меняет job type/deduplication key скрыто.
В batch на каждого адресата создаётся отдельный view: смена locale/tenant не
мутирует shared localizer. Observation X04 использует живой handler context;
ошибка metrics exporter не делает повторную отправку письма необходимой.

Pin действует с момента capture, а не с первой попытки: `jobs.After` может
отложить её надолго. Перед enqueue архив/pin должен быть долговечным и
гарантировать доступность до заявленного предела доставки. GC не удаляет
артефакт между admission pin и фиксацией задания: приложение согласует pin
registration с enqueue либо получает durable retention lease до enqueue.
Неудавшийся enqueue может оставить ограниченный orphan pin для последующей
очистки; успешно поставленная job не остаётся без обещанного pin. Если срок
планирования выходит за допустимый pin horizon, enqueue отказывает либо
приложение явно выбирает другую presentation policy до постановки.

**Текущая реализация.** i18n даёт immutable `Message`, `SnapshotRef`, view и
bounded in-process `Lease`; `tenancyjobs` даёт durable tenant restoration.
Locale/catalog policy не встроена в seal/actor, а controller lease не durable.
Application payload, archive/pin transaction, recipient authorization и retry
outcomes остаются владельцу worker.

**Application DX.** Worker: `restore tenant → authorize recipient → select view →
Render(ctx, message) → deliver`. Интеграционный сценарий проверяет queued retry и
изменённое предпочтение; восстановление не заменяется `WithLocale`.

### X07. Storage, config, runtime и health: жизненный цикл каталога

**Механизм и референс.** Immutable activation I08 через существующие
[storage](../modules/en/storage.md), [runtime](../modules/en/runtime.md),
[health](../modules/en/health.md) и [vvcfg](../modules/en/vvcfg.md).
Загрузка bytes, validation, activation и готовность — разные операции.

**Зачем.** Ошибка нового перевода не должна обнулить рабочий catalog. И наоборот,
процесс без обязательного initial bundle не должен отвечать ready только потому,
что в DI зарегистрирован конструктор. Reload не должен жить бесконтрольно.

**Наша адаптация.** Strict config задаёт source, locales, grammar/budgets и
разрешённую stale policy. Сначала внедряется embedded startup bundle X01.
Для external bundles application-owned loader читает доверенный immutable
object/version через Store, ограничивает bytes, закрывает stream, проверяет
manifest/hash/schema и строит кандидат отдельно. Tenant object namespace
определяется проверенной scope, а не locale или публичным URL параметром.

Только владелец активации заменяет active handle; при validation failure
старый snapshot остаётся доступным в пределах policy. Одновременные reload
используют ожидаемую revision/сериализацию публикации: медленный старый loader
не может перезаписать новый catalog. Rollback — явная операция. Активные/pinned
snapshots, их bytes и число загрузок ограничены. Retention pin включает срок
от capture через scheduled delay, backlog, deferrals и retries, плюс отдельно
объявленное время хранения для последующей проверки результата.
`jobs.Policy.Retention` относится к terminal jobs и не задаёт срок доступности
каталога до первого запуска. Для неограниченного ожидания вводится конечная
delivery/pin expiry: после неё job не подменяет версию, а получает явный отказ
по delivery policy. GC соблюдает зарегистрированные pins/leases, а обычный
evictable cache не является единственной копией артефакта.
Отдельные реплики могут обновляться в
разное время: fleet rollout решает deployment, а не локальный pointer swap.

Watcher/poller, если выбран, предоставляется через существующий `runtime.Runner`
и supervisor; constructor не запускает фоновые задачи. Это infrastructure
activity и для API replica: помещение только в `module.Workers` отключит reload
под `module.Serving`. Application wiring включает именно этот runner, не все
business workers. Drain останавливает
новые активации и закрывает принадлежащие загрузчику ресурсы.
Health probe читает состояние snapshot, не рендерит сообщения и не ходит в TMS
на каждом scrape. Нет initial required catalog — startup refusal/NotReady;
необязательное обновление не удалось, last-known-good допустим — Degrading
либо Informational по решению приложения. `Live` остаётся независимым.
Public health сохраняет stable codes; подробный report доступен оператору.

Публикация/rollback может вызвать app audit с action/revision после успешной
операции; обычный Render не пишет audit. Общий audit framework не становится
условием поставки i18n. Сигналы load/validate/swap отправляются по X04 с разных
границ; storage span для `Open` не заменяет измерение чтения и compilation.

**Текущая реализация.** `Load`/`LoadFS` строго и bounded загружают canonical
artifact; `Controller` реализует opaque-CAS activation/rollback, last-known-good,
bounded retention/pins и explicit `Prune`. Он не является `runtime.Runner` и не
создаёт watcher, timer, durable pin store или health contribution. External
storage/polling, config, readiness, drain и fleet rollout остаются приложению.

**Application DX.** Application wires `load-and-validate` до activation API/workers.
Если нужен reload, она добавляет свой `runtime.Runner`, который читает,
валидирует и вызывает `Controller.Activate`, и отдельный `health.Probe`
над состоянием этого runner. Сам `Controller` не реализует ни один из
этих interfaces. Нет `i18nstorage`, `i18nhealth` или универсального i18n watcher.

### Сквозные пользовательские пути

Путь API: public language hints → auth/tenant admission → разрешённые settings
и immutable view → locale в `port` → business command → public-path resolution
→ wording через тот же view → terminal i18n observation → HTTP/gRPC response.
Request span живёт до окончания presentation; ранняя ошибка admission использует
публичный source. Private catalog не требуется, чтобы отобразить отказ доступа.

Путь worker: durable tenant restoration → recipient authorization → pinned/
current policy → нужный snapshot → Render → delivery. Cache/shared work
получает explicit inputs, telemetry — свой действующий context; ни один шаг
не заимствует язык/права первого HTTP запроса.

Для `remotehttp` приложение отдельно решает, отправлять ли уже нормализованную
locale upstream; существующий `remotehttp.WithRequestHook` позволяет задать
header. Identity, raw headers и catalog handles автоматически не
переносятся. Входящий public message можно сохранить либо заменить своим
message по известному code; повторная локализация проходит штатные path/code
правила и не парсит чужой human text. Общая ревизия каталогов между сервисами
не предполагается. В текущем public envelope нет Params/domain/schema/revision,
поэтому нельзя обещать восстановление параметризованного сообщения для местного
перевода; при отсутствии проверенного mapping сохраняется разрешённый upstream
text или применяется безопасный общий fallback. Для frontend действует I09.

| Интеграционный checkpoint | Что он должен обнаружить |
|---|---|
| Два module sets, одна неверная required translation, API и worker profiles | Bootstrap отказывает до обслуживания; доктор не исполняет providers; выбранные роли не скрывают неполную проверку |
| Custom renderer, renamed/nested DTO path, auth refusal, HTTP triplet и gRPC | Потеря `port.Hops`, code registry или operation context при подключении messages |
| Router-level 404/405 в `crudgin.Routing`, `crudnet.Routing`, Fiber `ErrorHandler` | Отдельный renderer остался без source; проверить доступные отказные пути каждого binding и публичную locale до admission |
| Два tenant с одним ID/locale и разными overrides; unknown/inactive scope | Чужой текст/negative cache, чтение private catalog до admission, fallback вместо отказа авторизации |
| Один request с несколькими violations во время reload | Смешивание snapshot/policy revisions внутри ответа |
| Успешный fallback, missing, unsampled request и observer panic | Двойной учёт, потеря метрик без span, изменение исходной ошибки или результата из-за telemetry |
| Тысячи tenant/IDs/revisions, PII canaries | Неограниченные metric labels, private args/text в traces/logs, незаявленные поля `vv-otel/v1` |
| Cache hit/miss/Disabled; два языка и shared flight | Locale/scope из чужого context, отсутствие auth на hit, key без formatting/catalog inputs |
| Queued retry после смены lifecycle, прав адресата и языка | Pin вместо авторизации, восстановление одного tenant как actor, неверная current/pinned policy |
| Отложенный первый запуск позже обычного retry window, backlog и истёкший pin | Каталог удалён до первого запуска; enqueue/expiry/GC нарушили обещанный lifetime; latest незаметно заменил pin |
| Invalid reload, concurrent publications, pinned retention, health probe | Потеря last-known-good, перезапись нового старым, unbounded snapshot retention, зависимость liveness от каталога |
| i18n-only и application-owned i18n + tenancy + OTel + errs сборки | App factory должен явно передавать authority, snapshot/view и providers; optional components выключаются без смены текста, codes и dependency graph базового consumer |

## Собственная ценность: полезные комбинации

Это кандидаты на отличительные возможности Frostgrove, а не заявление, что
каждая идея впервые придумана здесь. Проверять их ценность нужно на пути
пользователя, а не количеством новых packages.

| Комбинация | Что пользователь получает сверх отдельного translator | Из чего собирается | Как доказать пользу |
|---|---|---|---|
| Объяснимый перевод | Один отчёт отвечает, почему выбран язык, ключ и слой, какая версия дала текст и где сработал fallback | I01 + I02 + I08 + I11 | Убрать ключ из `fr-CA`, получить fallback и установить причину без логирования персональных аргументов |
| Сообщение как проверяемый контракт модуля | Модуль объявляет текст/схему один раз; приложение переопределяет wording; Go/TS получают типы и совместимые public subsets | I02 + I05 + I06 + I07 + I09 | Переименовать required argument: CI останавливает несовместимый каталог/клиент; правка wording не меняет ID и error code |
| Воспроизводимое представление между request и worker | Сообщение можно показать сейчас или позже с осознанной политикой языка/версии, без скрытой зависимости от ambient context | I04 + I05 + I08 + I10 | После смены языка и rollback каталога pinned delivery воспроизводится, current-policy delivery использует новый выбор |

Первую комбинацию можно получить уже на узком cardinal-профиле.
Вторая не обязана ждать общего Go/JS formatter: IDs/types полезны сами по себе.
Третья не требует, чтобы i18n импортировал jobs, audit, storage или tenancy.

## Границы реализации и совместимость

Сохраняются [D-048](../ai/decisions/D-048-the-contract-manifest-is-closed.md),
[D-033](../ai/decisions/D-033-optional-dependencies-are-their-own-modules.md),
[D-051](../ai/decisions/D-051-a-satellite-carries-one-dependency-decision.md) и
[extension architecture roadmap](2026-09-01-extension-architecture-roadmap.md).
Они ограничивают граф зависимостей, но не заменяют содержание механизмов выше.

- Рабочий путь — один optional module `github.com/frostgrove/vv/i18n`, сначала
  один public package. Каталог, resolver, compiler-facing types и error adapter
  организуются по файлам; это одна выбранная i18n-экосистема.
- Root `errs`/`port` остаётся без third-party i18n dependencies и без нового
  translation facade. i18n адаптирует существующий MessageSource; обратного
  импорта и внесения i18n в contract manifest нет.
- Runtime не тянет Fx, router, OTel, audit, tenancy, jobs backend,
  storage provider или translation SaaS SDK. Нет `i18nhttp`, `i18ngrpc`,
  `i18notel`, `i18ntenancy` и других packages пересечения двух расширений.
- Существующие transports остаются владельцами header/metadata projection.
  Нужный opt-in locale precedence меняется там, с parity/compatibility tests;
  новый transport bridge ради этого не нужен.
- Для module contribution достаточно обычных typed values и передачи в
  application root. Отдельные reflection registry, observer framework,
  service locator или новая container abstraction не нужны.
- Compiler/tool distribution выбирается отдельно от runtime. Артефакт можно
  подготовить вне процесса; загрузка не выполняет сеть, package init discovery,
  environment fallback или изменяемый global locale.

## Поставка по завершённым пользовательским срезам

Текущий результат отделяет shipped module contract от application-owned
интеграций:

| Этап | Текущий статус |
|---|---|
| **M0** | Завершён: выбран и зафиксирован `frostgrove-mf2/v1`, `messageformat-go/v0.8.6`, locale/time-zone identities, dependency boundary и bounded capability corpus. |
| **M1** | Завершён для module/transport seams: resolver, immutable catalog/view, typed messages, error adapter, observer, strict loading и CRUD HTTP/gRPC precedence реализованы. |
| **M2** | Завершён для bounded authoring toolchain: canonical source, source/review digests, extract locations, двухфазный loss-aware merge, fail-early review, context-aware review/check/pseudo/compile/generate/export и tenant-overlay invariants реализованы. Operator output ceilings применяются внутри producers до proportional work. Application composition и внешние providers не генерируются. |
| **M3** | Завершён для объявленного профиля: exact decimals/integers, cardinal/ordinal/select/multi-selector, formatting-locale separation, date/time/money/unit, rich type/id/direction/subparts и bidi покрыты. |
| **M4** | Частично и намеренно: Go/TS type export, public manifest/address и in-process controller/pins реализованы; JS formatting parity, external distribution/watcher, durable job pins, tenant control plane и runtime/health wiring остаются приложению. |

Ниже сохранён первоначальный milestone plan как историческая матрица
acceptance-сценариев. Формы будущего времени в этой таблице описывают исходный
план, а не текущую готовность; актуальный статус приведён выше.

| Этап | Содержание | Проверяемый результат |
|---|---|---|
| **M0 — реальный сценарий и capability profile** | Выбрать сценарий/владельца/корпус; испытать go-i18n cardinal baseline и richer-кандидата при необходимости; зафиксировать engine/data versions, grammar, source/argument schema, supported corpus и dependency allow-list | Таблица поддерживаемых/отвергаемых конструкций, реальные примеры переводчика, dependency/Go-version evidence. Если `errs.Messages` хватает, full-i18n не строится |
| **M1 — небольшой полезный runtime** | I01/I02/I03/I05/I06 и минимум I07/I08/I11/I12; X01/X02 module bootstrap и все error renderers, X03 tenant defaults/shared view, X04 typed observation, X07 embedded startup | App message и error family; сохранены hops/codes/context; module validation до API/workers; tenant admission до settings; callback не меняет результат; base dependency graph прежний |
| **M2 — authoring и проверенная системная сборка** | Typed generation, extract/merge/review, Explain/coverage/pseudo; X03 validated tenant overlays, optional X04 app OTel wiring, X05 cache identity, X01 offline check | Неверный аргумент останавливает build; fallback объясним без PII; tenant overlays изолированы; общий `errs` contract сохраняется; способ composition выбирает приложение |
| **M3 — richer messages и presentation** | I03 richer profile и I04 formatters по реальному спросу; I12 metadata/cache/rich-output rules; отдельное решение о фактической locale в transport output | Select/ordinal/совместные selectors, decimal и zone/currency corpus для каждой обещанной capability; миграция profile проверена. Без этого не объявляем full MessageFormat/date support |
| **M4 — frontend, delivery и управляемые обновления** | I09 Go/TS types и проверенный JS target; I10/X06 tenant-restored worker; I08/X07 external load/activation/rollback, runtime/health и retention при необходимости | Private catalogs не выходят; версии совместимы; pinning переживает retry, admission и recipient checks; concurrent reload сохраняет policy/LKG; нужный runner работает и на API replicas |

Исторический порядок зависимостей: M1 после M0, M2 после стабильного manifest M1; richer engine в M3
может исследоваться параллельно M2. TS types и job policy не требуют всех
форматтеров M3; общий Go/JS runtime export требует конкретного compatible
profile. Hot reload, rich parts, TMS import и дополнительные форматы не блокируют
первый полезный релиз и не считаются включёнными по умолчанию.
Комбинация `errs + tenancy + OTel` остаётся application integration
checkpoint, а не release gate чистого i18n module: в ней должны быть
два module catalogs, разные tenant views и реальный error-rendering path.
Нельзя закрыть M2 только отдельными unit-тестами translator: должны пройти
соответствующие X01–X05 integration checkpoints. Jobs/reload checkpoints X06/X07
закрываются вместе с выбранными delivery/activation slices M4.

### Сценарии, которыми закрывается реализация

| Проверка | Наблюдаемая гарантия |
|---|---|
| Разные `q`, `q=0`, wildcard, malformed/oversized header, `zh-Hant`, неизвестный tag | Выбран supported locale либо явный no-match; запрещённый range не выдан за успешный match; вход ограничен |
| Header не совпадает с заранее выбранной locale; auth отказывает до service | Все включённые HTTP bindings и gRPC соблюдают precedence; ни один не подменяет выбор незаметно |
| Внутренний post-auth слой выбрал другую locale, handler вернул обычную ошибку | Внешний error renderer получает context операции; unary, stream и net/http fixtures различают этот случай и ранний auth refusal |
| Module `fr-CA`, app `fr`, app `fr-CA`, пропущенный ключ и цикл fallbacks | Приоритет слоёв/языков детерминирован; цикл отвергнут; один перевод не составлен из разных plural-каталогов |
| Русские/арабские формы, decimal scale, missing arg, unsupported ordinal | Каждая заявленная способность подтверждена; остальные конструкции отвергаются явно |
| Arabic/LTR plain text с разнонаправленными аргументами | Вставки изолированы до flattening; punctuation/числа не меняют порядок соседней фразы; rich output не является условием этой гарантии |
| Та же violation на нескольких языках и Internal/500 | Не меняются code/kind/status/path/wrapping/wire shape; internal details не становятся публичным текстом |
| Duplicate key, invalid template, огромные файл/аргумент/output, tiny output ceiling, cancellation и конкурентное чтение | Invalid artifact не активируется; producer отказывает до proportional clone/format/hash, canceled build не публикует output; чтение не видит частичных мутаций; budgets и race/fuzz fixtures проходят |
| Изменённый source hash/schema, старый binary, rollback | Review/compatibility policy срабатывает; snapshot воспроизводим; старый бинарник не принимает несовместимую схему |
| Go/TS export с private domain и неподдерживаемым синтаксисом | Private сообщения не выходят; unsupported conversion останавливает export; parity подтверждена только для subset |
| Retry после смены locale/catalog, потеря pinned artifact | Pinned/current policy имеет различимые результаты; отсутствие версии не маскируется |
| Inspection и обычная эксплуатация | Reasons ограничены; args/text/raw headers/identity не попадают в default logs, metrics и audit |
| Base-only, i18n-only и application HTTP/gRPC consumer с `GOWORK=off` | Независимые dependency graphs, одна i18n-экосистема, отсутствие комбинационных modules |

Эти строки остаются acceptance corpus. Реализованные module/transport гарантии
проверяет текущий test suite; durable/external application integrations из M4 не
следует считать частью i18n. Межплатформенное форматирование отдельно не заявлено:
TS export фиксирует типы и identity, а не parity runtime. Наличие одного `T(key)`
или плоского JSON loader ни один из этих результатов не заменяет.
