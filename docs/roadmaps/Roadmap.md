# Roadmap

Everything that was planned here is built. What follows is the remainder: eight
items, none of them a subsystem, four of them expiring at the first tag.

Two documents used to live at the repository root — one for the framework's
shape, one for the error subsystem — and between them they carried sixteen
sections of design and nine phases of delivery. Both are spent. The design half
is now `docs/decisions/`, the delivery half is the tree, and the consumer half
is `docs/modules/`. This document is the leftover.

## Where the tree stands

`crud`, `query`, `errs` and `port` are the contract manifest and it is closed
([[D-048]]). The error subsystem ships end to end: a driver error becomes a code
(`errs/sqlerr`, four dialects), a fault (`sqlfault`), every *other* violation the
same payload caused (`catalog` + `probe` + `repo/decorators/faults`), a
client-named path ([[D-043]]) and a public payload that names nothing internal
([[D-044]]). Four transports carry it — `crudnet`, `crudfiber`, `crudgin`,
`crudgrpc` — and the classification happens once, in `port`.

Both directions ship. `remote` holds another service's resource as a
`port.Repository`, over `crudhttp.Transport` or `crudgrpc.Transport`, and a
refusal arrives wrapping the same sentinel it would have wrapped locally
([[UC-018]], [[FL-018]]). A filter written in Go crosses intact, because the
closed predicate AST gained one marshaller ([[D-054]]); what cannot cross is
refused by name rather than dropped ([[D-053]]).

Four engines are live and tested: PostgreSQL, MySQL, MariaDB, SQLite.

## 1. The organisation name

`shardit-io` stays for now. "Shard it" promises horizontal sharding this library
does not do, and `github.com/shardit` is held by another account, so the `-io`
suffix is a workaround rather than a choice.

This is the one item on the list an agent cannot decide. It is a name the owner
will live with.

**The cheap moment is now.** No tag has been pushed and there is no remote, so a
rename costs a `sed` and nothing else. After `v0.1.0` it costs a deprecation
cycle.

Whoever renames next: a `sed` across the imports is the easy half. What breaks is
everything that is **not** an import, and it broke the same way twice already —
`go-rx-crud` → `rx` and `rx` → `vv` both leaked at the identical line, a `grep`
pattern in `make release` that still named the old module path. The full list:
`Makefile` (`version`, `release`), `go.work`, every `go.mod`, `//go:generate`
lines **and their copies as string literals in tests**, `exec.Command`
arguments, `docker-compose.yml` (project name and credentials), DSN environment
variables, the generated-file name and its `Code generated by` header, runtime
SQL identifiers, and test function names carrying the product name.

The guard that worked was `assertDirective`, which compares the generate lines
byte for byte and fails the integration suite rather than failing silently.

## 2. `errs` gets its own module

Decided, and deliberately not done yet. [[D-033]] is amended from *no external
requirement* to *no third-party requirement* so `errs` can be split; [[D-036]]
measured why it cannot be split **before** the first tag: every module requiring
the root then fails to walk its module graph, and no `replace` or workspace edit
fixes it. It ships as a package of the root module until the tag exists.

The reason to split at all is release cadence, not dependency weight. `errs` is
meant to outlive this repository — the JPA half of the split, a set of interfaces
and value types every Go service can adopt, including services with no database.
It should not be forced to move a version because a Fiber binding did.

## 3. The dependency-diff gate

`make check` runs three structural arms today — `check-deps`, `check-tiers`,
`check-todo`, `check-tidy` — and each was verified by breaking the invariant and
watching it fail. One arm is missing and it needs CI, which does not exist yet.

Snapshot `go list -deps` for **every public package** and fail the pull request
on any change, so dependency creep needs an explicit reviewed diff. That is the
shape `grpc-go#7766` uses; Kubernetes does the same thing with
`import-restrictions.yaml`. Both enforce the boundary with a *check* rather than
a module, and a check is the only thing that works inside a workspace — `go.work`
hides a root-module dependency leak completely, which is the measurement that put
this on the list.

## 4. `retract` in the release vocabulary

MVS has no upper bound, so lockstep **cannot** be mechanically enforced:
`go get vv@v0.2.0` followed by `go get vv/http/crudgin@v0.1.0` builds fine, and
the dangerous direction — old binding, new library — is what a bare `go get -u`
produces. `retract` in the root `go.mod` is the only lever, and there is nothing
to retract until a tag exists.

## 5. More engines

SQL Server, Oracle, CockroachDB. Each needs a live server in
`docker-compose.yml`, a corpus **capture** — the corpus is captured from a real
server, never written by hand — a `crud.Dialect`, a `catalog` back-end and a
`probe` matrix row. None of it can be done without the servers.

The control that must hold for a new engine:
`TestEveryClassifiableCorpusCaseGetsTheCodeItsClassNames`.

MariaDB is the precedent and it earned its place three times over: it settled a
question about MySQL error `4025`, it turned up a divergence nobody predicted
(`1366` is `22007` there and `HY000` on MySQL), and it gave `crud.MySQL`'s
"targets MySQL and MariaDB" its first test — 19 conformance subtests and 110
engine-behaviour subtests, none of which had ever run.

## 6. `CodeExclusion` is reachable from no engine

Two gaps in `errs/sqlerr`, both left open on purpose:

- **No `23P01` arm.** PostgreSQL's exclusion-constraint violation is not in the
  corpus, so `errs.CodeExclusion` is declared, kind-mapped and rendered — and
  produced by nothing. Provoking an `EXCLUDE` and capturing it is the cheap
  follow-up.
- **No class-23 fallback.** A MySQL class-23 number nobody provoked stays
  unclassified rather than being guessed at. The classifier is keyed on
  `(dialect, sqlstate, native)` and no arm of it is a SQLSTATE-class test,
  because three of the four engines break that assumption in three different
  ways ([[D-046]]).

## 7. Whether the framework retries a retryable class

[[D-040]] says no, and it is written and in force.

The argument for yes is recorded rather than dismissed: a serialisation failure
inside a repository-**owned** transaction is the framework's own to retry, and
nobody else can see it. If that argument wins, D-040 is superseded rather than
bent.

## 8. Two shapes left undecided

**The tag-name helper.** The validation bridge is dependency-free and lives in
`errs`, which settled where it goes. What is still open is whether `errs` should
ship the `RegisterTagNameFunc` helper itself — that would mean naming the `json`
tag in a package that otherwise knows nothing about transports. Nothing ships
today, and the consequence is pinned instead:
`TestWithoutTheTagNameFuncEveryPathIsGoFieldNames` in `test/bridge/` asserts that
a consumer who forgets the registration gets Go field names in every path.

The question got sharper when gRPC landed: a fourth transport exists whose wire
names are not the `json` tag either, so a helper naming one tag would have been
wrong for it on the day it shipped.

**Generated wiring for Fiber and Gin.** `cmd/vv -binding` writes `net` or
`none`. Fiber and Gin wiring would make a generated file import a satellite
module — which a consumer may do and the library's own generated output may not
([[D-033]]). `-binding none` plus `ServingFor` is the hand-written way in today.

## What is deliberately not on this list

Settled, and each would need a superseding decision rather than a change of mind.

| | Answer | Where |
|---|---|---|
| Pre-flight probing as a default | **No, for any endpoint shape**, and no mechanism ships | [[D-042]] |
| Cap defaults — constraints, rows, probe time, savepoints | Exported constants: 16, 50, 250ms, 32. **No cap** on the catalog load | [[D-042]] |
| Whether the envelope splits the two origins | **It does not.** One list, grouped by what the client can act on | [[UC-017]] |
| Composite primary keys in the probe | The probe refuses rather than being silently wrong; general support stays a `crud` seam question nothing here opens | [[D-042]] |
| `crud/crudtest`'s recorder growing a `DataSource()` | **No.** The premise was wrong — `crud.KeyOf` already keys a recorder as itself | [[D-041]] |
| CHECK evaluation in the probe | Not shipped. Recovering the expression from engine text is DDL parsing, which [[D-041]] forbids in as many words | [[D-042]] |
| NOT NULL, length, range and enum checks in the probe | Not shipped, in Go or in SQL. Every gap is a chance to report a violation the server would not have raised | [[D-042]] |
| Anything else joining the contract manifest | The manifest is `crud query errs port` and is **closed** | [[D-048]] |
| RFC 9457 problem+json as a second envelope | Not shipped. The `Renderer` seam is there for a consumer who wants it | — |
| A generated per-model client | Not shipped. `remote.Resource` is typed by the model; per-field methods would be a second generator with nothing new to say | [[UC-018]] |
| Retries, circuit breaking or back-off in the client | **No.** The framework does not retry for the caller, and that holds on the calling side too | [[D-040]] |
| A Fiber or a Gin client transport | **No.** A consumer calling out uses `net/http` whatever it serves with, and the three bindings register the same routes | [[FL-013]] |
| `crud.PrimaryOnly` and `crud.Unsorted` crossing a transport | Not possible: the DSL has no word for either, and the document decoder refuses an invented key. Accepted and documented rather than refused | [[D-053]] |

## Conventions

`[[D-NNN]]`, `[[UC-NNN]]` and `[[FL-NNN]]` point into `docs/`. A decision that
does not exist yet is written as *the proposed D-NNN* rather than as a link, so
nobody follows it to nothing.

A decision may exist before the code it governs. Those carry **`in force from
phase N`** in their status line and head their evidence `Proven by (owed)`, so a
reader can tell a rule the tree obeys from a rule the tree owes. **The set is
currently empty.** The next decision written ahead of its code goes back into it.
