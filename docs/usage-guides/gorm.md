# Killing CRUD boilerplate in a gorm project

You already use [gorm](https://gorm.io). Your models are declared, your
associations work, `AutoMigrate` keeps the schema honest. What you are tired of
is the other 80% of every resource: the list handler with page/limit/sort/filter
parsing, the get handler, the create handler, the patch handler that has to tell
"field absent" from "field set to null", the delete handler, and the same five
error mappings in each one — times every model you own.

rx-crud takes that layer. **gorm keeps everything it is good at**: models,
migrations, associations, hooks, the query builder for the queries that carry
real business meaning. rx-crud replaces the mechanical CRUD around them.

The two share your `*sql.DB` and your transactions, so this is additive. Nothing
about your existing gorm code changes — and your gorm structs are the models,
unchanged.

# Part I — what you get

## 1. The declaration

Per model, forever:

```go
var Members = basic.Define[Member, uint, MemberUpdate]("members",
    basic.Scope(crud.IsNull("DeletedAt")))     // gorm soft deletes, once

app.Use("/members", crudfiber.New(Members.Bind(src)).Routes())
```

`Member` is **your existing gorm struct** — `gorm.Model` embedded, associations
and all. `MemberUpdate` is generated by `rxcrud`. Drop the `basic.Scope` line if
the model has no `DeletedAt`.

That is the entire per-resource cost. Everything below falls out of those lines.

---

## 2. The API that comes out

| Route | |
| --- | --- |
| `GET /members` | list — filter, sort, paginate, search from the query string |
| `POST /members/query` | list — the full JSON filter DSL |
| `GET /members/count`, `POST /members/count` | count with the same filters |
| `GET /members/:id` | one row, `?preload=…&select=…` |
| `POST /members` | create |
| `PATCH /members/:id` | partial update |
| `PUT /members/:id` | replace — where the database generates the key it will not create, so an unused id is 404 |
| `DELETE /members/:id` | delete |
| `POST /members/bulk-delete` | `{"ids": […]}` |

### Listing

```bash
curl '/members?page=2&limit=20&sort=-createdAt,name&q=ann&searchFields=name,email'
curl '/members?f=age:gte:18&f=name:startsWith:An&preload=team'
curl '/members?f=createdAt:gte:2026-01-01T00:00:00Z&select=id,name'
```

`f=field:op:value` repeats and ANDs. Only the first two colons are structural,
so timestamps survive.

```bash
curl -XPOST /members/query -d '{
  "page": 2, "limit": 20,
  "sort": ["-createdAt", "team.name"],
  "preload": ["team", {"path": "team.labels", "filter": {"slug": {"in": ["go","rust"]}}}],
  "filter": {
    "age":        {"gte": 18, "lt": 65},
    "team.name":  {"contains": "core"},
    "or":         [ {"name": {"contains": "ann"}}, {"teamID": 7} ],
    "not":        {"name": "spam"}
  }
}'
```

```json
{
  "items": [ … ],
  "page": 2, "limit": 20,
  "total": 143, "totalPages": 8,
  "hasNext": true, "hasPrev": true
}
```

`team.name` walks the association you already declared to gorm — see
[§14](#14-associations-filters-and-preloads).

Operators: `eq ne gt gte lt lte like notLike ilike contains startsWith endsWith
in notIn between isNull isNotNull`, plus `$`-prefixed and symbolic aliases. A
bare value means `eq`, a bare array means `in`, `null` means `IS NULL`.

Field names match case- and separator-insensitively — `createdAt`, `created_at`
and `CreatedAt` are the same column — so your TypeScript client keeps its own
conventions.

### Writing

```bash
curl -XPOST  /members     -d '{"name":"Ann","teamID":1}'
curl -XPATCH /members/42  -d '{"age": null}'
curl -XDELETE /members/42                     # {"deleted": 1}
```

The PATCH body is where most hand-written handlers get it wrong. Three states,
three behaviours, no `map[string]any` anywhere:

```json
{}                      → nothing happens, no UPDATE is issued
{"name": "Ann"}         → UPDATE members SET name = $1
{"age": null}           → UPDATE members SET age = NULL
{"age": 31}             → UPDATE members SET age = 31
```

And only what *changed* is written: sending a field that already holds that
value produces no SQL for it. That is the exact behaviour gorm's `Updates` with
a struct cannot give you — it cannot see a zero value you meant.

On create the body binds onto the model, then the auto-increment key is cleared
— a client cannot choose its own id.

### Errors

| Situation | Status | Body |
| --- | --- | --- |
| unknown filter field, bad value type, bad id | 400 | `{"error":"bad_request","path":"filter.nope","message":"unknown field \"nope\" on model Member"}` |
| row missing, or outside your access scope | 404 | `{"error":"not_found"}` |
| policy denied | 403 | `{"error":"forbidden", …}` |
| duplicate key, foreign key or NOT NULL violation; `FindOne` matched several rows; a stale `version` | 409 | `{"error":"conflict"}` |
| anything else | 500 | `{"error":"internal_error"}` — no detail leaks |

An unknown field is a **rejection**, never a silently ignored clause. That is the
difference between a typo you notice in five seconds and a filter that quietly
returns the whole table.

## 3. Bounding it: the handler config

The DSL is driven by untrusted input, so the handler takes a config. Everything
here is optional; empty lists allow anything the model maps.

```go
app.Use("/members", crudfiber.New(Members.Bind(src),
    crudfiber.WithQuery[Member, uint, MemberUpdate](&query.Config{
        Filterable:  []string{"Name", "Age", "CreatedAt", "Team.*"},  // `.*` allows a subtree
        Sortable:    []string{"CreatedAt", "Name", "Team.Name"},
        Selectable:  []string{"ID", "Name", "Age"},
        Searchable:  []string{"Name"},
        Preloadable: []string{"Team", "Team.Labels"},

        MaxDepth:      4,   // and/or nesting, and path length
        MaxConditions: 32,
        MaxPreloads:   4,
    }),
).Routes())
```

The other options on the same call:

| Option | For |
| --- | --- |
| `WithTransform` | render rows through a presenter — hide columns from the wire |
| `BeforeSave` | fill server-owned fields on create/replace |
| `BeforeUpdate` | inspect or reject a PATCH DTO |
| `WithScope` | add repository options per request (`?includeArchived`) |
| `ReadOnly` | mount only the read routes |
| `AllowClientID` | let a create carry its own primary key |
| `MaxBulk` | cap ids per bulk delete |
| `WithErrorHandler` | your own error → response mapping |

Depth, condition and preload limits apply whether or not you set the lists.

Every name above exists in `crudgin` and `crudnet` too, spelled the same, taking
the same arguments. The only difference is what the five callback options carry:
a `fiber.Ctx`, a `*gin.Context`, or an `*http.Request`. The ones that write a
response return nothing outside the Fiber binding, because neither
`gin.HandlerFunc` nor `http.HandlerFunc` returns an error.

## 4. Typed queries in Go

Not everything is an HTTP request. The generated metamodel gives compile-checked
filters over your gorm struct, associations included:

```go
members := specs.Executor(Members.Bind(src))

adults := specs.Where(store.Member_.Age.Gte(18)).
    And(store.Member_.Team.Name.Eq("core"))        // walks the association

list, err := members.FindAll(ctx, adults, crud.OrderBy(store.Member_.CreatedAt.Desc()))
page, err := members.FindPage(ctx, adults, crud.Page(2), crud.Limit(20))
n,    err := members.CountBy(ctx, adults)
one,  err := members.FindOne(ctx, store.Member_.Name.Eq("Ann"))   // ErrNotFound / ErrNotUnique
```

This is JPA's `Specification` / `JpaSpecificationExecutor` in Go. Specifications
compose (`And`, `Or`, `Not`, `AllOf`, `AnyOf`), are pure functions, and are
unit-testable without a database. Rename a field and this breaks at **build
time** — unlike `db.Where("team_id = ?", …)`.

The plain repository is right there too:

```go
m,    err := members.GetByID(ctx, 42, crud.Preload("Team"))
page, err := members.Get(ctx, crud.Where(crud.Gte("Age", 18)), crud.Page(1), crud.Limit(50))
m,    err  = members.Update(ctx, 42, store.MemberUpdate{Age: crud.Null[int]()})
n,    err := members.Delete(ctx, 1, 2, 3)
```

## 5. The real shape: DSL inside a transaction

This is what a serious endpoint looks like. A filter arrives from the client, a
usecase opens one transaction, does something gorm is better at, runs the
repository with the compiled DSL *inside that same transaction*, and commits.

```go
type teamUsecase struct {
    db      *gorm.DB
    members crud.Repo[Member, uint, store.MemberUpdate]
    cfg     *query.Config
}

func (uc teamUsecase) PromoteMembers(
    ctx context.Context, teamID uint, req *query.Request,
) (Result, error) {

    // 1. The DSL is compiled and validated before anything opens. An unknown
    //    field fails here, not halfway through a transaction.
    opts, err := req.Compile(uc.members.Meta(), uc.cfg)
    if err != nil {
        return Result{}, err
    }

    var out Result
    // 2. gorm owns the transaction — so gorm's hooks still run on gorm's writes.
    err = uc.db.Transaction(func(tx *gorm.DB) error {
        // 3. rx-crud joins it. One line — every repository call made with txCtx
        //    from here on runs on this transaction.
        txCtx := crud.WithExecutor(ctx, crudsql.From(tx.Statement.ConnPool))

        // 4. The client's filter, narrowed by something it cannot override.
        page, err := uc.members.Get(txCtx, append(opts, crud.Where(crud.Eq("TeamID", teamID)))...)
        if err != nil {
            return err
        }
        out.Matched = page.Total

        // 5. Something gorm is better at, in the same transaction.
        if err := tx.Model(&Team{}).Where("id = ?", teamID).
            Update("name", gorm.Expr("name || ' (promoted)'")).Error; err != nil {
            return err
        }

        // 6. …and repository writes, still the same transaction.
        for _, m := range page.Items {
            renamed := "Sr. " + m.Name
            updated, err := uc.members.Update(txCtx, m.ID, store.MemberUpdate{Name: &renamed})
            if err != nil {
                return err
            }
            out.Promoted = append(out.Promoted, updated.Name)
        }
        return nil
    })
    // 7. gorm committed, or rolled everything back — both halves together.
    return out, err
}
```

The handler above it is four lines:

```go
app.Post("/teams/:id/promote", func(c fiber.Ctx) error {
    var req query.Request
    if err := c.Bind().Body(&req); err != nil {
        return crudfiber.DefaultErrorHandler(c, err)
    }
    out, err := uc.PromoteMembers(c.Context(), teamIDOf(c), &req)
    if err != nil {
        return crudfiber.DefaultErrorHandler(c, err)
    }
    return c.JSON(out)
})
```

On Gin, with `crudgin.DefaultErrorHandler` doing the same job:

```go
r.POST("/teams/:id/promote", func(c *gin.Context) {
    var req query.Request
    if err := json.NewDecoder(c.Request.Body).Decode(&req); err != nil {
        crudgin.DefaultErrorHandler(c, err)
        return
    }
    out, err := uc.PromoteMembers(c.Request.Context(), teamIDOf(c), &req)
    if err != nil {
        crudgin.DefaultErrorHandler(c, err)
        return
    }
    c.JSON(http.StatusOK, out)
})
```

Three things worth noticing:

- **`crud.WithExecutor(ctx, crudsql.From(tx.Statement.ConnPool))` is the whole
  integration.** Inside `db.Transaction`, gorm swaps `Statement.ConnPool` for
  the live `*sql.Tx`, which is exactly what `crudsql.From` wants. rx-crud never
  opens a connection of its own when the context carries one. Anything gorm
  writes, rx-crud sees; anything rx-crud writes, gorm sees; a returned error
  rolls back both. It captures *every* repository the context reaches, which is
  what makes the seam work — and what you have to be deliberate about if this
  process also talks to a second database. Then say which one:
  `crud.WithExecutorFor(ctx, db, crudsql.From(tx.Statement.ConnPool))`, and
  repositories bound elsewhere carry on using their own.
- **The client's DSL and your own predicate compose.** `crud.Where` **ANDs** —
  it never replaces — so `crud.Where(crud.Eq("TeamID", teamID))` cannot be
  widened by anything the client sent.
- **Validation happens first.** `req.Compile` resolves every path against the
  model before a transaction exists.

The other direction works too: `members.Tx(ctx, fn)` opens a transaction through
rx-crud, and a `Tx` inside a context that already carries one **joins** it
rather than nesting — the outer owner keeps control of commit and rollback.

---

## 6. What gorm still owns

rx-crud is not trying to replace gorm, and the line is clean:

| gorm | rx-crud |
| --- | --- |
| models, `AutoMigrate`, schema | list / get / create / patch / delete endpoints |
| association writes (`Association().Append`) | filter, sort, paginate, search from the wire |
| hooks (`BeforeSave`, `AfterFind`, …) | partial updates with three-state semantics |
| `Joins`, `Group`, `Having`, raw SQL | the same API across twenty resources |
| soft-delete writes | multi-tenant row scoping, in SQL |

They share a connection and a transaction, so the boundary can run through a
single request handler. Move one model's list endpoint over first; the rest
follows on its own.

# Part II — how to set it up

## Before you start: adding the module

```bash
go get github.com/shardit-io/qq                 # the library
go get github.com/shardit-io/qq/http/crudfiber  # …and your HTTP framework
```

The library itself has **no external dependencies**. Anything that would add one
is a module of its own in the same repository, so you take the Fiber binding or
the Gin binding — `.../http/crudgin` — and neither drags the other in. If you
are on neither, take `.../http/crudnet`: it is `net/http` and imports nothing, so
it ships in the library and there is no second `go get` at all. On gorm
over `database/sql` there is no driver package to add either: `crudsql` is part
of the library.

```go
import (
    "github.com/shardit-io/qq/crud"
    "github.com/shardit-io/qq/repo/basic"
    "github.com/shardit-io/qq/adapter/crudsql"
    "github.com/shardit-io/qq/http/crudfiber"   // or .../http/crudgin, .../http/crudnet
)
```

The one thing worth knowing about the multi-module layout: the library and every
binding are tagged together and are meant to be used at the same version. There
is never a `replace` to write — the bindings name a published version of the
library, and `go get` resolves it like any other dependency.

## 7. The datasource

Nothing to generate, no feature flags. gorm already holds a `*sql.DB`:

```go
sqlDB, err := db.DB()
if err != nil {
    return err
}
src := crudsql.Postgres(sqlDB)   // or crudsql.MySQL(sqlDB)
```

Same connection pool, same settings, same metrics. That is the entire wiring.

For transactions, prefer letting gorm own them — `db.Transaction(...)` plus the
one `crud.WithExecutor` line from [§5](#5-the-real-shape-dsl-inside-a-transaction).
`repo.Tx(...)` also works and opens a plain `database/sql` transaction; gorm
hooks do not run inside it, because gorm is not the one issuing the statements.

## 8. Declare the repository

**Your gorm struct is the rx-crud model.** No second struct, no changes:

```go
type Member struct {
    gorm.Model                // ID, CreatedAt, UpdatedAt, DeletedAt
    TeamID uint
    Name   string `gorm:"size:120"`
    Age    *int

    Team *Team `gorm:"foreignKey:TeamID" rel:"belongs_to"`
}
```

| gorm field | rx-crud sees |
| --- | --- |
| `gorm.Model` (embedded) | flattened into `id`, `created_at`, `updated_at`, `deleted_at` |
| `ID uint` | primary key, auto-increment |
| `TeamID uint` | column `team_id` |
| `Age *int` | column `age`, **nullable** |
| `DeletedAt gorm.DeletedAt` | one column — it is a `Valuer`/`Scanner`, not a struct to flatten |
| `Team *Team` | a **relation**, because of the `rel` tag — never a column |

The `gorm` and `rel` tags coexist on the same field: gorm ignores `rel`, rx-crud
ignores `gorm`. One struct, two libraries, no duplication. Association fields
*without* a `rel` tag are skipped entirely — neither a column nor an edge.

```go
var Members = basic.Define[Member, uint, store.MemberUpdate]("members",
    basic.Scope(crud.IsNull("DeletedAt")))
```

`Define` validates eagerly — a broken mapping panics at package initialisation,
not on the first request.

### Table names line up by default

gorm pluralises the snake_case struct name; so does rx-crud. `Member` → `members`
either way. Two cases to know:

- **A `TableName()` method is honoured by both.** rx-crud's `crud.Tabler` is the
  same interface, so a custom table name needs no second declaration.
- **Irregular plurals differ.** gorm uses `inflection` (`Person` → `people`);
  rx-crud appends `s`. Pass the table explicitly — `basic.Define[…]("people")` —
  or give the model a `TableName()`.

If your project sets a custom `NamingStrategy`, column names may diverge too.
Diff them once in a test:

```go
func TestMemberMappingMatchesGorm(t *testing.T) {
    s, err := crud.SchemaOf[Member]()
    if err != nil {
        t.Fatal(err)
    }
    stmt := &gorm.Statement{DB: db}
    if err := stmt.Parse(&Member{}); err != nil {
        t.Fatal(err)
    }
    for _, f := range s.Fields {
        if stmt.Schema.LookUpField(f.Column) == nil {
            t.Errorf("github.com/shardit-io/qq maps %q, gorm has no such column", f.Column)
        }
    }
    if Members.Meta().Table != stmt.Schema.Table {
        t.Fatalf("table = %q, gorm says %q", Members.Meta().Table, stmt.Schema.Table)
    }
}
```

## 9. Soft deletes

This is the one gorm behaviour that does not come along for free. gorm adds
`WHERE deleted_at IS NULL` inside its own query builder; rx-crud sees the raw
table and would happily hand back tombstones.

**Reads** — one line on the declaration, and no query option can widen it back
open:

```go
var Members = basic.Define[Member, uint, store.MemberUpdate]("members",
    basic.Scope(crud.IsNull("DeletedAt")))
```

That covers `Get`, `GetAll`, `GetByID`, `Count`, `Exists`, `Delete`, `DeleteAll`
and both halves of `Update`. A caller sending
`{"filter":{"deletedAt":{"isNotNull":true}}}` gets an empty page, not the
tombstones.

**Relations need their own line.** A scope is a `WHERE` clause and a `WHERE`
clause only constrains its own `FROM`. A preload is a second statement against a
second table, and a nested filter opens a correlated subquery with its own
`FROM`, so neither inherits the parent query's narrowing. Say what should happen
at each relation you expose:

```go
var Members = basic.Define[Member, uint, store.MemberUpdate]("members",
    basic.Scope(crud.IsNull("DeletedAt")),                        // members
    basic.RelationScope("Posts", crud.IsNull("DeletedAt")),       // ?preload=posts
    basic.RelationScope("Team", crud.IsNull("DeletedAt")))        // ?filter={"team.name":…}
```

Without the second and third lines `?preload=posts` returns the tombstones, and
`{"filter":{"posts.title":"…"}}` answers questions about them. A relation that
points back at the *same* model needs no declaration — `basic.Scope` follows it
at any depth, because there the answer is not in doubt.

**Deletes** — `repo.Delete` issues a real `DELETE`. If you want gorm's soft
delete, override the method in your service layer, which you have anyway:

```go
func (s MemberService) Delete(ctx context.Context, ids ...uint) (int64, error) {
    res := s.db.WithContext(ctx).Delete(&Member{}, ids)   // gorm sets deleted_at
    return res.RowsAffected, res.Error
}
```

The handler calls the interface, so it never knows the difference. Inside a
transaction, use the `tx` from `db.Transaction` for the same reason.

## 10. Generate the DTO and the metamodel

The one type rx-crud needs beyond your model is the partial-update DTO. You do
not write it:

```go
//go:generate go run github.com/shardit-io/qq/cmd/rxcrud -dir ../models -types Member,Team \
//    -readonly CreatedAt,UpdatedAt,DeletedAt -import myapp/models -into .
package store
```

`go generate ./...` produces `rxcrud_gen.go` in **your** package:

```go
// Code generated by rxcrud. DO NOT EDIT.
package store

// MemberUpdate is the partial-update DTO for models.Member.
type MemberUpdate struct {
    TeamID *uint         `json:"teamID,omitempty"`
    Name   *string       `json:"name,omitempty"`
    Age    crud.Opt[int] `json:"age,omitzero"`
}

type MemberAttrs struct {
    ID        specs.Ord[models.Member, uint]
    CreatedAt specs.Cmp[models.Member, time.Time]
    TeamID    specs.Ord[models.Member, uint]
    Name      specs.Str[models.Member]
    Age       specs.Ord[models.Member, int]
    Team      MemberTeamAttrs          // the association, expanded
}

var Member_ = specs.Metamodel[models.Member, MemberAttrs]()
```

Note the types. `Age` was `*int` — a nullable column — so it became
`crud.Opt[int]`, which has **three** states. `Name` was a plain `string`, so a
pointer's two states are enough. That distinction is the whole reason PATCH
handlers are annoying to write by hand.

| Flag | Why |
| --- | --- |
| `-types Member,Team` | gorm models carry `gorm` tags, not `db` ones, so name them explicitly |
| `-readonly CreatedAt,UpdatedAt,DeletedAt` | gorm owns these: still filterable and sortable, never patchable |
| `-import myapp/models` + `-into .` | write into your own package if the models live elsewhere |
| `-skip Internal` | drop a field entirely, like `db:"-"` |
| `-depth 2` | how far to expand associations into the metamodel |
| `-no-meta` | DTOs only |

If your models and repositories live in the same package, drop `-import`/`-into`
and the file lands next to them.

## 11. Mount it

```go
func main() {
    db, _ := gorm.Open(postgres.Open(dsn), &gorm.Config{})
    sqlDB, _ := db.DB()
    src := crudsql.Postgres(sqlDB)

    app := fiber.New()
    app.Use("/members", crudfiber.New(store.Members.Bind(src)).Routes())
    app.Use("/teams", crudfiber.New(store.Teams.Bind(src)).Routes())

    log.Fatal(app.Listen(":8080"))
}
```

On Gin it is the same two lines with a different verb, because Gin has no
mountable sub-application:

```go
    r := gin.New()
    crudgin.New(store.Members.Bind(src)).Mount(r, "/members")
    crudgin.New(store.Teams.Bind(src)).Mount(r, "/teams")

    log.Fatal(r.Run(":8080"))
```

`Register(r)` takes a group you already built, when the routes need middleware:
`crudgin.New(…).Register(r.Group("/members", authMiddleware))`.

On plain `net/http` there is no framework to add at all:

```go
    mux := http.NewServeMux()
    crudnet.New(store.Members.Bind(src)).Mount(mux, "/members")

    log.Fatal(http.ListenAndServe(":8080", mux))
```

Everything from here on — every option, every status, every response shape — is
identical across the three. Where they differ is a table in
`docs/flows/FL-013-a-request-through-another-binding.md`; the one most likely to
matter is that the Gin and `net/http` bindings accept JSON request bodies only.

## 12. Your business rules: the service layer

The handler takes an **interface**, not a struct. Embed the repository, override
what you care about, and the handler cannot tell the difference:

```go
type MemberService struct {
    crud.Repo[Member, uint, store.MemberUpdate]   // embedding gives you every method
    db *gorm.DB
}

func (s MemberService) Save(ctx context.Context, m *Member) error {
    if m.Name == "" {
        return fmt.Errorf("%w: name is required", crud.ErrForbidden)
    }
    if err := s.Repo.Save(ctx, m); err != nil {
        return err
    }
    return s.db.WithContext(ctx).Create(&AuditLog{Subject: m.ID}).Error
}

// gorm's soft delete instead of a hard one — see §9.
func (s MemberService) Delete(ctx context.Context, ids ...uint) (int64, error) {
    res := s.db.WithContext(ctx).Delete(&Member{}, ids)
    return res.RowsAffected, res.Error
}

app.Use("/members", crudfiber.New(MemberService{
    Repo: store.Members.Bind(src),
    db:   db,
}).Routes())
```

`crud.ErrForbidden` maps to 403, `crud.ErrNotFound` to 404, `crud.ErrConflict`
to 409 — wrap whichever fits.

## 13. Multi-tenancy and authorization

gorm's global scopes live in gorm's builder, so rx-crud needs its own gate:

```go
var policy = security.ScopeField[Member, uint]("TenantID",
    func(ctx context.Context) (any, error) {
        t, ok := ctx.Value(tenantKey{}).(uint)
        if !ok {
            return nil, security.Denied(security.Read, "no tenant in context")
        }
        return t, nil
    })

members := store.Members.Bind(src, security.Gate(policy))
```

From that one line:

- every read gets `AND tenant_id = $n`, in SQL, not in Go;
- another tenant's id returns **404, not 403** — a 403 would confirm the row exists;
- `Save` into another tenant is refused, and so is overwriting a row that belongs to one;
- `TenantID` is frozen: a PATCH naming it is rejected before any SQL runs;
- an unscoped `DeleteAll` is refused unless you opt in.

The predicate AST is closed, so a client cannot compose its way out. `Policy`
also takes `Authorize(ctx, action)` and `Inspect(ctx, action, *M)`, and
`security.Combine` ANDs several policies — which is how a tenant scope and the
soft-delete scope stack.

**`Scope` stops at the statement's own `FROM`**, exactly like a gorm scope does.
A preload is a second statement against a second table and a nested filter opens
a correlated subquery with its own `FROM`, so neither inherits it — and
`?preload=members` would read that table raw. Say what happens at each relation:

```go
var policy = security.Combine(
    security.ScopeField[Team, uint]("TenantID", tenantOf),
    security.ScopeRelationField[Team, uint]("Members", "TenantID", tenantOf),
)
```

That is the per-principal half. The per-table half — the soft-delete tombstones
from [section 9](#9-soft-deletes), which are a property of the model rather than
of who is asking — belongs on the blueprint as `basic.RelationScope`, and the
two stack: a preload of `Members` gets both the tenant check and the
`deleted_at IS NULL`.

The path is resolved when the policy is declared, so a typo panics at start-up
rather than leaking rows in production. For anything the helper cannot express,
`Policy.RelationScopes` takes a `func(ctx) (*crud.RelationScopes, error)`
directly, with `AtPath` for one route and `ForModel` for a model wherever it is
reached.

## 14. Associations, filters and preloads

Add a `rel` tag next to the `gorm` one and the association becomes navigable
from filters, sorts and preloads. gorm's own tags stay exactly as they are:

```go
type Team struct {
    gorm.Model
    Name string

    Members []Member `gorm:"foreignKey:TeamID"      rel:"has_many"`
    Labels  []Label  `gorm:"many2many:team_labels;" rel:"many_to_many,join=team_labels"`
}

type Member struct {
    gorm.Model
    TeamID uint
    Name   string

    Team *Team `gorm:"foreignKey:TeamID" rel:"belongs_to"`
}
```

The defaults line up with gorm's: `belongs_to` looks for `<Field>ID` on this
struct, `has_many` for `<ThisModel>ID` on the target, and a `many2many` join
table uses `<model>_id` / `<target>_id` — the same columns gorm's `AutoMigrate`
creates. Override with `fk=`, `ref=`, `table=`, `join=`, `joinFK=`, `joinRef=`
when your schema differs.

Then, over HTTP:

```bash
curl -XPOST /teams/query -d '{
  "filter":  {"labels.slug": {"in": ["go","rust"]}, "members.age": {"gte": 30}},
  "preload": ["members.team", "labels"],
  "sort":    ["-createdAt", "name"]
}'
```

and in Go, `store.Team_.Labels.Slug.Eq("go")` — typed and compile-checked.

Two things worth knowing about how that runs, both places rx-crud deliberately
differs from `Joins`/`Preload`:

- **A relation filter is a correlated `EXISTS`, not a join.** A join against a
  to-many association multiplies rows: a team with two matching labels becomes
  two rows, `LIMIT 20` returns fewer than twenty distinct teams, and `COUNT(*)`
  reports a number that does not exist. `EXISTS` is a semi-join — one row in,
  one row out — and the planner still turns it into a hash semi-join. This is
  the class of bug that makes `Joins` + pagination quietly wrong.
- **A preload is a batched second query, not a join.** One statement per
  relation per level, keys deduplicated, no N+1 — the same shape as gorm's
  `Preload`. It cannot be paginated, because a `LIMIT` over a batched load would
  truncate some parents' children and not others.

Preloads only **read**. Association writes stay on gorm
(`db.Model(&team).Association("Labels").Append(...)`), which is the right place
for them.

## 15. Testing without a database

`../../crud/crudtest` is an in-memory datasource that records the SQL a repository
produces and replays canned rows:

```go
func TestServiceRejectsEmptyName(t *testing.T) {
    rec := crudtest.Postgres()
    svc := MemberService{Repo: store.Members.Bind(rec)}

    if err := svc.Save(context.Background(), &Member{}); !errors.Is(err, crud.ErrForbidden) {
        t.Fatalf("err = %v", err)
    }
    if len(rec.Statements()) != 0 {
        t.Fatal("nothing should have reached the database")
    }
}
```

For the HTTP layer, Fiber's `app.Test(req)` drives the whole handler; on Gin and
`net/http` it is `httptest.NewRecorder()` and `ServeHTTP(w, req)`.

## 16. Gotchas

**Soft deletes need the scope.** Covered in [§9](#9-soft-deletes) — it is the
first thing to add and the easiest to forget.

**gorm hooks do not run on rx-crud writes.** `BeforeSave`, `AfterFind`,
`BeforeDelete` and friends live in gorm's callback chain; a statement rx-crud
issues never enters it. The same goes for `default` tags, which gorm applies in
Go. Put invariants you cannot lose in the database, in a `security.Policy`, or
in your service layer. Where a hook is genuinely load-bearing, keep that
operation on gorm and override the method — [§12](#12-your-business-rules-the-service-layer).

**Column names are derived, not read from gorm.** They agree for gorm's default
`NamingStrategy`, including `TeamID` → `team_id`. A custom naming strategy, a
`gorm:"column:…"` override or a table prefix will diverge. The mapping test in
[§8](#table-names-line-up-by-default) catches it at build time; a
`db:"actual_name"` tag fixes it per field.

**Association fields are ignored without a `rel` tag.** Neither a column nor an
edge. That is what makes gorm structs work as-is, and it means a typo'd relation
tag fails silently as "no relation". Check `Meta().Relations` if a preload
unexpectedly 400s.

**`gorm.Model` gives you `uint`.** Declare repositories as
`basic.Define[Member, uint, …]` — the ID type parameter is checked against the
primary key at start-up, so a mismatch panics immediately rather than at runtime.

**Sorting through a to-many relation is refused.** A collection has no single
value to sort by.

**`Save` is an upsert.** No key → INSERT; key set → `ON CONFLICT DO UPDATE`.
Columns tagged `immutable` survive the conflict. It is not gorm's `Save`, which
issues a full `UPDATE` of every field.
