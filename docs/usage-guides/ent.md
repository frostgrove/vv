# Killing CRUD boilerplate in an ent project

You already use [ent](https://entgo.io). Your schemas are good, your queries are
typed, your migrations work. What you are tired of is the other 80% of every
resource: the list handler with page/limit/sort/filter parsing, the get handler,
the create handler, the patch handler that has to tell "field absent" from
"field set to null", the delete handler, and the same five error mappings in
each one — times every entity you own.

rx-crud takes that layer. **ent keeps everything it is good at**: schema,
migrations, edges, hooks, typed query builders for the queries that carry real
business meaning. rx-crud replaces the mechanical CRUD around them.

The two share your `*sql.DB` and your transactions, so this is additive. Nothing
about your existing ent code changes.

# Part I — what you get

## 1. The declaration

Per entity, forever:

```go
var Users = basic.Define[ent.User, int64, store.UserUpdate](entuser.Table)

app.Use("/users", crudfiber.New(Users.Bind(src)).Routes())
```

`ent.User` is **ent's own generated struct** — you do not write a second model
and you do not add tags to the generated one. `store.UserUpdate` is generated by
`rxcrud`. `entuser.Table` is ent's own table constant.

That is the entire per-resource cost. Everything below falls out of those two
lines.

---

## 2. The API that comes out

| Route | |
| --- | --- |
| `GET /users` | list — filter, sort, paginate, search from the query string |
| `POST /users/query` | list — the full JSON filter DSL |
| `GET /users/count`, `POST /users/count` | count with the same filters |
| `GET /users/:id` | one entity, `?select=…` |
| `POST /users` | create |
| `PATCH /users/:id` | partial update |
| `PUT /users/:id` | replace — where the database generates the key it will not create, so an unused id is 404 |
| `DELETE /users/:id` | delete |
| `POST /users/bulk-delete` | `{"ids": […]}` |

### Listing

```bash
curl '/users?page=2&limit=20&sort=-createdAt,name&q=ann&searchFields=name,email'
curl '/users?f=active:eq:true&f=age:gte:18&f=email:endsWith:@corp.com'
curl '/users?f=createdAt:gte:2026-01-01T00:00:00Z&select=id,name,email'
```

`f=field:op:value` repeats and ANDs. Only the first two colons are structural,
so timestamps survive.

```bash
curl -XPOST /users/query -d '{
  "page": 2, "limit": 20,
  "sort": ["-createdAt", "name"],
  "filter": {
    "active": true,
    "age":    {"gte": 18, "lt": 65},
    "email":  {"endsWith": "@corp.com"},
    "or":     [ {"name": {"contains": "ann"}}, {"tenantID": 7} ],
    "not":    {"name": "spam"}
  }
}'
```

```json
{
  "items": [ … ],
  "page": 2, "limit": 20,
  "total": 143, "totalPages": 8,
  "hasNext": true, "hasPrev": true
}
```

Operators: `eq ne gt gte lt lte like notLike ilike contains startsWith endsWith
in notIn between isNull isNotNull`, plus `$`-prefixed and symbolic aliases. A
bare value means `eq`, a bare array means `in`, `null` means `IS NULL`.

Field names match case- and separator-insensitively — `createdAt`, `created_at`
and `CreatedAt` are the same column — so your TypeScript client keeps its own
conventions.

### Writing

```bash
curl -XPOST  /users     -d '{"email":"a@x.io","name":"Ann","tenantID":1}'
curl -XPATCH /users/42  -d '{"age": null}'
curl -XDELETE /users/42                       # {"deleted": 1}
```

The PATCH body is where most hand-written handlers get it wrong. Three states,
three behaviours, no `map[string]any` anywhere:

```json
{}                      → nothing happens, no UPDATE is issued
{"name": "Ann"}         → UPDATE users SET name = $1
{"age": null}           → UPDATE users SET age = NULL
{"age": 31}             → UPDATE users SET age = 31
```

And only what *changed* is written: sending a field that already holds that
value produces no SQL for it.

On create the body binds onto the entity, then the generated primary key is
cleared — a client cannot choose its own id.

### Errors

| Situation | Status | Body |
| --- | --- | --- |
| unknown filter field, bad value type, bad id | 400 | `{"error":"bad_request","path":"filter.nope","message":"unknown field \"nope\" on model User"}` |
| row missing, or outside your access scope | 404 | `{"error":"not_found"}` |
| policy denied | 403 | `{"error":"forbidden", …}` |
| duplicate key, foreign key or NOT NULL violation; `FindOne` matched several rows; a stale `version` | 409 | `{"error":"conflict"}` |
| anything else | 500 | `{"error":"internal_error"}` — no detail leaks |

An unknown field is a **rejection**, never a silently ignored clause. That is the
difference between a typo you notice in five seconds and a filter that quietly
returns the whole table.

## 3. Bounding it: the handler config

The DSL is driven by untrusted input, so the handler takes a config. Everything
here is optional; empty lists allow anything the model maps.

```go
app.Use("/users", crudfiber.New(Users.Bind(src),
    crudfiber.WithQuery[ent.User, int64, store.UserUpdate](&query.Config{
        Filterable:  []string{"Name", "Email", "Active", "CreatedAt"},
        Sortable:    []string{"CreatedAt", "Name"},
        Selectable:  []string{"ID", "Name", "Email"},
        Searchable:  []string{"Name", "Email"},
        Preloadable: []string{"Posts", "Posts.Comments"},   // `.*` allows a subtree

        MaxDepth:      4,   // and/or nesting, and path length
        MaxConditions: 32,
        MaxPreloads:   4,
    }),
).Routes())
```

The other options on the same call:

| Option | For |
| --- | --- |
| `WithTransform` | render entities through a presenter — hide columns from the wire |
| `BeforeSave` | fill server-owned fields on create/replace |
| `BeforeUpdate` | inspect or reject a PATCH DTO |
| `WithScope` | add repository options per request (`?includeArchived`) |
| `ReadOnly` | mount only the read routes |
| `AllowClientID` | let a create carry its own primary key |
| `MaxBulk` | cap ids per bulk delete |
| `WithErrorHandler` | your own error → response mapping |

Depth, condition and preload limits apply whether or not you set the lists.

Every name above exists in `crudgin` and `crudnet` too, spelled the same, taking
the same arguments. The only difference is what the five callback options carry:
a `fiber.Ctx`, a `*gin.Context`, or an `*http.Request`. The ones that write a
response return nothing outside the Fiber binding, because neither
`gin.HandlerFunc` nor `http.HandlerFunc` returns an error.

## 4. Typed queries in Go

Not everything is an HTTP request. The generated metamodel gives compile-checked
filters over ent's own entity type:

```go
users := specs.Executor(Users.Bind(src))

adults := specs.Where(store.User_.Age.Gte(18)).
    And(store.User_.Active.Eq(true)).
    And(store.User_.Email.EndsWith("@corp.com"))

list, err := users.FindAll(ctx, adults, crud.OrderBy(store.User_.CreatedAt.Desc()))
page, err := users.FindPage(ctx, adults, crud.Page(2), crud.Limit(20))
n,    err := users.CountBy(ctx, adults)
one,  err := users.FindOne(ctx, store.User_.Email.Eq("a@x.io"))   // ErrNotFound / ErrNotUnique
```

This is JPA's `Specification` / `JpaSpecificationExecutor` in Go. Specifications
compose (`And`, `Or`, `Not`, `AllOf`, `AnyOf`), are pure functions, and are
unit-testable without a database. Rename a field in your ent schema and this
breaks at **build time**.

The plain repository is right there too:

```go
u,    err := users.GetByID(ctx, 42)
page, err := users.Get(ctx, crud.Where(crud.Eq("Active", true)), crud.Page(1), crud.Limit(50))
u,    err  = users.Update(ctx, 42, store.UserUpdate{Age: crud.Null[int]()})
n,    err := users.Delete(ctx, 1, 2, 3)
```

### Writing many rows at once

`Update` addresses one row and diffs it; `UpdateAll` addresses a filter and is
one statement, the way `DeleteAll` is `Delete`'s filtered partner:

```go
n, err := users.UpdateAll(ctx, store.UserUpdate{Active: ptr(false)},
    crud.Where(crud.Eq("TenantID", tenant)))
```

ent's equivalent is `client.User.Update().Where(…)`, and either is fine — they
end up as the same `UPDATE`. Reach for this one when the filter came from the
DSL, because then it is already a `[]crud.Option`. Note the one difference from
`Update`: there is no single row to diff against, so every field the DTO defines
is written to every matching row. A DTO that defines nothing writes nothing.

### Optimistic locking

`Update` is load-then-write. Inside a transaction the load locks the row; outside
one, two concurrent updates can interleave and the second overwrites the first.
Tag an integer column `version` and that stops being possible — the write pins
itself to the version it read, and a loser gets `crud.ErrStaleVersion` (which
wraps `crud.ErrConflict`, so the handler answers 409) instead of silently
winning.

ent has no equivalent, and the column is invisible to it, so this is additive:
add `field.Int("version").Default(1)` to the schema and the tag to a model
struct. See the README for the full rules.

## 5. The real shape: DSL inside a transaction

This is what a serious endpoint looks like. A filter arrives from the client, a
usecase opens one transaction, does something ent is better at, runs the
repository with the compiled DSL *inside that same transaction*, and commits.

```go
type userUsecase struct {
    client *ent.Client
    users  crud.Repo[ent.User, int64, store.UserUpdate]
    cfg    *query.Config
}

func (uc userUsecase) DeactivateUsers(
    ctx context.Context, tenantID int64, req *query.Request,
) (Result, error) {

    // 1. The DSL is compiled and validated before anything opens. An unknown
    //    field fails here, not halfway through a transaction.
    opts, err := req.Compile(uc.users.Meta(), uc.cfg)
    if err != nil {
        return Result{}, err
    }

    // 2. ent owns the transaction, so ent's hooks and privacy rules still run.
    tx, err := uc.client.Tx(ctx)
    if err != nil {
        return Result{}, err
    }
    defer tx.Rollback()

    // 3. rx-crud joins it. One line — every repository call made with txCtx
    //    from here on runs on this transaction.
    txCtx := crud.WithExecutor(ctx, crudsql.From(tx))

    // 4. The client's filter, narrowed by something it cannot override.
    page, err := uc.users.Get(txCtx, append(opts, crud.Where(crud.Eq("TenantID", tenantID)))...)
    if err != nil {
        return Result{}, err
    }

    ids := make([]int64, 0, len(page.Items))
    for _, u := range page.Items {
        ids = append(ids, u.ID)
    }

    // 5. ent's builder, same transaction: a bulk update expressed the ent way.
    if len(ids) > 0 {
        if _, err := tx.User.Update().Where(entuser.IDIn(ids...)).SetActive(false).Save(ctx); err != nil {
            return Result{}, err
        }
    }

    // 6. …and repository writes, still the same transaction.
    for _, id := range ids {
        name := "deactivated"
        if _, err := uc.users.Update(txCtx, id, store.UserUpdate{Name: &name}); err != nil {
            return Result{}, err
        }
    }

    // 7. One commit for all of it.
    if err := tx.Commit(); err != nil {
        return Result{}, err
    }
    return Result{Matched: page.Total, IDs: ids}, nil
}
```

The handler above it is four lines:

```go
app.Post("/users/deactivate", func(c fiber.Ctx) error {
    var req query.Request
    if err := c.Bind().Body(&req); err != nil {
        return crudfiber.DefaultErrorHandler(c, err)
    }
    out, err := uc.DeactivateUsers(c.Context(), tenantOf(c), &req)
    if err != nil {
        return crudfiber.DefaultErrorHandler(c, err)
    }
    return c.JSON(out)
})
```

On Gin, with `crudgin.DefaultErrorHandler` doing the same job:

```go
r.POST("/users/deactivate", func(c *gin.Context) {
    var req query.Request
    if err := json.NewDecoder(c.Request.Body).Decode(&req); err != nil {
        crudgin.DefaultErrorHandler(c, err)
        return
    }
    out, err := uc.DeactivateUsers(c.Request.Context(), tenantOf(c), &req)
    if err != nil {
        crudgin.DefaultErrorHandler(c, err)
        return
    }
    c.JSON(http.StatusOK, out)
})
```

Three things worth noticing:

- **`crud.WithExecutor` is the whole integration.** rx-crud never opens a
  connection of its own when the context carries one. Anything ent writes,
  rx-crud sees; anything rx-crud writes, ent sees; a rollback takes both.
  It captures *every* repository the context reaches, which is what makes the
  seam work — and what you have to be deliberate about if this process also
  talks to a second database. Then say which one:
  `crud.WithExecutorFor(ctx, db, crudsql.From(tx))`, and repositories bound
  elsewhere carry on using their own.
- **The client's DSL and your own predicate compose.** `crud.Where` **ANDs** —
  it never replaces — so `crud.Where(crud.Eq("TenantID", tenantID))` cannot be
  widened by anything the client sent.
- **Validation happens first.** `req.Compile` resolves every path against the
  model before a transaction exists.

Both directions work. If rx-crud opens the transaction instead
(`users.Tx(ctx, fn)` with the datasource from [step 8](#8-the-datasource)), it
opens a real `ent.Tx`, and a `Tx` inside a context that already carries one
**joins** it rather than nesting — the outer owner keeps control of commit.

---

## 6. What ent still owns

rx-crud is not trying to replace ent, and the line is clean:

| ent | rx-crud |
| --- | --- |
| schema, migrations | list / get / create / patch / delete endpoints |
| edges, eager loading, graph traversal | filter, sort, paginate, search from the wire |
| hooks, privacy, interceptors | partial updates with three-state semantics |
| aggregations, `GroupBy`, conflict-aware upserts | the same API across twenty resources |
| queries that carry business meaning | multi-tenant row scoping, in SQL |

They share a connection and a transaction, so the boundary can run through a
single request handler. Move one resource's list endpoint over first; the rest
follows on its own.

# Part II — how to set it up

## Before you start: adding the module

```bash
go get github.com/shardit-io/go-rx-crud                 # the library
go get github.com/shardit-io/go-rx-crud/http/crudfiber  # …and your HTTP framework
```

The library itself has **no external dependencies**. Anything that would add one
is a module of its own in the same repository, so you take the Fiber binding or
the Gin binding — `.../http/crudgin` — and neither drags the other in. If you
are on neither, take `.../http/crudnet`: it is `net/http` and imports nothing, so
it ships in the library and there is no second `go get` at all. On ent
over `database/sql` there is no driver package to add either: `crudsql` is part
of the library.

```go
import (
    "github.com/shardit-io/go-rx-crud/crud"
    "github.com/shardit-io/go-rx-crud/repo/basic"
    "github.com/shardit-io/go-rx-crud/adapter/crudsql"
    "github.com/shardit-io/go-rx-crud/http/crudfiber"   // or .../http/crudgin, .../http/crudnet
)
```

The one thing worth knowing about the multi-module layout: the library and every
binding are tagged together and are meant to be used at the same version. There
is never a `replace` to write — the bindings name a published version of the
library, and `go get` resolves it like any other dependency.

## 7. Enable `sql/execquery`

This ent feature flag puts `ExecContext`/`QueryContext` on `*ent.Client` and
`*ent.Tx`. That pair is the entire surface rx-crud needs — it is why no adapter
has to reach inside ent.

```go
//go:generate go run -mod=mod entgo.io/ent/cmd/ent generate --feature sql/execquery ./schema
```

or in `entc.go`:

```go
err := entc.Generate("./schema", &gen.Config{
    Features: []gen.Feature{gen.FeatureExecQuery},
})
```

Regenerate. Nothing else in your ent code changes.

## 8. The datasource

rx-crud needs a `crud.Source`: something that can `Exec`, `Query` and name its
dialect. You have two choices, and the second is worth twenty lines.

**Fastest** — bind the `*sql.DB` you already gave ent:

```go
src := crudsql.Postgres(db)   // or crudsql.MySQL(db)
```

Everything in Part I works. The only thing you give up is `repo.Tx(...)` opening
an *ent* transaction — you can still join one with `crud.WithExecutor`, which is
the pattern from [§5](#5-the-real-shape-dsl-inside-a-transaction) anyway.

**Better** — an ent-backed source, so `repo.Tx` opens a real `ent.Tx`: one
transaction that ent's own builders and rx-crud both write into, and that ent
commits or rolls back. It does **not** mean rx-crud's writes start firing ent's
hooks — those live in ent's builders, and rx-crud sends its own statements, as
[§16](#16-gotchas) says. What you gain is the transaction, not the callbacks:

```go
package store

// Compile-time proof that ent's own types fit rx-crud's seam.
var (
    _ crudsql.Queryer = (*ent.Client)(nil)
    _ crudsql.Queryer = (*ent.Tx)(nil)
)

type Source struct {
    crudsql.Executor
    client  *ent.Client
    dialect crud.Dialect
}

func New(client *ent.Client, d crud.Dialect) Source {
    return Source{Executor: crudsql.From(client), client: client, dialect: d}
}

func (s Source) Dialect() crud.Dialect { return s.dialect }

func (s Source) Begin(ctx context.Context) (crud.Tx, error) {
    tx, err := s.client.Tx(ctx)
    if err != nil {
        return nil, err
    }
    return entTx{Executor: crudsql.From(tx), tx: tx}, nil
}

type entTx struct {
    crudsql.Executor
    tx *ent.Tx
}

func (t entTx) Commit(context.Context) error   { return t.tx.Commit() }
func (t entTx) Rollback(context.Context) error { return t.tx.Rollback() }
```

`entTx` has no `Begin`, so it is not a `crud.Beginner`: a nested `Begin` inside
an ent transaction answers `crud.ErrNoTxSupport` rather than opening a savepoint.
`crudsql.DB` gives you one for free because it holds the `*sql.Tx`; here ent owns
it. Add a `Begin` that issues `SAVEPOINT` if you need one — or keep the
transaction flat, which is what `Tx` joining rather than nesting already
encourages.

```go
client := ent.NewClient(ent.Driver(entsql.OpenDB(dialect.Postgres, db)))
src    := store.New(client, crud.Postgres{})   // same connection pool as ent
```

## 9. Declare the repository

This is the part people expect to be painful. It is not: **ent's generated
entity struct is an rx-crud model with no changes and no tags.**

```go
// ent's generated type. You do not touch it.
type User struct {
    config       `json:"-"`
    ID           int64     `json:"id,omitempty"`
    TenantID     int64     `json:"tenant_id,omitempty"`
    Email        string    `json:"email,omitempty"`
    Age          *int      `json:"age,omitempty"`
    Active       bool      `json:"active,omitempty"`
    CreatedAt    time.Time `json:"created_at,omitempty"`
    Edges        UserEdges `json:"edges"`
    selectValues sql.SelectValues
}
```

| ent field | rx-crud sees |
| --- | --- |
| `config` (embedded, all-unexported) | nothing |
| `selectValues` (unexported) | nothing |
| `Edges UserEdges` | nothing — a struct field with no `rel` tag is never a column |
| `ID int64` | primary key, database-generated |
| `TenantID int64` | column `tenant_id` |
| `Age *int` | column `age`, **nullable** |
| `CreatedAt time.Time` | column `created_at` |

So:

```go
import entuser "myapp/ent/user"

var Users = basic.Define[ent.User, int64, store.UserUpdate](entuser.Table)
```

`Define` validates eagerly — a broken mapping panics at package initialisation,
not on the first request.

### If your keys are UUIDs

`field.UUID("id", uuid.UUID{})` works everywhere — the key is bindable, filters
and `in`-lists take it, preloads index by it, and the DSL turns the string a
client sends into one. Two things differ from an `int64` key:

```go
var Rooms = basic.Define[ent.Room, uuid.UUID, store.RoomUpdate](entroom.Table)
```

The ID type parameter is `uuid.UUID`, and on a hand-written model struct the tag
is `db:"id,pk,noauto"` — the database does not generate this key, ent's
`Default(uuid.New)` does, in Go. Which brings the sharp edge: **rx-crud does not
run that default**. A `Save` with an unset key is refused with
`crud.ErrMissingID` rather than writing the zero UUID, so nothing silently
corrupts — but you have to supply the key, in a `BeforeSave` hook or a service
layer. The same is true of `field.Time(...).Default(time.Now)`, and that one has
no safety net: a zero time is a legal value, so it lands. Put those defaults in
the database, or fill them in before the write.

On MySQL, note that `uuid.UUID.Value()` hands the driver the 36-character string
form, not the 16 raw bytes — the column is `char(36)`, not `binary(16)`.
PostgreSQL's `uuid` type takes the string.

### Verify the mapping once

rx-crud derives column names from Go field names; ent knows the real ones. Diff
them and never think about it again:

```go
func TestUserMappingMatchesEnt(t *testing.T) {
    s, err := crud.SchemaOf[ent.User]()
    if err != nil {
        t.Fatal(err)
    }
    got := s.Columns()
    slices.Sort(got)
    want := slices.Sorted(slices.Values(entuser.Columns))
    if !slices.Equal(got, want) {
        t.Fatalf("github.com/shardit-io/go-rx-crud maps %v, ent has %v", got, want)
    }
    if Users.Meta().Table != entuser.Table {
        t.Fatalf("table = %q, ent says %q", Users.Meta().Table, entuser.Table)
    }
}
```

Copy it per entity. It catches the one thing that can go wrong: an ent schema
field whose name does not snake_case the way rx-crud assumes.

## 10. Generate the DTO and the metamodel

The one type rx-crud needs beyond your entity is the partial-update DTO. You do
not write it:

```go
//go:generate go run github.com/shardit-io/go-rx-crud/cmd/rxcrud -dir ../ent -types User,Article \
//    -readonly CreatedAt -import myapp/ent -into .
package store
```

`go generate ./...` produces `rxcrud_gen.go` in **your** package:

```go
// Code generated by rxcrud. DO NOT EDIT.
package store

// UserUpdate is the partial-update DTO for ent.User.
type UserUpdate struct {
    TenantID *int64        `json:"tenantID,omitempty"`
    Email    *string       `json:"email,omitempty"`
    Name     *string       `json:"name,omitempty"`
    Age      crud.Opt[int] `json:"age,omitzero"`
    Active   *bool         `json:"active,omitempty"`
}

type UserAttrs struct {
    ID        specs.Ord[ent.User, int64]
    TenantID  specs.Ord[ent.User, int64]
    Email     specs.Str[ent.User]
    Name      specs.Str[ent.User]
    Age       specs.Ord[ent.User, int]
    Active    specs.Attr[ent.User, bool]
    CreatedAt specs.Cmp[ent.User, time.Time]
}

var User_ = specs.Metamodel[ent.User, UserAttrs]()
```

Note the types. `Age` was `*int` on the entity — a nullable column — so it
became `crud.Opt[int]`, which has **three** states. `Email` was a plain
`string`, so a pointer's two states are enough. That distinction is the whole
reason PATCH handlers are annoying to write by hand.

| Flag | Why |
| --- | --- |
| `-types User,Article` | ent entities carry no `db` tags, so name them explicitly |
| `-import myapp/ent` + `-into .` | write into **your** package — `UserUpdate` would collide with ent's own update builder, and `ent generate` owns that directory |
| `-readonly CreatedAt` | server-owned: still filterable and sortable, never patchable |
| `-skip Internal` | drop a field entirely, like `db:"-"` |
| `-no-meta` | DTOs only |

## 11. Mount it

```go
func main() {
    db, _ := sql.Open("pgx", dsn)
    client := ent.NewClient(ent.Driver(entsql.OpenDB(dialect.Postgres, db)))
    src := store.New(client, crud.Postgres{})

    app := fiber.New()
    app.Use("/users", crudfiber.New(store.Users.Bind(src)).Routes())
    app.Use("/articles", crudfiber.New(store.Articles.Bind(src)).Routes())

    log.Fatal(app.Listen(":8080"))
}
```

On Gin it is the same two lines with a different verb, because Gin has no
mountable sub-application:

```go
    r := gin.New()
    crudgin.New(store.Users.Bind(src)).Mount(r, "/users")
    crudgin.New(store.Articles.Bind(src)).Mount(r, "/articles")

    log.Fatal(r.Run(":8080"))
```

`Register(r)` takes a group you already built, when the routes need middleware:
`crudgin.New(…).Register(r.Group("/users", authMiddleware))`.

On plain `net/http` there is no framework to add at all:

```go
    mux := http.NewServeMux()
    crudnet.New(store.Users.Bind(src)).Mount(mux, "/users")

    log.Fatal(http.ListenAndServe(":8080", mux))
```

Everything from here on — every option, every status, every response shape — is
identical across the three. Where they differ is a table in
`docs/flows/FL-013-a-request-through-another-binding.md`; the one most likely to
matter is that the Gin and `net/http` bindings accept JSON request bodies only.

## 12. Your business rules: the service layer

The handler takes an **interface**, not a struct. Embed the repository, override
what you care about, and the handler cannot tell the difference:

```go
type UserService struct {
    crud.Repo[ent.User, int64, store.UserUpdate]   // embedding gives you every method
    client *ent.Client
}

func (s UserService) Save(ctx context.Context, u *ent.User) error {
    if !strings.Contains(u.Email, "@") {
        return fmt.Errorf("%w: email is not an address", crud.ErrForbidden)
    }
    if err := s.Repo.Save(ctx, u); err != nil {
        return err
    }
    return s.client.AuditLog.Create().SetSubject(u.ID).Exec(ctx)
}

app.Use("/users", crudfiber.New(UserService{
    Repo:   store.Users.Bind(src),
    client: client,
}).Routes())
```

`crud.ErrForbidden` maps to 403, `crud.ErrNotFound` to 404, `crud.ErrConflict`
to 409 — wrap whichever fits.

## 13. Multi-tenancy and authorization

If you use ent's [privacy layer](https://entgo.io/docs/privacy/), keep it — but
rx-crud's statements do not go through ent's builders, so give rx-crud its own
gate:

```go
var policy = security.ScopeField[ent.User, int64]("TenantID",
    func(ctx context.Context) (any, error) {
        t, ok := ctx.Value(tenantKey{}).(int64)
        if !ok {
            return nil, security.Denied(security.Read, "no tenant in context")
        }
        return t, nil
    })

users := store.Users.Bind(src, security.Gate(policy))
```

From that one line:

- every read gets `AND tenant_id = $n`, in SQL, not in Go;
- another tenant's id returns **404, not 403** — a 403 would confirm the row exists;
- `Save` into another tenant is refused, and so is overwriting a row that belongs to one;
- `TenantID` is frozen: a PATCH naming it is rejected before any SQL runs;
- an unscoped `DeleteAll` is refused unless you opt in.

The predicate AST is closed, so a client cannot compose its way out. `Policy`
also takes `Authorize(ctx, action)` and `Inspect(ctx, action, *M)`, and
`security.Combine` ANDs several policies.

**`Scope` stops at the statement's own `FROM`.** It is a predicate over one
model, so it narrows the query that reads that model and nothing else: a preload
is a second statement against a second table, and a nested filter opens a
correlated subquery with its own `FROM`. If a tenanted model exposes relations —
see [section 14](#14-relations-edges-vs-github.com/shardit-io/go-rx-crud-relations) — say what happens at
each of them, or `?preload=comments` reads that table raw.

There are two places to say it, and which one is right depends on whose fact it
is. A rule about the model goes on the blueprint, once:

```go
var Articles = basic.Define[Article, int64, ArticleUpdate]("articles",
    basic.RelationScope("Comments", crud.Eq("Published", true)))
```

A rule about the *principal* cannot: the blueprint is built at start-up and the
tenant arrives per request. That is `RelationScopes`, the companion to `Scope`:

```go
var policy = security.Combine(
    security.ScopeField[Article, int64]("TenantID", tenantOf),
    security.ScopeRelationField[Article, int64]("Comments", "TenantID", tenantOf),
)
```

The path is resolved when the policy is declared, so a typo panics at start-up
rather than leaking rows in production, and it may be several hops
(`"Comments.Author"`). For anything the helper cannot express, `Policy` takes
the hook directly:

```go
RelationScopes: func(ctx context.Context) (*crud.RelationScopes, error) {
    t, err := tenantOf(ctx)
    if err != nil { return nil, err }
    return (*crud.RelationScopes)(nil).
        AtPath("Comments", crud.Eq("TenantID", t)).
        ForModel(reflect.TypeOf(Comment{}), crud.Eq("TenantID", t)), nil  // wherever it is reached
},
```

Both narrowings apply where both are declared, and neither can be widened by
anything the client sends. The safe shape, and the one to reach for first, is
still a foreign key that already implies the tenant: children reached through
their parent's key are the parent's children whatever the scope says.

## 14. Relations: edges vs rx-crud relations

**This is the one place ent and rx-crud do not overlap for free.** ent's `Edges`
field is ent's own loading mechanism; rx-crud ignores it, so `?preload=posts`
will not work out of the box. Two good options:

**A — let ent load edges.** Keep flat resources on ent entities and use ent's
`WithPosts()` where you genuinely need a graph. Most CRUD endpoints do not.

**B — a thin model struct for the resources that need relations.** It maps the
same table; your ent schema does not change.

```go
type Article struct {
    ID          int64               `db:"id,pk,auto"`
    AuthorID    int64               `db:"author_id"`
    Title       string              `db:"title"`
    PublishedAt crud.Opt[time.Time] `db:"published_at"`
    TenantID    int64               `db:"tenant_id,immutable"`
    CreatedAt   time.Time           `db:"created_at,generated"`

    Author   *Author   `rel:"belongs_to"`                     // fk: AuthorID
    Comments []Comment `rel:"has_many"`                       // fk: ArticleID on Comment
    Tags     []Tag     `rel:"many_to_many,join=article_tags"` // article_id / tag_id
}
```

Then, over HTTP:

```bash
curl -XPOST /articles/query -d '{
  "filter":  {"tags.slug": {"in": ["go","rust"]}, "author.name": {"contains":"an"}},
  "preload": ["author", "comments.author", "tags"],
  "sort":    ["-views", "author.name"]
}'
```

and in Go, `store.Article_.Author.Name.Eq("Ann")` — typed and compile-checked.

Two things worth knowing about how that runs:

- **A relation filter is a correlated `EXISTS`, not a join.** A join against a
  to-many edge multiplies rows: an article with two matching tags becomes two
  rows, `LIMIT 20` returns fewer than twenty distinct articles, and `COUNT(*)`
  reports a number that does not exist. `EXISTS` is a semi-join — one row in,
  one row out.
- **A preload is a batched second query, not a join.** One statement per
  relation per level, keys deduplicated, no N+1. It cannot be paginated,
  because a `LIMIT` over a batched load would truncate some parents' children
  and not others.

`immutable` and `generated` are the two tags you cannot express on an ent
struct, and they are exactly what stops a client rewriting `tenant_id` or
forging a timestamp.

## 15. Testing without a database

`../../crud/crudtest` is an in-memory datasource that records the SQL a repository
produces and replays canned rows:

```go
func TestServiceRejectsBadEmail(t *testing.T) {
    rec := crudtest.Postgres()
    svc := UserService{Repo: store.Users.Bind(rec)}

    u := ent.User{Email: "not-an-address"}
    if err := svc.Save(context.Background(), &u); !errors.Is(err, crud.ErrForbidden) {
        t.Fatalf("err = %v", err)
    }
    if len(rec.Statements()) != 0 {
        t.Fatal("nothing should have reached the database")
    }
}
```

For the HTTP layer, Fiber's `app.Test(req)` drives the whole handler; on Gin and
`net/http` it is `httptest.NewRecorder()` and `ServeHTTP(w, req)`.

## 16. Gotchas

**ent's Go-side defaults do not apply to rx-crud writes.**
`field.Time("created_at").Default(time.Now)` is Go code inside ent's builder. A
`POST /users` through rx-crud never runs it, so the column gets the zero value.
Three ways out, best first: put the default in the database (`DEFAULT now()`)
and mark the field `generated` on a model struct; set it in a `BeforeSave` hook;
or keep creates on ent's builder and let rx-crud own reads and updates.

**ent hooks, privacy rules and interceptors run inside ent's builders.** A write
that goes through rx-crud does not trigger them. Put invariants you cannot lose
in the database, in a `security.Policy`, or in your service layer. The same is
true of ent's Go-side defaults, and that half is pinned by a test
(`TestEntsGoSideDefaultsDoNotApplyToRxCrudWrites`): ent's builder fills in
`field.Bool("active").Default(true)`, an rx-crud `Save` writes the model's
`false`. No schema in the test tree declares a hook, so the hook half is
reasoned, not executed — it is the same code path.

**Column names are derived, not read from ent.** They agree for every normal ent
schema (`field.Int64("tenant_id")` → `TenantID` → `tenant_id`), but a field
named `emailAddress` gives ent the column `emailAddress` and rx-crud
`email_address`. The mapping test in [§9](#verify-the-mapping-once) catches it
at build time.

**`Edges` is ignored, not an error.** A struct-shaped field without a `rel` tag
is neither a column nor a relation. That is what makes ent entities work as-is,
and it means a typo'd relation tag fails silently as "no relation". Check
`Meta().Relations` if a preload unexpectedly 400s.

**Sorting through a to-many relation is refused.** A collection has no single
value to sort by.

**`Save` is an upsert.** No key → INSERT; key set → `ON CONFLICT DO UPDATE`.
Columns tagged `immutable` survive the conflict.
