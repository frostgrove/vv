# OpenTelemetry registry v1 to v2

The telemetry contract identifier changes from vv-otel/v1 to vv-otel/v2.
The module instrumentation scope keeps its name and published version.
Neither contract identifier is an OTel schema URL.

This migration changes registry authority and generated metadata. It does not
implement the planned adapters or replace the application's SDK. Current
fail-fast assembly consumes every enabled provider-compatible metric descriptor,
including planned descriptors, but only signals marked implemented are emitted.
Construction is not availability.
The complete contract is [otel-spec](../modules/otel-spec.md).

## Real SDK proof

The unpublished `test/oteltelemetry` package now runs the adapters against OTel
Go SDK v1.44.0. It verifies the native SERVER → Frostgrove INTERNAL → native
CLIENT parent chain, command span completion and status, exact allowed
attributes, command histogram data and an exemplar carrying the command span's
exact trace/span IDs. It also covers error privacy, unsampled execution,
trace-only and meter-only assembly, provider isolation and absence of global
mutation.

An in-process gRPC receiver exercises the official OTLP trace and metric
exporters without an external Collector or network. `make check-otel-live` runs
both proofs with `GOWORK=off` and `-race`; it is intentionally outside offline
`make check`. Pinned Weaver live validation remains OT-D05 work because the
Frostgrove wire manifest is not a Weaver registry.

## Preserved behavior and API

- Existing command and storage span names are unchanged.
- vv.command.duration keeps its name, description, seconds unit, explicit
  boundaries and 100-series bound.
- vv.cache.operations keeps its name, description, {operation} unit,
  facade/backend attribute sets and 116-series bound.
- cache_backend and memory_backend remain existing wire values; the distinct
  cache_memory component describes only future aggregate gauges.
- CacheOperationName, CacheOutcomeName, CacheBackendOperationName,
  CacheBackendOutcomeName, AllowedErrorCode, CommandSpanName and StorageSpanName
  retain their signatures and existing mappings.
- Existing exported names retain their spelling, including OutcomeOk,
  OpStorageTemporaryUrl and the ErrorCode…Id constants.
- AttributeMetadata and MetricMetadata retain their field order/types and both
  exported maps remain available. Calculated bound values may change when a
  registry vocabulary expands.

The v1 global operation-outcome bound was handwritten as 13 although its
combined vocabulary already had 16 values. V2 derives attribute bounds from
declared signal variants instead of retaining that stale number.

## New registry authority

Every component declares source inventories and total normalization mappings.
Real enum inventories are checked against source declarations. Registry-owned
vocabularies explicitly identify not-yet-implemented root observer contracts.
Source spellings remain distinct from wire spellings: remote BulkDelete,
runtime per-replica and jobs cancelled/timed_out have explicit normalizations.
Method provenance identifies files and interfaces, including complete embedded
method sets. Every actual method is mapped or explicitly excluded with a
reason. Free-function inventories also detect added exported declarations.
Typed source shapes cover 77 current surfaces and ten explicitly planned
storage-stream/executor-navigation/lifecycle/scheduler/C01 contracts. Mapped
members and signal inputs are reciprocal; direct measurements also require a
callable observation boundary. All other members have privacy/semantic
exclusions. Current fields,
accessors, callbacks and embedded interfaces are AST-checked; planned shapes
become AST-checked when their implementation card reconciles/promotes them.
An implemented signal cannot depend on a planned source input.
Singleton bindings name an attribute-owned finite domain; unrelated enum
values cannot enter via an unrestricted constant.
Each variant resolves its own component identity before checking domain
ownership, including mixed facade/backend signals. Only explicitly global
error domains can be shared across components.
Current callback inventories now connect `cache.Observer`,
`cachememory.Observer`, `auth.Observer`, `health.Probe`, `runtime.Observer` and
`jobs.WorkerObserver` to every signal they trigger. Config and both resource
option functions are AST-checked trace-only resource-name sources.
The runtime resource-name check consumes generated `MaxResourceNameBytes` and
`ValidResourceName`; its byte and charset policy cannot drift from the registry.
Their type is now `ApprovedName`. Literal call sites remain valid; dynamic
strings use `ApproveName`/`MustApproveName` or an explicit low-level
conversion, which runtime validation still checks. One `Telemetry` shares a
32-distinct-name budget across service and storage; duplicates are free and an
unused configured default is not pre-reserved.

Signals declare finite attribute variants. Cardinality is their deduplicated
tuple union, with omission distinct from a present value. Every metric requires
an authored positive budget; these are ceilings only. Trace-only declarations and error-code labels cannot enter
metric variants. Every histogram has an independently generated boundary
accessor.
The A04 Goexit terminal is span-only: goroutine_exit with Error status, no
error.type/code and no duration/counter observation. All bounded-operation
span wrappers admit that complete terminal shape; command metric100 and legacy
cache metric116 bounds remain unchanged. Command and storage now implement the
terminal; planned wrappers adopt the same recorder later.
Resolved span names and exact status/attribute variant descriptors are also
generated. Single-name constants contain the exact name; multi-name spans
have closed lookup helpers, without changing the permissive v1 helper API.
The generic generated matcher is available to future adapters, so they do not
need handwritten copies of cache/jobs unions.
Current command, storage and cache emitters admit complete candidate attribute
sets through it before OTel emission. A rejected set reaches no emitting API,
and the admitted slice never aliases its input.

The checked-in wire manifest and generated Go must match the same registry,
including every resolved variant field and complete migration metadata. The
migration note must be a repository-relative regular Markdown file and wire
changes are nonempty and unique. Generation/check/version workflows handle both outputs. Tests reject nested
duplicate JSON keys, stale artifacts, unknown or incomplete mappings,
incompatible metric types/units/bounds, forbidden dimensions and output-name
collisions.

## Stable signal IDs

The registry assigns stable integer IDs 1–59 across 18 components and 45 metric
descriptors (59 signals total). Signal is uint16 and Signals is []Signal;
IDs are not bit positions and the selector has no 64-signal limit. The ID range
is 1..65535, with zero invalid. AllSignals() returns an independent copy of the
active closed list. The independent embedded signal_history.json freezes the whole v2
roster. Editing the registry and migration signal_ids ledger together cannot
rename, delete or reuse a historical ID. Retirement is explicit and retains
the historical ledger reservation; it never releases an ID.
New descriptors append unused IDs rather than deriving positions from name
sorting.
The independent `availability_history.json` freezes the current six/53 runtime
roster. A signal may only append a `planned` → `implemented` promotion; an
unrecorded flip or regression fails generation.
`Config.Disable` accepts `Signals{SignalX, ...}`. `New` copies that slice,
rejects unknown and duplicate explicit IDs before disabled/provider handling,
then normalizes a private set; legacy aliases union idempotently afterward.
`Disable` was appended to `Config`, so positional/unkeyed `Config` literals no
longer compile and must move to keyed fields.

Each descriptor states tracer, meter or context_only provider requirements and
the exact native metric API kind. `New` obtains only selected provider families,
tracer before meter, and creates metric instruments in increasing signal-ID
order: 14 float64 histograms, 13 int64 histograms, 12 int64 counters and six
int64 observable gauges. It registers no callbacks. `Disabled` touches no
provider/API, while an enabled configuration requires at least one provider.

Assembly failure is a redacted `*AssemblyError` classified by stable sentinels.
Only an error returned by an instrument constructor is unwrapped; provider and
constructor panic objects are discarded. `Must` panics with that typed error.
There is no construction rollback or provider lifecycle ownership.

Log correlation uses separate context-only, explicit-handler metadata. Its
trace_id/span_id/trace_flags constants have no signal ID and are not OTel
attributes. TraceHandler can therefore remain independent of Telemetry.
The exact lower_hex widths are 32, 16 and 2 respectively.

## Planned measurement corrections

Storage operation bytes retain ID 5 and describe successful returned persisted
size only (Put Info.Size or Stage Staged.Info.Size), not consumed input bytes.
No input reader wrapping is introduced. Authentication/remote durations use
vv.authentication.duration and vv.remote.duration.

The new cache event/item signal union is 31 facade plus 18 backend tuples;
both observer callbacks source the mixed signals and the separate legacy
counter remains 116. Byte distribution bounds are 14/6 for
encoded/payload and 13/11 for backend value/charged bytes. Explicit source
presence predicates are separate from non-negative numeric admission:
empty cached String/Bytes payloads and empty backend values remain measured
zeros; absent/ambiguous fields are omitted. Legacy optional span events keep
their v1 attribute sets; new reason/memoization belongs to the rich planned
counter/distributions. Generated exact matchers take closed source facts;
descriptors expose copy-safe descriptions/boundaries and numeric admission.
This does not change current instrumentation because these signals are planned.
`Backend.Stats` is the only aggregate collection call; `Stats.Closed` gates
entries, bytes and limits so closed backends contribute no capacity.

ID 58 adds vv.storage.cleanup.removed with More and a source-checked
0..storage.MaxCleanupLimit bound. ID 59 adds
vv.jobs.worker.recovery.released with More for successful recovery only and a
0..jobs.MaxReclaimBatch (1000) bound.
Worker Active/Limit are explicitly excluded as stale event-sampled state;
Elapsed=0 is omitted because clock failure has no separate presence bit.
EnqueueOnce uses its public return enum; transaction forms remain staged
regardless of internal placement details.

Every worker projection consumes its outer event operation/outcome and callback;
items/bytes also consume failure, while result counts consume outer Results.
Numeric maxima are 1000 worker items, 67108864 worker bytes
(`jobs.MaxClaimBytes`), 1–256 delivery-result items and 1000 released leases.
Handler queue-delay/attempt measurements consume the `AdapterHandler`
invocation; attempt is in 1..`jobs.MaxAttemptOrdinal` (4129). Scheduler result
fields are in 0..`jobs.MaxDefinitions` (4096).
Worker admission/result unions are 8/13. Its 42 disposition tuples depend on
the OT-C05 root-emitter correction: nonzero dispositions project their own
Reason, while other commands project command.Reason. The current root emitter
does not yet preserve that distinction; this migration does not change it.

Current `runtime.Observer` state callbacks source transitions only.
`RunnerState.Err`, `StartedAt` and `EndedAt` are not unique completion events;
planned `LifecycleObserver` events alone source run/drain counts and durations.

Generation from the OTel directory now names both local outputs explicitly;
make generate also runs this satellite. Check/version workflows compare or
update both artifacts without creating a nested otel/otel directory.
